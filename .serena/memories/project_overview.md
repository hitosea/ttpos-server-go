# Project Overview (ttpos-server-go)

## Purpose
- Build a **modern POS backend** for the catering industry, supporting multiple terminals (pos/shop/kds/qds/assistant/tablet/mobile/menu/member) and business scenarios: ordering, table management, membership, delivery, reporting, etc.
- The backend uses a collaborative architecture of "Go Main Project (main) + GoFrame Middleware (ttpos-bmp) + WebSocket/redis-proxy", supporting scaling from 50 to 500 merchants.
- **The frontend implementation has been migrated to the independent repository `ttpos-flutter`. The PHP Admin and the built-in Vue3 Admin in this repository are considered LEGACY modules, used only for compatibility/reference and not for active evolution.**

## Tech Stack
- **Go Main (`main/`)**: Go 1.23+, Gin, GORM, MySQL 8.0+, Redis 6.0+, RocketMQ (optional), OpenTelemetry, Swagger.
- **Go Middleware (`ttpos-bmp/`)**: Go 1.23+, GoFrame v2.x, MySQL, Redis, gRPC, Nacos, OTel.
- **Shared Lib (`ttpos-api/`)**: gRPC / HTTP interface definitions and shared types.
- **Frontend Repo (Independent)**: `ttpos-flutter` (Flutter Monorepo, covering pos/shop/kds/qds/assistant/tablet/mobile/menu/member).
- **Legacy Modules** (Maintainance only, not for new features):
  - PHP Admin (`admin/`): PHP 8.0+, ThinkPHP 6.0 (Only for bugfix/data ops when necessary).
  - Built-in Vue3 Admin (`admin/views/`): Vue 3 + TypeScript + Vite + Element Plus (Legacy frontend, use `ttpos-flutter` for new features).
- **Infrastructure**: Docker / Docker Compose, Nginx, Redis Cluster, MySQL Master-Slave, SkyWalking, Prometheus + Grafana.

## Code Structure (Rough)
- `main/`: Go Main Business Service
  - `app/`: Layered structure (controller/service/repository/model/dto/constant).
  - `config/`: Configuration structure and loading.
  - `middleware/`: Gin middlewares.
  - `pkg/`: Common infrastructure (DB manager, event bus, lock, i18n, etc.).
  - `router/`: HTTP routes.
- `ttpos-bmp/`: GoFrame Microservice Middleware
  - `app/<module>/api`, `internal/controller`, `internal/logic`, `internal/dao`, `internal/model`, `router`, `manifest/{config,protobuf,sql}`.
- `ttpos-api/`: Shared API / gRPC definitions (Go packages).
- `admin/`: **Legacy PHP Admin**, follows ThinkPHP MVC (Controller/Service/Model/Validate).
- `admin/views/`: **Legacy Vue3 Admin Frontend**.
- `docs/`: Documentation system (agent/human/shared/team/others), the SSOT for current architecture and workflows.
- `.cursor/rules/`: Agent-facing rules (go-main.mdc/php.mdc/vue.mdc/database.mdc/workflows.mdc, etc.), the definitive source for constraints.

## Development Conventions (Brief)
- **Go Main (`main/`)**:
  - Strict Layering: API(handler) → Service → Repository → Model. API relies ONLY on Service, never Repository. Service gets DB via `ctx.GetDB()`. All DB ops MUST be encapsulated in Repository.
  - Naming: Struct ID fields in PascalCase (e.g., `StaffId`), URLs in snake_case. Interfaces `IXXXSrv`, implementation `xxxSrv` in the same file.
  - API Response: `data` MUST be an object (map/struct), **NEVER null or direct array**.
  - I18n Fields: Request and Response MUST use `dto.LocaleResponse`. Field names MUST use `LocaleName` / `LocaleXXXName` format. Custom map/struct forbidden.
  - Error Handling: No `panic`. Unified `return error`, wrapped with `errors.WithMessage`.
  - Transaction: Multi-table/multi-step updates MUST use transactions (`repository.CommonRepo.Transaction` or `db.Transaction`). Repository in transaction MUST be constructed with `tx`. No manual `Commit/Rollback`.
- **ttpos-bmp (GoFrame)**:
  - Strict structure `app/<module>/{api,internal,manifest}`. `dao/do/entity/service` are auto-generated by GoFrame CLI, DO NOT EDIT manually.
  - DB ops via `dao`. Transactions via `g.DB().Transaction`. Errors via `gerror`. Logs via `g.Log()`. Config via `g.Cfg()`.
  - Protobuf rules (Naming, Req/Resp suffix, Service naming) follow `ttpos-bmp/.cursor/rules/proto-rules.mdc`.
- **Legacy PHP Admin (`admin/`) & Built-in Vue3 Admin**:
  - Treated as **Legacy Systems**. Use only for fixing old online features or ops tasks. New features belong to `main/` + `ttpos-bmp/` + `ttpos-flutter`.
  - If modification is mandatory, follow `php.mdc` / `vue.mdc` but avoid new coupling or heavy refactoring.

## High-Level Tasks on Completion

- If DB schema changed:
  - Create migration script in `admin/database/migrations/` (PHP Phinx, **legacy tables only**) or `ttpos-bmp/manifest/sql/` (GoFrame). Follow field rules (int for time, decimal for money, required timestamps).
  - Sync Go/PHP models and DTOs. DO NOT introduce new core logic in legacy modules.
- Record key learnings or pitfalls to Graphiti (using `docs/agent/templates/graphiti-episode.md` template), especially regarding microservice splitting and legacy compatibility strategies.
