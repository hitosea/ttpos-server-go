# 编排示例

> 以下为用户自然语言指令示例，Claude 收到后按 SKILL.md 的流程拆解并执行。

---

## 一、并行执行

### 全包类型检查

```
帮我同时检查所有包的类型错误，并行跑完后汇总结果。
```

**拆解**：每个包一个独立任务，全部并行 → 汇总

---

### 多视角 Code Review

```
同时从三个角度审查这个文件：
- 安全性（注入、权限、输入验证）
- 性能（N+1 查询、不必要的 await）
- 逻辑正确性（边界条件、竞态、错误处理）
汇总所有发现。
```

**拆解**：3 个并行 `code-reviewer` 任务 → 汇总

---

## 二、DAG 依赖链

### 设计 → 实现 → 验证

```
开发一个"用户数据导出"功能：
1. 先设计 API 接口（Zod schema，支持 CSV/JSON）
2. 设计完后并行实现后端和前端
3. 前后端都完成后跑类型检查
```

**拆解**：

| # | 任务 | Agent | 隔离 | 依赖 |
|---|------|-------|------|------|
| 1 | 设计 API 接口 | Explore | — | — |
| 2 | 实现后端 | general-purpose | worktree | 1 |
| 3 | 实现前端 | general-purpose | worktree | 1 |
| 4 | 类型检查 | general-purpose | — | 2, 3 |

并行组：[1] → [2, 3] → [4]

---

### 调研 → 决策 → 实施

```
帮我选一个实时通知方案：
1. 同时调研 Socket.IO 和 SSE 的优缺点
2. 调研完后对比选型并实施
```

**拆解**：[调研 Socket.IO(Explore), 调研 SSE(Explore)] → [选型实施(general-purpose)]

---

### 重构三步走

```
把这个大文件拆成更小的模块：
1. 先分析结构，输出拆分方案
2. 执行拆分
3. 跑类型检查验证
```

**拆解**：[分析(Explore)] → [拆分(general-purpose)] → [验证(general-purpose)]，严格串行

---

## 三、Worktree 并行实现

### 多模块并行开发

```
实现订单模块的重构：
1. 先分析现有代码结构
2. 并行重构 Service 层和 Repository 层（改不同文件）
3. 合并后跑代码审查
```

**拆解**：

| # | 任务 | Agent | 隔离 | 依赖 |
|---|------|-------|------|------|
| 1 | 分析现有代码 | Explore | — | — |
| 2 | 重构 Service 层 | general-purpose | worktree | 1 |
| 3 | 重构 Repository 层 | general-purpose | worktree | 1 |
| 4 | 代码审查 | code-reviewer | — | 2, 3 |

并行组：[1] → [2(worktree), 3(worktree)] → [合并 → 4]

> Layer 2 的两个 agent 在独立 worktree 中并行工作，完成后 manager 按 ID 升序 cherry-pick 合并，再启动 Layer 3 审查。

---

## 四、批量处理

### 批量生成文档

```
为项目里的每个路由文件各生成一份 API 文档，并行处理。
```

**拆解**：每个文件一个并行任务 → 汇总

---

## 五、PR 前检查流水线

```
帮我跑 PR 前全套检查：
1. ESLint 和类型检查并行
2. 都通过后跑单元测试
3. 测试通过后跑构建
```

**拆解**：

| # | 任务 | 依赖 |
|---|------|------|
| 1 | ESLint | — |
| 2 | TypeScript 类型检查 | — |
| 3 | 单元测试 | 1, 2 |
| 4 | 生产构建 | 3 |

并行组：[1, 2] → [3] → [4]

---

## 六、错误排查

### 多方向并行排查

```
用户登录后偶尔 token 失效，帮我同时排查：
- token 生成和验证逻辑
- session 过期和刷新机制
- 相关中间件和错误处理
汇总发现。
```

**拆解**：3 个并行 `explore` 排查任务 → 汇总

---

## 七、跨目录批量修改

```
项目里有多个包都用了旧的函数名，帮我同时在每个包里查找替换，互不干扰。
```

**拆解**：每个包/目录一个并行 `general-purpose` 任务（worktree 隔离）→ 依次合并 → 汇总变更
