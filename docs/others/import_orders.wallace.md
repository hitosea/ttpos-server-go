# 历史订单导入 TTPOS 方案（给客户的说明稿）

## 1. 这件事要解决什么问题？

- **目标**：在更换到 TTPOS 时，把旧收银/点餐系统中的历史订单数据迁移过来，用于：
  - 历史营业额、折扣、赠菜、免单、税费等统计与对账；
  - 客服 / 财务 / 税务的历史订单查询；
  - （可选）会员消费分析、菜品销量分析等。
- **不做的事情**：
  - 不保证 100% 还原旧系统的计算过程和营销玩法，只保证**金额结果可对账**；
  - 不做实时双向同步，仅在约定窗口内做一次或有限次数导入。

---

## 2. 客户先做三件决策

- **第 1 步：选择最关心的功能维度（可以多选）**

| 功能维度                                         | 业务目的                                                 | 最低推荐导入深度                     |
| ------------------------------------------------ | -------------------------------------------------------- | ------------------------------------ |
| 基础营业统计（按日 / 月 / 门店 / 堂食 & 外带等） | 看清历史营业额、折扣、赠菜、免单、服务费、税费等整体走势 | 方案 A：只导入账单汇总               |
| 历史订单详情查询（客服 / 财务 / 税务场景）       | 按订单号快速查到当时的账单信息，用于客诉处理或单据核对   | 方案 A：只导入账单汇总               |
| 菜品销量与结构分析                               | 分析历史爆款 / 滞销菜品，评估价格策略和菜单结构          | 方案 B：账单 + 订单 + 菜品明细       |
| 会员消费分析（按会员 / 等级 / 渠道）             | 看清历史会员贡献、复购情况、客单价等                     | 方案 B + 会员字段映射（接近方案 C）  |
| 按来源渠道 / 国籍 / 分批等维度分析               | 分析不同渠道（外卖平台）、客群（国籍）、出菜节奏等       | 方案 B（基础）或方案 C（高精度还原） |
| 税务与合规报表支持                               | 满足当地税务检查、发票核对等合规要求                     | 方案 A：只导入账单汇总               |

- **第 2 步：选择导入时间范围**

  - 只导入近 3 个月 / 6 个月 / 12 个月，还是全部历史数据？
  - 是否有税务或审计要求的最低保留年限（例如需保留近 5 年）？

- **第 3 步：确认导入深度（A / B / C）**

| 导入方案 | 导入内容（简要）                                                            | 能做什么                                             | 典型适用   |
| -------- | --------------------------------------------------------------------------- | ---------------------------------------------------- | ---------- |
| 方案 A   | 每张账单的汇总信息（金额、状态、时间、门店、堂食/打包等）                   | 营业统计、税务/财务对账、按单号查询基础信息          | 小型门店   |
| 方案 B   | 方案 A + 每次结账记录 + 每道菜品明细（包含折扣、服务费、税费、赠菜/退菜等） | 菜品销量分析、菜单优化、部分会员分析                 | 大多数连锁 |
| 方案 C   | 方案 B + 自助餐套餐、分批类型、订单来源、国籍、会员积分记录等更多关联维度   | 接近还原旧系统的数据视图，用于深度运营和数据中台对接 | 大型集团   |

> 建议：大部分商户选 **方案 B + 近 12 个月数据**，成本可控，又能支撑日常运营分析。

## 3. 客户需要提供哪些数据？（按功能维度对照）

在与您沟通时，我们会先确认您选择了哪些功能维度，然后根据下表，明确旧系统需要导出的字段明细。

| 功能维度                               | 商户需提供的关键字段（来自旧系统导出或接口）                                                                                                                      |
| -------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **基础营业统计**                       | 每笔订单：门店/店号、业务日期与时间、订单编号、订单状态（完成/取消等）、堂食/打包、总金额、折扣金额、赠菜金额、免单金额、服务费、税费、实收金额、支付方式（可选） |
| **历史订单详情查询**                   | 在“基础营业统计”字段基础上，增加：退款/取消标记、订单备注、当班号、收银员标识（工号或账号）、若有发票号/税号也建议一并提供                                        |
| **菜品销量与结构分析**                 | 在“基础营业统计”字段基础上，增加每笔订单内的菜品明细：菜品编码或名称、规格、数量、单价、折扣后金额、服务费、税费、赠菜/退菜标记、所属分类（大类/小类，如有）      |
| **会员消费分析**                       | 在“菜品明细”字段基础上，增加：会员唯一标识（如手机号/会员号/会员 UUID）、会员等级、会员注册时间；并提供一份会员等级/权益规则说明文档                              |
| **按来源渠道 / 国籍 / 分批等维度分析** | 在“基础营业统计”或“菜品明细”字段基础上，增加：订单来源（平台/渠道）、国籍标识、自助餐标记及套餐信息、分批类型/批次标识等；同时提供对应的枚举值列表与中文说明      |
| **税务与合规报表支持**                 | 在“基础营业统计”字段基础上，确保：税率/税额字段清晰、抹零结果（抹零金额或抹零后的应收金额）、支付金额与支付方式、发票号/税号（若涉及开票）                        |

> 实际执行时，我们会根据您导出的样例文件，和您一起确认：哪些字段可以一一对应到 TTPOS 的 `SaleBill` 及相关结构，哪些需要用“备注/其他费用”方式处理。

## 4. 我们这边会做什么？（导入流程）

1. **需求确认 & 范围锁定**
   - 与您确认：功能维度、导入时间范围、导入方案（A/B/C）。
2. **样本数据 & 字段对照**
   - 您提供一批样本数据（建议：1 ～ 2 家门店、7 ～ 30 天）；
   - 我们输出《字段映射表 + 规则差异说明》，列清楚每一列如何落到 TTPOS。
3. **试导 & 对账**
   - 选定试点门店，导入一小段时间的数据；
   - 与您一起对比：日总营业额、抽查订单明细、会员消费记录等。
4. **正式导入 & 验收**
   - 根据试导结果调整规则，执行全量导入；
   - 双方签字确认：数据范围、对账结果、导入完成时间。

---

## 5. 风险与边界（需要提前确认）

- **数据质量前置**：若旧系统金额不一致、状态缺失、存在多版本订单，导入后我们只能做到“按您提供的数据对账”，无法替您纠正历史业务错误。
- **规则差异**：服务费、税费、抹零、积分、优惠券叠加等规则如与 TTPOS 不一致，导入时会以**金额结果正确**为优先，计算过程可能简化或写入备注。
- **历史数据只读**：为保证审计安全，导入后的历史订单默认设置为只读，不支持在 TTPOS 中直接修改原始金额，只能通过补录调整单据的方式修正。
- **项目成本与周期**：历史导入是独立项目，工作量与费用取决于：导入深度、数据量、功能维度数量以及旧系统供应商的配合程度，我们会在字段确认后给出具体评估。

## 6. 给决策层的一页话术（可直接对客户说）

- **一句话概括**：  
  “我们可以把您旧系统的历史订单导入到 TTPOS，至少保证营业额和税务对得上；如果您愿意多提供一些字段，还可以一起做菜品销量、会员分析等更深入的报表。”

- **您这边需要先做的事情**：

  1. 告诉我们：您最关心哪几类分析（例如：门店营业、菜品销量、会员、税务）；
  2. 决定导入的时间范围（近 3/6/12 个月，还是更长）；
  3. 配合旧系统供应商，按上表把对应字段导出给我们（先给一批样本，再做全量）。

- **我们这边承诺的结果**：
  - 在约定范围内，TTPOS 能和旧系统的关键报表对得上；
  - 导入前给您看字段映射和差异说明；
  - 导入后和您一起做对账验收，确认无误再正式切到新系统。
