## 🎯 背景和动机

### 问题描述

当前门店在前台主要依赖「桌台列表」和简单的区域维度管理桌台，缺少与真实餐厅空间一致的「桌台地图」视图：

- 前台收银员/点餐员需要在列表里查找桌号，空间位置感弱，尤其是大店/多区域门店，易点错桌、找错桌。
- 新管理端（桌面端）缺少可视化的桌台布局配置能力，实施同学无法帮助商户复刻真实门店布局。
- 收银机、点餐助手没有与配置侧打通的桌台地图模式，不同终端的桌台体验割裂。
- 云平台在商家层面对「桌台地图」「数据管理」缺少统一的开关和控制，难以分批试点或按商户策略启用能力。

### 业务价值

- 提升前厅桌台查找和翻台效率，降低排队和找桌时间。
- 帮助新员工通过直观地图快速熟悉门店布局，降低培训成本。
- 支持大店/多区域/复杂桌型门店的精细化运营，减少点错桌、结错单等操作失误。
- 在云平台侧提供统一的「桌台地图」「数据管理」开关能力，支持按商家策略渐进式开启。
- 为后续基于空间维度的运营能力（如区域热力、翻台效率分析等）打下基础。

## 💡 解决方案概述

### 方案描述

在「新管理端-桌面端」中，为餐厅管理模块新增「桌台地图」配置能力，提供一个可编辑画布，用于摆放、调整各区域桌台的位置、形状和容量，并与现有桌台数据打通。  
在「收银机 / 点餐助手」中，增加「桌台地图模式」切换按钮，针对已开启并完成地图配置的商家，根据管理端画布实时渲染可交互的桌台地图视图，支持放大缩小、筛选等操作。  
在「云平台-商家管理」中，为商家新增「桌台地图」「数据管理」两个控制开关，用于开启/关闭相关能力，并影响终端是否展示地图模式入口。

### 核心功能点

1. **新管理端（桌面端）-桌台地图配置画布**（任务 36930）

   - 餐厅区域列表：显示区域名称、桌数、状态（已设置/未设置）、编辑入口。
   - 编辑页：左侧为该区域桌台列表（勾选控制是否出现在画布），右侧为可缩放画布。
   - 支持在画布中拖拽桌台、切换桌台样式（圆桌/方桌）、调整桌台尺寸。
   - 桌台样式默认按该类型最大就餐人数展示（如 1-2 人用 2 人，3-4 人用 4 人等）。

2. **收银机/点餐助手-桌台地图模式展示**（任务 36909）

   - 在桌台页增加「地图模式」切换按钮，仅对开启并已设置桌台地图的商家展示。
   - 按管理端配置渲染桌台地图，可缩放画布，并支持按条件筛选后保留布局、隐藏无关桌台。
   - 地图模式与原有列表模式之间保持状态联动（选中桌台、筛选条件等）。

3. **云平台-商家管理-桌台地图相关开关**（任务 36936）
   - 在商家添加/编辑页增加「桌台地图」开关，默认关闭，控制商家是否具备桌台地图能力。
   - 增加「数据管理」开关，作为后续桌台相关数据管理、分析能力的前置控制。
   - 与下游新管理端、收银机/点餐助手等终端联动，未开启时隐藏相关菜单或按钮。

### 风险识别

**潜在风险**：

1. 桌台地图配置与现有桌台/订单/排队等业务的耦合度较高，兼容旧数据和历史门店配置存在复杂度。
2. 大规模桌台数量（如 200+ 桌）下，地图渲染性能和交互响应可能成为瓶颈。
3. 不同终端（收银机/点餐助手）屏幕尺寸和交互方式差异较大，需要统一交互模型。

**缓解措施**：

1. 通过清晰的数据模型设计，将桌台基础信息与空间布局信息解耦，提供版本化或灰度方案。
2. 在前端引入虚拟化渲染、分层绘制等技术，并对复杂布局进行压测与优化。
3. 优先在典型终端（桌面端、主流分辨率）上统一交互规范，其它终端通过适配层收敛差异。

## 📝 附录

### User Story（初稿）

**作为** 商户管理员  
**我想** 在新管理端（桌面端）中为每个区域配置与真实门店一致的桌台地图布局  
**以便于** 前台在各终端可以按真实空间位置管理桌台、提高翻台效率并减少操作错误。

**作为** 收银员/点餐员  
**我想** 在收银机或点餐助手中以「地图模式」查看和操作桌台  
**以便于** 快速定位桌台、减少点错桌，并在高峰期更快完成点单和结账。

**作为** 平台运营/实施人员  
**我想** 在云平台为商家开启/关闭「桌台地图」「数据管理」能力  
**以便于** 按商家分批试点、控制功能范围，并为后续数据分析能力做准备。

### AC 验收标准（初稿）

1. **WHEN** 商户在新管理端为某区域至少配置 1 张桌台并保存 **THEN** 该区域在桌台地图列表中状态应显示为「已设置」，且前台终端可按配置展示布局。
2. **IF** 云平台未为商家开启「桌台地图」 **THEN** 新管理端不展示桌台地图菜单，收银机/点餐助手也不展示地图模式切换按钮。
3. **WHEN** 收银员在地图模式下按条件筛选桌台（如某区域/状态） **THEN** 地图中仅保留满足条件的桌台位置，其它桌台被隐藏但整体布局不坍塌。
4. **WHEN** 在云平台关闭某商家的「桌台地图」或「数据管理」能力 **THEN** 相关终端入口应在合理时间内同步隐藏或禁用，且不影响既有订单处理流程。
