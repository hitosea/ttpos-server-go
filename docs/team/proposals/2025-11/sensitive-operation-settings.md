## 🎯 背景和动机

### 问题描述

普通员工在进行折扣/退款操作时，缺乏有效的权限控制机制。当前系统没有对敏感操作（如折扣、退款）进行二次验证，可能导致：

- 员工误操作或滥用权限
- 财务风险增加
- 门店经理/店长无法有效监管敏感操作

**用户故事**：

> 作为门店经理/店长，我想在业务设置中配置折扣/退款操作的权限验证，以便于控制普通员工进行敏感操作时的权限，降低财务风险。

### 业务价值

- ✅ 提供配置能力：为门店经理/店长提供敏感操作权限配置的入口
- ✅ 增强管理控制：门店经理/店长可以指定授权验证人
- ✅ 为后续验证功能打基础：为密码验证功能提供配置数据支持
- ✅ 符合餐饮行业管理规范：支持重要操作需要上级授权的管理需求

### 目标用户

- [x] 商户管理员（店长/门店经理）
- [x] 普通员工（收银员、服务员）

---

## 💡 解决方案概述

### 方案描述

在业务设置中新增"敏感操作设置"模块，支持配置折扣和退款操作是否需要权限密码验证，以及选择授权验证人。**本功能需要在两个终端实现：1) 新管理端（Go 项目的 shop 目录：`main/app/api/v1/shop/`）- 仅实现后端接口，无前端；2) (旧)商家后台（PHP 项目的 admin/shop 目录：`admin/app/shop/`）- 实现后端接口和 Vue 前端。** **注意：本提案仅包含业务设置页面的配置功能，密码验证逻辑将在其他任务中实现。**

### 核心功能点

1. **折扣操作权限设置**

   - 支持开启/关闭折扣操作密码验证开关
   - 支持多选授权员工（授权验证人）
   - 设置保存后，配置信息存储到数据库

2. **退款操作权限设置**

   - 支持开启/关闭退款操作密码验证开关
   - 支持多选授权员工（授权验证人）
   - 设置保存后，配置信息存储到数据库

3. **授权员工管理**
   - 支持多选员工作为授权验证人
   - 选中的员工标记为"授权验证人"
   - 支持员工列表展示和搜索

**说明**：本功能仅负责设置页面的配置和保存，不包含前端的密码验证逻辑实现。

### 影响范围

**涉及终端**：

- [x] **新管理端**：Go 项目的 shop 目录（`main/app/api/v1/shop/`）- 业务设置配置页面
- [x] **(旧)商家后台**：PHP 项目的 admin/shop 目录（`admin/app/shop/`）- 业务设置配置页面

**涉及模块**：

- [x] UI 组件（仅商家后台的设置页面，Vue 前端）
- [x] API 接口（Go：业务设置保存和查询接口；PHP：业务设置保存和查询接口）
- [x] 数据模型（业务设置表，存储折扣/退款权限配置和授权员工列表）

**不涉及**：

- ❌ 前端密码验证逻辑（POS、Assistant 端的验证将在其他任务中实现）
- ❌ 权限验证接口（验证逻辑将在其他任务中实现）

- **预估 SP**: 3-4 SP（待技术评审确认）

**分解**：

- Go 新管理端 API 接口开发（设置保存、查询）：0.5 天
- PHP 商家后台 API 接口开发（设置保存、查询）：0.5 天

### 风险识别

**潜在风险**：

1. 授权员工选择器需要支持多选和搜索，UI 交互需要优化
2. 设置数据需要与后续的验证逻辑任务对接，数据结构设计要预留扩展性
3. 需要在两个终端（新管理端 Go 和商家后台 PHP）都实现，需要确保一致性

**缓解措施**：

1. 参考现有的员工选择组件，复用成熟的交互模式
2. 在数据模型设计中考虑后续验证逻辑的需求，预留必要字段
3. 统一两个终端的实现方式，确保数据格式一致，API 接口行为一致

## 📝 附录

### User Story（初稿）

**作为** 门店经理/店长  
**我想** 在业务设置中配置折扣/退款操作的权限验证  
**以便于** 控制普通员工进行敏感操作时的权限，降低财务风险

### AC 验收标准（初稿）

1. **WHEN** 调用新管理端业务设置保存接口，传入折扣权限验证开关参数 **THEN** 系统 **SHALL** 保存开关状态到数据库
2. **WHEN** 调用新管理端业务设置查询接口 **THEN** 系统 **SHALL** 正确返回之前保存的折扣权限验证开关状态
3. **WHEN** 在商家后台的业务设置页面打开"折扣"权限验证开关 **THEN** 系统 **SHALL** 保存开关状态到数据库
4. **WHEN** 在商家后台的业务设置页面打开"退款"权限验证开关 **THEN** 系统 **SHALL** 保存开关状态到数据库
5. **IF** 授权员工选择器支持多选（商家后台前端） **THEN** 系统 **SHALL** 允许选择多个员工作为授权验证人
6. **IF** 授权员工已选择并保存 **THEN** 系统 **SHALL** 将选中的员工 ID 列表保存到数据库
7. **WHEN** 重新打开设置页面（商家后台）或调用查询接口（新管理端） **THEN** 系统 **SHALL** 正确显示之前保存的开关状态和授权员工列表
8. **WHEN** 通过新管理端 API 和商家后台分别保存设置 **THEN** 系统 **SHALL** 确保两个终端的数据格式一致，API 行为一致

**注意**：密码验证逻辑的验收标准将在其他任务中定义。
