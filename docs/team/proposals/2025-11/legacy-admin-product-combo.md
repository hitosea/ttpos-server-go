## 🎯 背景和动机

### 问题描述

在旧管理端的商品管理模块中，创建或编辑套餐时，套餐组的可选数量字段允许输入 0，这会导致业务逻辑错误。

**问题场景**：
> 商户在创建套餐时，如果某个套餐组的可选数量设置为 0，意味着该套餐组不允许选择任何商品，这与套餐的业务逻辑不符。套餐组应该至少允许选择 1 个商品。

### 业务价值

- 防止数据错误：避免创建无效的套餐配置
- 提升用户体验：明确提示用户输入有效值
- 减少后续问题：避免因数据错误导致的业务异常

## 💡 解决方案概述

### 方案描述

在旧管理端（PHP Admin 模块）的商品管理-套餐编辑页面，对套餐组的"可选数量"字段添加表单验证，禁止输入 0 或小于 1 的值。

**实现方式**：
> 在前端表单验证中添加最小值限制（min=1），并在后端接口中也进行相应的数据校验，确保套餐组的可选数量至少为 1。

### 核心功能点

1. 前端表单验证：套餐组可选数量字段最小值为 1，不允许输入 0 或负数
2. 后端数据校验：在保存套餐时验证套餐组可选数量，如果为 0 或小于 1，返回错误提示
3. 用户提示：当用户输入无效值时，显示明确的错误提示信息

## 📝 附录

### User Story（初稿）

**作为** 商户管理员  
**我想** 在创建套餐时，套餐组的可选数量字段不允许输入 0  
**以便于** 确保套餐配置的有效性，避免创建无效的套餐

### AC 验收标准（初稿）

1. **WHEN** 用户在套餐编辑页面输入套餐组可选数量为 0 **THEN** 系统 **SHALL** 显示错误提示"可选数量不能小于 1"
2. **WHEN** 用户在套餐编辑页面输入套餐组可选数量为负数 **THEN** 系统 **SHALL** 显示错误提示"可选数量不能小于 1"
3. **WHEN** 用户通过接口直接提交可选数量为 0 的数据 **THEN** 系统 **SHALL** 返回错误响应，拒绝保存
4. **WHEN** 用户输入可选数量为 1 或更大的正整数 **THEN** 系统 **SHALL** 允许保存
