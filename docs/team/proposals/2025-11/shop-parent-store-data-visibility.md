## 🎯 背景和动机

### 问题描述

当前新管理端首页和报表中心仅展示当前登录账号所属门店的数据，对于总部账号或有下级门店的账号，无法查看下级门店的经营数据。这导致总部或区域管理人员需要切换账号才能查看不同门店的数据，效率低下，无法进行统一的数据分析和对比。

### 业务价值

- **提升管理效率**：总部和区域管理人员可以在一个账号下查看所有下级门店的数据，无需频繁切换账号
- **数据统一分析**：支持跨门店数据对比和分析，帮助管理层做出更准确的经营决策
- **权限清晰**：根据账号类型（总部/有下级门店/无下级门店）动态显示门店选择功能，确保权限控制清晰
- **用户体验优化**：门店选择器支持树形结构展示，搜索功能，操作便捷

## 💡 解决方案概述

### 方案描述

在新管理端首页和报表中心增加门店选择功能，根据账号类型动态显示门店选择下拉按钮。总部账号和有下级门店的账号可以看到下拉按钮，点击后弹出门店选择弹窗，支持选择自己及所有下级门店。选择门店后，首页和报表中心的数据将根据选中的门店进行筛选展示。门店默认选择自己，无下级门店的账号不显示下拉按钮。

### 核心功能点

1. **门店选择器组件**
   - 根据账号类型（总部/有下级门店/无下级门店）动态显示/隐藏下拉按钮
   - 总部账号：可见下拉按钮，可选择自己及所有下级门店
   - 有下级门店的账号：可见下拉按钮，可选择自己及所有下级门店
   - 无下级门店的账号：不可见下拉按钮

2. **门店选择弹窗**
   - 树形结构展示门店层级关系（总部 → 一级门店 → 二级门店...）
   - 支持搜索功能，可按门店名称搜索
   - 单选框选择模式，点击门店即选中并关闭弹窗
   - 门店默认选择自己

3. **数据筛选**
   - 首页数据：根据选中的门店UUID筛选统计数据（总销售额、实收金额、店内概况、区域数据等）
   - 报表中心数据：根据选中的门店UUID筛选报表数据（渠道营业统计、商品销售统计、用户分析等）
   - 选择门店后，数据实时更新

4. **状态持久化**
   - 门店选择状态保存在前端（localStorage 或 Vuex）
   - 刷新页面后保持上次选择的门店
   - 切换页面时保持门店选择状态

### 风险识别

**潜在风险**：

1. **权限控制风险**：需要确保账号只能查看有权限的下级门店数据，不能越权访问
2. **性能风险**：如果门店层级很深或门店数量很多，树形结构渲染和数据查询可能影响性能
3. **数据一致性风险**：选择门店后，需要确保所有相关接口都正确传递门店UUID参数
4. **状态管理风险**：门店选择状态需要在多个页面间保持一致，需要合理设计状态管理方案

**缓解措施**：

1. 在后端接口中严格校验账号权限，确保只能查询有权限的门店数据
2. 对门店树形结构进行懒加载或分页处理，优化大数据量场景下的性能
3. 统一封装数据请求方法，确保门店UUID参数在所有接口中正确传递
4. 使用 Vuex 或 Pinia 进行全局状态管理，确保门店选择状态在页面间同步

## 📝 附录

### User Story（初稿）

**作为** 总部账号或区域管理人员  
**我想** 在新管理端首页和报表中心选择查看不同门店的数据  
**以便于** 统一管理和分析所有下级门店的经营情况，无需切换账号

### AC 验收标准（初稿）

1. **WHEN** 总部账号登录新管理端 **THEN** 系统 **SHALL** 在首页和报表中心显示门店选择下拉按钮
2. **IF** 账号有下级门店 **THEN** 系统 **SHALL** 显示门店选择下拉按钮，可查看自己及所有下级门店
3. **IF** 账号无下级门店 **THEN** 系统 **SHALL** 不显示门店选择下拉按钮
4. **WHEN** 用户点击门店选择下拉按钮 **THEN** 系统 **SHALL** 弹出门店选择弹窗，以树形结构展示门店层级关系
5. **WHEN** 用户在弹窗中搜索门店名称 **THEN** 系统 **SHALL** 过滤显示匹配的门店
6. **WHEN** 用户点击某个门店 **THEN** 系统 **SHALL** 选中该门店并关闭弹窗
7. **WHEN** 用户选择门店后 **THEN** 系统 **SHALL** 根据选中的门店UUID筛选首页和报表中心的数据
8. **WHEN** 用户刷新页面 **THEN** 系统 **SHALL** 保持上次选择的门店状态

### 技术实现要点

#### 前端实现

1. **门店选择器组件**
   - 位置：首页和报表中心页面顶部
   - 显示条件：根据账号类型（`user_type`）和是否有下级门店（`has_children`）判断
   - 组件：使用 Element Plus 的 `el-select` 或自定义下拉组件

2. **门店选择弹窗**
   - 使用 Element Plus 的 `el-dialog` 组件
   - 树形结构：使用 `el-tree` 组件展示门店层级
   - 搜索功能：使用 `el-input` 实现实时搜索
   - 单选框：使用 `el-radio` 或 `el-tree` 的节点选择功能

3. **状态管理**
   - 使用 Vuex 或 Pinia 存储当前选中的门店UUID
   - 使用 localStorage 持久化门店选择状态
   - 在路由守卫中恢复门店选择状态

4. **数据请求**
   - 封装统一的 API 请求方法，自动携带门店UUID参数
   - 在首页和报表中心的所有数据请求中添加门店UUID筛选

#### 后端实现

1. **获取门店树形结构接口**
   - 路径：`GET /api/v1/shop/store-tree`
   - 功能：根据当前账号权限返回门店树形结构
   - 权限校验：确保只能查询有权限的门店

2. **获取下级门店列表接口**
   - 路径：`GET /api/v1/shop/sub-stores`
   - 功能：获取当前账号的所有下级门店列表
   - 参数：`parent_uuid`（可选，用于递归查询）

3. **数据筛选逻辑**
   - 在首页统计接口中添加 `store_uuid` 参数
   - 在报表中心各统计接口中添加 `store_uuid` 参数
   - 根据门店UUID筛选订单、商品、用户等数据

#### 数据库查询优化

1. **门店层级查询**
   - 使用递归查询或预计算的层级路径（`parent_company_uuids`）
   - 考虑使用缓存优化门店树形结构查询

2. **数据筛选性能**
   - 确保门店UUID字段有索引
   - 对于大数据量场景，考虑分页或限制查询范围
