## 🎯 背景和动机

### 问题描述

当前库存管理存在以下问题：

1. **库存控制不够灵活**：无法通过可售量控制商品售卖，无法支持负库存场景
2. **沽清判断逻辑不统一**：不同终端（收银机、点餐助手、平板、扫码点餐、会员端、外卖）的下单、送厨、结账环节缺乏统一的沽清判断机制
3. **进销存计算与可售量关系不明确**：已配置成本卡的商品，在关闭进销存计算时，无法正确处理可售量与库存的关系
4. **负库存场景不支持**：当商品配置成本卡但在收银机关闭进销存计算时，无法允许负库存，影响正常售卖流程
5. **库存显示不准确**：套餐的"可售量"与"库存"概念混淆，原材料计算方式需要优化

### 业务价值

解决这些问题能带来以下业务价值：

- **提升库存管理灵活性**：支持通过可售量控制商品售卖，满足不同场景需求
- **支持负库存场景**：允许在特定条件下产生负库存，入库后自动弥补，提升售卖连续性
- **统一沽清判断逻辑**：所有终端统一使用沽清设置进行库存判断，保证数据一致性
- **优化库存计算**：明确进销存计算与可售量的关系，支持关闭进销存时的灵活售卖
- **提升用户体验**：减少因库存限制导致的订单失败，提升顾客满意度

## 💡 解决方案概述

### 方案描述

建立统一的沽清判断机制，支持灵活的库存管理策略：

1. **统一沽清判断**：在收银机、点餐助手、平板、扫码点餐、会员端、外卖的下单、送厨、结账环节，统一根据沽清设置进行库存判断
2. **可售量控制**：支持通过可售量控制商品售卖，下单时扣减可售量和库存
3. **负库存支持**：在特定场景下（已配置成本卡但关闭进销存计算）允许负库存，入库后自动弥补
4. **进销存计算灵活控制**：支持开启/关闭进销存计算，结合售罄和可售量设置，实现灵活的库存管理策略
5. **库存显示优化**：统一库存显示逻辑，支持负库存显示，优化套餐库存计算方式

### 核心功能点

1. **收银端沽清商品设置**：支持开启/关闭售罄、设置可售量、开启/关闭进销存计算，根据配置组合实现不同的库存控制策略
2. **统一沽清判断逻辑**：收银机、点餐助手、平板、扫码点餐、会员端、外卖在下单、送厨、结账时统一使用沽清设置进行库存判断
3. **可售量管理**：支持通过可售量控制商品售卖，下单时扣减可售量和库存，支持可售量不足时的提示
4. **负库存支持**：允许在特定场景下产生负库存（已配置成本卡但关闭进销存计算），入库后自动弥补
5. **库存查询优化**：物品库存查询支持负库存显示，出入库明细正常记录负库存场景的出库
6. **商品管理优化**：旧商家后台商品管理中，库存通过成本卡实时计算且不可修改，套餐"可售量"改为"库存"
7. **库存重新计算**：开启/关闭售罄、可售量时，需要重新计算库存

### 风险识别

**潜在风险**：
1. **数据一致性风险**：多个终端同时下单时，库存扣减可能出现并发问题，导致超卖或数据不一致
2. **负库存业务风险**：允许负库存可能导致库存管理混乱，需要明确业务规则和权限控制
3. **性能风险**：实时库存计算可能影响下单性能，特别是套餐商品需要计算多个原材料库存
4. **兼容性风险**：旧商家后台与新管理端的库存显示逻辑需要保持一致，避免用户困惑
5. **迁移风险**：未配置成本卡的商品默认行为变更，可能影响现有商户的使用习惯

**缓解措施**：
1. **并发控制**：使用分布式锁或数据库事务保证库存扣减的原子性，防止超卖
2. **权限控制**：负库存功能需要权限控制，仅允许特定角色或场景使用
3. **性能优化**：库存计算采用缓存机制，减少实时计算压力；套餐库存计算采用批量查询
4. **兼容性保证**：保持旧商家后台的库存显示逻辑，新管理端采用新的计算方式，逐步迁移
5. **默认行为保持**：未配置成本卡的商品保持原有默认行为（关闭售罄，无限售卖），避免影响现有商户

### User Story（初稿）

**作为** 商户管理员  
**我想** 在收银端设置商品的沽清规则（售罄、可售量、进销存计算）  
**以便于** 灵活控制商品的售卖策略，满足不同业务场景需求

**作为** 收银员  
**我想** 在下单时系统自动根据沽清设置判断商品是否可售  
**以便于** 避免超卖，提升订单成功率

**作为** 商户管理员  
**我想** 在特定场景下允许负库存  
**以便于** 在关闭进销存计算时仍能正常售卖，后续通过入库弥补负库存

**作为** 商户管理员  
**我想** 查看商品的实时库存（包括负库存）  
**以便于** 及时了解库存状况，做出补货决策

### AC 验收标准（初稿）

#### 场景1：未配置成本卡的商品

1. **IF** 开启售罄 **THEN** 系统 **SHALL** 不允许再售卖该商品
2. **IF** 关闭售罄 **THEN** 系统 **SHALL** 允许无限售卖
3. **IF** 关闭售罄且设置可售量 **THEN** 系统 **SHALL** 只允许售卖可售量数量，下单时扣减可售量

#### 场景2：已配置成本卡的商品（不允许负库存）

1. **IF** 设置可售量且库存不足 **THEN** 系统 **SHALL** 不允许售卖，提示库存不足
2. **IF** 设置可售量且库存充足 **THEN** 系统 **SHALL** 允许售卖，下单时扣减可售量和库存

#### 场景3：已配置成本卡的商品（允许负库存）

1. **IF** 设置可售量且库存不足但允许负库存 **THEN** 系统 **SHALL** 允许售卖，下单时扣减可售量和库存（允许负库存）
2. **IF** 关闭进销存计算且关闭售罄 **THEN** 系统 **SHALL** 允许无限售卖，可能产生负库存

#### 场景4：收银端沽清设置

1. **IF** 不配置成本卡且开启售罄 **THEN** 系统 **SHALL** 不允许再售卖
2. **IF** 不配置成本卡且关闭售罄 **THEN** 系统 **SHALL** 允许无限售卖
3. **IF** 不配置成本卡且关闭售罄且设置可售量 **THEN** 系统 **SHALL** 只允许售卖可售量数量
4. **IF** 配置成本卡且开启进销存计算 **THEN** 系统 **SHALL** 根据物品库存判断
5. **IF** 配置成本卡且关闭进销存计算且开启售罄 **THEN** 系统 **SHALL** 不允许再售卖
6. **IF** 配置成本卡且关闭进销存计算且关闭售罄 **THEN** 系统 **SHALL** 允许无限售卖
7. **IF** 配置成本卡且关闭进销存计算且关闭售罄且设置可售量 **THEN** 系统 **SHALL** 只允许售卖可售量数量

#### 场景4.1：默认设置

1. **WHEN** 商品首次配置成本卡 **THEN** 系统 **SHALL** 默认关闭进销存计算
2. **WHEN** 商品首次配置成本卡 **THEN** 系统 **SHALL** 默认关闭售罄
3. **WHEN** 商品首次配置成本卡 **THEN** 系统 **SHALL** 默认关闭可售量（不设置可售量限制）
4. **WHEN** 商品未配置成本卡 **THEN** 系统 **SHALL** 默认关闭售罄，允许无限售卖

#### 场景5：库存显示

1. **WHEN** 查询物品库存 **THEN** 系统 **SHALL** 显示当前库存（包括负库存）
2. **WHEN** 查看出入库明细 **THEN** 系统 **SHALL** 正常记录出库，即使产生负库存
3. **WHEN** 查看商品库存（旧商家后台） **THEN** 系统 **SHALL** 通过成本卡实时计算库存，且不可修改

#### 场景6：库存重新计算

1. **WHEN** 开启/关闭售罄 **THEN** 系统 **SHALL** 重新计算库存
2. **WHEN** 设置/修改可售量 **THEN** 系统 **SHALL** 重新计算库存

### 详细需求说明

#### 1. 收银机、点餐助手、平板、扫码点餐、会员端、外卖 - 下单、送厨、结账（沽清相关）

**核心规则**：下单、送厨、结账判断根据沽清中设置来判断

**说明**：外卖（包括 Grab 外卖等第三方外卖平台）也使用沽清中的设置来判断商品是否可售

**场景1：未配置成本卡，设置了可售量**
- 通过可售量进行售卖，下单扣减可售量

**场景2：已配置了成本卡，设置了可售量，物品库存不足，不允许负库存**
- 通过可售量进行售卖，下单扣减可售量和库存
- 即使设置可售量，但库存不足，依然不可售卖（使用库存不足提示）

**场景3：已配置了成本卡，设置了可售量，物品库存不足，允许负库存**
- 通过可售量进行售卖，下单扣减可售量和库存
- 根据可售量进行售卖

#### 2. 收银端 - 沽清商品设置（结合进销存+商品库存方式）

**默认设置规则**：

1. **配置成本卡的商品**：
   - 默认关闭进销存计算
   - 默认关闭售罄
   - 默认关闭可售量（不设置可售量限制）
   - 默认行为：允许无限售卖

2. **未配置成本卡的商品**：
   - 默认关闭售罄
   - 默认行为：允许无限售卖

**Given 不配置成本卡**

1. 开启售罄，则不可再售卖（注意：下单减库存/结账减库存，是下单减库存的，先下单再售罄再结账，允许）
2. 关闭售罄，则无限售卖
3. 关闭售罄，设置可售量，则只允许售卖可售量数量（售卖需扣减可售，注意：下单减库存/结账减库存，是下单减库存的，先下单再售罄再结账，允许）

**Given 配置成本卡**

1. 开启进销存计算，则根据物品库存判断库存
2. 关闭进销存计算，开启售罄，则不可再售卖
3. 关闭进销存计算，关闭售罄，则无限售卖
4. 关闭进销存计算，关闭售罄，设置可售量，则只允许售卖可售量数量（售卖需扣减可售）

**Given 开启or关闭或进行售罄、可售**

- Then 需要重新计算库存

**注意事项**：

1. 关闭进销存时，只是不采用进销存计算来计算库存可售，需根据设置的可售量进行售卖，此时可能会产生负库存
2. 十翅制作需要10个鸡翅，目前鸡翅库存10。收银机关闭十翅桶的通过进销存计算，并售卖了2份十翅桶，则10-10-10=-10库存，在出入库明细中照常出库20，在鸡翅的库存将显示-10
3. **默认设置**：
   - 未配置成本卡的商品：默认关闭售罄，允许无限售卖
   - 配置成本卡的商品：默认关闭进销存计算、默认关闭售罄、默认关闭可售量，允许无限售卖
4. 以往未配置成本卡的，默认不配置成本卡，关闭售罄，无限售卖（保持向后兼容）

#### 3. 物品库存查询

1. 允许负库存（作用在商品配置成本卡，但在收银机关闭进销存计算时的售卖，入库后弥补负库存）
2. 示例：十翅制作需要10个鸡翅，目前鸡翅库存10。收银机关闭十翅桶的通过进销存计算，并售卖了2份十翅桶，则10-10-10=-10库存，在出入库明细中照常出库20，在鸡翅的库存将显示-10

#### 4. 新管理端 - 出入库明细（沽清相关）

1. 已配置成本卡，在收银机关闭进销存计算时的售卖，正常出库物品
2. 示例：十翅制作需要10个鸡翅，目前鸡翅库存10。收银机关闭十翅桶的通过进销存计算，并售卖了2份十翅桶，则10-10-10=-10库存，在出入库明细中照常出库20，在鸡翅的库存将显示-10

#### 5. 旧商家后台 - 商品管理（沽清相关）

1. 添加/编辑中库存通过此商品或套餐关联商品的成本卡实时计算，并且不可修改。（最少是0）
2. 套餐的"可售量"改成库存
3. 注：原材料计算方式不保留

#### 6. 新管理端 - 物品库存明细（沽清相关）

1. 允许负库存（作用在商品配置成本卡，但在收银机关闭进销存计算时的售卖，入库后弥补负库存）
2. 示例：十翅制作需要10个鸡翅，目前鸡翅库存10。收银机关闭十翅桶的通过进销存计算，并售卖了2份十翅桶，则10-10-10=-10库存，在出入库明细中照常出库20，在鸡翅的库存将显示-10

- ✅ 技术团队提出改进方案
- ✅ 需要团队讨论和评审的需求

### 与 Spec 的区别

| 阶段        | 文档类型      | 详细程度 | 用途               |
| ----------- | ------------- | -------- | ------------------ |
| **需求发起** | Proposal      | 粗略     | 团队评审、决策是否做 |
| **需求确认** | Requirements  | 详细     | User Story + AC，开发依据 |
| **技术设计** | Design        | 详细     | 技术方案，实现指导 |
| **任务分解** | Tasks         | 详细     | 开发执行，进度追踪 |

### 流转路径

```
提案 (Proposal) 
  ↓ 评审批准
需求文档 (Requirements) 
  ↓ 技术评审
设计文档 (Design) 
  ↓ SP 评估 ≤ 5
任务分解 (Tasks)
  ↓
开发实现
```
