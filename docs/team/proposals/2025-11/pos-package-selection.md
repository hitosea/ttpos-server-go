## 🎯 背景和动机

### 问题描述

当前套餐商品在收银端、点餐助手、平板、会员端、自助点餐机等终端选择时，所有分组商品都是固定必选的，无法支持"可选分组"的场景。商户在后台已经可以配置套餐分组类型（固定/可选）和商品加价，但前端选择界面还没有适配这些功能。

**具体问题**：

- 无法区分固定分组和可选分组
- 无法显示"已选 X 份"、"还差 X 份"等选择状态
- 无法显示商品加价信息
- 无法在前端完成可选分组的商品选择
- 购物车中套餐价格计算未包含加价金额

### 业务价值

- **提升套餐灵活性**：支持可选分组，满足不同顾客需求
- **提高客单价**：通过加价商品引导顾客选择高价值商品
- **改善用户体验**：清晰的选择状态提示，减少操作困惑
- **统一前后端逻辑**：前端选择逻辑与后台配置保持一致

### 目标用户

## 💡 解决方案概述

### 方案描述

基于已有的套餐分组类型和加价功能（已在商家管理端实现），在前端各终端实现套餐商品选择功能：

1. **修改商品列表接口**：返回套餐分组类型、可选数量、商品加价等字段
2. **前端选择界面**：根据分组类型显示不同的选择逻辑
   - 固定分组：显示所有商品，必选
   - 可选分组：显示选择状态（已选 X 份、还差 X 份），支持步进器选择
3. **加购接口适配**：加购参数保持不变，但需要传递加价信息
4. **数据库扩展**：`sale_order_product` 表增加 `add_price` 字段
5. **价格计算调整**：购物车中套餐价格 = 套餐原始定价 + 所有子商品加价总和

### 核心功能点

1. **分组类型显示**

   - 固定分组：显示所有商品，默认选中，不可取消
   - 可选分组：显示选择状态，支持选择/取消

2. **选择状态提示**

   - 已选 X 份：当前已选择的数量（一个商品数量是 2，选了 1 份则显示"已选 1 份"）
   - 还差 X 份：当前还差的份数（可选数量 - 已选份数）
   - 商品数量角标：套餐内商品数量 × 选择份数（如商品数量是 2，选 1 份显示 2，选 2 份显示 4）

3. **加价显示**

   - 只有加价 > 0 的商品才显示价格
   - 0 元加价不显示价格

4. **选择交互**

   - 可选类型：点击商品后出现步进器（数量为 0 时不显示）
   - 可选类型：默认商品默认+1 份，必选商品必须保持一份
   - 固定类型：选择组内所有商品
   - 选择验证：分组已选满时提示"当前已选满，请删除商品再试"
   - 确定验证：分组未选满时提示"xx 还没有选满"

5. **数据存储**

   - `sale_order_product` 表增加 `add_price` 字段
   - 子商品记录单商品加价金额
   - 套餐主商品记录所有子商品加价总和

6. **价格计算**

   - 套餐单价 = 套餐原始定价 + 子商品加价 × 子商品数量 + ...
   - 购物车详情接口返回正确的套餐价格

7. **加购接口增强**
   - 请求参数支持传递子商品加价金额
   - 加购前验证分组选择是否符合套餐设置
   - 固定分组：验证是否选择所有商品
   - 可选分组：验证已选数量是否等于可选数量

## 📝 技术实现要点

### 1. 接口修改

**商品列表接口** (`GET /api/v1/{terminal}/product/list`)

需要在套餐分组信息中返回：

- `group_type`: 分组类型（0-固定，1-可选）
- `optional_count`: 可选数量
- `add_price`: 商品加价金额

**购物车详情接口** (`GET /api/v1/{terminal}/order/cart/info`)

需要在套餐商品中返回：

- `add_price`: 加价金额（子商品和主商品）
- 计算后的套餐总价（包含加价）

**套餐加购接口** (`POST /api/v1/{terminal}/order/cart/product_package/add`)

**请求参数变更**：

- `ProductRequest` 结构体增加 `add_price` 字段，用于传递子商品的加价金额

**接口功能增强**：

1. **传递加价参数**：接收并传递子商品的加价金额到后续处理流程
2. **分组选择验证**：
   - 固定分组（`group_type = 0`）：验证分组内所有商品是否都已选择
   - 可选分组（`group_type = 1`）：验证已选商品数量是否等于 `optional_count`
   - 验证失败时返回明确的错误提示

### 2. 数据库变更

**表**: `ttpos_sale_order_product`

新增字段：

```sql
ALTER TABLE `ttpos_sale_order_product`
ADD COLUMN `add_price` decimal(22,4) NOT NULL DEFAULT 0.00
COMMENT '加价金额。子商品记录单商品加价金额；套餐主商品记录所有子商品加价总和'
AFTER `sauce_price`;
```

**字段说明**：

- 子商品：记录该子商品的加价金额
- 套餐主商品：记录所有子商品的加价总和 = Σ(子商品加价 × 子商品数量)

### 3. 价格计算逻辑

**套餐单价计算**：

```
套餐单价 = 套餐原始定价 + Σ(子商品加价 × 子商品数量)
```

**示例**：

- 套餐原始定价：99 元
- 子商品 1：加价 5 元，数量 2 → 加价总额 = 5 × 2 = 10 元
- 子商品 2：加价 3 元，数量 1 → 加价总额 = 3 × 1 = 3 元
- **套餐单价** = 99 + 10 + 3 = **112 元**

### 4. 前端选择逻辑

**固定分组（group_type = 0）**：

- 显示分组内所有商品
- 所有商品默认选中，不可取消
- 不显示"已选 X 份"、"还差 X 份"

**可选分组（group_type = 1）**：

- 显示选择状态："已选 X 份"、"还差 X 份"
- 点击商品后显示步进器（数量为 0 时不显示）
- 默认商品默认+1 份
- 必选商品必须保持一份（减最后一份时提示：必选商品不可删除）
- 选择满额时提示："当前已选满，请删除商品再试"
- 未选满时提示："xx 还没有选满"

**加价显示**：

- 只有 `add_price > 0` 的商品才显示价格
- 0 元加价不显示价格

### 5. 套餐加购接口修改

**接口位置**: `main/app/service/order_product.go` - `OrderCartProductPackageAdd`

**修改内容**：

1. **请求参数扩展**：

   - `ProductRequest` 结构体增加 `AddPrice float64` 字段
   - 前端传递子商品的加价金额

2. **加价参数传递**：

   - 在构建 `subProduct` 时，从 `productReq.AddPrice` 获取加价金额
   - 传递给 `ProductParams` 结构体（需要在该结构体中添加 `AddPrice` 字段）

3. **分组选择验证**：
   - 在加购前，查询套餐的分组配置信息（`group_type`、`optional_count`）
   - **固定分组验证**：
     - 获取分组内所有商品列表
     - 验证请求中的商品是否包含分组内所有商品
     - 验证失败返回："固定分组必须选择所有商品"
   - **可选分组验证**：
     - 统计请求中该分组的已选商品数量（按份数统计）
     - 验证已选数量是否等于 `optional_count`
     - 验证失败返回："该分组需要选择 {optional_count} 个商品，当前已选 {实际数量} 个"
   - 验证逻辑应在构建商品参数之前执行

**验证流程**：

```
1. 接收加购请求
2. 查询套餐分组配置（group_type, optional_count）
3. 按分组UUID分组统计已选商品
4. 遍历每个分组：
   - 如果是固定分组：验证是否包含所有商品
   - 如果是可选分组：验证已选数量是否等于 optional_count
5. 验证通过后，继续后续加购流程
6. 传递加价参数到商品创建流程
```

**错误提示**：

- 固定分组未选满："固定分组必须选择所有商品，请重新选择"
- 可选分组未选满："该分组需要选择 {optional_count} 个商品，当前已选 {实际数量} 个，还差 {差值} 个"
- 可选分组超出："该分组最多选择 {optional_count} 个商品，当前已选 {实际数量} 个，请删除多余商品"
