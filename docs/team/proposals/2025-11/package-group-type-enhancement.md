## 🎯 背景和动机

### 问题描述

在套餐分组类型和加价功能的基础上，需要进一步支持**必选**和**默认选中**功能，以提供更灵活的套餐配置能力。当前可选分组中，所有商品都是平等的，无法引导顾客优先选择某些商品。

**具体问题**：

- 可选分组中无法设置某些商品为"必选"（必须选择才能下单）
- 可选分组中无法设置某些商品为"默认选中"（用户选购时默认选中）
- 收银端商品列表接口未返回必选和默认选中字段
- 前端选择界面无法根据必选和默认属性进行交互

**示例场景**：

> 一个"汉堡套餐"包含：
>
> - 固定分组：1 个汉堡（必选）
> - 可选分组：饮料 3 选 1（可乐、雪碧、橙汁）
>   - 其中"大杯可乐"设置为**必选**（必须选择才能下单）
>   - 其中"中杯可乐"设置为**默认选中**（默认选中，但可以取消）
> - 可选分组：小食 5 选 2（薯条、鸡块、鸡翅、洋葱圈、玉米杯）

### 业务价值

- **提升套餐灵活性**：通过必选和默认选中，引导顾客选择商家推荐的商品
- **提高客单价**：通过必选高价值商品，确保套餐的最低价值
- **改善用户体验**：默认选中常用商品，减少顾客选择时间
- **统一前后端逻辑**：前后端都支持必选和默认选中功能

## 💡 解决方案概述

### 方案描述

在套餐分组类型和加价功能的基础上，增加**必选**和**默认选中**两个属性：

1. **必选属性**：

   - 可选分组中的商品可以设置为"必选"
   - 必选商品必须选择才能下单
   - 必选商品在顾客选择时自动选中且不可取消
   - 必选数量不能大于可选数量

2. **默认选中属性**：

   - 可选分组中的商品可以设置为"默认选中"
   - 默认选中商品在用户选购时默认选中，但可以取消
   - 默认数量不能大于可选数量

3. **数据库扩展**：

   - `ttpos_product_package_group_item` 表增加 `is_required`（必选）和 `is_default`（默认选中）字段
   - 固定分组的这两个字段填默认值 0

4. **接口扩展**：

   - 商家管理端：创建/编辑/查询接口支持必选和默认选中字段
   - 收银端：商品列表接口返回必选和默认选中字段

5. **前端交互**：
   - 必选商品自动选中且不可取消
   - 默认选中商品默认选中但可以取消
   - 验证必选数量不能大于可选数量

### 核心功能点

1. **数据库扩展**

   - `ttpos_product_package_group_item` 表增加：
     - `is_required`：必选字段（0-不必选，1-必选）
     - `is_default`：默认选中字段（0-默认不选中，1-默认选中）
   - 固定分组的这两个字段填默认值 0

2. **商家管理端 API 接口扩展**

   - `/shop/product/add [POST]`：创建套餐接口
     - `ProductShopAddPackageGroupProductReq` 增加 `is_required`、`is_default` 字段
   - `/shop/product/edit [POST]`：编辑套餐接口（同步增加字段）
   - `/shop/product/detail [GET]`：商品详情查询接口（返回新增字段）

3. **收银端 API 接口扩展**

   - `/api/v1/{terminal}/product/list [GET]`：商品列表接口
     - `PackageProductDetail` 结构体增加 `is_required`、`is_default` 字段
     - 返回套餐分组商品的必选和默认选中信息

4. **数据迁移**

   - 创建 SQL 迁移文件，为现有数据设置默认值
   - 现有商品必选和默认选中默认为 0（不必选、不默认选中）

5. **业务逻辑验证**

   - 必选数量不能大于可选数量
   - 默认数量不能大于可选数量
   - 必选商品必须保持一份（减最后一份时提示：必选商品不可删除）

6. **前端选择交互**
   - 必选商品：自动选中且不可取消
   - 默认选中商品：默认选中但可以取消
   - 必选商品减最后一份时提示："必选商品不可删除"

## 🛠️ 开发实现思路

### 1. 数据库表结构扩展

#### `ttpos_product_package_group_item` 表

- 增加 `is_required` 字段：`TINYINT DEFAULT 0 COMMENT '必选 0-不必选 1-必选'`
- 增加 `is_default` 字段：`TINYINT DEFAULT 0 COMMENT '默认选中 0-默认不选中 1-默认选中'`

**字段说明**：

- 必选：要求本套餐必选选择该商品才能下单
- 默认选中：表示默认选中，即用户选购该商品时默认选中该商品
- 固定分组的这两个字段填默认值 0

### 2. 商家管理端 API 接口参数扩展

#### `/shop/product/add [POST]` 创建套餐接口

**`ProductShopAddPackageGroupProductReq` 参数增加**：

```go
IsRequired int `json:"is_required"` // 必选 0-不必选 1-必选
IsDefault  int `json:"is_default"`  // 默认选中 0-默认不选中 1-默认选中
```

#### `/shop/product/edit [POST]` 编辑套餐接口

- 同步增加上述字段

#### `/shop/product/detail [GET]` 商品详情查询接口

- 返回数据中增加上述字段

### 3. 收银端商品列表接口扩展

#### `/api/v1/{terminal}/product/list [GET]` 商品列表接口

**`PackageProductDetail` 结构体增加**：

```go
IsRequired int `json:"is_required"` // 必选 0-不必选 1-必选
IsDefault  int `json:"is_default"` // 默认选中 0-默认不选中 1-默认选中
```

**响应格式示例**：

```json
{
  "package_group_list": {
    "list": [
      {
        "uuid": 789012,
        "group_type": 1,
        "optional_count": 2,
        "products": {
          "list": [
            {
              "detail": {...},
              "num": 1,
              "add_price": 5.00,
              "is_required": 1,    // ⭐ 新增：必选
              "is_default": 0,      // ⭐ 新增：默认选中
              "can_edit": true
            }
          ]
        }
      }
    ]
  }
}
```

### 4. SQL 迁移文件

创建迁移文件，为现有数据设置默认值：

- `is_required = 0`（不必选）
- `is_default = 0`（不默认选中）

### 5. 业务逻辑验证

- 必选数量不能大于可选数量
- 默认数量不能大于可选数量
- 必选商品必须保持一份（减最后一份时提示：必选商品不可删除）
- 固定分组时，`is_required` 和 `is_default` 必须为 0

### 6. 前端选择交互逻辑

**必选商品**：

- 自动选中且不可取消
- 减最后一份时提示："必选商品不可删除"
- 在可选分组中，必选商品必须保持至少 1 份

**默认选中商品**：

- 默认选中但可以取消
- 用户可以自由增加或减少数量
- 取消后可以重新选择

**验证逻辑**：

- 保存套餐时验证：必选数量 <= 可选数量
- 保存套餐时验证：默认数量 <= 可选数量
- 前端选择时验证：必选商品不能删除到最后一份

## 📝 附录

### User Story（初稿）

**作为** 商户管理员  
**我想** 在可选分组中设置某些商品为必选或默认选中  
**以便于** 引导顾客选择商家推荐的商品，提高客单价，改善用户体验

**作为** 收银员/顾客  
**我想** 在选择套餐商品时，看到必选和默认选中商品的标识，并能够正确选择  
**以便于** 快速完成套餐选择，了解哪些商品是必选的

### AC 验收标准（初稿）

#### AC1：必选属性设置

**Given** 可选分组商品  
**When** 设置商品为必选  
**Then** 系统 **SHALL** 提供"必选"复选框  
**And** 必选商品在顾客选择时自动选中且不可取消  
**And** 必选数量不能大于可选数量

#### AC2：默认选中属性设置

**Given** 可选分组商品  
**When** 设置商品为默认选中  
**Then** 系统 **SHALL** 提供"默认选中"复选框  
**And** 默认选中商品在用户选购时默认选中，但可以取消  
**And** 默认数量不能大于可选数量

#### AC3：固定分组限制

**Given** 固定分组商品  
**When** 设置必选或默认选中  
**Then** 系统 **SHALL** 不允许设置（固定分组的必选和默认选中必须为 0）

#### AC4：商家管理端接口支持

**Given** 创建或编辑套餐  
**When** 传递 `is_required` 和 `is_default` 字段  
**Then** 系统 **SHALL** 正确保存和返回这些字段

#### AC5：收银端商品列表接口支持

**Given** 查询商品列表  
**When** 返回套餐分组商品信息  
**Then** 系统 **SHALL** 包含 `is_required` 和 `is_default` 字段

#### AC6：前端选择交互

**Given** 可选分组包含必选商品  
**When** 顾客选择套餐商品  
**Then** 系统 **SHALL**：

- 必选商品自动选中且不可取消
- 减最后一份时提示："必选商品不可删除"
- 默认选中商品默认选中但可以取消

#### AC7：验证逻辑

**Given** 保存套餐配置  
**When** 必选数量大于可选数量  
**Then** 系统 **SHALL** 提示错误："必选不可大于可选数量"

**Given** 保存套餐配置  
**When** 默认数量大于可选数量  
**Then** 系统 **SHALL** 提示错误："默认不可大于可选数量"
