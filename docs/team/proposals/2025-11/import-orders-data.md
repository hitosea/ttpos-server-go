## 🎯 背景和动机

### 问题描述

华莱士正在从旧的 POS 系统迁移到 TTPOS 系统，在系统切换过程中，需要将旧系统的历史订单数据完整地导入到 TTPOS 系统中，以保证数据的连续性和完整性。

当前面临的问题：

1. 旧系统和新系统的数据结构不一致
2. 历史订单数据量大，需要批量导入能力
3. 数据迁移需要保证数据完整性和准确性
4. 需要支持数据校验和错误处理机制

### 业务价值

解决这个问题能带来以下业务价值：

- **数据连续性**：保证历史数据的完整性，方便后续数据分析和对账
- **业务平滑过渡**：确保系统切换过程中业务不中断，历史数据可查询
- **数据分析基础**：完整的历史数据为后续的经营分析提供基础
- **合规要求**：满足财务和税务对历史订单数据的保存要求
- **客户服务**：支持查询历史订单，提供更好的售后服务

## 💡 解决方案概述（MVP - 最小可执行方案）

### 一句话概括

**华莱士提供标准 Excel → Shop 管理端上传 → 解析写入数据库 → 返回结果**

### 方案描述

提供一个简单直接的订单数据导入功能，支持从 Excel 文件批量导入历史订单数据到 TTPOS 系统。

**实现步骤**：

1. 华莱士按约定格式准备 Excel 文件（订单基本信息 + 明细）
2. Shop 管理端添加"导入订单"页面，提供文件上传
3. 后端接收文件，使用 `excelize` 解析 Excel
4. 校验必填字段和关联数据（门店、商品等）
5. 批量写入 `order` 和 `order_detail` 表
6. 返回导入结果（成功 X 条，失败 Y 条及原因）

### 核心功能点（MVP）

1. **Excel 上传**：在 Shop 管理端提供文件上传入口
2. **数据解析**：解析 Excel 文件，读取订单数据
3. **基础校验**：校验必填字段和数据格式
4. **直接导入**：将数据写入订单相关表
5. **结果反馈**：显示导入成功数量和失败原因

### 🚫 MVP 暂不包含

- ~~模板下载功能~~（由华莱士按约定格式准备）
- ~~实时进度条~~（小批量数据直接同步处理）
- ~~数据预览~~（直接导入，信任数据源）
- ~~详细日志下载~~（仅返回基本错误信息）
- ~~回滚机制~~（导入前备份数据库即可）
- ~~异步队列~~（小批量同步处理即可）

## 📊 初步评估

### 技术复杂度

- [x] **低**：基础的文件上传和数据解析，逻辑简单
- [ ] **中**：需要前后端联调，基础业务逻辑
- [ ] **高**：涉及架构调整、第三方集成、复杂算法

### 工作量预估（MVP）

- **预计天数**: 2-3 天
- **预估 SP**: 3 SP

**MVP 工作量拆分**：

- 确认 Excel 格式和字段映射：0.5 天
- 后端：文件上传 + Excel 解析 + 数据写入：1 天
- 前端：上传页面 + 结果展示：0.5 天
- 测试和修复：0.5 天

### 风险识别（MVP）

**主要风险**：

1. **数据格式不规范**：Excel 格式不符合约定
2. **关联数据缺失**：引用的商品、门店等不存在

**缓解措施**：

1. **前置沟通**：明确 Excel 格式规范，华莱士提供符合要求的数据
2. **基础校验**：校验必填字段和关联数据存在性，失败时给出明确提示
3. **小批量测试**：先用少量数据测试，确认无误后再批量导入

## 📝 附录

### User Story（初稿）

**作为** 系统管理员  
**我想** 将华莱士旧系统的历史订单数据批量导入到 TTPOS 系统  
**以便于** 保证数据的连续性和完整性，支持历史数据查询和分析

### AC 验收标准（MVP）

1. **WHEN** 管理员上传符合格式的 Excel 文件 **THEN** 系统 **SHALL** 成功解析并导入数据
2. **WHEN** 上传的数据存在格式错误 **THEN** 系统 **SHALL** 提示错误原因
3. **WHEN** 导入完成 **THEN** 系统 **SHALL** 显示成功数量和失败原因
4. **IF** 导入的订单号已存在 **THEN** 系统 **SHALL** 跳过该订单并提示

### 数据字段映射（基于订单详情页面）

根据订单详情页面显示，华莱士需要提供以下字段数据：

| 字段名称 | 字段说明 | 示例值 | 是否必填 | 备注 |

| **订单号** | 订单唯一标识 | 202511262200768599 | ✅ 必填 | 用于去重，重复则跳过 |
| **订单类型** | 订单类型 | 桌台订单/点餐订单 | ✅ 必填 | 1=点餐订单, 2=桌台订单 |

| **桌号** | 桌台编号 | A02 | ⚠️ 条件必填 | 桌台订单必填 |
| **订单金额** | 订单总金额 | 92.00 | ✅ 必填 | 单位：元，保留2位小数 |

#### Excel 格式要求

**Sheet 1: 订单基本信息**
- 表头：订单号、订单类型、用餐方式、订单来源、订单状态、桌号、订单金额、实付金额、订单开始时间、订单结束时间、支付方式、支付时间、收银员、会员、国籍、门店ID、桌台ID、会员ID、收银员ID

**Sheet 2: 订单商品明细**
- 表头：订单号、商品名称、商品ID/SKU、单价、购买数量、商品总价
- 一个订单号可以有多行商品明细

#### 数据校验规则

1. **必填字段校验**：订单号、订单类型、用餐方式、订单状态、订单金额、实付金额、订单时间、支付方式、支付时间、收银员
2. **关联数据校验**：门店ID必须在系统中存在
3. **数据格式校验**：
   - 订单号：字符串，不能为空
   - 金额：数字，保留2位小数，必须 ≥ 0
   - 时间：格式 YYYY-MM-DD HH:mm:ss
   - 数量：正整数
4. **业务逻辑校验**：
   - 订单号重复则跳过（已存在）
   - 桌台订单必须填写桌号
   - 商品总价 = 单价 × 数量
   - 订单金额应等于所有商品总价之和（允许一定误差）

### 技术实现要点（MVP）

1. **Excel 文件处理**：

   - 支持 `.xlsx` 格式
   - 使用 Go 的 `excelize` 库
   - 单次限制 5000 条（超过建议分批）

2. **基础校验**：

   - 必填字段检查（订单号、时间、金额）
   - 关联数据检查（门店、商品是否存在）
   - 数据格式检查（日期、金额格式）

3. **导入逻辑**：
   - 使用事务保证一致性
   - 订单号重复则跳过
   - 批量插入（每批 500 条）
