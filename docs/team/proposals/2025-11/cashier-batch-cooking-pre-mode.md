## 🎯 背景和动机

### 问题描述

当前收银机分批送厨功能仅支持**后置关联模式**，即商品下单后才进行分批类型关联。这种方式存在以下问题：

1. **操作效率低**：收银员需要先下单，再在分批送厨弹窗中选择类型，操作步骤多
2. **灵活性不足**：无法在选购商品时就预先规划分批类型，需要记忆哪些商品要分到哪一批
3. **用户体验差**：在购物车中无法直观看到商品的分批类型，容易出错

**示例场景**：

> 收银员在点餐时，需要将主食和饮料分开送厨。当前流程是：先全部下单 → 点击送厨 → 在弹窗中选择类型。如果商品较多，容易选错类型或遗漏。

### 业务价值

解决这个问题能带来以下业务价值：

- **提升操作效率**：减少操作步骤，在选购商品时即可关联分批类型
- **降低操作错误率**：购物车中直观显示分批类型，减少选错概率
- **提升用户体验**：收银员可以提前规划分批策略，操作更流畅
- **支持复杂场景**：支持同一商品选择不同分批类型，满足多样化需求

## 💡 解决方案概述

### 方案描述

在收银机中新增**前置关联模式**，允许收银员在选购商品时就关联分批类型。具体包括：

1. **商品选购阶段**：显示分批类型选择器，默认选择排序第一的类型，可切换
2. **购物车展示**：购物车中显示商品关联的分批类型（使用缩写或全名，带颜色标识）
3. **送厨操作**：点击送厨后，弹出分批送厨弹窗，显示已关联类型的商品，支持更换类型

### 核心功能点

1. **分批类型选择器**

   - 在点餐/开桌时显示分批类型列表（来源商家后台）
   - 默认选择排序第一的类型
   - 支持切换类型，切换后新加购商品关联新类型

2. **购物车类型展示**

   - 购物车中显示商品关联的分批类型（有缩写显示缩写，无缩写显示全名）
   - 使用类型颜色进行视觉区分
   - 同一商品选择不同分批类型时，分开显示（如：主食-西瓜，水果-西瓜）

3. **分批送厨弹窗增强**
   - 显示需要分批送厨的商品及其关联类型
   - 商品边框显示类型颜色
   - 未送厨商品支持点击"更换"图标更换类型
   - 点击类型按钮，将已关联该类型的未送厨商品进行送厨

### 技术实现参考

根据任务描述，技术实现思路包括：

1. **业务设置接口调整**

   - `/cashier/base` 接口增加字段，告知前端商户的分批送厨模式（前置/后置）

2. **购物车签名计算**

   - 将 `batch_tag_uuid` 加入到商品签名计算的参数中
   - 相同商品而不同分批类型的购物车商品在购物车中要分开两条数据显示

3. **加购接口调整**

   - 当前置模式时，加购接口需要增加 `batch_tag_uuid` 字段
   - 接口处理逻辑中，如果是前置模式时，需要计算新加购商品的签名
   - 如果签名相同的商品要合并在一起

4. **更换类型接口**

   - 当前置模式开启时，增加一个接口对未送厨的商品进行更换分批类型
   - 已经送厨的商品不能修改商品的分批类型
   - 该接口仅在前置模式时使用

5. **分批送厨弹窗调整**

   - 当前置模式开启时，用户点击送厨后仍然是所有商品都送厨
   - 分批送厨的商品也仍然是变为预送厨模式
   - 弹出的分批送厨弹窗中所有的分批送厨商品都是已经关联了分批类型
   - 点击对应的类型按钮则送出对应的类型商品

6. **分批类型列表接口**
   - 修改获取分批送厨弹框的销售订单商品列表接口，分批类型列表的排序根据 sort 排序，优先级高的在前
   - 新加一个分批类型列表接口，也是根据 sort 排序，优先级高的在前

## 📝 附录

### User Story（初稿）

**作为** 收银员  
**我想** 在选购商品时就关联分批类型，以便于提前规划分批送厨策略，减少操作步骤和错误率

### AC 验收标准（初稿）

#### AC1：前置关联模式基础功能

**Given** 商户开启了前置关联模式  
**When** 收银员点餐或开桌，选购商品  
**Then** 显示分配类型选择器（来源商家后台类型）  
**And** 默认选择排序第一的类型  
**And** 可以切换类型

#### AC2：商品关联类型

**Given** 前置关联模式开启  
**When** 收银员选择商品并加购  
**Then** 选购商品与当前选中的分批类型进行关联  
**And** 购物车中可见商品已根据关联类型而显示对应类型（无缩写则为全名称，有颜色）

#### AC3：同一商品不同类型分开显示

**Given** 前置关联模式开启  
**When** 收银员选购同一商品，但选择不同的分批类型  
**Then** 购物车中分开体现，如：主食-西瓜，水果-西瓜  
**And** 参考商品退菜逻辑，下单两份退一份后分开展示

#### AC4：不需要分批送厨的商品

**Given** 前置关联模式开启  
**When** 选购不需要分批送厨的商品  
**Then** 不受类型影响  
**And** 已下单未下单无需显示类型或 D 标识

#### AC5：分批送厨弹窗

**Given** 前置关联模式开启，有未送厨商品  
**When** 收银员点击送厨按钮  
**Then** 有真正未下单的商品，按钮高亮  
**And** 出现分批送厨弹窗，显示需要分批送厨的商品  
**And** 可见商品所关联的类型边框（使用类型颜色）

#### AC6：更换分批类型

**Given** 前置关联模式开启，有未真正送厨商品  
**When** 收银员点击"更换"图标  
**Then** 可以更换类型  
**And** 更换后同步到收银机购物车及点餐助手

#### AC7：按类型送厨

**Given** 前置关联模式开启，分批送厨弹窗已打开  
**When** 收银员点击下方类型按钮  
**Then** 将已关联此类型未送厨的商品进行送厨（包括点餐助手）

## 📄 模板使用说明

### 与后置关联模式的区别

| 特性           | 后置关联模式（已实现）                | 前置关联模式（本提案）         |
| -------------- | ------------------------------------- | ------------------------------ |
| **关联时机**   | 商品下单后，在送厨弹窗中选择          | 商品选购时即关联               |
| **购物车显示** | 显示商品及关联类型，未下单商品标识"D" | 显示商品及关联类型，带颜色标识 |
| **操作流程**   | 下单 → 送厨 → 选择类型                | 选择类型 → 加购 → 送厨         |
| **灵活性**     | 较低，需要记忆                        | 较高，可提前规划               |

### 技术实现要点

1. **购物车签名计算**：需要包含 `batch_tag_uuid`，确保相同商品不同类型能分开显示
2. **数据同步**：更换类型操作需要同步到点餐助手端
3. **模式切换**：通过业务设置控制，确保两种模式互不干扰
