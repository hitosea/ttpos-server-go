## 🎯 背景和动机

### 问题描述

商户希望设置特价菜品来吸引顾客，提升销量，但当前系统缺乏灵活的特价菜管理功能，无法快速设置和展示特价商品。虽然系统已有满减营销活动功能，但缺少针对单个商品的特价设置能力，无法实现更精细化的营销策略。

### 业务价值

- **提升商品销量**：通过特价促销快速清理库存，促进库存周转
- **吸引顾客消费**：特价商品在点餐界面突出显示，吸引顾客关注和下单
- **灵活营销策略**：支持按时间段、按周期、按用户类型等维度设置特价规则，实现精细化营销
- **提升商户运营效率**：统一的活动管理入口，简化特价菜设置流程
- **增强竞争力**：与满减活动形成互补，提供更多营销工具选择

## 💡 解决方案概述

### 方案描述

在营销活动管理中增加"特价菜"活动类型，与"满减/每满减"活动并列。商户可以创建特价菜活动，为指定商品设置特价价格，并配置活动规则（名称、时间、周期、活动时段）、参与规则（适用用户、限购数）和同享规则。**满减、优惠券、特价菜三者不可同享**，用户在结账时只能选择其中一种优惠方式。**但多个特价菜活动之间可以同享**，用户可以选择多个特价菜活动同时生效。特价商品在点餐界面显示原价和特价（原价划掉），在结账页面显示可参与的特价菜活动供用户选择。

### 核心功能点

1. **创建活动，增加特价菜选择**
   - 在"添加促销活动"页面增加"特价菜"选项，与"满减/每满减"并列
   - 特价商品选择：支持选择多个商品，显示商品名称、原价，设置特价（必填）
   - 活动规则配置：
     - 活动名称（必填，1-50字符）
     - 活动时间：永久有效或自定义日期范围
     - 活动周期：每天/每周/每月
     - 活动时段：可设置多个时间段（最多5个），格式为 HH:mm-HH:mm
   - 参与规则配置：
     - 适用用户：全部用户/全部会员（必选）
     - 单笔订单商品限购数：不限购或指定数量
     - 单笔订单相同商品限购数：不限购或指定数量
   - 同享规则：
     - **满减、优惠券、特价菜三者不可同享**：用户在结账时只能选择其中一种优惠方式
     - **特价菜可与特价菜同享**：用户可以选择多个特价菜活动同时生效

2. **点餐页面，显示可参与的活动**
   - 在点餐页面显示"可参与活动X项,已生效X项"提示（支持 POS 收银端）
   - 特价商品在商品列表中显示原价（划掉）和特价，突出显示特价标识
   - **多规格商品处理**：
     - 在点餐页面商品列表中，多规格商品显示最低规格的原价及特价
     - 在商品详情页面，显示每个规格对应的原价及特价
   - 在结账页面"优惠活动"区域显示可参与的特价菜活动列表（支持 POS 收银端和 Assistant 助手端）
   - 支持用户选择/取消选择多个特价菜活动（特价菜活动之间可以同享）
   - 当用户已选择满减或优惠券时，特价菜活动显示为不可参与
   - 显示不可参与的特价菜活动（可展开/收起查看原因）

3. **活动管理功能**
   - 活动列表：显示活动名称、状态、时间、周期等信息
   - 活动编辑：支持编辑未开始和进行中的活动
   - 活动失效：手动设置活动为失效状态
   - 活动删除：支持删除已结束/未开始/已失效的活动

### 风险识别

**潜在风险**：

1. **价格计算逻辑复杂**：特价菜价格需要与会员折扣、会员卡折扣、优惠券、满减活动等叠加计算，需要明确优先级和叠加规则
2. **活动时间判断复杂**：需要根据活动周期（每天/每周/每月）和活动时段判断活动是否生效，涉及时区处理
3. **同享规则冲突**：满减、优惠券、特价菜三者互斥，需要确保用户在结账时只能选择其中一种，避免同时使用导致的价格计算错误。但多个特价菜活动之间可以同享，需要正确处理多个特价菜活动叠加的情况
4. **库存管理**：特价商品可能存在库存不足的情况，需要明确处理逻辑

**缓解措施**：

1. **明确价格计算规则**：参考现有满减活动的价格计算逻辑，特价菜价格作为商品原价参与后续折扣计算，明确同享规则优先级
2. **统一时间判断逻辑**：复用满减活动的时间判断逻辑，确保活动生效时间判断准确
3. **清晰的同享规则提示**：在UI上明确显示"满减、优惠券、特价菜三者不可同享，但特价菜可与特价菜同享"的规则，在结账页面当用户已选择满减或优惠券时，自动将特价菜活动显示为不可参与状态；当用户已选择特价菜活动时，自动将满减活动和优惠券显示为不可参与状态，但允许继续选择其他特价菜活动
4. **完善库存校验**：在活动创建时校验商品库存，在点餐时实时校验库存状态

## 📝 附录

### User Story（初稿）

**作为** 商户管理员  
**我想** 创建特价菜活动，为指定商品设置特价价格和活动规则  
**以便于** 通过特价促销吸引顾客消费，提升商品销量和营业额

**作为** 收银员  
**我想** 在点餐页面看到特价商品和可参与的特价菜活动  
**以便于** 向顾客推荐特价商品，提升客单价

**作为** 助手端店员  
**我想** 在助手端结账页面选择特价菜活动  
**以便于** 为顾客选择最优惠的活动，提升顾客满意度

**作为** 顾客  
**我想** 在点餐时看到特价商品和可参与的特价菜活动  
**以便于** 选择优惠商品，节省消费成本

### AC 验收标准（初稿）

1. **WHEN** 商户管理员在"添加促销活动"页面选择"特价菜" **THEN** 系统 **SHALL** 显示特价菜配置页面
2. **IF** 商户管理员创建特价菜活动 **THEN** 系统 **SHALL** 验证活动名称（1-50字符）、至少选择一个商品、每个商品必须设置特价、活动时间不能为空
3. **WHEN** 商户管理员选择特价商品 **THEN** 系统 **SHALL** 显示商品名称、原价，并允许输入特价（必填）
4. **IF** 商户管理员设置活动周期为"每周" **THEN** 系统 **SHALL** 允许选择星期几生效
5. **IF** 商户管理员设置活动周期为"每月" **THEN** 系统 **SHALL** 允许选择每月的哪几天生效
6. **WHEN** 商户管理员设置活动时段 **THEN** 系统 **SHALL** 支持添加多个时段（最多5个），格式为 HH:mm-HH:mm
7. **IF** 特价菜活动在有效期内且当前时间在活动时段内 **THEN** 系统 **SHALL** 在点餐页面显示特价商品（原价划掉，显示特价），支持 POS 收银端、Assistant 助手端、Mobile 扫码端、Tablet 平板端、Delivery 外送端
8. **WHEN** 用户在点餐页面查看商品列表 **THEN** 系统 **SHALL** 显示"可参与活动X项,已生效X项"提示
9. **IF** 商品为多规格商品且参与特价菜活动 **THEN** 系统 **SHALL** 在点餐页面商品列表中显示最低规格的原价及特价
10. **WHEN** 用户查看多规格商品的详情页面 **THEN** 系统 **SHALL** 显示每个规格对应的原价及特价
11. **WHEN** 用户在 POS 收银端或 Assistant 助手端结账页面查看优惠活动 **THEN** 系统 **SHALL** 显示可参与的特价菜活动列表，支持选择/取消选择多个特价菜活动
12. **IF** 用户已选择优惠券 **THEN** 系统 **SHALL** 将特价菜活动和满减活动显示为不可参与状态
13. **IF** 用户已选择满减活动 **THEN** 系统 **SHALL** 将特价菜活动和优惠券显示为不可参与状态
14. **IF** 用户已选择特价菜活动 **THEN** 系统 **SHALL** 将满减活动和优惠券显示为不可参与状态，但允许继续选择其他特价菜活动
15. **WHEN** 用户选择多个特价菜活动 **THEN** 系统 **SHALL** 允许同时生效，在订单计算时对符合条件的商品使用对应的特价价格
16. **WHEN** 用户选择特价菜活动 **THEN** 系统 **SHALL** 在订单计算时使用特价价格，并正确计算折扣后的最终价格
17. **IF** 用户尝试同时选择满减、优惠券、特价菜中的多个 **THEN** 系统 **SHALL** 提示"满减、优惠券、特价菜三者不可同享，请选择其中一种"
18. **IF** 同一商品同时满足多个特价菜活动条件 **THEN** 系统 **SHALL** 使用价格最低的特价（或按活动优先级规则）
19. **IF** 多规格商品的不同规格设置了不同的特价 **THEN** 系统 **SHALL** 在商品详情页面正确显示每个规格对应的特价
