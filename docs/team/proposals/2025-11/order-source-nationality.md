## 🎯 背景和动机

### 问题描述

**任务来源：华莱士客户需求**

当前收银系统在点餐时缺少订单来源和顾客国籍的记录能力，导致：

1. **订单来源不明确**：无法区分订单是来自店内堂食还是外卖平台（Grab、Line Man、悟空外卖、Foodpanda 等），影响商户对不同渠道订单的统计和管理。

2. **顾客国籍信息缺失**：部分商户（特别是国际化餐饮品牌）需要记录顾客国籍信息，用于：

   - 消费习惯分析
   - 精准营销
   - 服务优化（如语言偏好）
   - 数据统计报表

3. **数据追踪困难**：订单详情页无法显示订单来源和顾客国籍，不利于后续的数据分析和业务决策。

### 业务价值

**核心价值**：

- ✅ **提升渠道管理能力**：清晰区分店内和外卖订单，便于商户分渠道统计和管理
- ✅ **支持多元化经营**：支持多外卖平台订单接入，满足商户多渠道运营需求
- ✅ **增强数据分析能力**：记录顾客国籍信息，为精准营销和服务优化提供数据基础
- ✅ **提高运营效率**：一键查看订单来源，快速定位问题订单
- ✅ **满足国际化需求**：支持多国籍顾客信息记录，助力餐饮品牌国际化发展

**量化指标**：

- 支持 4+ 主流外卖平台订单来源标识
- 内置 8 个常用国家/地区选项
- 通过后台开关灵活控制功能显示

### 目标用户

- [x] 收银员（点餐时选择订单来源和国籍）
- [x] 商户管理员（后台配置外卖来源和国籍选项）
- [x] 店长（查看订单详情，分析渠道数据）
- [ ] 厨房人员
- [ ] 顾客
- [x] 其他: 运营人员（数据分析和报表统计）

## 💡 解决方案概述

### 方案描述

**功能分为三大模块：**

#### 1. 收银端-点餐方式增加"外卖"选项

在收银机点餐界面增加"外卖"按钮（与"堂食"、"外带"等并列），点击后弹出外卖来源选择：

- 如果不选择外卖来源 = 店内来源（堂食/外带）
- 选择外卖来源后，订单标记为对应平台的外卖订单
- **控制逻辑**：后台开启"外卖功能"后才显示该按钮

#### 2. 收银端/助手端-点餐/桌台增加"国籍"选项

在点餐流程和桌台管理中增加"国籍"选择：

- 提供下拉选择或快捷按钮
- 可选可不选（非必填）
- 选择后记录到订单信息中
- **控制逻辑**：后台开启"国籍功能"后才显示该选项

#### 3. 新管理端-业务设置增加配置管理

新增两个独立的配置模块：

**A. 外卖来源管理**

- 功能开关：默认关闭
- 开启后：收银机点餐界面出现"外卖"选项
- 外卖来源可增删改查
- 默认预置来源：Grab、Line Man、悟空外卖、Foodpanda
- 支持自定义添加其他外卖平台

**B. 国籍管理**

- 功能开关：默认关闭
- 开启后：收银机/助手端点餐、桌台界面出现"国籍"选项
- 国籍选项可增删改查
- 默认预置国籍：泰国、中国、美国、日本、韩国、英国、法国、俄罗斯
- 支持自动多语言翻译
- 支持自定义添加其他国家/地区

### 核心功能点

1. **订单来源标识**

   - 新增"外卖"点餐方式
   - 外卖来源选择（多个外卖平台）
   - 订单详情显示具体来源

2. **国籍信息记录**

   - 点餐时可选择顾客国籍
   - 桌台管理时可记录国籍
   - 订单详情显示国籍信息

3. **后台配置管理**

   - 外卖功能开关 + 来源管理（增删改查）
   - 国籍功能开关 + 国籍管理（增删改查）
   - 支持多语言自动翻译

4. **数据展示**
   - 收银机/商家后台订单详情展示订单来源
   - 收银机/商家后台订单详情展示顾客国籍
   - 支持后续数据统计和报表分析

## 📊 初步评估

### 技术复杂度

- [ ] **低**：纯 UI 调整，无业务逻辑变更
- [x] **中**：需要前后端联调，基础业务逻辑
- [ ] **高**：涉及架构调整、第三方集成、复杂算法

**复杂度说明**：

- 前端需要在多个终端（POS、Assistant、Shop）增加 UI 控件
- 后端需要修改订单模型，增加配置管理接口
- 需要处理多语言翻译
- 需要考虑数据兼容性（历史订单没有这些字段）

### 工作量预估

[粗略估算，具体 SP 在技术方案评审时确定]

**分模块预估**：

- 后端开发（订单模型 + 配置管理 + API）：2-3 天
- 前端开发（POS + Assistant + Shop）：3-4 天
- 测试（功能测试 + 兼容性测试）：2 天
- 联调和 Bug 修复：1 天

- **预计天数**: 8-10 天
- **预估 SP**: 5-8 SP（待技术评审确认）

### 风险识别

**潜在风险**：

1. **数据兼容性风险**：历史订单没有订单来源和国籍字段，需要处理空值展示
2. **多终端一致性风险**：POS 和 Assistant 需要保持功能和交互一致
3. **多语言翻译风险**：国籍名称的多语言翻译可能不准确
4. **性能风险**：订单表增加字段后，查询性能可能受影响
5. **权限控制风险**：需要确认是否需要角色权限控制（当前需求明确"不控制角色权限"）

**缓解措施**：

1. **数据兼容性**：空值时显示"未记录"或"店内"，不影响核心业务
2. **多终端一致性**：复用同一套 UI 组件，统一交互逻辑
3. **多语言翻译**：使用成熟的翻译库，支持后台手动修正
4. **性能优化**：增加索引，避免全表扫描
5. **权限控制**：当前版本不做权限控制，后续可扩展

## 📝 附录

### User Story（初稿）

**作为** 收银员  
**我想** 在点餐时选择订单来源（店内/外卖平台）和顾客国籍  
**以便于** 商户能够准确区分不同渠道的订单，并记录顾客国籍信息用于数据分析

**作为** 商户管理员  
**我想** 在后台配置外卖来源和国籍选项，并控制功能开关  
**以便于** 根据实际业务需求灵活启用或关闭相关功能

**作为** 店长  
**我想** 在订单详情中查看订单来源和顾客国籍  
**以便于** 分析不同渠道和不同国籍顾客的消费习惯

### AC 验收标准（初稿）

#### AC1: 收银端-点餐方式增加外卖选项

**GIVEN** 后台已开启"外卖功能"开关  
**WHEN** 收银员进入点餐界面  
**THEN** 应显示"外卖"按钮（与"堂食"、"外带"等并列）

**GIVEN** 收银员点击"外卖"按钮  
**WHEN** 弹出外卖来源选择  
**THEN** 应显示：Grab、Line Man、悟空外卖、Foodpanda 及后台自定义的外卖平台

**GIVEN** 收银员未选择外卖来源  
**WHEN** 创建订单  
**THEN** 订单标记为"店内来源"

**GIVEN** 后台已关闭"外卖功能"开关  
**WHEN** 收银员进入点餐界面  
**THEN** 不显示"外卖"按钮

#### AC2: 收银端/助手端-点餐/桌台增加国籍选择

**GIVEN** 后台已开启"国籍功能"开关  
**WHEN** 收银员/店员进入点餐或桌台界面  
**THEN** 应显示"国籍"选择控件

**GIVEN** 收银员/店员点击"国籍"选择  
**WHEN** 弹出国籍列表  
**THEN** 应显示：泰国、中国、美国、日本、韩国、英国、法国、俄罗斯及后台自定义的国籍

**GIVEN** 收银员/店员未选择国籍  
**WHEN** 创建订单  
**THEN** 订单的国籍字段为空（可选字段）

**GIVEN** 后台已关闭"国籍功能"开关  
**WHEN** 收银员/店员进入点餐或桌台界面  
**THEN** 不显示"国籍"选择控件

#### AC3: 新管理端-业务设置增加配置管理

**GIVEN** 管理员进入"业务设置"页面  
**WHEN** 查看外卖配置模块  
**THEN** 应显示：

- 外卖功能开关（默认关闭）
- 外卖来源列表（Grab、Line Man、悟空外卖、Foodpanda）
- 增删改查操作按钮

**GIVEN** 管理员开启"外卖功能"开关  
**WHEN** 保存配置  
**THEN** 收银机点餐界面应显示"外卖"选项

**GIVEN** 管理员进入"业务设置"页面  
**WHEN** 查看国籍配置模块  
**THEN** 应显示：

- 国籍功能开关（默认关闭）
- 国籍列表（泰国、中国、美国、日本、韩国、英国、法国、俄罗斯）
- 增删改查操作按钮
- 多语言翻译状态

**GIVEN** 管理员开启"国籍功能"开关  
**WHEN** 保存配置  
**THEN** 收银机/助手端点餐、桌台界面应显示"国籍"选项

#### AC4: 订单详情显示

**GIVEN** 订单有订单来源信息  
**WHEN** 查看订单详情  
**THEN** 应显示具体的外卖来源或"店内"

**GIVEN** 订单有国籍信息  
**WHEN** 查看订单详情  
**THEN** 应显示顾客国籍

**GIVEN** 订单没有订单来源或国籍信息（历史订单）  
**WHEN** 查看订单详情  
**THEN** 应显示"未记录"或默认值，不影响订单其他信息展示
