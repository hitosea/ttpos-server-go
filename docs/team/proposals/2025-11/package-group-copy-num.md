## 🎯 背景和动机

### 问题描述

当前套餐分组支持可选分组类型（`group_type=1`），可以设置可选数量（`optional_count`），表示本组商品中要求选择多少个商品。但是在订单商品表（`sale_order_product`）中，缺少字段来记录套餐子商品在分组中被选择了多少份。

**示例场景**：
> 套餐"双人套餐"中有一个可选分组"主餐"，可选数量为 2（即需要选择 2 个主餐）。当用户选择了"牛排"和"鸡排"各 1 份时，系统需要在订单商品表中记录每个子商品在分组中的份数信息，以便后续的统计、对账、退菜等业务逻辑能够正确处理。

### 业务价值

- **准确记录订单信息**：完整记录套餐分组中每个子商品的选择份数，确保订单数据的准确性
- **支持复杂套餐场景**：满足套餐分组可选份数的业务需求，支持更灵活的套餐配置
- **便于后续业务处理**：为退菜、统计、对账等功能提供准确的数据基础
- **提升系统扩展性**：为未来可能的分组份数相关功能提供数据支持

## 💡 解决方案概述

### 方案描述

在 `sale_order_product` 表中新增 `copy_num` 字段，用于记录该子商品在套餐分组中被选择的份数。该字段主要用于套餐子商品，普通商品和套餐主商品该字段值为 0 或默认值。

**字段设计**：
- **字段名**：`copy_num`
- **类型**：`DECIMAL(12,4)`
- **默认值**：`0`
- **注释**：表示该子商品在分组中被选择多少份

### 核心功能点

1. **数据库字段新增**：在 `sale_order_product` 表中增加 `copy_num` 字段
2. **数据模型更新**：更新 Go 和 PHP 的数据模型，添加 `copy_num` 字段定义,并修改shop_01.sql文件
3. **业务逻辑适配**：在创建订单商品时，正确记录套餐子商品的份数信息
4. **API 接口更新**：订单相关接口返回 `copy_num` 字段信息
5. **数据迁移**：为现有数据设置默认值（0）

## 📝 附录

### User Story（初稿）

**作为** 收银员/商户管理员  
**我想** 在订单中准确记录套餐分组中每个子商品的选择份数  
**以便于** 后续的统计、对账、退菜等业务能够正确处理套餐分组可选份数的场景

### AC 验收标准（初稿）

1. **WHEN** 创建包含套餐分组可选份数的订单 **THEN** 系统 **SHALL** 在 `sale_order_product` 表中正确记录每个子商品的 `copy_num` 字段
2. **IF** 套餐子商品属于可选分组 **THEN** 系统 **SHALL** 记录该子商品在分组中被选择的份数
3. **IF** 普通商品或套餐主商品 **THEN** 系统 **SHALL** 设置 `copy_num` 为 0 或默认值
4. **WHEN** 查询订单详情 **THEN** API **SHALL** 返回 `copy_num` 字段信息
5. **IF** 现有订单数据 **THEN** 系统 **SHALL** 通过数据迁移设置 `copy_num` 默认值为 0

### 技术细节（初稿）

**字段定义**：
```sql
ALTER TABLE `ttpos_sale_order_product` 
ADD COLUMN `copy_num` DECIMAL(12, 4) NOT NULL DEFAULT 0 COMMENT '表示该子商品在分组中被选择多少份' 
AFTER `unit_num`;
```

**Go Model 字段**：
```go
CopyNum float64 `gorm:"column:copy_num;type:decimal(12,4);not null;default:0.00;comment:'表示该子商品在分组中被选择多少份'" json:"copy_num"`
```
