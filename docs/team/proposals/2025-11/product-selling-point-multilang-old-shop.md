## 🎯 背景和动机

### 问题描述

旧商家后台的商品管理模块仅支持单一语言的“商品卖点”字段，套餐与成品商品都无法针对不同语言维护差异化文案。多语言门店需要在外部表格维护翻译并人工拼接，既难以保障翻译一致性，也无法在会员端、平板点餐端、H5 菜单中正确展示本地化卖点。此外，卖点字段缺少长度限制提示，容易出现溢出导致前端排版错乱，商品图片更新后也常因缓存与数据耦合导致展示延迟，影响商户对商品详情的管理体验。

### 业务价值

- 支持跨语言市场的商品营销，提升门店品牌一致性
- 减少运营手动维护多份卖点的成本与出错率
- 确保会员端、平板端、H5 菜单展示与后台配置实时同步，改善顾客体验

## 💡 解决方案概述

### 方案描述

在旧商家后台的商品管理模块中，为套餐与成品商品的“商品卖点”引入多语言配置能力：基于系统支持的语言包提供动态表单，每个语言版本限制 500 字符。前端保存时将多语言卖点结构化存储（如 JSON），后端 API 与数据模型同步扩展，商品详情接口根据终端请求语言自动返回匹配的卖点。编辑页面提供实时字符计数与翻译参考，同时在卖点与商品图片更新后触发终端缓存刷新，确保会员端、平板端、H5 菜单即时展示最新内容。

### 核心功能点

1. 商品套餐与成品的卖点字段支持多语言录入，单语言限制 500 字符并给出提示
2. 商品卖点字段为非必填项，未填写时允许保存且后续可回退到主语言或保持为空
3. 后端 API、数据模型与前端终端（会员端/平板/H5）对接多语言卖点的读取与展示
4. 商品编辑保存后同步刷新详情缓存与图片资源引用，保障前台展示及时更新

### 风险识别

**潜在风险**：

1. 旧后台与前端终端共享的数据结构不一致，可能导致卖点字段解析失败
2. 多语言字段填充不完整，终端回退逻辑缺失造成空白展示


**缓解措施**：

1. 统一接口协议与序列化格式，提供灰度验证环境覆盖全终端
2. 默认回退到主语言卖点，并在后台提供必填校验与提示

## 📝 附录

### User Story（初稿）

**作为** 商家后台运营  
**我想** 在商品套餐与成品商品中为不同语言配置独立的卖点文案与图片  
**以便于** 顾客在会员端、平板端、H5 菜单中都能看到符合其语言环境的商品卖点

### AC 验收标准（初稿）

1. **WHEN** 商家在旧后台为任意商品保存多语言卖点 **THEN** 各终端在对应语言环境下展示配置内容，不超过 500 字符
2. **IF** 终端缺少匹配语言 **THEN** 系统自动回退展示主语言卖点且记录监控日志
3. **WHEN** 商家更新商品图片或卖点 **THEN** 会员端、平板端、H5 菜单在 5 分钟内展示最新内容
4. **IF** 商家未填写任何语言的商品卖点 **THEN** 表单仍可保存成功且终端展示为空或默认文案
