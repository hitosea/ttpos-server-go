## 🎯 背景和动机

### 问题描述

当前系统缺少用户维度的订单统计分析功能，商户无法了解：
- 不同国籍顾客的订单分布情况
- 不同点餐方式来源（店内/外卖）的订单占比
- 不同桌台方式来源的订单分布
- 不同用餐方式（打包/店内用餐）的订单占比

这些数据对于商户进行精准营销、优化服务流程、调整运营策略具有重要意义。

### 业务价值

- **精准营销**：了解不同国籍顾客的消费习惯，制定针对性营销策略
- **渠道优化**：分析点餐方式来源分布，优化各渠道资源配置
- **服务提升**：了解桌台方式和用餐方式偏好，优化服务流程
- **数据驱动决策**：为商户提供数据支持，辅助运营决策

## 💡 解决方案概述

### 方案描述

在报表中心新增"用户分析"统计页面，提供多维度订单统计分析功能：

1. **按国籍统计**：统计不同国籍的订单数和占比
2. **按点餐方式来源统计**：统计店内/外卖等不同来源的订单数和占比
3. **按桌台方式来源统计**：统计不同桌台来源的订单数和占比
4. **按用餐方式统计**：统计打包/店内用餐不同用餐方式的订单数和占比

所有统计结果按订单数升序排序，并显示占比百分比。

### 核心功能点

1. 新增用户分析统计页面，支持日期范围筛选
2. 按国籍维度统计订单数和占比（%）
3. 按点餐方式来源维度统计订单数和占比（%）
4. 按桌台方式来源维度统计订单数和占比（%）
5. 按用餐方式维度统计订单数和占比（%）
6. 所有统计结果按订单数升序排序
7. 支持数据导出功能（Excel格式）

### 风险识别

**潜在风险**：
1. 历史订单可能缺少部分字段（如国籍），统计结果可能不完整
2. 多维度统计查询可能影响数据库性能，需要优化查询逻辑
3. 字段定义不明确可能导致统计口径不一致

**缓解措施**：
1. 制定历史数据补齐策略，或明确统计范围（仅统计有完整数据的订单）
2. 使用索引优化、聚合查询优化等手段提升查询性能
3. 在技术设计阶段明确各字段的定义和统计口径

## 📝 附录

### User Story（初稿）

**作为** 商户管理员/运营人员  
**我想** 查看按国籍、点餐方式来源、桌台方式来源、用餐方式统计的订单数和占比  
**以便于** 了解用户分布情况，制定精准营销策略和优化服务流程

### AC 验收标准（初稿）

1. **WHEN** 用户进入用户分析页面 **THEN** 系统应显示四个统计维度（国籍、点餐方式来源、桌台方式来源、用餐方式）
2. **WHEN** 用户选择日期范围 **THEN** 系统应按选定时间范围统计订单数据
3. **WHEN** 系统统计各维度数据 **THEN** 应显示订单数和占比（%），占比保留2位小数
4. **WHEN** 系统展示统计结果 **THEN** 应按订单数升序排序
5. **WHEN** 订单缺少某个维度字段（如国籍） **THEN** 应归类为"未记录"或"其他"
6. **WHEN** 用户点击导出按钮 **THEN** 系统应导出Excel文件，包含所有统计维度数据
