## 🎯 背景和动机

### 问题描述

当前新管理端（Go Main 模块）的支付管理功能需要与 ERP 系统进行对接，以实现支付数据在 TTPOS 和 ERPNext 之间的同步。目前支付应用的配置和管理分散在旧管理端（PHP）中，新管理端尚未完成 ERP 对接功能的迁移。

**现状**：
- 支付应用配置存储在旧 PHP 管理端中
- 新管理端已有基础的支付管理接口
- ERP RPC 服务已实现 Selling 等业务模块对接
- 缺少支付数据与 ERP 的同步机制

### 业务价值

[解决这个问题能带来什么业务价值？]

- 统一支付数据管理，避免数据孤岛
- 实现支付流水在 ERP 中的财务核算
- 支持多门店支付数据的集中管理和分析
- 为后续财务报表和对账功能提供数据基础
- 加速旧管理端向新管理端的迁移进程

## 💡 解决方案概述

### 方案描述

在新管理端（Go Main 模块）中实现支付管理与 ERP 的完整对接功能：

1. **支付应用管理**：支持在新管理端配置和管理支付应用（微信、支付宝、银行卡等），并同步到 ERP 的 Mode of Payment
2. **支付流水同步**：订单支付成功后，自动将支付记录同步到 ERP 的 Payment Entry
3. **对账功能**：支持从 ERP 查询支付流水，实现与本地数据的对账
4. **数据迁移**：提供从旧 PHP 管理端迁移支付配置数据到新管理端的工具

### 核心功能点

1. **支付应用 CRUD**：支持支付应用的创建、查询、更新、删除，并同步到 ERP
2. **支付方式映射**：建立 TTPOS 支付方式与 ERP Mode of Payment 的映射关系
3. **支付流水同步**：订单支付后自动创建 ERP Payment Entry
4. **对账接口**：查询 ERP 支付记录，与本地数据进行核对
5. **数据迁移工具**：从 PHP `payment_app` 表迁移数据到 Go Main 模块

## 📊 初步评估

### 技术复杂度

- [ ] **低**：纯 UI 调整，无业务逻辑变更
- [x] **中**：需要前后端联调，基础业务逻辑
- [ ] **高**：涉及架构调整、第三方集成、复杂算法

**说明**：虽然涉及第三方 ERP 集成，但 RPC 框架和 Selling 模块对接已有成熟案例，主要是业务逻辑的实现和数据同步。

### 工作量预估

[粗略估算，具体 SP 在技术方案评审时确定]

- **预计天数**: 5-8 天
- **预估 SP**: 5-8 SP（待技术评审确认）

**工作量分解**（粗略）：
- 数据模型设计和迁移：1-2 天
- 后端 API 开发（CRUD + 同步）：2-3 天
- ERP 对接（Mode of Payment + Payment Entry）：2-3 天
- 前端页面开发：1-2 天
- 测试和联调：1 天

### 风险识别

**潜在风险**：
1. **数据迁移风险**：旧 PHP 管理端的支付配置数据结构可能与新设计不完全兼容
2. **ERP API 限制**：ERPNext 的 Payment Entry 创建可能有字段或权限限制
3. **性能问题**：大量支付流水同步可能影响 ERP 性能
4. **数据一致性**：支付同步失败时的补偿机制和数据一致性保障

**缓解措施**：
1. 提前分析旧数据结构，设计兼容的迁移方案，提供数据校验工具
2. 提前调研 ERPNext Payment Entry API，确认必填字段和权限配置
3. 采用异步队列（RabbitMQ）进行支付流水同步，避免阻塞主流程
4. 设计重试机制和失败日志，支持手动补偿同步

## 📝 附录

### User Story（初稿）

**作为** 商户管理员  
**我想** 在新管理端配置支付应用并自动同步到 ERP  
**以便于** 实现支付数据的统一管理和财务核算

**作为** 财务人员  
**我想** 查看 ERP 中的支付流水并与本地数据对账  
**以便于** 确保支付数据的准确性和完整性

### AC 验收标准（初稿）

1. **WHEN** 管理员在新管理端创建支付应用 **THEN** 系统 **SHALL** 自动在 ERP 中创建对应的 Mode of Payment
2. **WHEN** 订单支付成功 **THEN** 系统 **SHALL** 异步将支付记录同步到 ERP Payment Entry
3. **IF** 支付同步失败 **THEN** 系统 **SHALL** 记录失败日志并支持重试
4. **WHEN** 财务人员查询支付流水 **THEN** 系统 **SHALL** 同时显示本地和 ERP 的支付记录
5. **WHEN** 执行数据迁移命令 **THEN** 系统 **SHALL** 将旧管理端的支付配置迁移到新管理端
