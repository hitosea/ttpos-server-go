## 🎯 背景和动机

### 问题描述

当前仓库模块缺少统一的商品库存查询功能，无法根据商品类型（有成本卡/无成本卡）灵活计算库存。不同商品类型的库存计算逻辑不同，需要统一封装为领域服务，遵循 DDD 设计原则，提供清晰的库存查询接口。

**现状问题**：
- 库存计算逻辑分散在多个地方，缺乏统一抽象
- 有成本卡商品和无成本卡商品的库存计算逻辑存在差异，但代码中未明确区分
- 缺少统一的库存查询领域服务，不利于后续扩展和维护

### 业务价值

- **统一库存管理**：提供统一的库存查询接口，简化业务调用
- **灵活扩展**：基于 DDD 设计，便于后续扩展新的商品类型或库存计算规则
- **代码可维护性**：清晰的领域模型和策略模式，提升代码可读性和可维护性
- **业务准确性**：确保不同商品类型的库存计算逻辑正确执行

## 💡 解决方案概述

### 方案描述

使用 DDD（领域驱动设计）在仓库模块设计商品库存查询功能。通过领域服务封装库存计算逻辑，使用策略模式处理不同商品类型（有成本卡/无成本卡）的库存计算差异。

**核心设计思路**：
1. **领域服务**：创建 `ProductInventoryService` 领域服务，负责库存查询
2. **策略模式**：为有成本卡商品和无成本卡商品分别实现库存计算策略
3. **统一接口**：提供统一的 `GetProductInventory(productId)` 方法
4. **库存计算规则**：
   - **有成本卡商品**：
     - 判断是否开启成本卡控制
     - 若开启：根据成本卡计算材料用量得到库存
     - 若未开启：判断是否标记售罄 → 售罄返回0 → 否则判断是否设置可售量 → 设置则返回设置值 → 否则返回99999999
   - **无成本卡商品**：
     - 判断是否标记售罄 → 售罄返回0 → 否则判断是否设置可售量 → 设置则返回设置值 → 否则返回99999999

### 核心功能点

1. **商品库存查询领域服务**
   - 提供统一的库存查询接口
   - 自动识别商品类型（有成本卡/无成本卡）
   - 根据商品类型选择对应的库存计算策略

2. **有成本卡商品库存计算策略**
   - 成本卡控制开关判断
   - 成本卡材料用量计算
   - 售罄状态判断
   - 可售量设置判断

3. **无成本卡商品库存计算策略**
   - 售罄状态判断
   - 可售量设置判断
   - 无限库存处理

4. **库存计算规则配置**
   - 成本卡控制开关配置
   - 售罄标记配置
   - 可售量设置配置

## 📊 初步评估

### 技术复杂度

- [ ] **低**：纯 UI 调整，无业务逻辑变更
- [x] **中**：需要前后端联调，基础业务逻辑
- [ ] **高**：涉及架构调整、第三方集成、复杂算法

**说明**：
- 需要设计 DDD 领域服务结构
- 需要实现策略模式处理不同商品类型
- 需要整合现有的成本卡、材料用量等业务逻辑
- 需要确保与现有代码的兼容性

### 工作量预估

- **预计天数**: 3-5 天
- **预估 SP**: 5 SP（待技术评审确认）

**分解**：
- 领域服务设计：1 天
- 有成本卡商品库存计算策略：1-2 天
- 无成本卡商品库存计算策略：0.5 天
- 单元测试和集成测试：1 天
- 文档和代码审查：0.5 天

### 风险识别

**潜在风险**：
1. **成本卡材料用量计算复杂度**：成本卡可能涉及多个材料，需要准确计算材料库存和用量关系
2. **性能影响**：库存查询可能被频繁调用，需要确保计算性能
3. **数据一致性**：库存计算依赖多个数据源（商品、成本卡、材料库存），需要保证数据一致性
4. **现有代码兼容性**：需要确保新功能不影响现有库存相关功能

**缓解措施**：
1. **详细技术方案设计**：在 Spec 设计阶段详细分析成本卡材料用量计算逻辑，必要时进行技术预研
2. **缓存策略**：对库存计算结果进行缓存，减少重复计算
3. **事务处理**：使用数据库事务确保数据一致性
4. **渐进式迁移**：先实现新功能，逐步替换现有库存查询逻辑，保持向后兼容

### User Story（初稿）

**作为** 仓库管理员  
**我想** 查询商品的实时库存  
**以便于** 准确了解商品可售数量，避免超卖或库存积压

**作为** 系统开发者  
**我想** 使用统一的库存查询接口  
**以便于** 简化业务代码，提高代码可维护性

### AC 验收标准（初稿）

1. **WHEN** 查询有成本卡商品的库存 **AND** 成本卡控制已开启 **THEN** 系统 **SHALL** 根据成本卡计算材料用量得到库存
2. **WHEN** 查询有成本卡商品的库存 **AND** 成本卡控制未开启 **AND** 商品标记售罄 **THEN** 系统 **SHALL** 返回库存为 0
3. **WHEN** 查询有成本卡商品的库存 **AND** 成本卡控制未开启 **AND** 商品未标记售罄 **AND** 设置了可售量 **THEN** 系统 **SHALL** 返回设置的可售量值
4. **WHEN** 查询有成本卡商品的库存 **AND** 成本卡控制未开启 **AND** 商品未标记售罄 **AND** 未设置可售量 **THEN** 系统 **SHALL** 返回 99999999（无限库存）
5. **WHEN** 查询无成本卡商品的库存 **AND** 商品标记售罄 **THEN** 系统 **SHALL** 返回库存为 0
6. **WHEN** 查询无成本卡商品的库存 **AND** 商品未标记售罄 **AND** 设置了可售量 **THEN** 系统 **SHALL** 返回设置的可售量值
7. **WHEN** 查询无成本卡商品的库存 **AND** 商品未标记售罄 **AND** 未设置可售量 **THEN** 系统 **SHALL** 返回 99999999（无限库存）
