## 🎯 背景和动机

### 问题描述

随着 Grab 外卖业务的接入，现有的分类管理功能无法满足外卖场景的需求。当前分类管理存在以下问题：

1. **缺乏外卖显示控制**：分类无法独立控制是否在外卖平台显示，所有店内分类会直接同步到外卖平台
2. **总部分类权限不灵活**：总部创建的分类下发到分店后，分店无法根据自身外卖业务需求选择性展示
3. **缺乏平台同步机制**：分类变更后无法自动同步到 Grab 平台，需要手动操作
4. **外卖对接未完成时功能可见**：在外卖 API 对接未完成连接前，增强功能就已经显示，容易造成混淆

### 业务价值

解决这个问题能带来以下业务价值：

- **支持多渠道运营**：分店可以灵活控制店内和外卖平台的分类展示，适应不同渠道的经营策略
- **提升管理效率**：自动同步分类变更到 Grab 平台，减少手动操作，降低出错率
- **增强总分店协作**：总部统一管理分类，分店可根据实际情况灵活配置外卖显示
- **优化用户体验**：外卖顾客可以看到专门针对外卖优化的分类结构

## 💡 解决方案概述

### 方案描述

在新管理端的分类管理模块中，增强分类配置功能，支持分类的多渠道显示控制和平台同步：

1. **增加外卖显示开关**：每个分类增加"显示在店内"和"显示在 Grab 外卖"的独立开关，支持灵活配置
2. **总分店权限优化**：总部来源的分类被分店选择后，分店可以独立控制该分类是否在外卖平台显示
3. **自动平台同步**：分类的外卖相关配置变更后，自动同步到 Grab 平台
4. **功能显示控制**：只有在外卖 API 对接完成连接后，才显示分类增强功能，避免未配置时的混淆

### 核心功能点

1. **分类多渠道显示配置**
   - 每个分类独立配置"店内显示"和"外卖显示"开关
   - 支持分类仅在店内显示、仅在外卖显示、或同时在两个渠道显示
   
2. **总分店分类权限管理**
   - 总部创建的分类下发到分店后，分店可以选择是否启用外卖显示
   - 分店对总部来源的分类有外卖显示权限，不影响店内显示
   
3. **Grab 平台自动同步**
   - 分类的外卖显示状态变更后，自动同步到 Grab 平台
   - 分类名称、描述、排序等信息变更后，自动同步到 Grab 平台
   - 提供同步状态反馈和失败重试机制
   
4. **功能入口控制**
   - 外卖 API 对接未完成连接时，隐藏分类增强功能入口
   - 完成连接后，自动显示分类增强功能
   - 提供配置引导，帮助用户完成外卖对接

## 📊 初步评估

### 技术复杂度

- [ ] **低**：纯 UI 调整，无业务逻辑变更
- [x] **中**：需要前后端联调，基础业务逻辑
- [ ] **高**：涉及架构调整、第三方集成、复杂算法

**复杂度说明**：
- 需要扩展分类数据模型，增加外卖显示字段
- 需要实现 Grab 平台的分类同步接口
- 需要处理总分店的权限控制逻辑
- 需要实现外卖 API 连接状态检查和功能显示控制

### 工作量预估

- **预计天数**: 3-5 天

**工作量分解**：
- 数据库迁移和模型扩展：0.5 天
- 后端 API 开发（分类 CRUD 增强、Grab 同步）：1.5 天
- 前端界面开发（分类管理增强）：1.5 天
- 权限控制逻辑实现：0.5 天
- 测试和联调：1 天

### 风险识别

**潜在风险**：
1. **Grab API 同步失败**：网络问题或 API 限流导致同步失败
2. **总分店数据一致性**：总部分类变更后，分店的外卖显示配置可能冲突
3. **外卖订单依赖**：分类变更可能影响正在进行中的外卖订单
4. **权限控制复杂度**：总分店的权限边界需要明确定义

**缓解措施**：
1. **同步失败处理**：实现重试机制和失败日志记录，提供手动重试功能
2. **数据一致性保护**：分类变更时检查是否有未完成的外卖订单，提供变更确认机制
3. **权限明确化**：制定清晰的权限规则文档，前端界面明确标注权限范围
4. **配置状态检查**：实时检查外卖 API 连接状态，动态控制功能显示

## 📝 附录

### User Story（初稿）

**作为** 分店店长  
**我想** 灵活控制分类在店内和外卖平台的显示  
**以便于** 根据不同渠道的经营策略优化分类展示，提升外卖业务转化率

**作为** 总部运营人员  
**我想** 统一创建和下发分类，同时允许分店自主选择外卖显示  
**以便于** 既保证品牌统一性，又给予分店经营灵活性

### AC 验收标准（初稿）

#### AC1：分类外卖显示配置

**GIVEN** 我是一个分店管理员，已登录新管理端，外卖 API 已完成连接  
**WHEN** 我在分类管理页面编辑一个分类  
**THEN** 系统应该显示"显示在店内"和"显示在 Grab 外卖"两个独立的开关

**GIVEN** 我是一个分店管理员，正在编辑分类  
**WHEN** 我开启"显示在 Grab 外卖"开关并保存  
**THEN** 系统应该自动将该分类同步到 Grab 平台，并显示同步成功的提示

#### AC2：总部分类权限控制

**GIVEN** 我是一个分店管理员，收到了总部下发的分类  
**WHEN** 我编辑这个总部来源的分类  
**THEN** 系统应该允许我修改"显示在 Grab 外卖"开关，但其他字段可能受限

**GIVEN** 我是一个分店管理员，开启了总部分类的外卖显示  
**WHEN** 总部后续修改该分类的其他信息  
**THEN** 我的外卖显示设置不应该被覆盖

#### AC3：功能入口控制

**GIVEN** 我是一个新用户，还未完成 Grab API 对接  
**WHEN** 我进入分类管理页面  
**THEN** 系统不应该显示"显示在 Grab 外卖"相关的功能入口

**GIVEN** 我刚完成 Grab API 对接  
**WHEN** 我刷新分类管理页面  
**THEN** 系统应该显示分类增强功能，包括外卖显示开关

#### AC4：Grab 平台同步

**GIVEN** 我是一个分店管理员，正在编辑分类  
**WHEN** 我修改分类的外卖显示状态、名称或描述  
**THEN** 系统应该自动触发 Grab 平台同步，并显示同步状态

**GIVEN** Grab 平台同步失败（网络问题）  
**WHEN** 同步失败时  
**THEN** 系统应该显示错误提示，并提供"重试"按钮供我手动触发同步
