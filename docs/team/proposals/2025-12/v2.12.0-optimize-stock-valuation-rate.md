## 🎯 背景和动机

### 问题描述

当前 TTPOS 系统在创建库存盘点时存在以下问题：

1. **强制估值率赋值问题**：当盘点物品的估值率为空时，系统强行将其设置为 1，导致：
   - 直接覆盖该物品在仓库中的真实估值率（Stock-Bin 中的 Valuation Rate）
   - 影响所有采购批次的估值率（Stock Ledger）
   - 直接影响物品的财务计算和成本核算

2. **UI 冗余字段**：物品管理页面（添加/查看）存在估值率字段，但该字段应该由 ERP 系统通过采购入库自动计算生成，不应在 TTPOS 侧手动维护

3. **缺少有效验证**：当物品没有估值率时，系统没有给出明确的提示和阻止，而是静默地进行了错误的赋值操作

### 业务价值

解决此问题能够带来：

- **准确的成本核算**：确保物品估值率来自真实的采购数据，而非随意赋值
- **规范的业务流程**：强制通过采购入库建立库存，保证数据完整性
- **清晰的错误提示**：当数据异常时及时告知用户，避免静默错误
- **简化 UI 界面**：移除不必要的字段，降低操作复杂度

## 💡 解决方案概述

### 方案描述

**核心思路**：移除 TTPOS 侧对估值率的手动维护能力，改为从 ERPNext 系统实时读取物品的真实估值率，并在盘点提交时进行严格验证。

具体实现：
1. 从物品管理 UI 中移除估值率字段的显示和编辑
2. 在后端盘点逻辑中，当估值率为 0 时，不再强制赋值为 1，而是从 ERPNext Bin 表中查询真实估值率
3. 若查询到的估值率仍为 0，则阻止盘点提交并给出明确提示："xx物品库存物品估值率为空，无法提交盘点单"
4. 增强盘点单与仓库的关联验证，确保盘点物品都在选定仓库中

### 核心功能点（本次范围：仅后端）

1. **新增 Bin 查询服务**：实现查询 ERPNext Bin 表的 gRPC 服务，支持按 `item_code` 和 `warehouse` 查询物品在指定仓库的估值率
2. **调整盘点保存逻辑**：在 `SaveStockReconciliation` 方法中，当 `item.ValuationRate` 为 0 时，调用 Bin 查询服务获取真实估值率，移除强制赋值为 1 的逻辑
3. **增加提交验证逻辑**：在 `SubmitStockReconciliation` 方法中，验证所有物品的估值率，若为空则阻止提交并返回明确错误信息

> **前端改进**（后续迭代）：移除 UI 估值率字段、增加仓库物品验证、优化物品源过滤等

### 风险识别

**潜在风险**：
1. **数据迁移风险**：历史上已经被错误赋值为 1 的估值率数据需要如何处理？
2. **用户流程变更**：用户需要理解必须先采购入库才能盘点，可能影响使用习惯
3. **ERPNext Bin 表查询性能**：大量盘点物品时的查询性能需要验证

**缓解措施**：
1. **数据修复**：提供数据修复脚本或工具，帮助用户识别和修正错误的估值率
2. **用户培训**：提供操作文档和培训，说明正确的业务流程
3. **性能优化**：考虑批量查询或缓存策略，减少对 ERPNext 的查询压力

## 📝 附录

### User Story（初稿）

**作为** 仓库管理员  
**我想** 在进行库存盘点时，系统能够自动读取物品的真实估值率（来自采购数据）  
**以便于** 确保盘点结果准确反映物品的实际成本，不会因为系统的错误赋值导致财务数据失真

### AC 验收标准（初稿）

**AC1：估值率从 ERPNext 读取**
- **GIVEN** 物品已通过采购入库，在 ERPNext Bin 表中有估值率记录
- **WHEN** 创建盘点单并保存时
- **THEN** 系统应自动查询并使用 Bin 表中的估值率，而非强制赋值为 1

**AC2：估值率为空时阻止提交**
- **GIVEN** 物品在指定仓库中没有估值率（Bin 表中为 0 或无记录）
- **WHEN** 尝试提交盘点单时
- **THEN** 系统应阻止提交并提示："xx物品库存物品估值率为空，无法提交盘点单"

**AC3：移除 UI 估值率字段**
- **GIVEN** 用户访问物品添加页或物品查看页
- **WHEN** 页面加载完成后
- **THEN** 不应显示估值率字段

**AC4：仓库物品验证**
- **GIVEN** 已保存的盘点单中包含物品 A、B、C
- **WHEN** 修改盘点单的仓库为仓库 X，但物品 A 不在仓库 X 中
- **THEN** 系统应提示："盘点单中有不在此仓库的物品"，并提供"清空当前物品"和"我知道了"按钮

**AC5：物品源过滤**
- **GIVEN** 用户在盘点页面选择了仓库 X
- **WHEN** 点击"物品源"选择物品时
- **THEN** 只显示仓库 X 中的物品
