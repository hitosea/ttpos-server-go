## 🎯 背景和动机

### 问题描述

TTPOS 侧进行统一账号管理后，用户可以进行多门店切换。但是当前员工管理功能中存在权限问题：

1. **隐私信息泄露风险**：门店管理员可以在员工管理中直接修改用户的姓名、邮箱、手机号、密码等私人信息
2. **权限边界不清**：门店级别的管理员不应该有权限修改用户的全局账号信息
3. **账号管理混乱**：用户被拉进门店的方式不统一，缺乏规范的邀请流程

**用户痛点**：
- 用户担心自己的私人信息被门店管理员随意修改
- 门店管理员可能误操作修改了用户的账号信息，影响用户在其他门店的使用
- 缺乏规范的员工邀请机制，无法追溯员工加入门店的流程

### 业务价值

解决这个问题能带来以下业务价值：

- ✅ **保护用户隐私**：确保用户的私人信息只能由用户自己修改，提升用户信任度
- ✅ **明确权限边界**：门店只能管理门店相关的信息（角色、权限密码等），不能修改全局账号信息
- ✅ **规范管理流程**：通过邀请机制规范员工加入门店的流程，便于审计和追溯
- ✅ **提升安全性**：防止门店管理员恶意修改用户账号信息，提升系统安全性
- ✅ **符合数据保护法规**：符合 GDPR、个人信息保护法等法规要求

## 💡 解决方案概述

### 方案描述

**核心思路**：将用户信息分为两类：**全局账号信息**（私人信息）和**门店关联信息**（门店相关配置）。

1. **限制门店权限**：门店管理员只能修改员工在该门店的角色、权限密码等门店相关信息，不能修改用户的姓名、邮箱、手机号、登录密码等私人信息
2. **规范邀请流程**：新增员工邀请功能，门店管理员通过生成邀请链接/邀请码的方式邀请用户加入门店
3. **用户自主管理**：用户的私人信息（姓名、邮箱、手机号、密码）由用户自己在个人中心修改

### 核心功能点

1. **员工信息编辑权限限制**
   - 门店管理员编辑员工时，只能修改：角色、权限密码、状态（启用/禁用）
   - 姓名、邮箱、手机号、登录密码改为只读显示，并提示"用户私人信息需要在个人中心修改"
   - 后端接口限制，拒绝修改私人信息的请求

2. **员工邀请功能**（新功能）
   - 门店管理员通过手机号/邮箱邀请用户加入门店
   - 邀请时可以预设角色和权限密码
   - 系统自动判断用户是否已在平台注册
   - **情况一：未注册用户** - 用户通过邀请链接完成注册并加入门店
   - **情况二：已注册用户** - 用户接受邀请后直接关联到门店
   - 邀请记录可追溯，支持邀请状态查询

3. **个人中心信息管理**
   - 用户可以在个人中心修改自己的姓名、邮箱、手机号、密码
   - 修改后同步到所有关联的门店（如果需要）

### 风险识别

**潜在风险**：
1. **向后兼容性**：现有门店管理员可能已经习惯直接修改员工信息，需要做好用户教育
2. **邀请流程复杂度**：邀请功能需要与统一账号管理集成，可能涉及复杂的账号关联逻辑
3. **数据迁移**：如果统一账号管理还未完全实现，可能需要数据迁移
4. **用户注册流程**：未注册用户通过邀请注册，需要确保注册流程简洁且安全
5. **账号匹配问题**：已注册用户接受邀请时，需要准确匹配手机号/邮箱，避免误关联
6. **通知送达率**：短信/邮件通知可能被拦截或延迟，需要提供备选方案（如站内消息）

**缓解措施**：
1. **用户教育**：在员工编辑页面添加明确的提示说明，告知管理员权限变更
2. **分阶段实施**：先完成权限限制调整，再开发邀请功能，降低风险
3. **充分测试**：邀请功能需要充分测试各种场景（新用户、已存在用户、多门店等）
4. **注册流程优化**：简化未注册用户的注册流程，只收集必要信息（姓名、密码）
5. **多重验证**：已注册用户接受邀请时，验证手机号/邮箱匹配，并记录操作日志
6. **通知冗余**：同时使用短信、邮件、站内消息三种方式通知用户，提高送达率
7. **邀请码管理**：提供邀请码查询和管理功能，方便管理员查看邀请状态

5. **IF** 邀请的手机号/邮箱已注册 **THEN** 系统 **SHALL** 发送邀请通知，用户接受后直接关联到门店
6. **WHEN** 用户在个人中心修改私人信息 **THEN** 系统 **SHALL** 更新全局账号信息，并同步到所有关联门店（如需要）

## 🔧 邀请流程详细设计

### 数据库设计

#### 邀请记录表（ttpos_staff_invitation）

```sql
CREATE TABLE ttpos_staff_invitation (
    id bigint PRIMARY KEY AUTO_INCREMENT,
    uuid bigint UNIQUE COMMENT '邀请记录ID',
    company_uuid bigint COMMENT '门店ID',
    inviter_uuid bigint COMMENT '邀请人（门店管理员）ID',
    invite_type tinyint COMMENT '邀请类型：1-手机号，2-邮箱',
    invite_value varchar(255) COMMENT '邀请值（手机号或邮箱）',
    invite_code varchar(64) UNIQUE COMMENT '邀请码（用于生成邀请链接）',
    role_uuids text COMMENT '预设角色ID列表（JSON格式）',
    permission_password varchar(255) COMMENT '预设权限密码（加密）',
    status tinyint COMMENT '状态：0-待接受，1-已接受，2-已拒绝，3-已过期，4-已取消',
    expire_time int COMMENT '过期时间（时间戳）',
    accept_time int COMMENT '接受时间（时间戳）',
    accepted_user_uuid bigint COMMENT '接受邀请的用户ID（全局用户ID）',
    create_time int COMMENT '创建时间',
    update_time int COMMENT '更新时间',
    delete_time int COMMENT '删除时间',
    INDEX idx_company_uuid (company_uuid),
    INDEX idx_invite_code (invite_code),
    INDEX idx_invite_value (invite_type, invite_value),
    INDEX idx_status (status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='员工邀请记录表';
```

### 邀请流程设计

#### 场景一：邀请未注册用户

**流程步骤**：

1. **门店管理员发起邀请**
   ```
   门店管理员 → 输入手机号/邮箱 → 选择角色 → 设置权限密码（可选）→ 提交邀请
   ```

2. **系统处理**
   - 检查手机号/邮箱是否已在平台注册（查询 `ttpos_global_user` 表）
   - 如果未注册，创建邀请记录，状态为"待接受"
   - 生成唯一的邀请码（如：`INV-{timestamp}-{random}`）
   - 设置邀请有效期（默认7天）
   - 发送邀请短信/邮件（包含邀请链接）

3. **用户接受邀请**
   ```
   用户点击邀请链接 → 跳转到注册页面 → 填写姓名、设置密码 → 完成注册 → 自动加入门店
   ```

4. **系统处理**
   - 创建全局用户账号（`ttpos_global_user`）
   - 创建门店员工记录（`ttpos_staff`）
   - 创建用户-门店关联记录（`ttpos_user_company`）
   - 更新邀请记录状态为"已接受"
   - 设置用户在该门店的角色和权限密码

**API 设计**：

```go
// 1. 生成邀请
POST /api/v1/shop/staff/invitation/create
{
    "invite_type": 1,  // 1-手机号，2-邮箱
    "invite_value": "13800138000",
    "role_uuids": [1, 2],
    "permission_password": "1234"  // 可选
}

// 响应
{
    "invite_code": "INV-20251222-ABC123",
    "invite_link": "https://shop.ttpos.com/invitation/accept?code=INV-20251222-ABC123",
    "expire_time": 1703232000
}

// 2. 检查邀请状态（用户点击邀请链接时）
GET /api/v1/shop/staff/invitation/check?code=INV-20251222-ABC123

// 响应
{
    "status": "pending",  // pending, accepted, expired, cancelled
    "company_name": "测试门店",
    "inviter_name": "张三",
    "roles": [{"uuid": 1, "name": "收银员"}],
    "is_registered": false  // 用户是否已注册
}

// 3. 接受邀请（未注册用户）
POST /api/v1/shop/staff/invitation/accept
{
    "invite_code": "INV-20251222-ABC123",
    "real_name": "李四",
    "password": "Password123!",
    "confirm_password": "Password123!"
}

// 4. 接受邀请（已注册用户）
POST /api/v1/shop/staff/invitation/accept
{
    "invite_code": "INV-20251222-ABC123"
}
// 需要用户已登录，从 token 中获取用户信息
```

#### 场景二：邀请已注册用户

**流程步骤**：

1. **门店管理员发起邀请**
   ```
   门店管理员 → 输入手机号/邮箱 → 选择角色 → 设置权限密码（可选）→ 提交邀请
   ```

2. **系统处理**
   - 检查手机号/邮箱是否已在平台注册
   - 如果已注册，查询全局用户信息
   - 检查用户是否已经是该门店的员工
     - 如果已经是员工，返回错误提示
     - 如果不是，创建邀请记录，状态为"待接受"
   - 生成邀请码和邀请链接
   - 发送邀请通知（站内消息/短信/邮件）

3. **用户接受邀请**
   ```
   用户登录系统 → 查看邀请通知 → 点击接受 → 自动关联到门店
   ```

4. **系统处理**
   - 获取用户全局账号信息
   - 创建门店员工记录（`ttpos_staff`），使用全局账号的姓名、邮箱、手机号
   - 创建用户-门店关联记录（`ttpos_user_company`）
   - 更新邀请记录状态为"已接受"
   - 设置用户在该门店的角色和权限密码

```go

{

        "uuid": 12345,
        "real_name": "李四",
        "username": "lisi@example.com",
        "phone": "13800138000"
    },
    "is_registered": true,
    "expire_time": 1703232000
}

// 2. 用户接受邀请（已注册用户，需要登录）
POST /api/v1/shop/staff/invitation/accept
{
    "invite_code": "INV-20251222-ABC123"
}
// 从 JWT token 中获取用户信息，验证邀请的手机号/邮箱是否匹配
```

### 安全考虑

1. **邀请码唯一性**：使用时间戳 + 随机字符串确保唯一性
2. **邀请有效期**：默认7天，过期后无法接受
3. **重复邀请检测**：如果用户已经是该门店员工，不允许重复邀请
4. **手机号/邮箱验证**：已注册用户接受邀请时，验证邀请的手机号/邮箱与登录账号是否匹配
5. **权限控制**：只有门店管理员可以生成邀请，只有被邀请的用户可以接受邀请

## 📄 模板使用说明

### 何时使用此模板

- ✅ 产品经理提出新功能想法
- ✅ 用户反馈需求建议
- ✅ 技术团队提出改进方案
- ✅ 需要团队讨论和评审的需求

### 与 Spec 的区别

| 阶段        | 文档类型      | 详细程度 | 用途               |
| ----------- | ------------- | -------- | ------------------ |
| **需求发起** | Proposal      | 粗略     | 团队评审、决策是否做 |
| **需求确认** | Requirements  | 详细     | User Story + AC，开发依据 |
| **技术设计** | Design        | 详细     | 技术方案，实现指导 |
| **任务分解** | Tasks         | 详细     | 开发执行，进度追踪 |

### 流转路径

```
提案 (Proposal) 
  ↓ 评审批准
需求文档 (Requirements) 
  ↓ 技术评审
设计文档 (Design) 
  ↓ SP 评估 ≤ 5
任务分解 (Tasks)
  ↓
开发实现
```
