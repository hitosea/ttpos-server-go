## 🎯 背景和动机

### 问题描述

当前在配置 Grab 外卖或 LINE MAN 外卖时，系统不会自动创建对应的支付方式。这导致：

1. **数据不一致**：外卖订单可能使用 Grab 支付或 LINE MAN 支付，但系统中没有对应的支付方式记录
2. **ERP 同步缺失**：如果商户开启了 ERP 同步，这些支付方式无法自动同步到 ERP 系统
3. **统计不准确**：支付方式统计中缺少外卖平台支付数据，影响财务对账和报表分析

### 业务价值

- ✅ **自动化配置**：配置外卖平台时自动创建对应支付方式，减少手动操作
- ✅ **数据完整性**：确保支付方式数据与外卖平台配置保持一致
- ✅ **ERP 集成**：自动同步支付方式到 ERP，提升数据一致性
- ✅ **财务对账**：支持按支付方式统计和核对，提升财务准确性

## 💡 解决方案概述

### 方案描述

在配置 Grab 外卖或 LINE MAN 外卖时，系统自动创建对应的支付方式：

1. **Grab 支付方式**：配置 Grab 外卖时自动创建
   - 来源标识：系统（Source = 0）
   - 不在旧后台、新管理端显示（IsShowCashier = 0, IsShowAssistant = 0 等）
   - 如果开启 ERP，自动同步至 ERP

2. **LINE MAN 支付方式**：配置 LINE MAN 外卖时自动创建
   - 来源标识：系统（Source = 0）
   - 不在旧后台、新管理端显示（IsShowCashier = 0, IsShowAssistant = 0 等）
   - 如果开启 ERP，自动同步至 ERP

### 核心功能点

1. **自动创建支付方式**
   - 配置 Grab 外卖时，自动创建"Grab"支付方式
   - 配置 LINE MAN 外卖时，自动创建"LINE MAN"支付方式
   - 支付方式来源标识为"系统"（Source = 0）

2. **隐藏显示控制**
   - 不在旧后台显示（IsShowCashier = 0）
   - 不在新管理端显示（相关显示字段设为 0）
   - 仅用于系统内部记录和 ERP 同步

3. **ERP 同步集成**
   - 检测商户是否开启 ERP
   - 如果开启，自动调用 ERP 同步接口
   - 同步支付方式到 ERP 系统

4. **去重处理**
   - 检查支付方式是否已存在（通过名称或 code）
   - 避免重复创建

### 风险识别

**潜在风险**：
1. **支付方式 code 冲突**：需要确保生成的 code 不与现有支付方式冲突
2. **ERP 同步失败**：ERP 同步失败时的回滚和错误处理
3. **重复创建**：配置多次保存时可能重复创建支付方式
4. **数据一致性**：删除外卖配置时，支付方式如何处理

**缓解措施**：
1. **code 生成策略**：使用独立的 code 范围（如 20000+），避免与现有支付方式冲突
2. **事务处理**：支付方式创建和 ERP 同步放在同一事务中，失败时回滚
3. **幂等性检查**：创建前检查支付方式是否已存在（通过名称或特定标识）
4. **删除策略**：明确删除外卖配置时是否删除支付方式，或仅标记为禁用

## 📝 附录

### User Story（初稿）

**作为** 商户管理员  
**我想** 在配置 Grab/LINE MAN 外卖时，系统自动创建对应的支付方式  
**以便于** 确保支付方式数据完整，并自动同步到 ERP 系统

### AC 验收标准（初稿）

1. **WHEN** 商户配置 Grab 外卖并保存 **THEN** 系统 **SHALL** 自动创建"Grab"支付方式，来源标识为"系统"，且不在旧后台、新管理端显示
2. **WHEN** 商户配置 LINE MAN 外卖并保存 **THEN** 系统 **SHALL** 自动创建"LINE MAN"支付方式，来源标识为"系统"，且不在旧后台、新管理端显示
3. **IF** 商户已开启 ERP 同步 **THEN** 系统 **SHALL** 自动将支付方式同步到 ERP
4. **IF** 支付方式已存在（通过名称判断） **THEN** 系统 **SHALL** 跳过创建，避免重复
5. **WHEN** 多次保存外卖配置 **THEN** 系统 **SHALL** 不会重复创建支付方式（幂等性）

### 技术实现要点

1. **触发时机**：在外卖平台配置保存时触发
2. **支付方式属性**：
   - Source = 0（系统默认）
   - IsShowCashier = 0（不在收银端显示）
   - IsShowAssistant = 0（不在助手端显示）
   - IsShowKiosk = 0（不在自助机显示）
   - IsShowMemberRecharge = 0（不在会员充值显示）
   - Status = 1（启用状态）
3. **ERP 同步**：参考 `payment_method.go` 中的 `Create` 方法，使用相同的 ERP 同步逻辑
4. **去重策略**：通过 `payment_name` 字段检查是否已存在
