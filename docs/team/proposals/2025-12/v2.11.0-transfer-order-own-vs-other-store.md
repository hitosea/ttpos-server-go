## 🎯 背景和动机

### 问题描述

当前新管理端的调拨单列表页面，将本店提交的调拨单和其他门店提交的调拨单混合展示在一起，导致：

1. **信息混乱**：用户难以快速区分哪些是本店发起的调拨，哪些是其他门店发起的调拨
2. **查找效率低**：当调拨单数量较多时，店长或仓管人员需要逐条查看才能找到目标调拨单
3. **管理不便**：本店提交的调拨单和收到的调拨单通常需要不同的处理流程和关注重点，混合展示不利于分类管理

### 业务价值

通过增加筛选功能，将本店提交的调拨单和其他门店提交的调拨单分开管理，可以带来以下价值：

- **提升管理效率**：店长/仓管可以快速筛选查看需要关注的调拨单类型
- **减少操作错误**：明确区分调拨单来源，避免混淆导致的处理错误
- **改善用户体验**：符合用户实际业务场景的信息组织方式
- **增强业务清晰度**：便于分别统计和管理"发出的调拨"和"收到的调拨"

## 💡 解决方案概述

### 方案描述

在新管理端的调拨单列表页增加"提交方"筛选按钮，支持按调拨单的提交来源进行筛选：

1. **全部**：展示本店所有相关的调拨单（包括本店提交的和其他门店提交给本店的）
2. **本店提交**：仅展示由本店发起的调拨单（本店作为调出方）
3. **他店提交**：仅展示由其他门店发起的调拨单（本店作为调入方）

用户可以根据实际业务需求快速切换筛选条件，提升调拨单管理效率。

### 核心功能点

1. **筛选按钮组**：在调拨单列表页顶部增加"提交方"筛选按钮组（全部/本店提交/他店提交）
2. **动态列表刷新**：点击筛选按钮后，列表内容根据筛选条件实时更新
3. **筛选状态保持**：用户选择的筛选条件在页面刷新或重新进入时保持（可选增强）
4. **与其他筛选条件联动**：与现有的日期、状态等筛选条件协同工作

### 风险识别

**潜在风险**：
1. **数据量大时的性能问题**：如果调拨单数据量很大，筛选查询可能影响性能
2. **与现有筛选条件的交互冲突**：需要确保新增筛选条件与现有筛选（日期、状态等）协同工作

**缓解措施**：
1. **数据库索引优化**：确保调拨单表的相关字段（如调出门店 ID、调入门店 ID）有合适的索引
2. **筛选逻辑测试**：充分测试各种筛选条件组合，确保逻辑正确且无性能问题

## 📝 附录

### User Story（初稿）

**作为** 商户管理员（店长）或仓管人员  
**我想** 在调拨单列表页快速筛选"本店提交的调拨单"和"其他门店提交的调拨单"  
**以便于** 分别管理发出的调拨和收到的调拨，提升管理效率

### AC 验收标准（初稿）

根据 DooTask 任务中的描述：

1. **WHEN** 用户选择"全部" **THEN** 系统 **SHALL** 展示本店所有相关调拨单内容（包括本店提交的和其他门店提交的）

2. **WHEN** 用户选择"本店提交" **THEN** 系统 **SHALL** 展示本店提交的调拨单内容（本店作为调出方）

3. **WHEN** 用户选择"他店提交" **THEN** 系统 **SHALL** 展示其他门店提交的调拨单内容（本店作为调入方）

4. **IF** 用户切换筛选条件 **THEN** 列表 **SHALL** 实时更新并正确展示对应的调拨单

5. **IF** 筛选结果为空 **THEN** 系统 **SHALL** 显示友好的空状态提示
