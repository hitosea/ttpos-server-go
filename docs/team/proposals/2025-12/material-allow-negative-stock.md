## 🎯 背景和动机

### 问题描述

当前系统在物品库存管理时，不允许负库存操作。但在实际业务场景中，某些物品（如原材料、半成品等）可能需要允许负库存，以便在库存不足时仍能继续业务操作，后续通过补货或调整来平衡库存。

**示例**：
> 餐厅在高峰期时，某些原材料可能临时短缺，但为了不影响正常营业，需要允许先出库后补货，即允许负库存。

### 业务价值

- 提升业务灵活性，适应不同物品的库存管理策略
- 减少因库存不足导致的业务中断
- 支持更精细化的库存控制策略
- 提高系统对不同业务场景的适应性

## 💡 解决方案概述

### 方案描述

在物品管理功能中增加"允许负库存"的设置选项，允许商户针对不同物品配置是否允许负库存。当允许负库存时，即使当前库存不足，也可以进行出库操作；当不允许负库存时，保持原有的库存校验逻辑。

**技术实现**：
1. 在 `material` 表中增加 `allow_negative_stock` 字段（integer类型）
2. 在添加物品和编辑物品的接口中增加该字段的设置
3. 在 `erpSrv.AddMaterial` 方法中增加 `AllowNegativeStock` 参数
4. 在相关的同步物品接口中同步该字段的逻辑

### 核心功能点

1. **数据库层面**：在 `material` 表中增加 `allow_negative_stock` 字段（integer(1)，默认 0）
2. **API 层面**：添加物品和编辑物品接口增加 `allow_negative_stock` 参数
3. **服务层面**：`erpSrv.AddMaterial` 方法增加 `AllowNegativeStock` 参数
4. **同步逻辑**：相关同步物品接口需要同步该字段的设置

### 风险识别

**潜在风险**：
1. 负库存可能导致库存数据不准确，需要明确业务规则
2. 同步接口需要确保字段正确传递，避免数据不一致
3. 历史数据需要处理默认值

**缓解措施**：
1. 明确负库存的业务规则和使用场景，提供清晰的用户提示
2. 在同步接口中增加字段校验和日志记录
3. 数据库迁移时设置默认值为 0（不允许负库存），保持向后兼容

## 📝 附录

### User Story（初稿）

**作为** 商户管理员  
**我想** 在添加或编辑物品时设置是否允许负库存  
**以便于** 针对不同物品采用不同的库存管理策略，提高业务灵活性

### AC 验收标准（初稿）

1. **WHEN** 商户管理员添加物品时 **THEN** 系统 **SHALL** 提供"允许负库存"选项
2. **WHEN** 商户管理员编辑物品时 **THEN** 系统 **SHALL** 可以修改"允许负库存"设置
3. **IF** 物品设置为允许负库存 **THEN** 系统 **SHALL** 在库存不足时仍允许出库操作
4. **IF** 物品设置为不允许负库存 **THEN** 系统 **SHALL** 在库存不足时阻止出库操作
5. **WHEN** 同步物品数据时 **THEN** 系统 **SHALL** 正确同步 `allow_negative_stock` 字段
