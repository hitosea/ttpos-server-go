## 🎯 背景和动机

### 问题描述

根据附图显示,商家端"商品数据"页面需要展示"当前店内Grab商品:0"这样的统计信息,但目前缺少相应的后端接口支持。商家需要能够快速了解当前已同步到TTPOS系统的Grab平台商品数量。

从代码分析来看,现有的外卖管理系统(`takeout_app_service.go`)已经具备了:
- 获取Grab菜单数据的能力 (`GetGrabMenu`)
- 从平台导入到TTPOS的能力 (`ConvertMenuData`)
- 推送菜单到平台的能力 (`PushMenuToGrab`)

但缺少一个统计当前TTPOS系统中Grab商品数量的接口。

### 业务价值

- 为商家提供直观的数据统计,便于了解当前Grab商品同步状态
- 帮助商家判断是否需要重新导入或更新Grab商品数据
- 为后续的商品管理功能提供基础数据支持
- 提升商家对外卖管理系统的可见性和信任度

## 💡 解决方案概述

### 方案描述

在商家端外卖管理模块中,新增一个接口用于获取当前店内已导入的Grab商品列表。该接口应该能够:

1. 统计当前TTPOS系统中所有关联到Grab平台的商品数量
2. 支持分页查询商品详细列表
3. 返回商品的基本信息(商品ID、名称、价格、上下架状态等)

技术实现方面,可以通过查询`ttpos_product_takeout`表(关联外卖平台的商品映射表)来获取Grab商品数据,结合`ttpos_product`表获取商品详细信息。

### 核心功能点

1. **统计接口**: 快速返回当前Grab商品总数
2. **列表接口**: 支持分页查询,返回商品详细列表
3. **状态筛选**: 支持按商品上下架状态筛选
4. **多语言支持**: 商品名称等信息支持多语言展示

### 风险识别

**潜在风险**:
1. 商品数据量较大时,查询性能可能受影响
2. 多语言数据获取可能增加查询复杂度
3. 需要考虑商品删除/下架的状态判断逻辑

**缓解措施**:
1. 实现缓存机制,缓存商品统计数据(有效期5分钟)
2. 优化SQL查询,使用JOIN减少查询次数
3. 明确定义商品状态过滤规则,在Service层统一处理

## 📝 附录

### User Story(初稿)

**作为** 商户管理员  
**我想** 查看当前店内已导入的Grab商品列表  
**以便于** 了解当前外卖商品的同步状态,并进行后续管理

### AC 验收标准(初稿)

1. **WHEN** 访问商品数据页面 **THEN** 系统 **SHALL** 显示"当前店内Grab商品:X"的统计信息
2. **WHEN** 点击查看详情 **THEN** 系统 **SHALL** 展示分页的商品列表
3. **IF** 商品已下架或删除 **THEN** 系统 **SHALL** 正确过滤或标注状态
4. **WHEN** 商品导入完成后 **THEN** 系统 **SHALL** 在5分钟内更新统计数据
