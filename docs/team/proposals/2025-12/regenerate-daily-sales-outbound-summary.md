## 🎯 背景和动机

### 问题描述

当前系统通过定时任务 `DailySalesOutboundSummaryTask` 自动生成每日销售出库汇总记录，但存在以下问题：

1. **数据修正困难**：当发现某一天的销售出库汇总记录有误时（如数据统计错误、营业时段配置错误等），无法便捷地重新生成该天的记录
2. **手动处理复杂**：需要手动删除旧记录并重新执行统计逻辑，操作繁琐且容易出错
3. **缺乏管理工具**：管理员无法通过管理后台或命令行工具快速修复历史数据

**示例场景**：
> 某门店在 2025-12-10 的营业时段配置错误，导致销售出库汇总记录统计不准确。管理员发现后需要修正数据，但当前只能手动删除数据库记录，然后等待定时任务重新生成，或者需要开发人员手动执行 SQL 和代码逻辑。

### 业务价值

解决这个问题能带来以下业务价值：

- **提升数据准确性**：快速修正历史销售出库汇总记录，确保报表数据准确
- **降低运维成本**：减少需要开发人员介入的数据修正场景
- **提高操作效率**：管理员可以自主处理数据修正，无需等待定时任务或开发支持
- **增强系统可靠性**：提供数据修复能力，提升系统容错性

## 💡 解决方案概述

### 方案描述

提供一个管理功能，支持重新生成指定日期的销售出库汇总记录。功能包括：

1. **删除旧记录**：根据指定的门店和日期，删除该日期所有营业时段的销售出库汇总记录（软删除）
2. **重新生成记录**：复用现有的 `DailySalesOutboundSummaryTask` 中的统计逻辑，重新计算并生成该日期的销售出库汇总记录
3. **支持多种调用方式**：
   - 管理后台界面操作（Shop 商家管理端）
   - 命令行工具（Command）
   - API 接口（供其他系统调用）

### 核心功能点

1. **按日期删除旧记录**
   - 支持指定门店和日期
   - 根据 `opening_hours` 字段匹配该日期的所有营业时段记录
   - 软删除（更新 `delete_time` 字段）
   - 记录操作日志

2. **重新生成汇总记录**
   - 复用 `getDailySalesOutboundRecords` 方法获取销售出库数据
   - 复用 `saveOutboundSummaryRecords` 方法保存新记录
   - 支持指定营业时段或自动识别所有营业时段
   - 事务保证数据一致性

3. **操作入口**
   - Shop 商家管理端：库存管理 → 出入库记录 → 重新生成按钮
   - 命令行：`./main command regenerate-sales-outbound --company-uuid=xxx --date=2025-12-10`
   - API 接口：`POST /api/shop/inventory/regenerate-sales-outbound-summary`

4. **安全控制**
   - 权限校验（仅管理员可操作）
   - 操作确认（二次确认）
   - 操作日志记录
   - 分布式锁防止并发操作

### 风险识别

**潜在风险**：
1. **数据一致性风险**：删除和重新生成过程中，如果有其他操作同时进行，可能导致数据不一致
2. **性能风险**：重新生成大量历史数据可能耗时较长，影响系统性能
3. **误操作风险**：管理员误删重要日期的数据，需要提供回滚机制

**缓解措施**：
1. **分布式锁**：使用 Redis 分布式锁，确保同一门店同一日期只能有一个重新生成操作
2. **异步处理**：对于大量数据，考虑异步处理，提供任务进度查询
3. **操作确认**：前端提供二次确认，命令行提供 `--dry-run` 预览模式
4. **操作日志**：详细记录操作日志，包括操作人、时间、删除的记录数、生成的记录数等
5. **数据备份**：在删除前备份旧记录（可选，或通过数据库 binlog 恢复）

## 📝 附录

### User Story（初稿）

**作为** 商户管理员  
**我想** 重新生成指定日期的销售出库汇总记录  
**以便于** 修正历史数据错误，确保报表数据准确

**作为** 系统管理员  
**我想** 通过命令行工具批量重新生成多个门店的销售出库汇总记录  
**以便于** 快速修复批量数据问题

### AC 验收标准（初稿）

1. **WHEN** 管理员在 Shop 商家管理端选择门店和日期，点击"重新生成"按钮 **THEN** 系统 **SHALL** 提示确认对话框，显示将删除的记录数和预计生成的记录数
2. **IF** 管理员确认操作 **THEN** 系统 **SHALL** 删除该日期所有营业时段的旧记录，并重新生成新的汇总记录
3. **WHEN** 操作完成后 **THEN** 系统 **SHALL** 显示操作结果，包括删除的记录数、生成的记录数、操作耗时
4. **IF** 操作过程中发生错误 **THEN** 系统 **SHALL** 回滚事务，保持数据一致性，并返回错误信息
5. **WHEN** 通过命令行工具执行重新生成 **THEN** 系统 **SHALL** 支持 `--dry-run` 参数预览操作，支持 `--company-uuid` 和 `--date` 参数指定门店和日期
6. **IF** 同一门店同一日期正在执行重新生成操作 **THEN** 系统 **SHALL** 拒绝新的操作请求，返回"操作进行中"提示

### 技术实现要点（初稿）

1. **提取公共方法**：将 `DailySalesOutboundSummaryTask` 中的 `ProcessCompany`、`getDailySalesOutboundRecords`、`saveOutboundSummaryRecords` 等方法提取为可复用的 Service 方法
2. **新增 Service 方法**：创建 `RegenerateSalesOutboundSummary` 方法，接收门店 UUID 和日期参数
3. **API 接口**：`POST /api/shop/inventory/regenerate-sales-outbound-summary`
   - 请求参数：`company_uuid`（必填）、`date`（必填，格式：YYYY-MM-DD）
   - 响应：操作结果、删除记录数、生成记录数
4. **命令行工具**：新增 `regenerate-sales-outbound` 子命令
   - 参数：`--company-uuid`、`--date`、`--dry-run`
5. **前端界面**：在出入库记录列表页面添加"重新生成"按钮，点击后弹出日期选择对话框
