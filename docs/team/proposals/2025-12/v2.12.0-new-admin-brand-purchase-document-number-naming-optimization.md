## 🎯 背景和动机

### 问题描述

总店在审核的时候，发现品牌采购中的订单编号不是唯一性，导致用户在搜索单据及操作单据时容易出错。

**当前命名规则**：业务前缀 + 时间戳（yyyyMMdd） + 序列号

**问题影响**：
- 同一日期内生成的单据编号可能重复
- 用户在搜索单据时容易混淆
- 操作单据时可能误操作其他单据
- 影响审核效率和准确性

### 业务价值

- ✅ **提升单据唯一性**：确保集团内品牌采购单据编号全局唯一
- ✅ **提升用户体验**：方便用户快速查找、修改、审批单据
- ✅ **降低操作风险**：防止误操作，减少业务错误
- ✅ **提升审核效率**：审核人员可以准确识别和操作目标单据

## 💡 解决方案概述

### 方案描述

通过增加时间戳颗粒度，将时间戳从日期级别（yyyyMMdd）提升到秒级别（yyyyMMddHHmmss），尽可能确保毫秒级的不重复，从而保证单据编号在集团内的唯一性。

**新的命名规则**：业务前缀 + 时间戳（yyyyMMddHHmmss） + 序列号

### 核心功能点

1. **时间戳格式优化**：从 `yyyyMMdd` 升级为 `yyyyMMddHHmmss`
2. **单据编号生成逻辑调整**：更新所有相关单据的编号生成规则
3. **历史数据兼容**：之前的数据不做修改，保持向后兼容
4. **业务前缀标准化**：统一使用英文缩写前缀

### 涉及功能板块

**需要调整的单据类型**：

1. **采购申请（外部）**：`PR` + `20250403091512` + `0001`
   - 调整前缀为英文缩写，之前数据不做修改

2. **采购收货（外部）**：`PRC` + `20250403091512` + `0001`
   - 调整前缀为英文缩写，之前数据不做修改

3. **品牌采购（内部）**：`TPHY` + `20250403091512` + `0001`

4. **品采收货（内部）**：`TPHY` + `20250403091512` + `0001`

5. **盘点单**：`ST` + `20250403091512` + `0001`

6. **调拨单**：`TR` + `20250403091512` + `0001`

### 风险识别

**潜在风险**：
1. **历史数据兼容性**：需要确保历史单据编号不受影响，系统能正确识别新旧格式
2. **并发生成冲突**：同一秒内生成多个单据时，序列号分配需要保证唯一性
3. **前端展示影响**：单据编号长度增加，需要检查前端展示是否受影响
4. **搜索功能影响**：需要确保搜索功能能同时支持新旧格式

**缓解措施**：
1. **历史数据保护**：明确不修改历史数据，只对新生成的单据应用新规则
2. **序列号机制**：使用数据库序列或分布式 ID 生成器确保唯一性
3. **前端适配**：检查并调整前端展示，确保长编号能正常显示
4. **搜索兼容**：搜索功能支持模糊匹配，兼容新旧格式

## 📝 附录

### User Story（初稿）

**作为** 总店审核人员  
**我想** 品牌采购单据编号具有唯一性  
**以便于** 准确搜索、识别和操作目标单据，避免误操作

### AC 验收标准（初稿）

**AC1：核心功能验证**
- **Given** 用户在品牌采购模块创建新单据
- **When** 系统生成单据编号
- **Then** 单据编号格式为：业务前缀 + 时间戳（yyyyMMddHHmmss）+ 序列号
- **And** 单据编号在集团内全局唯一

**AC2：边界场景处理**
- **Given** 同一秒内生成多个单据
- **When** 系统分配序列号
- **Then** 序列号递增，确保编号唯一性
- **And** 不会出现重复编号

**AC3：交互验证**
- **Given** 历史单据使用旧格式编号
- **When** 用户搜索或查看历史单据
- **Then** 系统能正确识别和展示历史单据编号
- **And** 新单据使用新格式编号，两种格式可以共存

**AC4：涉及单据类型验证**
- **Given** 以下单据类型：采购申请、采购收货、品牌采购、品采收货、盘点单、调拨单
- **When** 创建新单据
- **Then** 所有单据类型都使用新的编号生成规则
- **And** 各单据类型的前缀正确（PR、PRC、TPHY、ST、TR）
