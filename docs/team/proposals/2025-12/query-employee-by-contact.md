## 🎯 背景和动机

### 问题描述

当前收银机/点餐助手在进行敏感操作（如退菜、打折、取消订单等）时，需要手动输入授权员工的邮箱或手机号，操作时间较长，影响收银效率。

**现状**：
- 收银员需要完整输入授权员工的邮箱或手机号
- 输入错误需要重新输入
- 无法快速选择常用授权员工
- 操作流程繁琐，延长了结账时间

### 业务价值

- **提升收银效率**：减少授权操作时间，提高高峰期处理能力
- **改善用户体验**：简化操作流程，降低输入错误率
- **提高准确性**：通过下拉选择避免输入错误
- **支持快速授权**：常用授权员工可快速选择，无需完整输入

## 💡 解决方案概述

### 方案描述

新增一个简化的员工查询接口，支持根据邮箱或手机号（支持模糊搜索）查询员工信息，返回员工基本信息（UUID、姓名、邮箱、手机号），用于前端下拉列表展示和快速选择。

**与现有接口的区别**：
- 现有 `/shop/staff/search` 接口返回复杂的门店和角色信息，主要用于管理端
- 新接口返回简化的员工基本信息，专门用于收银端/助手端的快速授权选择

### 核心功能点

1. **根据邮箱或手机号查询员工**
   - 支持精确匹配（完整邮箱/手机号）
   - 支持模糊搜索（部分匹配）
   - 自动识别输入的是邮箱还是手机号

2. **返回员工基本信息**
   - 员工 UUID（用于后续授权验证）
   - 员工姓名
   - 员工邮箱
   - 员工手机号

3. **支持下拉列表展示**
   - 返回结果限制在 20 条以内
   - 支持按关键词过滤
   - 不区分大小写搜索

4. **权限控制**
   - 仅返回当前门店可见范围内的授权员工
   - 基于 Shop 管理端配置的授权员工列表

### 风险识别

**潜在风险**：
1. **性能风险**：如果授权员工数量很大，模糊搜索可能影响性能
2. **权限风险**：需要确保只返回当前门店可见的授权员工
3. **兼容性风险**：需要兼容现有授权验证逻辑

**缓解措施**：
1. **性能优化**：限制返回结果数量（最多 20 条），使用数据库索引优化查询
2. **权限控制**：复用现有的门店可见性逻辑，确保数据安全
3. **向后兼容**：保持现有手动输入方式，新接口作为增强功能

## 📝 附录

### User Story（初稿）

**作为** 收银员/点餐助手  
**我想** 通过下拉列表快速选择授权员工（而不需要手动输入完整邮箱/手机号）  
**以便于** 提高敏感操作的授权效率，减少操作时间

### AC 验收标准（初稿）

1. **WHEN** 收银员点击授权账号输入框或下拉箭头按钮 **THEN** 系统 **SHALL** 显示下拉列表，下拉列表的员工为 Shop 管理端所配置的授权员工
2. **WHEN** 收银员在输入框中输入关键词（邮箱） **THEN** 系统 **SHALL** 实时过滤下拉列表，仅显示匹配的员工（模糊搜索，不区分大小写）
3. **WHEN** 收银员选择下拉列表中的员工 **THEN** 系统 **SHALL** 自动填充该员工的账号到输入框，并关闭下拉列表
4. **WHEN** 收银员手动输入账号 **THEN** 系统 **SHALL** 保持原有验证逻辑不变，下拉列表根据输入内容实时过滤
5. **WHEN** 收银员点击下拉列表外部区域 **THEN** 系统 **SHALL** 关闭下拉列表
6. **WHEN** Shop 管理端更新授权员工配置 **THEN** 系统 **SHALL** 在授权时获取最新列表
7. **WHEN** 查询结果超过 20 条 **THEN** 系统 **SHALL** 仅返回前 20 条匹配结果

### 接口设计（初稿）

**接口路径**：`GET /shop/staff/query-by-contact`

**请求参数**：
```json
{
  "keyword": "string",  // 搜索关键词（邮箱或手机号，支持模糊匹配）
  "limit": 20          // 返回结果数量限制（默认 20）
}
```

**响应数据**：
```json
{
  "code": 200,
  "data": [
    {
      "uuid": 123456,
      "real_name": "张三",
      "email": "zhangsan@example.com",
      "phone": "13800138000"
    }
  ],
  "message": "success"
}
```
