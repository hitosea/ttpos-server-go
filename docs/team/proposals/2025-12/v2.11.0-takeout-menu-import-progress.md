## 🎯 背景和动机

### 问题描述

当前外卖菜单导入功能(`ImportMenu`)在执行时,前端无法获知导入进度,用户体验不佳:

1. **缺乏进度反馈**: 导入过程可能需要较长时间(特别是商品数量多时),但用户只能看到"正在推送,完成后将会通知"和"正在获取,完成后将会通知",无法了解具体进度
2. **重复操作风险**: 用户不知道导入是否正在进行中,可能重复点击导入按钮,导致并发问题
3. **状态不明确**: 导入失败或中断时,用户无法知道具体在哪个环节出现问题

### 业务价值

实现进度条显示后可以带来以下价值:

- **提升用户体验**: 用户可以实时看到导入进度(如"正在同步分类 3/10","正在导入商品 50/200"),减少等待焦虑
- **避免重复操作**: 通过状态标识防止用户在导入进行中重复触发
- **问题定位**: 导入失败时可以明确告知用户在哪个环节失败,便于排查问题
- **提高效率**: 用户可以根据进度预估完成时间,合理安排工作

## 💡 解决方案概述

### 方案描述

在外卖菜单导入过程中实现实时进度反馈机制:

1. **数据库层面**: 在 `ttpos_takeout` 表中新增字段记录导入状态和进度信息
2. **后端服务**: 在 `ImportMenu` 方法执行过程中实时更新进度信息
3. **前端轮询**: 前端通过轮询接口获取最新进度并展示进度条
4. **状态管理**: 通过状态字段防止并发导入

### 核心功能点

1. **数据库设计**
   
   **a. ttpos_takeout 表字段扩展**（记录当前导入状态）
   - `import_status`: 导入状态(0-未导入,1-导入中,2-导入成功,3-导入失败)
   - `import_progress`: 导入进度(JSON格式,包含当前步骤、总步骤数、当前项、总项数等)
   - `import_start_time`: 导入开始时间
   - `import_end_time`: 导入结束时间
   - `import_error`: 导入错误信息
   
   **b. ttpos_takeout_import_log 新表**（记录历史导入日志）
   - `id`: 主键ID
   - `uuid`: 唯一标识
   - `platform`: 外卖平台(grab/lineman等)
   - `import_type`: 导入类型(1-TTPOS推送到平台, 2-平台推送到TTPOS)
   - `import_direction`: 导入方向描述(如"TTPOS推送商品数据到Grab")
   - `status`: 导入状态(0-进行中, 1-成功, 2-失败)
   - `progress`: 进度百分比(0-100)
   - `success_count`: 成功数量
   - `failure_count`: 失败数量
   - `total_count`: 总数量
   - `error_message`: 错误信息
   - `start_time`: 开始时间
   - `end_time`: 结束时间
   - `duration`: 耗时(秒)
   - `create_time`: 创建时间
   - `update_time`: 更新时间
   - `delete_time`: 删除时间

2. **进度更新机制**
   - 在 `syncCategories` 阶段更新进度:"正在同步分类 X/Y"
   - 在 `syncProducts` 阶段更新进度:"正在导入商品 X/Y"
   - 每完成一个步骤同时更新 `ttpos_takeout` 表和 `ttpos_takeout_import_log` 表

3. **日志记录机制**
   - 每次导入开始时在 `ttpos_takeout_import_log` 表中创建新记录
   - 导入过程中实时更新日志记录的进度和状态
   - 导入完成后记录最终结果、耗时、成功/失败数量
   - 支持UI展示历史导入记录列表(如截图所示)

4. **进度查询接口**
   - 新增 API 接口 `GET /api/takeout/import/progress` 返回当前导入进度
   - 新增 API 接口 `GET /api/takeout/import/logs` 返回历史导入日志列表
   - 返回格式包含:状态、当前步骤描述、进度百分比、预估剩余时间

5. **并发控制**
   - 导入开始前检查 `import_status`,如果为"导入中"则拒绝新的导入请求
   - 导入完成或失败后更新状态为"成功"或"失败"

### 风险识别

**潜在风险**:
1. **性能影响**: 频繁更新数据库进度可能影响导入性能
2. **并发问题**: 多个用户同时导入可能导致状态混乱
3. **进度不准确**: 商品数量预估不准确可能导致进度条不准确

**缓解措施**:
1. **批量更新**: 不是每个商品都更新,而是每处理 N 个商品更新一次(如每 10 个)
2. **分布式锁**: 使用 Redis 分布式锁确保同一时间只有一个导入任务
3. **预扫描**: 导入前先扫描一遍获取准确的商品总数

## 📝 附录

### User Story(初稿)

**作为** 商户管理员  
**我想** 在导入外卖菜单时看到实时进度  
**以便于** 了解导入状态,避免重复操作,并在出错时快速定位问题

### AC 验收标准(初稿)

1. **WHEN** 用户点击"导入菜单"按钮 **THEN** 系统 **SHALL** 检查是否有正在进行的导入任务,如果有则提示"导入正在进行中,请稍后再试"
2. **WHEN** 导入任务开始 **THEN** 系统 **SHALL** 在 `ttpos_takeout` 表中记录导入状态为"导入中",并在 `ttpos_takeout_import_log` 表中创建新的日志记录
3. **WHEN** 导入过程中 **THEN** 系统 **SHALL** 实时更新进度信息,包括当前步骤(同步分类/导入商品)和完成百分比,同时更新日志表
4. **WHEN** 前端请求进度信息 **THEN** 系统 **SHALL** 返回当前导入状态、进度百分比、当前步骤描述
5. **WHEN** 前端请求历史日志 **THEN** 系统 **SHALL** 返回历史导入记录列表,按时间倒序排列,展示导入方向、状态、进度、时间等信息
6. **WHEN** 导入成功完成 **THEN** 系统 **SHALL** 更新状态为"导入成功",记录结束时间、成功数量、失败数量和耗时
7. **WHEN** 导入失败 **THEN** 系统 **SHALL** 更新状态为"导入失败",记录错误信息和失败原因
8. **IF** 导入任务异常中断(如服务重启) **THEN** 系统 **SHALL** 在重启后将状态重置为"导入失败"
9. **WHEN** 用户查看日志列表 **THEN** 系统 **SHALL** 展示类似截图的界面,包含导入方向(如"从Grab推送商品数据到TTPOS")、状态(进行中/成功/失败)、进度百分比、时间等信息

### 技术实现要点

#### 1. 数据库迁移

```sql
-- 1. 在 ttpos_takeout 表中新增字段(用于记录当前导入状态)
ALTER TABLE `ttpos_takeout` 
ADD COLUMN `import_status` tinyint NOT NULL DEFAULT 0 COMMENT '导入状态(0-未导入 1-导入中 2-导入成功 3-导入失败)' AFTER `menu`,
ADD COLUMN `import_progress` json COMMENT '导入进度(JSON格式)' AFTER `import_status`,
ADD COLUMN `import_start_time` int NOT NULL DEFAULT 0 COMMENT '导入开始时间' AFTER `import_progress`,
ADD COLUMN `import_end_time` int NOT NULL DEFAULT 0 COMMENT '导入结束时间' AFTER `import_start_time`,
ADD COLUMN `import_error` text COMMENT '导入错误信息' AFTER `import_end_time`,
ADD INDEX `idx_import_status` (`import_status`);

-- 2. 创建导入日志表 ttpos_takeout_import_log(用于记录历史导入日志)
CREATE TABLE IF NOT EXISTS `ttpos_takeout_import_log` (
    `id` bigint unsigned NOT NULL AUTO_INCREMENT COMMENT '主键ID',
    `uuid` bigint unsigned NOT NULL DEFAULT 0 COMMENT '唯一标识',
    `platform` varchar(50) NOT NULL DEFAULT '' COMMENT '外卖平台(grab/lineman等)',
    `import_type` tinyint NOT NULL DEFAULT 0 COMMENT '导入类型(1-TTPOS推送到平台 2-平台推送到TTPOS)',
    `import_direction` varchar(200) NOT NULL DEFAULT '' COMMENT '导入方向描述',
    `status` tinyint NOT NULL DEFAULT 0 COMMENT '导入状态(0-进行中 1-成功 2-失败)',
    `progress` int NOT NULL DEFAULT 0 COMMENT '进度百分比(0-100)',
    `success_count` int NOT NULL DEFAULT 0 COMMENT '成功数量',
    `failure_count` int NOT NULL DEFAULT 0 COMMENT '失败数量',
    `total_count` int NOT NULL DEFAULT 0 COMMENT '总数量',
    `error_message` text COMMENT '错误信息',
    `start_time` int NOT NULL DEFAULT 0 COMMENT '开始时间',
    `end_time` int NOT NULL DEFAULT 0 COMMENT '结束时间',
    `duration` int NOT NULL DEFAULT 0 COMMENT '耗时(秒)',
    `create_time` int NOT NULL DEFAULT 0 COMMENT '创建时间',
    `update_time` int NOT NULL DEFAULT 0 COMMENT '更新时间',
    `delete_time` int NOT NULL DEFAULT 0 COMMENT '删除时间',
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_uuid` (`uuid`),
    KEY `idx_platform` (`platform`),
    KEY `idx_import_type` (`import_type`),
    KEY `idx_status` (`status`),
    KEY `idx_create_time` (`create_time`),
    KEY `idx_delete_time` (`delete_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='外卖导入日志表';
```

#### 3. 核心代码改动点

在 `main/app/service/takeout.go` 的 `ImportMenu` 方法中:

```go
// 1. 导入开始前检查状态
if err := s.checkImportStatus(ctx, platform); err != nil {
    return nil, err
}

// 2. 创建导入日志记录
logUuid, err := s.createImportLog(ctx, &ImportLogParams{
    Platform: platform,
    ImportType: ImportTypeFromPlatform, // 2-从平台导入到TTPOS
    ImportDirection: fmt.Sprintf("从%s推送商品数据到TTPOS", platform),
})
if err != nil {
    return nil, err
}

// 3. 设置导入中状态
if err := s.updateImportStatus(ctx, platform, ImportStatusInProgress, nil); err != nil {
    return nil, err
}

// 4. 在 syncCategories 中更新进度
progress := &ImportProgress{
    CurrentStep: "sync_categories",
    StepName: "正在同步分类",
    CurrentCount: i,
    TotalCount: len(categories),
    Percentage: (i * 100) / len(categories),
}
// 同时更新 ttpos_takeout 和日志表
s.updateImportProgress(ctx, platform, logUuid, progress)

// 5. 导入完成后更新状态和日志
result := &ImportResult{
    SuccessCount: successCount,
    FailureCount: failureCount,
    TotalCount: successCount + failureCount,
}
s.updateImportStatus(ctx, platform, ImportStatusSuccess, result)
s.completeImportLog(ctx, logUuid, ImportStatusSuccess, result)
```
