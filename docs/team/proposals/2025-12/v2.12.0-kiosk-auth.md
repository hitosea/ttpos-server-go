## 🎯 背景和动机

### 问题描述

自助点餐机终端需要员工登录后才能启动设备，让顾客使用自助点餐功能。当前缺少自助点餐机终端的登录认证功能，无法启动设备并提供服务。

**当前痛点**：

- 自助点餐机设备启动后无法登录，无法进入点餐界面
- 缺少与 POS、Assistant、Tablet 等终端一致的登录认证机制
- 无法验证员工身份，存在安全风险
- 缺少图形验证码验证，无法防止暴力破解

### 业务价值

通过实现登录认证功能，可以带来以下业务价值：

- **设备安全**：确保只有授权员工才能启动自助点餐机设备
- **统一认证**：与 POS、Assistant、Tablet 等终端使用相同的登录认证机制，降低维护成本
- **用户体验**：支持记住密码功能，减少重复登录操作
- **安全防护**：图形验证码验证，防止暴力破解攻击

### 目标用户

- [ ] 收银员
- [ ] 商户管理员
- [x] 其他: 门店员工（启动设备）

## 💡 解决方案概述

### 方案描述

实现自助点餐机终端的登录认证功能，使用商家员工账号登录（与 POS、Assistant、Tablet 等终端一致），支持邮箱/手机号登录、图形验证码验证、记住密码功能，确保设备安全启动。

**核心流程**：

1. **登录界面**：显示登录表单（账号、密码、验证码）
2. **账号输入**：支持邮箱/手机号登录
3. **验证码验证**：显示图形验证码，用户输入验证
4. **身份认证**：调用统一认证接口，验证员工身份
5. **登录成功**：返回 Token，保存登录状态
6. **记住密码**：可选记住密码功能（加密存储）
7. **默认账号**：默认回显上一个登录账号

### 核心功能点

1. **登录功能**
   - 使用商家员工账号登录（与 POS、Assistant、Tablet 等终端一致）
   - 每个员工账号都可以登录自助点餐机
   - 支持邮箱/手机号登录
   - 图形验证码验证
   - 记住密码功能（加密存储）
   - 默认回显上一个登录账号

2. **Token 管理**
   - 登录成功后返回 Token 和 RefreshToken
   - 支持 Token 刷新机制
   - Token 过期后自动刷新

3. **退出登录**
   - 清除登录状态
   - 清除本地存储的 Token 和密码

### 风险识别

**潜在风险**：

1. **统一认证兼容性风险**：需要确保与现有统一认证服务（SaasLogin）兼容
2. **验证码显示风险**：图形验证码在大屏设备上的显示效果可能不佳
3. **密码存储安全风险**：记住密码功能需要安全加密存储

**缓解措施**：

1. 参考收银机、平板端等终端的登录认证实现，确保兼容性
2. 验证码显示适配大屏设备，确保清晰可见
3. 使用前端加密库对密码进行加密存储，不存储明文密码

## 📝 附录

### User Story（初稿）

**作为** 门店员工  

**我想** 使用我的员工账号登录自助点餐机  

**以便于** 启动设备，让顾客使用自助点餐功能

**作为** 门店员工  

**我想** 在自助点餐机上使用记住密码功能  

**以便于** 减少重复登录操作，提升使用效率

### AC 验收标准（初稿）

1. **WHEN** 员工打开自助点餐机 **THEN** 系统 **SHALL** 显示登录界面，包含账号输入框、密码输入框、验证码输入框

2. **WHEN** 员工输入账号（邮箱/手机号）和密码 **THEN** 系统 **SHALL** 显示图形验证码，要求用户输入验证码

3. **WHEN** 员工输入正确的账号、密码和验证码 **THEN** 系统 **SHALL** 调用统一认证接口，验证员工身份，登录成功返回 Token

4. **WHEN** 员工勾选"记住密码"选项 **THEN** 系统 **SHALL** 加密存储密码，下次登录时自动填充

5. **WHEN** 员工登录成功 **THEN** 系统 **SHALL** 保存 Token，进入首页界面

6. **WHEN** 员工点击退出登录 **THEN** 系统 **SHALL** 清除登录状态，返回登录界面

7. **WHEN** Token 过期 **THEN** 系统 **SHALL** 自动使用 RefreshToken 刷新 Token

8. **WHEN** 员工输入错误的账号、密码或验证码 **THEN** 系统 **SHALL** 显示错误提示，要求重新输入
