## 🎯 背景和动机

### 问题描述

当前外卖导入功能在处理 Grab 平台商品时，存在以下问题：

1. **语言配置不完善**：未能灵活处理语言映射和翻译，导致多语言环境下数据不一致
2. **外卖开关逻辑不清晰**：未配置外卖时无法启用外卖功能，增加了使用门槛
3. **商品导入配置流程缺失**：缺少配置跳转页面，用户无法便捷地访问 Grab 配置页面
4. **价格处理逻辑混乱**：价格在 TTPOS 和 Grab 之间传输时存在汇率换算问题
5. **商品属性映射不准确**：
   - 单位默认处理不合理
   - 税率默认处理不合理
   - 规格默认处理不合理
   - 属性组选择范围映射不正确

这些问题导致商户在使用 Grab 外卖导入功能时体验不佳，需要大量手动调整，影响了外卖平台集成的效率。

### 业务价值

解决这些问题能带来：

- **提升商户接入效率**：自动化处理语言、价格、属性映射，减少人工干预
- **降低使用门槛**：简化外卖开关逻辑，支持未配置也能启用外卖
- **提高数据一致性**：统一价格、单位、税率、规格处理规则
- **改善用户体验**：提供配置跳转链接，方便商户快速完成 Grab 配置
- **增强平台兼容性**：完善多语言支持和属性映射，适配更多场景

## 💡 解决方案概述

### 方案描述

针对当前外卖导入功能的问题，提出以下优化方案：

**语言配置优化**：
- 在 TTPOS 和 Grab 之间数据传输时，使用我们的语言体系与 Grab 对应语言进行映射互传
- 对于 Grab 有但 TTPOS 没有的语言，同步回来后执行自动翻译（保持相同语言如英文不变）

**外卖开关逻辑优化**：
- 支持未配置也可开启外卖功能
- 开启外卖后可直接进行外卖分类和外卖商品管理

**配置流程优化**：
- 配置完成后，显示外链链接页面，可跳转到 Grab 页面进行配置
- 支持跳过导入 Grab 商品步骤，直接使用店内商品
- 店内商品不会自动创建到 Grab

**价格处理规则统一**：
- TTPOS 填写的商品价格传给 Grab 时，不带汇率换算，仅传价格数字
- 从 Grab 传回价格时同样不换算，直接使用原始数字
- 订单显示价格及单位为 Grab 对应货币单位及对应价格（如 TTPOS 为¥，Grab 外卖订单为$）

**商品属性映射优化**：
- **属性组选择范围**：从 Grab 获取的商品数据，如有最小/最大选择数量，同步到 TTPOS 的属性组选择范围，回传时使用相同规则
- **单位处理**：从 Grab 新添加的商品，增加 "Grab" 单位，并默认存入 "Grab 单位"
- **税率处理**：从 Grab 新添加的商品，采用 "0%" 税率，当前门店没有则新增税率 "0%"，税率名称 "Grab"
- **规格处理**：从 Grab 新添加的商品，使用商品价格作为规格价格（单规格），规格使用 "默认"，如无该规格则新增

### 核心功能点

1. **多语言映射与翻译**：
   - 实现 TTPOS 和 Grab 语言体系映射
   - 对缺失语言自动调用翻译服务
   - 保持已有语言数据不变

2. **外卖开关逻辑优化**：
   - 支持未配置也可开启外卖
   - 开启后支持外卖分类和商品管理

3. **配置流程优化**：
   - 提供 Grab 配置页面跳转链接
   - 支持跳过商品导入步骤
   - 明确店内商品不会自动同步到 Grab

4. **价格处理规则**：
   - 价格传输不带汇率换算
   - 订单显示使用 Grab 货币单位

5. **商品属性映射**：
   - 属性组选择范围映射（最小/最大选择数量）
   - 默认单位 "Grab"
   - 默认税率 "0%" / "Grab"
   - 默认规格 "默认"

## 📊 初步评估

### 技术复杂度

- [ ] **低**：纯 UI 调整，无业务逻辑变更
- [x] **中**：需要前后端联调，基础业务逻辑
- [ ] **高**：涉及架构调整、第三方集成、复杂算法

**说明**：
- 需要调整多个模块的业务逻辑（语言、价格、属性映射）
- 需要集成翻译服务（可能是第三方或内部）
- 需要前后端联调配置页面和跳转逻辑

### 工作量预估

[粗略估算，具体 SP 在技术方案评审时确定]

- **预计天数**: 5-7 天
- **预估 SP**: 5-8（待技术评审确认）

**拆分**：
- 语言映射与翻译：1-2 天
- 外卖开关逻辑优化：0.5 天
- 配置流程优化：1 天
- 价格处理规则：0.5 天
- 商品属性映射（单位、税率、规格、属性组）：2-3 天
- 测试与联调：1 天

### 风险识别

**潜在风险**：
1. **翻译服务依赖**：如果翻译服务不稳定或响应慢，可能影响商品导入速度
2. **语言映射复杂度**：Grab 和 TTPOS 语言体系可能存在不完全对应的情况
3. **价格精度问题**：不同货币单位的价格精度（小数位数）可能不一致
4. **属性组映射边界情况**：Grab 的选择范围规则可能与 TTPOS 不完全匹配
5. **外卖开关逻辑变更影响**：可能影响已有商户的外卖配置流程

**缓解措施**：
1. **翻译服务**：增加重试机制和降级方案（如翻译失败时使用英文）
2. **语言映射**：建立详细的语言映射表，处理不对应的语言时使用默认值
3. **价格精度**：统一价格存储和显示精度，在传输时进行格式化
4. **属性组映射**：增加边界值校验，不支持的选择范围给出明确提示
5. **外卖开关逻辑**：做好向后兼容，测试已有商户的外卖配置不受影响

## 📝 附录

### User Story（初稿）

**作为** 商户管理员  
**我想** 在 TTPOS 中便捷地导入 Grab 外卖商品，并自动处理语言、价格、单位、税率、规格等属性  
**以便于** 快速完成外卖平台配置，减少人工调整工作量

### AC 验收标准（初稿）

1. **WHEN** 用户未配置外卖时 **THEN** 系统 **SHALL** 允许开启外卖功能，开启后可进行外卖分类和商品管理
2. **WHEN** 用户配置外卖后 **THEN** 系统 **SHALL** 显示 Grab 配置页面跳转链接
3. **WHEN** 用户从 Grab 导入商品时 **THEN** 系统 **SHALL** 自动映射语言，对于 Grab 有但 TTPOS 没有的语言执行自动翻译
4. **WHEN** 商品价格在 TTPOS 和 Grab 之间传输时 **THEN** 系统 **SHALL** 不进行汇率换算，直接使用原始价格数字
5. **WHEN** 从 Grab 导入商品时 **THEN** 系统 **SHALL** 自动创建或使用 "Grab" 单位、"0%" / "Grab" 税率、"默认" 规格
6. **WHEN** 从 Grab 导入商品的属性组时 **THEN** 系统 **SHALL** 正确映射最小/最大选择数量到 TTPOS 的属性组选择范围
7. **WHEN** 店内商品存在时 **THEN** 系统 **SHALL NOT** 自动同步店内商品到 Grab
