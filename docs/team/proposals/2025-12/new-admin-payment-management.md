## 🎯 背景和动机

### 问题描述

当前 TTPOS 系统中，支付方式的配置和管理需要通过数据库或配置文件手动操作，缺乏可视化的管理界面。商户无法自主管理支付方式，也无法灵活配置第三方支付渠道（如 LianlianPay）的相关参数，导致：

- 支付方式配置需要技术人员介入，响应慢
- 无法快速启用/禁用支付方式
- LianlianPay 等第三方支付渠道的配置参数（IP 白名单、密钥等）管理不便
- 缺乏统一的支付方式管理入口

### 业务价值

- **提升运营效率**：商户可自主管理支付方式，减少技术依赖
- **增强灵活性**：快速启用/禁用支付方式，适应业务变化
- **降低运维成本**：可视化配置，减少人工操作错误
- **提升用户体验**：统一的支付管理界面，操作更便捷

## 💡 解决方案概述

### 方案描述

在新管理端（Shop 商家管理端）新增支付管理功能模块，提供完整的支付方式 CRUD 操作界面，支持：

1. **支付方式基础管理**：添加、编辑、状态变更（启用/禁用）、删除支付方式
2. **LianlianPay 配置管理**：提供专门的配置界面，支持配置白名单 IP、商户号、支付方式公钥、商户私钥、Token、站点 ID 等参数

### 核心功能点

1. **支付方式列表**：展示所有支付方式，支持筛选和搜索
2. **添加支付方式**：支持添加新的支付方式，配置基本信息
3. **编辑支付方式**：修改支付方式的配置信息
4. **状态变更**：启用/禁用支付方式，控制是否在收银端显示
5. **删除支付方式**：删除不再使用的支付方式（需校验是否有关联订单）
6. **LianlianPay 专项配置**：
   - 白名单 IP 配置
   - 商户号配置
   - 支付方式公钥配置
   - 商户私钥配置
   - Token 配置
   - 站点 ID 配置

- **预估 SP**: 5（待技术评审确认）

### 风险识别

**潜在风险**：
1. 支付方式删除时需校验历史订单关联，避免数据不一致
2. LianlianPay 配置参数敏感，需要加密存储和传输
3. 状态变更可能影响正在进行的订单，需要合理的状态切换机制

**缓解措施**：
1. 删除前进行关联检查，有历史订单时提示或禁止删除
2. 敏感字段使用加密存储，传输使用 HTTPS
3. 状态变更采用软删除或状态标记，保留历史记录

## 📝 附录

### User Story（初稿）

**作为** 商户管理员  
**我想** 在管理端自主管理支付方式，包括添加、编辑、启用/禁用、删除，以及配置 LianlianPay 的相关参数  
**以便于** 快速响应业务需求，减少对技术人员的依赖，提升运营效率

### AC 验收标准（初稿）

1. **WHEN** 商户管理员进入支付管理页面 **THEN** 系统 **SHALL** 展示所有支付方式列表
2. **WHEN** 商户管理员点击"添加支付方式" **THEN** 系统 **SHALL** 弹出表单，支持填写支付方式基本信息
3. **WHEN** 商户管理员编辑支付方式 **THEN** 系统 **SHALL** 允许修改支付方式的配置信息
4. **WHEN** 商户管理员切换支付方式状态 **THEN** 系统 **SHALL** 更新支付方式状态，并同步影响收银端显示
5. **WHEN** 商户管理员删除支付方式 **THEN** 系统 **SHALL** 检查是否有关联订单，有则提示禁止删除
6. **WHEN** 商户管理员配置 LianlianPay **THEN** 系统 **SHALL** 提供白名单 IP、商户号、支付方式公钥、商户私钥、Token、站点 ID 等配置项
7. **IF** 配置了 LianlianPay 参数 **THEN** 系统 **SHALL** 加密存储敏感信息（私钥、Token 等）
