## 🎯 背景和动机

### 问题描述

当前 ttpos-takeout 模块已实现 GrabFood 的单个菜单项更新接口（`UpdateMenuItem` 和 `UpdateMenuModifier`），但在实际业务场景中存在以下痛点：

1. **批量更新效率低**：当需要同时更新多个商品或修饰符时（如批量调价、批量上下架），需要逐个调用单项更新 API，导致：
   - API 调用次数过多，增加网络开销
   - 更新耗时长，影响菜单同步实时性
   - 容易触发 API 限流（Rate Limit）

2. **数据一致性风险**：批量操作过程中，如果部分请求失败，可能导致菜单数据不一致

3. **日志记录冗余**：每次单项更新都会产生独立的日志记录，批量操作时会产生大量日志

**示例场景**：
> 商户在促销活动期间需要批量调整 50 个商品的价格和库存，当前实现需要发起 50 次 API 调用，耗时约 10-15 秒，且容易因网络波动导致部分商品更新失败。

### 业务价值

实现 GrabFood Batch Update Menu API 可以带来以下价值：

- **提升更新效率**：批量更新 50 个商品从 10-15 秒缩短至 1-2 秒，效率提升 80%+
- **降低 API 调用成本**：减少网络请求次数，降低 API 限流风险
- **提高数据一致性**：单次批量请求保证原子性，避免部分更新失败
- **优化日志管理**：批量操作产生单条日志记录，便于追踪和排查问题
- **改善商户体验**：批量操作响应更快，提升商户后台操作体验

## 💡 解决方案概述

### 方案描述

集成 GrabFood 官方提供的 Batch Update Menu API（`PUT /partner/v1/batch-update/menu`），支持在单次请求中批量更新多个菜单项（商品）和修饰符。

**技术方案**：
1. 在 `internal/logic/grab_menu/grab_menu.go` 中新增 `BatchUpdateMenu` 方法
2. 在 `internal/model/dto/grab/menu_update.go` 中新增批量更新请求/响应 DTO
3. 在 `manifest/protobuf/menu/menu.proto` 中定义 gRPC 批量更新接口
4. 在 `internal/controller/rpc/menu/` 中实现 gRPC Controller 层
5. 复用现有的 `service.Grab().BatchUpdateMenu()` SDK 方法（需确认 SDK 是否已支持）

### 核心功能点

1. **批量更新菜单项（商品）**
   - 支持单次请求更新多个商品的价格、库存、可用状态
   - 支持高级定价配置（Advanced Pricing）
   - 支持购买能力配置（Purchasability）
   - 单次最多更新 100 个商品

2. **批量更新修饰符**
   - 支持单次请求更新多个修饰符的价格、可用状态
   - 单次最多更新 100 个修饰符
   - ⚠️ **注意**：修饰符不支持 `maxStock` 和 `purchasabilities` 字段

3. **类型隔离设计**
   - ⚠️ **重要**：单次请求只能更新同一类型（`field` 为 `ITEM` 或 `MODIFIER`）
   - 如需同时更新商品和修饰符，需分别调用两次 API
   - 这是 GrabFood API 的设计限制，非本系统限制

4. **日志记录与追踪**
   - 批量操作生成单条 `menu_log` 记录
   - 记录类型为 `BATCH_UPDATE_ITEM` 或 `BATCH_UPDATE_MODIFIER`
   - 支持通过 `request_id` 追踪批量更新状态

5. **错误处理**
   - 支持部分成功/部分失败的场景（`status` 为 `partial_success`）
   - 详细记录失败的实体 ID 及错误原因（`errors` 数组）
   - 全部失败时 `status` 为 `fail`，全部成功时为 `success`

### 风险识别

**潜在风险**：
1. **GrabFood SDK 版本兼容性**：✅ 已确认当前使用的 `github.com/grab/grabfood-api-sdk-go v1.0.2` 已支持 Batch Update Menu API
   - SDK 提供 `BatchUpdateMenuItem` 结构体
   - SDK 提供 `BatchUpdateMenuResponse` 响应结构
   - SDK 提供 `MenuEntity` 和 `MenuEntityError` 辅助结构

2. **API 限流风险**：批量更新虽然减少请求次数，但单次请求数据量大，可能触发其他限流规则

3. **部分失败处理**：GrabFood API 可能返回部分成功/部分失败（`status=partial_success`），需要妥善处理和记录

4. **类型混合限制**：单次请求只能更新同一类型（ITEM 或 MODIFIER），如需混合更新需分两次调用

**缓解措施**：
1. **SDK 版本检查**：✅ 已确认 SDK 支持，直接使用 SDK 提供的结构体和方法

2. **分批处理**：在业务层实现分批逻辑，单次批量建议不超过 50 条记录，避免触发限流

3. **详细日志**：在 `menu_log` 表的 `error_msg` 字段中记录 JSON 格式的详细错误信息（包含失败实体的 `entityID` 和 `errMsg`）

4. **类型隔离**：在 gRPC Controller 层或业务层实现自动分组逻辑，将商品和修饰符分别批量更新

### User Story（初稿）

**作为** 系统管理员  
**我想** 通过单次 API 调用批量更新多个商品/修饰符的价格和库存  
**以便于** 提升菜单同步效率，减少 API 调用次数，降低限流风险

### AC 验收标准（初稿）

1. **WHEN** 调用批量更新 API 传入 10 个商品更新请求（`field=ITEM`）**THEN** 系统 **SHALL** 在 2 秒内完成所有商品的更新
2. **WHEN** 调用批量更新 API 传入 10 个修饰符更新请求（`field=MODIFIER`）**THEN** 系统 **SHALL** 在 2 秒内完成所有修饰符的更新
3. **WHEN** 批量更新部分失败（`status=partial_success`）**THEN** 系统 **SHALL** 在响应的 `errors` 数组中记录失败实体的 ID 和错误原因
4. **WHEN** 批量更新成功（`status=success`）**THEN** 系统 **SHALL** 在 `menu_log` 表中生成单条日志记录，`sync_type` 为 `BATCH_UPDATE_ITEM` 或 `BATCH_UPDATE_MODIFIER`
5. **IF** 批量更新超过 100 条记录 **THEN** 系统 **SHALL** 返回参数验证错误
6. **IF** `field` 不是 `ITEM` 或 `MODIFIER` **THEN** 系统 **SHALL** 返回参数验证错误
7. **WHEN** 批量更新商品时传入修饰符专有字段（如 `isFree`）**THEN** 系统 **SHALL** 忽略该字段（由 GrabFood API 处理）

### 技术实现要点

1. **DTO 定义**（`internal/model/dto/grab/menu_update.go`）:

根据 GrabFood SDK 的实际结构，批量更新请求需要使用 `field` 字段区分更新类型（ITEM 或 MODIFIER），并使用 `menuEntities` 数组存储批量更新的实体：

```go
// BatchUpdateMenuReq 批量更新菜单请求
// 参考 SDK: grabfood.BatchUpdateMenuItem
type BatchUpdateMenuReq struct {
    MerchantID   string       `json:"merchant_id" v:"required#商户ID不能为空"`  // Grab MerchantID
    Field        string       `json:"field" v:"required|in:ITEM,MODIFIER#字段类型不能为空|字段类型必须是ITEM或MODIFIER"` // 记录类型: ITEM 或 MODIFIER
    MenuEntities []MenuEntity `json:"menu_entities" v:"required|length:1,100#菜单实体不能为空|菜单实体数量必须在1-100之间"` // 菜单实体数组
}

// MenuEntity 菜单实体（商品或修饰符）
// 参考 SDK: grabfood.MenuEntity
type MenuEntity struct {
    ID               string                      `json:"id" v:"required#ID不能为空"`  // 商品ID或修饰符ID
    Price            *int64                      `json:"price,omitempty"`            // 价格 (minor unit)
    AvailableStatus  string                      `json:"available_status,omitempty"` // 可用状态
    MaxStock         *int64                      `json:"max_stock,omitempty"`        // 库存数量（仅商品）
    AdvancedPricings []UpdateAdvancedPricingReq  `json:"advanced_pricings,omitempty"` // 高级定价
    Purchasabilities []UpdatePurchasabilityReq   `json:"purchasabilities,omitempty"`  // 购买能力（仅商品）
}

// BatchUpdateMenuResp 批量更新菜单响应
// 参考 SDK: grabfood.BatchUpdateMenuResponse
type BatchUpdateMenuResp struct {
    MerchantID string            `json:"merchant_id"` // 商户ID
    Status     string            `json:"status"`      // 状态: ✅ 已完成 - 已发布 v2.12
    Errors     []MenuEntityError `json:"errors"`      // 错误列表（部分失败或全部失败时返回）
}

// MenuEntityError 菜单实体错误
// 参考 SDK: grabfood.MenuEntityError
type MenuEntityError struct {
    EntityID string `json:"entity_id"` // 失败的实体ID
    ErrMsg   string `json:"err_msg"`   // 错误消息
}
```

**关键设计说明**：
- **单次请求只能更新同一类型**：`field` 为 `ITEM` 时只能批量更新商品，为 `MODIFIER` 时只能批量更新修饰符
- **混合批量更新需分两次请求**：如需同时更新商品和修饰符，需分别调用两次 API
- **最大支持 100 条记录**：单次批量更新最多 100 个实体（根据 GrabFood API 限制）

2. **Logic 层方法**（`internal/logic/grab_menu/grab_menu.go`）:
```go
// BatchUpdateMenu 批量更新菜单项或修饰符
// 注意：单次请求只能更新同一类型（ITEM 或 MODIFIER）
func (s *sGrabMenu) BatchUpdateMenu(ctx context.Context, req *grabDto.BatchUpdateMenuReq) (*grabDto.BatchUpdateMenuResp, error) {
    g.Log().Infof(ctx, "[Grab] 批量更新菜单: merchantID=%s, field=%s, count=%d", 
        req.MerchantID, req.Field, len(req.MenuEntities))

    // 1. 参数验证
    if err := g.Validator().Data(req).Run(ctx); err != nil {
        g.Log().Errorf(ctx, "[Grab] 批量更新菜单参数验证失败: %v", err)
        return nil, gerror.NewCode(gcode.CodeValidationFailed, err.Error())
    }

    // 2. 构建 SDK 批量更新请求
    batchReq := grabfood.NewBatchUpdateMenuItem(req.MerchantID, req.Field)
    var menuEntities []grabfood.MenuEntity
    for _, entity := range req.MenuEntities {
        sdkEntity := grabfood.NewMenuEntity()
        sdkEntity.SetId(entity.ID)
        if entity.Price != nil {
            sdkEntity.SetPrice(*entity.Price)
        }
        if entity.AvailableStatus != "" {
            sdkEntity.SetAvailableStatus(entity.AvailableStatus)
        }
        if entity.MaxStock != nil {
            sdkEntity.SetMaxStock(*entity.MaxStock)
        }
        // 转换高级定价和购买能力配置...
        menuEntities = append(menuEntities, *sdkEntity)
    }
    batchReq.SetMenuEntities(menuEntities)

    // 3. 调用 Grab API
    resp, err := service.Grab().BatchUpdateMenu(ctx, req.MerchantID, batchReq)
    if err != nil {
        // 4. 记录失败日志
        s.logBatchUpdate(ctx, req.MerchantID, req.Field, len(req.MenuEntities), false, err.Error())
        return nil, gerror.Wrap(err, "调用 Grab BatchUpdateMenu API 失败")
    }

    // 5. 记录成功日志
    s.logBatchUpdate(ctx, req.MerchantID, req.Field, len(req.MenuEntities), true, "")

    // 6. 构建响应
    result := &grabDto.BatchUpdateMenuResp{
        MerchantID: resp.GetMerchantID(),
        Status:     resp.GetStatus(),
    }
    if len(resp.GetErrors()) > 0 {
        for _, err := range resp.GetErrors() {
            result.Errors = append(result.Errors, grabDto.MenuEntityError{
                EntityID: err.GetEntityID(),
                ErrMsg:   err.GetErrMsg(),
            })
        }
    }

    g.Log().Infof(ctx, "[Grab] 批量更新菜单成功: merchantID=%s, status=%s", 
        req.MerchantID, result.Status)
    return result, nil
}

// logBatchUpdate 记录批量更新日志
func (s *sGrabMenu) logBatchUpdate(ctx context.Context, merchantID, field string, count int, success bool, errMsg string) {
    logUUID := uuid.MustGetID()
    status := grabDto.MenuSyncStatusSuccess
    if !success {
        status = grabDto.MenuSyncStatusFail
    }

    logDo := &do.MenuLog{
        Uuid:         logUUID,
        MerchantId:   merchantID,
        ProviderName: string(consts.ProviderGrab),
        SyncType:     fmt.Sprintf("BATCH_UPDATE_%s", field), // BATCH_UPDATE_ITEM 或 BATCH_UPDATE_MODIFIER
        Status:       status,
        ErrorMsg:     errMsg,
        // 可选：在 menu_snapshot 字段中记录批量更新的实体ID列表（JSON格式）
    }

    _, err := dao.MenuLog.Ctx(ctx).Data(logDo).Insert()
    if err != nil {
        g.Log().Errorf(ctx, "[Grab] 插入批量更新日志失败: merchantID=%s, error=%v", merchantID, err)
    }
}
```

| **需求发起** | Proposal      | 粗略     | 团队评审、决策是否做 |
| **需求确认** | Requirements  | 详细     | User Story + AC，开发依据 |
| **技术设计** | Design        | 详细     | 技术方案，实现指导 |
| **任务分解** | Tasks         | 详细     | 开发执行，进度追踪 |

### 流转路径

```
提案 (Proposal) 
  ↓ 评审批准
需求文档 (Requirements) 
  ↓ 技术评审
设计文档 (Design) 
  ↓ SP 评估 ≤ 5
任务分解 (Tasks)
  ↓
开发实现
```
