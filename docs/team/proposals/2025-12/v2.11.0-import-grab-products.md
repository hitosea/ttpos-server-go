## 🎯 背景和动机

### 问题描述

- Grab 平台与店内商品未联动，门店需要手动维护重复的分类、规格/变体、属性组/属性值、单位，存在遗漏和错误风险。
- 新接入 Grab 的商家需要从 Grab 批量导入商品数据，并与店内商品建立关联或自动创建店内商品，否则无法在本地侧管理外卖商品。
- 多语言字段（名称、规格名、属性名等）需要按门店语言策略自动转换，减少手工补全工作量。

### 业务价值

- 减少外卖商品初始化的人工成本，提升上线速度。
- 保证 Grab 与店内商品数据一致性，降低错单和漏单风险。
- 通过多语言自动转换，降低运营人员的文本维护成本。

## 💡 解决方案概述

### 方案描述

- 在 Shop 后台提供“获取商品数据”流程：从 Grab 拉取商品列表，支持为每个 Grab 商品选择对应的店内商品；若未选择，则自动创建店内商品（默认下架）并建立 Grab 关联。
- 分层映射逻辑：
  - 分类：可选已有分类；若未选则新建并使用翻译服务生成本地语言名称。
  - 规格/变体：可选已有规格；未选则新建规格并映射翻译。
  - 属性组/属性值：可选已有；未选则新建并映射翻译。
  - 单位：可选已有；未选则新建并映射翻译。
- 数据保存后，店内商品与外卖商品形成关联，后续同步使用关联关系；默认 Grab 端商品保持启用状态，店内端新建商品默认下架，待运营确认。

### 核心功能点

1. Grab 商品列表拉取与筛选（包含分类/规格/属性/单位信息）。
2. 店内商品选择或自动创建，并建立 Grab-店内关联。
3. 分类/规格/属性/单位的选择或自动创建，支持翻译映射。
4. 导入状态与结果反馈（成功/失败明细）。

### 技术复杂度

- [ ] **低**
- [x] **中**：需要前后端联调，包含映射与自动创建逻辑
- [ ] **高**

### 工作量预估

- **预计天数**: 5 天
- **预估 SP**: 5（待技术评审确认）

### 风险识别

**潜在风险**：
1. 多语言翻译缺失导致创建名称不完整。
2. 映射错误导致错误关联或重复创建。
3. Grab 返回数据结构变更影响导入。

**缓解措施**：
1. 翻译失败时回退使用原文并标记待人工确认。
2. 关联前校验同名/同 UUID，提供去重提示。
3. 为 Grab 返回数据加校验与灰度开关，异常时中断导入并告警。

## 📝 附录

### User Story（初稿）

作为 商户管理员  
我想 将 Grab 的商品导入并映射到店内商品（或自动创建店内商品）  
以便 于快速上线外卖商品并保持两端数据一致

### AC 验收标准（初稿）

1. WHEN 从 Grab 拉取商品列表 THEN 支持为每个商品选择店内商品或新建店内商品，未选择时自动创建且默认下架（Grab 端保持可用）。
2. IF 未选择对应分类/规格/属性组/属性值/单位 THEN 系统自动创建对应记录，名称支持翻译转换为本地语言。
3. WHEN 导入完成 THEN 返回导入结果（成功/失败列表、自动创建的对象列表）。
