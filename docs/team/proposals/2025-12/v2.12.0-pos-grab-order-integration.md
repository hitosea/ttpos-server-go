## 🎯 背景和动机

### 问题描述

当前 TTPOS 系统已支持扫码点餐和外送订单处理，但尚未集成 Grab 外卖平台。随着东南亚市场的拓展，商户需要通过 POS 系统统一管理来自 Grab 平台的外卖订单，实现订单自动同步、快速接单/拒单、库存检查、以及与 KDS 厨显系统的联动。

目前的痛点包括：
- 商户需要在多个平台切换管理订单，效率低下
- Grab 订单无法与 TTPOS 库存系统联动，容易出现缺货情况
- 订单状态同步不及时，影响顾客体验
- 缺少商品关联检查机制，可能出现订单异常

### 业务价值

- **提升运营效率**：统一在 POS 收银机管理所有订单（扫码、外送、Grab外卖）
- **减少缺货风险**：接单前自动检查库存，避免接单后无法履约
- **提高订单处理速度**：60 秒内同步订单，30 秒内同步状态更新
- **增强容错能力**：支持自动重试、去重、异常标记等机制
- **改善顾客体验**：快速接单响应，准确的订单履约

### 目标用户

- [x] 收银员（接单/拒单操作）
- [x] 商户管理员（接单设置、外卖开关配置）
- [x] 厨房人员（KDS 接收订单制作任务）
- [ ] 顾客
- [x] 其他: 平台运营人员（监控订单同步状态）

## 💡 解决方案概述

### 方案描述

将 Grab 外卖订单集成到 TTPOS 收银系统中，实现以下核心流程：

1. **订单同步**：通过 Webhook 推送或定时轮询，在 60 秒内将 Grab 新订单同步到 POS 系统，支持失败重试（最多 3 次）和去重机制
2. **订单处理**：在 POS 收银机的"接单"菜单中统一显示扫码点餐、外送、Grab外卖订单，支持手动/自动接单、拒单、搜索等操作
3. **智能检查**：接单前自动进行商品关联检查和库存检查，异常订单标记并提示，避免履约风险
4. **状态同步**：POS 和 Grab 平台的订单状态双向同步（30 秒内），确保信息一致性
5. **KDS 联动**：接单成功后自动通知 KDS 厨显系统，展示制作任务

### 核心功能点

1. **订单同步机制**
   - Webhook 推送 + 定时轮询双模式
   - 失败重试队列（最多 3 次）
   - 重复订单识别和跳过
   - 双向状态同步（POS ↔ Grab）

2. **接单管理**
   - 统一接单入口（扫码/外送/Grab外卖）
   - 手动/自动接单切换
   - 自动接单金额上限设置
   - 语音播报提醒控制

3. **智能检查**
   - 商品关联检查（TTPOS 商品/规格映射）
   - 库存检查（开启自动接单时，库存不足需手动处理）
   - 异常订单标记和友好提示

4. **订单操作**
   - 接单/拒单（拒单原因来自 Grab）
   - 多维度搜索（外卖平台、联系人、序号）
   - 权限控制（无"外卖"权限不显示订单）

5. **价格处理**
   - 不做汇率换算，直接传递价格数字
   - 订单显示 Grab 货币单位和价格（如 $）

## 📊 初步评估

### 技术复杂度

- [ ] **低**：纯 UI 调整，无业务逻辑变更
- [ ] **中**：需要前后端联调，基础业务逻辑
- [x] **高**：涉及架构调整、第三方集成、复杂算法

**复杂度说明**：
- 需要对接 Grab API（Webhook + 轮询双模式）
- 涉及订单状态机设计（待接单 → 已接单 → 制作中 → 已完成）
- 商品关联映射和库存检查逻辑较复杂
- 需要消息队列处理订单同步和重试
- 双向状态同步需要保证一致性

- **预计天数**: 10-15 天

**分解估算**：

- 接单界面和逻辑：3-5 SP
- 商品关联和库存检查：2-3 SP
- KDS 联动和测试：2-3 SP

### 风险识别

**潜在风险**：
1. **Grab API 稳定性**：Webhook 推送可能延迟或丢失
2. **商品映射复杂度**：Grab 商品规格与 TTPOS 商品可能无法一一对应
3. **状态同步冲突**：双向同步可能出现状态不一致
4. **性能问题**：高峰期大量订单同步可能影响系统性能
5. **跨境时区问题**：东南亚多时区，订单时间处理需谨慎

**缓解措施**：
1. 实现轮询兜底机制，失败重试队列
2. 设计灵活的商品映射表，支持手动配置
3. 引入分布式锁，使用状态机保证一致性
4. 使用消息队列异步处理，限流保护
5. 统一使用 UTC 时间戳，前端按本地时区显示

## 📝 附录

### User Story（初稿）

**作为** 收银员  
**我想** 在 POS 收银机上统一接收和处理来自 Grab 外卖平台的订单  
**以便于** 提高订单处理效率，减少平台切换，避免缺货和订单异常

**作为** 商户管理员  
**我想** 配置自动接单规则（金额上限、库存检查）和语音提醒  
**以便于** 灵活控制接单策略，降低运营风险

**作为** 厨房人员  
**我想** 在 KDS 厨显上看到 Grab 外卖订单的制作任务  
**以便于** 及时制作菜品，确保按时出餐

### AC 验收标准（初稿）

**订单同步**：
1. **WHEN** Grab 平台有新订单 **THEN** 系统 **SHALL** 在 60 秒内同步到 POS 系统
2. **WHEN** 订单同步失败 **THEN** 系统 **SHALL** 进入重试队列，最多重试 3 次
3. **WHEN** 检测到重复订单 **THEN** 系统 **SHALL** 识别并跳过

**订单处理**：
1. **WHEN** 收银员点击"接单"按钮 **THEN** 系统 **SHALL** 更新订单状态为"已接单"并同步到 Grab
2. **WHEN** 订单中存在未关联的商品或规格 **THEN** 系统 **SHALL** 标记订单异常，不自动接单，并显示友好提示
3. **WHEN** 开启自动接单且库存不足 **THEN** 系统 **SHALL** 不自动接单，需要手动处理
4. **WHEN** 收银员没有"外卖"接单权限 **THEN** 系统 **SHALL** 不显示 Grab 外卖订单
5. **WHEN** 任意外卖在云平台均未开启 **THEN** 系统 **SHALL** 不显示外卖订单

**KDS 联动**：
1. **WHEN** 订单接单成功 **THEN** 系统 **SHALL** 自动通知 KDS 显示制作任务

**价格处理**：
1. **WHEN** 传递价格给 Grab **THEN** 系统 **SHALL** 不进行汇率换算，仅传价格数字
2. **WHEN** 显示 Grab 订单价格 **THEN** 系统 **SHALL** 使用 Grab 对应货币单位及价格
