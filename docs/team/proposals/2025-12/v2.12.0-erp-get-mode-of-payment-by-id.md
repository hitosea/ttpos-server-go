## 🎯 背景和动机

### 问题描述

当前 ERP 模块仅提供 `GetModeOfPaymentList` 批量查询接口，返回公司或分支下的所有支付方式列表。在以下场景中需要查询单个支付方式的详细信息：

1. **TTPOS 查询单个支付方式详情**：根据 `name` 或 `payment_id` 获取支付方式的完整信息
2. **验证支付方式状态**：在创建订单前验证支付方式是否存在、是否启用
3. **支付方式配置同步**：根据 `payment_id` 从 ERP 同步支付方式的最新配置
4. **数据一致性校验**：根据 `name` 或 `payment_id` 验证 TTPOS 与 ERP 的数据一致性
5. **POS 发票支付流程优化**：TTPOS 在创建 POS 发票时，支持传递 `payment_id` 而非 `mode_of_payment` 名称，由 ERP 自动解析

目前如果需要查询单个支付方式，只能先调用 `GetModeOfPaymentList` 获取全量列表，然后在客户端进行过滤，效率低且浪费网络带宽。

**核心痛点**：
- `PosInvoicePayment` 消息中的 `mode_of_payment` 字段必须传递 ERP 的完整名称（如 `Cash-0001 - ABC`），TTPOS 需要维护名称映射关系
- 支付方式名称可能变更，导致 TTPOS 的映射失效
- 跨公司、跨分支的支付方式名称不统一，增加 TTPOS 的维护成本

### 业务价值

- **提升查询效率**：避免返回不必要的数据，减少网络传输和处理时间
- **支持灵活查询**：支持通过 `name` 或 `payment_id` 两种方式查询，满足不同场景需求
- **降低系统负载**：减少不必要的数据传输，降低 ERP 和 gRPC 服务负载
- **改善用户体验**：更快的响应速度，特别是在支付方式较多的场景
- **简化 TTPOS 集成**：TTPOS 无需维护 `payment_id` → `mode_of_payment` 的映射关系
- **提高数据一致性**：通过 `payment_id` 唯一标识支付方式，避免名称变更导致的映射失效
- **降低维护成本**：支付方式名称变更时，TTPOS 无需修改代码

## 💡 解决方案概述

### 方案描述

在 `ttpos-erp` 模块的 `selling.proto` 中新增 `GetModeOfPayment` gRPC 接口，支持通过 `name` 或 `payment_id` 查询单个支付方式。

**技术实现**：
1. 在 Protobuf 中定义 `GetModeOfPaymentReq` 和 `GetModeOfPaymentResp` 消息
2. 在 `SellingService` 中添加 `GetModeOfPayment` RPC 方法
3. 在 Logic 层实现查询逻辑，调用 ERPNext Document Service 查询
4. 支持两种查询方式：
   - 通过 `name` 查询（精确匹配）
   - 通过 `payment_id`（`custom_payment_id` 字段）查询

### 核心功能点

1. **新增查询接口**：`GetModeOfPayment`
   - `GetModeOfPaymentReq`: 支持 `name` 或 `payment_id` 参数（二选一）
   - `GetModeOfPaymentResp`: 返回 `ModeOfPayment` 对象
   - Logic 层实现：调用 ERPNext Document Service 查询

2. **修改 PosInvoicePayment 消息**：
   - 新增 `payment_id` 字段（可选）
   - `mode_of_payment` 和 `payment_id` 必填其中之一
   - **自动解析逻辑**：当 `payment_id` 不为空时，调用 `GetModeOfPayment` 查询 `mode_of_payment` 值

3. **Logic 层实现**：
   - 参数校验：`name` 和 `payment_id` 至少提供一个
   - ERPNext 查询：调用 `service.Document().Get()` 或 `service.Document().List()` 
   - 数据映射：将 ERPNext 数据映射到 `ModeOfPayment` DTO
   - **支付流程集成**：在保存 POS 发票前，自动解析 `payment_id` 为 `mode_of_payment`

4. **错误处理**：
   - 参数缺失：返回参数错误
   - 支付方式不存在：返回 404 错误
   - ERPNext 查询失败：返回服务错误
   - Payment ID 无效：返回业务错误

### 风险识别

**潜在风险**：
1. **ERPNext 查询性能**：如果通过 `custom_payment_id` 查询未建立索引，性能可能较低
2. **重复代码**：与 `GetModeOfPaymentList` 存在部分重复逻辑
3. **向后兼容性**：修改 `PosInvoicePayment` 消息可能影响现有客户端
4. **支付流程性能**：每个支付项都需要查询一次 `mode_of_payment`，可能影响性能

**缓解措施**：
1. 优先使用 `name` 查询（ERPNext 主键，性能最优）；`payment_id` 查询使用 List + Filter
2. 提取公共方法，避免代码重复
3. 使用 `optional` 字段保持向后兼容，旧客户端仍可只传递 `mode_of_payment`
4. 批量查询优化：如果同一发票中有多个相同 `payment_id`，只查询一次并缓存

## 📝 附录

### API 设计（初稿）

#### 1. 新增查询接口

**GetModeOfPayment RPC 方法**：

```protobuf
// GetModeOfPaymentReq 查询单个支付方式请求
message GetModeOfPaymentReq {
  optional string name = 1;       // 支付方式名称（精确匹配），与 payment_id 二选一
  optional string payment_id = 2; // 支付方式唯一标识（PaymentID），与 name 二选一
}

// GetModeOfPaymentResp 查询单个支付方式响应
message GetModeOfPaymentResp {
  ModeOfPayment mode_of_payment = 1; // 支付方式信息
}
```

#### 2. 修改 PosInvoicePayment 消息

**新增 payment_id 字段**：

```protobuf
// PosInvoicePayment POS发票付款
message PosInvoicePayment {
  string mode_of_payment = 1; // 支付方式，与 payment_id 二选一（必填其中之一）
  double amount = 2;          // 金额，必填
  optional string payment_id = 3; // 支付方式唯一标识（PaymentID），与 mode_of_payment 二选一
  // 注意：当 payment_id 不为空时，系统自动调用 GetModeOfPayment 查询 mode_of_payment 值
}
```

**变更说明**：
- 新增 `payment_id` 字段（可选）
- `mode_of_payment` 和 `payment_id` 至少提供一个
- 当 `payment_id` 不为空时，`mode_of_payment` 可为空，系统自动解析

#### 3. Service 定义

```protobuf
service SellingService {
  // 查询单个支付方式
  rpc GetModeOfPayment (GetModeOfPaymentReq) returns (erp.ResponseInfo);
  
  // 现有接口：SavePosInvoice（逻辑需调整以支持 payment_id）
  rpc SavePosInvoice (SavePosInvoiceReq) returns (erp.ResponseInfo);
}
```

### User Story（初稿）

#### Story 1: 查询单个支付方式

**作为** TTPOS 后端服务  
**我想** 根据 `name` 或 `payment_id` 查询单个支付方式的详细信息  
**以便于** 验证支付方式状态、同步配置、提高查询效率

#### Story 2: POS 发票支付使用 PaymentID

**作为** TTPOS 后端服务  
**我想** 在创建 POS 发票时，可以直接传递 `payment_id` 而非 `mode_of_payment` 名称  
**以便于** 简化集成、降低维护成本、避免名称变更导致的映射失效

#### Story 3: 自动解析 PaymentID

**作为** ERP 服务  
**我想** 当收到包含 `payment_id` 的 POS 发票支付请求时，自动查询并解析为 `mode_of_payment`  
**以便于** TTPOS 无需维护映射关系，提高数据一致性

### AC 验收标准（初稿）

#### GetModeOfPayment 接口

1. **WHEN** 调用 `GetModeOfPayment` 并提供 `name` 参数 **THEN** 系统 **SHALL** 返回对应的支付方式信息
2. **WHEN** 调用 `GetModeOfPayment` 并提供 `payment_id` 参数 **THEN** 系统 **SHALL** 返回对应的支付方式信息
3. **IF** `name` 和 `payment_id` 都未提供 **THEN** 系统 **SHALL** 返回参数错误（400）
4. **IF** 支付方式不存在 **THEN** 系统 **SHALL** 返回 404 错误
5. **IF** ERPNext 查询失败 **THEN** 系统 **SHALL** 返回 500 错误

#### PosInvoicePayment 支付流程

6. **WHEN** 创建 POS 发票并在 `PosInvoicePayment` 中提供 `payment_id` **THEN** 系统 **SHALL** 自动调用 `GetModeOfPayment` 查询 `mode_of_payment` 值
7. **WHEN** 创建 POS 发票并在 `PosInvoicePayment` 中同时提供 `mode_of_payment` 和 `payment_id` **THEN** 系统 **SHALL** 优先使用 `payment_id` 进行解析
8. **IF** `PosInvoicePayment` 中 `mode_of_payment` 和 `payment_id` 都未提供 **THEN** 系统 **SHALL** 返回参数错误（400）
9. **IF** `payment_id` 无效或对应的支付方式不存在 **THEN** 系统 **SHALL** 返回业务错误，提示支付方式不存在
10. **WHEN** `payment_id` 解析成功后 **THEN** 系统 **SHALL** 使用解析得到的 `mode_of_payment` 创建 POS 发票

### 实现示例

#### 1. GetModeOfPayment 查询逻辑

```go
func (s *sSelling) GetModeOfPayment(ctx context.Context, req *selling.GetModeOfPaymentReq) (*selling.GetModeOfPaymentResp, error) {
    // 参数校验
    if req.Name == "" && req.PaymentId == "" {
        return nil, gerror.New("name 或 payment_id 至少提供一个")
    }

    var modeOfPayment *selling.ModeOfPayment

    if req.Name != "" {
        // 通过 name 查询（主键，性能最优）
        resp, err := service.Document().Get(ctx, erp.DocTypeModeOfPayment, req.Name, []string{
            "name", "enabled", "custom_payment_id",
        })
        // 处理响应...
    } else {
        // 通过 payment_id 查询
        filters := [][]string{{"custom_payment_id", "=", req.PaymentId}}
        resp, err := service.Document().List(ctx, &erp.ErpReq{
            DocType: erp.DocTypeModeOfPayment,
        }, &erp.RequestParams{
            Fields:  []string{"name", "enabled", "custom_payment_id"},
            Filters: filters,
            Limit:   1,
        })
        // 处理响应...
    }

    return &selling.GetModeOfPaymentResp{
        ModeOfPayment: modeOfPayment,
    }, nil
}
```

#### 2. SavePosInvoice 支付流程集成

```go
func (s *sSelling) SavePosInvoice(ctx context.Context, req *selling.SavePosInvoiceReq) (*selling.SavePosInvoiceResp, error) {
    // ... 其他逻辑 ...

    // 处理支付列表
    for i, payment := range req.Payments {
        // 新增逻辑：如果提供了 payment_id，自动解析 mode_of_payment
        if payment.PaymentId != "" {
            // 调用 GetModeOfPayment 查询
            mopResp, err := s.GetModeOfPayment(ctx, &selling.GetModeOfPaymentReq{
                PaymentId: payment.PaymentId,
            })
            if err != nil {
                return nil, gerror.Wrapf(err, "解析 payment_id %s 失败", payment.PaymentId)
            }
            
            // 验证支付方式是否启用
            if !mopResp.ModeOfPayment.Enabled {
                return nil, gerror.Newf("支付方式 %s 已禁用", mopResp.ModeOfPayment.Name)
            }
            
            // 使用解析得到的 mode_of_payment
            payment.ModeOfPayment = mopResp.ModeOfPayment.Name
        }
        
        // 验证 mode_of_payment 是否存在
        if payment.ModeOfPayment == "" {
            return nil, gerror.Newf("支付项 %d: mode_of_payment 和 payment_id 至少提供一个", i+1)
        }
        
        // 继续后续处理...
    }

    // ... 其他逻辑 ...
}
```

#### 3. 性能优化：批量查询缓存

```go
// 辅助函数：批量解析 payment_id
func (s *sSelling) resolvePaymentIDs(ctx context.Context, payments []*selling.PosInvoicePayment) error {
    // 收集所有需要解析的 payment_id
    paymentIDMap := make(map[string]*selling.PosInvoicePayment)
    for _, payment := range payments {
        if payment.PaymentId != "" {
            paymentIDMap[payment.PaymentId] = payment
        }
    }
    
    if len(paymentIDMap) == 0 {
        return nil
    }
    
    // 批量查询（如果有多个相同的 payment_id，只查询一次）
    cache := make(map[string]string) // payment_id -> mode_of_payment
    for paymentID := range paymentIDMap {
        if _, cached := cache[paymentID]; !cached {
            mopResp, err := s.GetModeOfPayment(ctx, &selling.GetModeOfPaymentReq{
                PaymentId: paymentID,
            })
            if err != nil {
                return gerror.Wrapf(err, "解析 payment_id %s 失败", paymentID)
            }
            cache[paymentID] = mopResp.ModeOfPayment.Name
        }
    }
    
    // 应用查询结果
    for _, payment := range payments {
        if payment.PaymentId != "" {
            payment.ModeOfPayment = cache[payment.PaymentId]
        }
    }
    
    return nil
}
```
