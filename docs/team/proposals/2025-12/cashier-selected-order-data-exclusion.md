## 🎯 背景和动机

### 问题描述

当前在收银机中，当订单被标记为"已选"后，这些订单的数据仍然会出现在各种统计报表和业务场景中，导致数据统计不准确。

**具体场景**：

1. **打印记录**：已选订单仍然出现在打印记录列表中，影响打印管理
2. **交班弹窗**：已选订单的金额仍然计入交班统计，导致钱箱金额、现金收入、退款金额等数据不准确
3. **交接班完成弹窗**：已选订单的金额仍然计入本班收入统计，影响交接班数据准确性
4. **营业数据**：已选订单的数据仍然计入各种营业统计（总销售额、订单数、支付方式统计、商品统计等），导致营业数据不准确

**业务影响**：
- 交班时钱箱金额计算错误，可能导致账务问题
- 营业数据统计不准确，影响经营决策
- 打印记录混乱，无法准确追溯订单打印情况

### 业务价值

解决已选订单数据统计问题，确保各项业务数据的准确性和可靠性。

**价值点**：
- ✅ **数据准确性**：确保交班、营业数据等关键统计的准确性，避免账务错误
- ✅ **财务管理**：准确的钱箱金额统计，保障资金安全
- ✅ **经营决策**：准确的营业数据支持，帮助商户做出正确的经营决策
- ✅ **操作规范**：清晰的订单状态管理，提升收银操作规范性

## 💡 解决方案概述

### 方案描述

当订单被标记为"已选"状态后，系统需要在所有相关的数据统计和展示场景中，自动排除这些已选订单的数据。

**核心思路**：
1. 在所有涉及订单数据查询的地方，增加"已选订单"的过滤条件
2. 在计算统计数据时，排除已选订单的金额、数量等数据
3. 确保交班、营业数据、打印记录等场景的一致性处理

**实现方式**：
- 后端 API 查询时增加订单状态过滤条件
- 统计数据计算时排除已选订单
- 前端展示时统一过滤已选订单数据

### 核心功能点

1. **打印记录过滤**：已选订单不在打印记录列表中显示
2. **交班弹窗数据过滤**：
   - 当前钱箱现金总计 = 原总计 - 本班已选订单的现金收入
   - 现金收入 = 原现金收入 - 本班已选订单的现金收入
   - 余额收入 = 原余额收入 - 本班已选订单的余额收入
   - 其他支付方式（微信、支付宝等）同理
   - 退款金额 = 原退款金额 - 本班已选订单的退款金额
   - 本班取出现金 = 原取出现金 + 本班已选订单的现金收入
   - 本班遗留金额 = 0
3. **交接班完成弹窗数据过滤**：
   - 本班收入现金 = 原现金 - 本班已选订单的现金收入
   - 本班取出现金 = 原取出现金 + 本班已选订单的现金收入
   - 本班遗留金额 = 0
4. **营业数据统计过滤**：
   - 总销售额、服务费、支付手续费、税费、商品数量、优惠折扣、会员折扣、退款金额、赠菜金额、免单金额、实收金额、VAT 等合计数据排除已选订单
   - 订单数、桌数、人数、最小/大订单金额、平均订单金额、人均等统计数据排除已选订单
   - 按桌台方式、点餐方式（外卖/店内）、支付方式、高峰期等维度的统计排除已选订单
   - 按商品、商品分类的销售统计排除已选订单

1. 数据一致性风险：多个统计场景需要统一处理，可能出现遗漏

### User Story（初稿）

**作为** 收银员  
**我想** 已选订单不在打印记录、交班统计、营业数据中显示  
**以便于** 确保各项业务数据的准确性，避免账务错误和统计偏差

**作为** 店长  
**我想** 查看准确的营业数据统计  
**以便于** 做出正确的经营决策

### AC 验收标准（初稿）

#### 打印记录场景

1. **WHEN** 查看打印记录列表 **THEN** 系统 **SHALL** 不显示已选订单的整条订单记录

#### 交班弹窗场景

2. **GIVEN** 备用金 500，现金收入 4500，中途取出 100，中途存入 50，本班已选订单现金收入 200  
   **WHEN** 打开交班弹窗  
   **THEN** 系统 **SHALL** 显示：
   - 当前钱箱现金总计 = 4950 - 200 = 4750
   - 现金收入 = 4500 - 200 = 4300
   - 余额收入 = 原余额收入 - 本班已选订单的余额收入
   - 微信收入 = 原微信收入 - 本班已选订单的微信收入（其他支付方式同理）
   - 退款金额 = 原退款金额 - 本班已选订单的退款金额
   - 本班取出现金 = 原取出现金 + 200
   - 本班遗留金额 = 0

#### 交接班完成弹窗场景

3. **GIVEN** 本班有已选订单（现金收入 200）  
   **WHEN** 交接班完成弹窗显示  
   **THEN** 系统 **SHALL** 显示：
   - 本班收入现金 = 原现金 - 200
   - 本班取出现金 = 原取出现金 + 200
   - 本班遗留金额 = 0

#### 营业数据场景

4. **GIVEN** 有已选订单（销售额 100）  
   **WHEN** 查看营业数据-合计  
   **THEN** 系统 **SHALL** 显示总销售额 = 原销售额 - 100

5. **GIVEN** 有已选订单  
   **WHEN** 查看营业数据-合计  
   **THEN** 系统 **SHALL** 排除已选订单的服务费、支付手续费、税费、商品数量、优惠折扣、会员折扣、退款金额、赠菜金额、免单金额、实收金额、VAT 等合计数据

6. **GIVEN** 有已选订单  
   **WHEN** 查看营业数据-合计  
   **THEN** 系统 **SHALL** 排除已选订单的订单数、桌数、人数、最小/大订单金额、平均订单金额、人均等统计数据

7. **GIVEN** 有已选订单  
   **WHEN** 查看营业数据-按桌台方式  
   **THEN** 系统 **SHALL** 排除已选订单的订单数（桌数）、人数、最小/大订单金额、平均订单金额、人均等统计数据

8. **GIVEN** 有已选订单  
   **WHEN** 查看营业数据-按点餐方式（外卖）  
   **THEN** 系统 **SHALL** 排除已选订单的订单数、最小/大订单金额、平均订单金额等统计数据

9. **GIVEN** 有已选订单  
   **WHEN** 查看营业数据-按点餐方式（店内）  
   **THEN** 系统 **SHALL** 排除已选订单的订单数、最小/大订单金额、平均订单金额等统计数据

10. **GIVEN** 有已选订单  
    **WHEN** 查看营业数据-按支付方式  
    **THEN** 系统 **SHALL** 排除已选订单的订单数、金额等统计数据

11. **GIVEN** 有已选订单  
    **WHEN** 查看营业数据-按高峰期  
    **THEN** 系统 **SHALL** 排除已选订单的高峰时间、订单数、金额等统计数据

12. **GIVEN** 有已选订单  
    **WHEN** 查看营业数据-按支付方式  
    **THEN** 系统 **SHALL** 排除已选订单的实收金额等统计数据

13. **GIVEN** 有已选订单  
    **WHEN** 查看营业数据-按商品  
    **THEN** 系统 **SHALL** 排除已选订单的销量、单价、合计等统计数据

14. **GIVEN** 有已选订单  
    **WHEN** 查看营业数据-按商品分类  
    **THEN** 系统 **SHALL** 排除已选订单的销售量、销售额、销售笔数、现金收入、退款金额、实收金额等统计数据
