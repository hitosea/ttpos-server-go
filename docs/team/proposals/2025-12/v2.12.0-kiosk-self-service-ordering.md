## 🎯 背景和动机

### 问题描述

当前餐饮行业面临人力成本上升、高峰期服务压力大等问题。传统点餐方式需要服务员引导，在高峰期容易出现排队等待、点餐效率低、服务体验差的情况。同时，随着数字化趋势和顾客自助服务习惯的养成，市场对自助点餐机的需求日益增长。

**当前痛点**：

- 高峰期顾客排队等待时间长，影响用餐体验

- 服务员需要同时处理点餐、收银、服务等多重任务，效率低下

- 人工点餐容易出现错单、漏单等问题

- 多语言环境下，人工点餐沟通成本高

- 顾客希望更自主、更便捷的点餐体验

### 业务价值

通过引入自助点餐机终端，可以带来以下业务价值：

- **提升服务效率**：减少人工点餐环节，释放服务员精力，提升整体服务效率

- **改善顾客体验**：顾客可自主选择商品、规格、套餐，点餐流程更顺畅，减少等待时间

- **降低运营成本**：减少人工点餐环节的人力成本，特别是在高峰期效果显著

- **提高订单准确性**：自助点餐减少人工沟通误差，降低错单、漏单率

- **支持多语言**：自助点餐机支持多语言切换，满足国际化需求

- **24小时服务**：无人值守场景下可提供24小时自助点餐服务

- **数据收集**：通过自助点餐收集顾客偏好数据，支持精准营销

## 💡 解决方案概述

### 方案描述

开发一套完整的自助点餐机终端应用（Kiosk），为顾客提供从登录、浏览菜单、选择商品、配置规格、下单、支付到取餐的完整自助点餐流程。终端采用大屏触摸交互，支持多语言切换，集成多种支付方式，提供友好的用户界面和流畅的操作体验。

**核心流程**：

1. **登录认证**：使用商家员工账号登录（与POS、Assistant等终端一致），支持邮箱/手机号登录，验证码验证，记住密码功能

2. **首页选择**：选择用餐方式（堂食/外带），选择语言（简体中文/繁体中文/英文等）

3. **商品浏览**：分类浏览商品，查看商品详情、价格、折扣信息

4. **商品选择**：选择商品规格、熟度、加料等定制选项

5. **套餐配置**：选择套餐，配置套餐内各分组菜品

6. **购物车管理**：查看已选商品，修改数量，查看订单总价

7. **订单确认**：确认取餐方式、支付方式

8. **支付流程**：生成支付二维码，支持多种支付方式（微信、支付宝、PromptPay等）

9. **支付结果**：显示支付成功/失败，生成取餐码，打印小票

### 核心功能点

1. **登录认证功能**

   - 使用商家员工账号登录（与POS、Assistant、Tablet等终端一致）

   - 每个员工账号都可以登录自助点餐机

   - 支持邮箱/手机号登录

   - 图形验证码验证

   - 记住密码功能（加密存储）

   - 默认回显上一个登录账号

2. **首页功能**

   - 轮播广告展示（图片/视频）

   - 用餐方式选择（堂食/外带）

   - 多语言切换（简体中文/繁体中文/英文等）

   - 呼叫服务员功能

3. **商品浏览与选择**

   - 分类导航（左侧分类列表）

   - 商品列表展示（网格布局）

   - 商品详情查看（图片、名称、价格、折扣）

   - 商品规格选择（中份/大份等）

   - 商品定制（熟度、加料等）

   - 套餐选择与配置

4. **购物车管理**

   - 实时显示已选商品

   - 商品数量调整

   - 商品删除

   - 订单总价计算（原价/现价/折扣）

5. **订单确认**

   - 取餐方式确认（堂食/外带）

   - 支付方式选择（多种支付方式）

   - 订单详情展示

6. **支付功能**

   - 支付二维码生成

   - 支付倒计时（90秒）

   - 支付状态轮询

   - 支付成功/失败处理

7. **支付结果**

   - 支付成功：显示取餐码，提示打印小票

   - 支付失败：提示重试，联系工作人员

8. **多语言支持**

   - 界面语言切换

   - 商品名称、描述多语言显示

   - 价格多币种显示

9. **异常处理**

   - 网络异常处理

   - 支付超时处理

   - 订单异常处理

   - 友好的错误提示

- [ ] **低**：纯 UI 调整，无业务逻辑变更

- [x] **中**：需要前后端联调，基础业务逻辑

- UI 需要适配大屏触摸交互

### 风险识别

**潜在风险**：

1. **支付集成风险**：多种支付方式集成复杂，可能出现支付失败、重复扣款等问题

2. **网络稳定性风险**：自助点餐机依赖网络，网络不稳定可能导致订单丢失、支付失败

3. **订单同步风险**：订单创建后需要同步到订单中心、KDS等系统，可能出现同步延迟或失败

4. **用户体验风险**：大屏触摸交互与移动端不同，需要重新设计交互流程

5. **多语言支持风险**：商品名称、描述等需要多语言数据，可能存在翻译不完整或错误

6. **设备兼容性风险**：不同品牌、型号的自助点餐机硬件差异，可能影响显示效果和交互体验

**缓解措施**：

1. 支付集成采用成熟的支付网关SDK，实现支付状态轮询和异常重试机制，增加支付日志和监控

2. 实现订单本地缓存，网络恢复后自动同步；支付流程增加超时处理和重试机制

3. 订单创建后立即返回订单号，异步同步订单状态；增加订单状态查询接口，支持订单状态修复

4. 参考现有Mobile端点餐流程，针对大屏触摸优化交互；进行用户测试，收集反馈优化

5. 建立多语言数据管理流程，确保商品数据完整性；提供多语言数据缺失时的降级方案

6. 在多种设备上进行测试，建立设备兼容性清单；提供设备配置参数，支持不同分辨率适配

**作为** 顾客  

**我想** 通过自助点餐机完成点餐和支付  

**以便于** 无需等待服务员，自主选择商品和规格，快速完成点餐流程

**作为** 顾客  

**我想** 在自助点餐机上选择用餐方式和支付方式  

**以便于** 根据自己的需求灵活选择，获得更好的用餐体验

**作为** 顾客  

**我想** 在自助点餐机上查看商品详情和价格  

**以便于** 了解商品信息，做出购买决策

**作为** 门店运营人员  

**我想** 通过自助点餐机减少人工点餐环节  

**以便于** 提升服务效率，降低运营成本，特别是在高峰期

### AC 验收标准（初稿）

1. **WHEN** 员工打开自助点餐机 **THEN** 系统 **SHALL** 显示登录界面，支持商家员工账号登录（邮箱/手机号），验证码验证，与POS、Assistant等终端登录方式一致

2. **WHEN** 员工使用任意员工账号登录成功 **THEN** 系统 **SHALL** 显示首页，包含轮播广告、用餐方式选择、语言选择

3. **WHEN** 顾客选择用餐方式（堂食/外带）和语言 **THEN** 系统 **SHALL** 进入点餐界面，显示商品分类和商品列表

4. **WHEN** 顾客点击商品 **THEN** 系统 **SHALL** 显示商品详情弹窗，支持选择规格、熟度、加料等选项

5. **WHEN** 顾客选择套餐 **THEN** 系统 **SHALL** 显示套餐配置界面，支持配置套餐内各分组菜品

6. **WHEN** 顾客添加商品到购物车 **THEN** 系统 **SHALL** 更新购物车，显示商品数量和总价

7. **WHEN** 顾客点击结算 **THEN** 系统 **SHALL** 显示订单确认页面，包含取餐方式、支付方式选择

8. **WHEN** 顾客选择支付方式并确认 **THEN** 系统 **SHALL** 生成支付二维码，开始90秒倒计时

9. **WHEN** 支付成功 **THEN** 系统 **SHALL** 显示取餐码，提示打印小票，提供返回首页按钮

10. **WHEN** 支付失败 **THEN** 系统 **SHALL** 显示失败提示，提供重试按钮和联系工作人员提示

11. **WHEN** 顾客切换语言 **THEN** 系统 **SHALL** 更新界面语言和商品名称、描述

12. **WHEN** 网络异常 **THEN** 系统 **SHALL** 显示友好提示，支持重试或联系工作人员
