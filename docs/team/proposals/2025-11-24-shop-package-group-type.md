## 🎯 背景和动机

### 问题描述

当前套餐商品的分组功能较为简单，所有分组商品都是固定必选的，无法满足商家灵活配置套餐的需求。商家希望能够：

1. **设置可选分组**：某些分组中的商品可以让顾客自由选择，而不是全部固定
2. **控制可选数量**：对于可选分组，可以设置需要选择多少个商品（如"3选1"、"5选2"等）
3. **支持商品加价**：某些商品在套餐中需要额外加价（如升级大杯、加料等）

**示例场景**：
> 一个"汉堡套餐"包含：
> - 固定分组：1个汉堡（必选）
> - 可选分组：饮料3选1（可乐、雪碧、橙汁）
> - 可选分组：小食5选2（薯条、鸡块、鸡翅、洋葱圈、玉米杯）
> - 其中"大杯可乐"需要加价2元

### 业务价值

- **提升套餐灵活性**：满足商家多样化的套餐配置需求
- **增强用户体验**：顾客可以根据喜好选择套餐内容
- **提高客单价**：通过加价功能引导顾客选择高价值商品
- **减少SKU数量**：通过可选分组减少需要创建的套餐变体数量

## 💡 解决方案概述

### 方案描述

在套餐分组功能中增加**分组类型**和**商品加价**两个核心能力：

1. **分组类型**：
   - **固定分组**（默认）：分组内所有商品必选，保持现有行为
   - **可选分组**：分组内商品可选择性，需要设置"可选数量"（如3选1、5选2）

2. **商品加价**：
   - 每个分组商品可以设置加价金额（默认0）
   - 加价金额会在套餐总价基础上累加

3. **必选与默认**：
   - 可选分组中可以设置某些商品为"必选"或"默认选中"
   - 必选数量不能超过可选数量

### 核心功能点

1. **数据库扩展**
   - `ttpos_product_package_group` 表增加：
     - `group_type`：分组类型（0-固定，1-可选）
     - `optional_count`：可选数量（可选分组时有效，表示本组商品中要求选择多少个）
   - `ttpos_product_package_group_item` 表增加：
     - `add_price`：加价字段（该商品需要加价多少钱，默认0）

2. **API 接口扩展**
   - `/shop/product/add [POST]`：创建套餐接口
     - `ProductShopAddPackageGroupReq` 增加 `group_type`、`optional_count` 字段
     - `ProductShopAddPackageGroupProductReq` 增加 `add_price` 字段
   - `/shop/product/edit [POST]`：编辑套餐接口（同步增加字段）
   - `/shop/product/detail [GET]`：商品详情查询接口（返回新增字段）

3. **数据迁移**
   - 创建 SQL 迁移文件，为现有数据设置默认值
   - 现有套餐分组默认为"固定分组"（`group_type=0`）
   - 现有商品加价默认为0（`add_price=0`）

4. **业务逻辑验证**
   - 必选数量不能大于可选数量
   - 可选数量不能大于分组内商品总数
   - 加价金额必须 >= 0

## 🛠️ 开发实现思路

### 1. 数据库表结构扩展

#### `ttpos_product_package_group` 表
- 增加 `group_type` 字段：`TINYINT DEFAULT 0 COMMENT '分组类型 0-固定 1-可选'`
- 增加 `optional_count` 字段：`INT DEFAULT 1 COMMENT '可选数量，表示本组商品中要求选择多少个商品'`

#### `ttpos_product_package_group_item` 表
- 增加 `add_price` 字段：`DECIMAL(10,2) DEFAULT 0.00 COMMENT '加价金额，表示该商品需要加价多少钱'`

### 2. API 接口参数扩展

#### `/shop/product/add [POST]` 创建套餐接口

**`ProductShopAddPackageGroupReq` 参数增加**：
```go
GroupType     int    `json:"group_type"`      // 分组类型 0-固定 1-可选
OptionalCount int    `json:"optional_count"`  // 可选数量（可选分组时有效）
```

**`ProductShopAddPackageGroupProductReq` 参数增加**：
```go
AddPrice float64 `json:"add_price"` // 加价金额，默认0
```

#### `/shop/product/edit [POST]` 编辑套餐接口
- 同步增加上述字段

#### `/shop/product/detail [GET]` 商品详情查询接口
- 返回数据中增加上述字段

### 3. SQL 迁移文件

创建迁移文件，为现有数据设置默认值：
- `group_type = 0`（固定分组）
- `optional_count = 1`
- `add_price = 0.00`

### 4. 业务逻辑验证

- 必选数量不能大于可选数量
- 可选数量不能大于分组内商品总数
- 加价金额必须 >= 0
- 固定分组时，`optional_count` 应等于分组内商品总数

## 📝 附录

### User Story（初稿）

**作为** 商户管理员  
**我想** 在套餐配置中设置可选分组和商品加价  
**以便于** 创建更灵活的套餐组合，满足不同顾客需求，提高客单价

### AC 验收标准（初稿）

#### AC1：分组类型设置
**Given** 套餐商品  
**When** 创建或编辑套餐分组  
**Then** 系统 **SHALL** 提供"分组类型"选项，默认选择"固定"  
**And** 选择"可选"类型时，**SHALL** 显示"可选数量"输入框（默认1）

#### AC2：可选数量设置
**Given** 可选分组  
**When** 设置可选数量  
**Then** 系统 **SHALL** 验证可选数量 <= 分组内商品总数  
**And** 必选数量 **SHALL** 不能大于可选数量

#### AC3：商品加价设置
**Given** 套餐分组商品  
**When** 设置商品加价  
**Then** 系统 **SHALL** 提供加价输入框，默认值为0  
**And** 加价金额 **SHALL** 必须 >= 0

#### AC4：必选与默认设置
**Given** 可选分组  
**When** 设置商品为必选或默认选中  
**Then** 系统 **SHALL** 提供"必选"和"默认"选项  
**And** 默认不设置必选和默认选中

#### AC5：商品数量显示
**Given** 套餐分组商品  
**When** 查看商品数量  
**Then** 系统 **SHALL** 显示商品的实际数量  
**Example**: 商品A数量是2，商品B数量是1，则显示2和1

#### AC6：可选数量计算逻辑
**Given** 可选分组，设置可选数量为3  
**When** 顾客选择商品  
**Then** 系统 **SHALL** 计算总数量为：商品A数量×选择份数×2 + 商品B数量×选择份数×1  
**Example**: 如果可选3份，商品A选2份（数量2），商品B选1份（数量1），则总共5杯饮料（2×2 + 1×1）

#### AC7：必选数量验证
**Given** 必选数量大于可选数量  
**When** 保存套餐配置  
**Then** 系统 **SHALL** 提示错误："必选不可大于可选数量"
