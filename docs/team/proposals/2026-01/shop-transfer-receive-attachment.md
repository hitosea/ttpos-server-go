## 🎯 背景和动机

### 问题描述

当前调拨单收货流程存在以下问题：

1. **收货无凭证**：收货完成后无法上传签收单、送货单等凭证，缺乏留档依据
2. **异常难追溯**：收货数量/质量有问题时，无法上传照片作为证据，责任难以界定
3. **审计不合规**：财务/审计需要收货附件作为原始凭证进行对账，当前无法满足

### 业务价值

- **满足合规需求**：为财务/审计提供收货凭证，符合内部审计要求
- **降低业务风险**：减少货物丢失/损坏纠纷，明确收货责任
- **提升管理效率**：快速查阅收货记录附件，减少跨部门沟通成本

### 目标用户

- [x] 店长/门店管理员 - 负责收货操作和店铺物料管理
- [x] 财务/审计人员 - 需要查阅收货凭证进行对账
- [x] 运营/区域管理 - 监督多店铺的调拨执行情况

## 💡 解决方案概述

### 方案描述

复用现有采购收货（外部）的附件上传功能逻辑，为调拨单收货增加附件上传能力。实现方式：新建 `TransferOrderFile` 关联表，复用 `PurchaseReceiptFile` 的代码模式（Model、Repository、Service 三层结构），在调拨单收货接口中集成附件保存逻辑。

### 核心功能点

1. **附件上传**：支持拍照、相册选图、文件管理器选择，格式包括 PDF/Word/Excel/JPG/PNG/GIF
2. **附件管理**：支持预览、下载、删除已上传的附件，单个附件≤20MB，最多10个
3. **业务规则**：保存操作附件非必填，确定收货时附件必填
4. **状态控制**：待收货状态可编辑附件，已完成状态仅可预览和下载

### 影响范围

**涉及终端**：
- [x] Shop 商家管理端

**涉及模块**：
- [x] UI 组件 - 前端附件上传组件（Flutter）
- [x] API 接口 - 调拨单收货接口增加附件参数
- [x] 数据模型 - 新建 `ttpos_transfer_order_file` 关联表
- [x] 业务逻辑 - 附件保存、验证、查询服务

## 📝 附录

### User Story（初稿）

**作为** 店长/门店管理员
**我想** 在调拨单收货时上传签收单、送货单等附件
**以便于** 留存收货凭证，满足财务审计要求，减少货物纠纷

### AC 验收标准（初稿）

1. **WHEN** 用户在待收货详情页点击上传 **THEN** 系统 **SHALL** 支持拍照/相册/文件选择方式上传附件
2. **WHEN** 用户点击确定收货且未上传附件 **THEN** 系统 **SHALL** 提示"请上传相关附件后确定收货"
3. **WHEN** 用户在已完成订单查看附件 **THEN** 系统 **SHALL** 仅支持预览和下载，不可编辑
4. **WHEN** 用户使用旧版本 App **THEN** 系统 **SHALL** 提示"您的软件版本过低，请升级后再试"
