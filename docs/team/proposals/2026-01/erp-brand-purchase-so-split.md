## 🎯 背景和动机

### 问题描述

当前品牌采购（内部采购）流程中，子门店向总部采购物资时，系统只会生成**单一的 Sales Order (SO)**，即使这些物品实际分布在总部的不同仓库。这导致以下问题：

1. **仓库无法独立处理**：所有商品在一个 SO 里，不同仓库无法独立管理各自负责的商品
2. **发货流程混乱**：多仓库发货时难以区分各自职责，容易发错货
3. **库存管理不清晰**：无法按仓库维度追踪采购履行进度

### 业务价值

- **仓库运营效率提升**：各仓库独立处理自己的 SO，可并行作业
- **发货准确率提高**：按仓库拆分后责任明确，减少发错货
- **库存可视化增强**：按仓库维度查看采购履行进度
- **管理成本降低**：减少手动拆单和协调工作

## 💡 解决方案概述

### 方案描述

在总部审批品牌采购单时，根据 TTPOS 数据库中各仓库的实际库存情况，将 PO 中的 Items 按仓库归属进行分组，然后为每个仓库组创建独立的 Sales Order。

核心流程变更：
- **当前**：1 PO → 1 SO
- **目标**：1 PO → N SO（每个有库存的仓库一个 SO）

### 核心功能点

1. **库存查询与分组**：审批时查询 TTPOS 各仓库库存，仅保留 `actual_qty > 0` 的仓库-Item 组合
2. **零库存校验**：若任一 Item 在所有仓库都无库存，拒绝整个采购申请
3. **SO 拆分创建**：按仓库分组传递给 BMP，为每个仓库创建独立 SO
4. **取消仓库指定**：PO 创建时不再需要指定单一 `warehouse_erp_code`

## 📊 初步评估

### 技术复杂度

- [ ] **低**：纯 UI 调整,无业务逻辑变更
- [ ] **中**：需要前后端联调,基础业务逻辑
- [x] **高**：涉及架构调整、第三方集成、复杂算法

**复杂度说明**：
- Main 层需改造审批流程，新增库存查询和分组逻辑
- gRPC 接口需要调整参数结构
- BMP 层需支持循环创建多个 SO
- 涉及跨系统数据一致性（TTPOS ↔ ERPNext）

- **预估 SP**: 8-13（待技术评审确认）

**是否需要拆分**：

- [x] **是**：需要拆分为多个 Spec

**拆分维度**：
- [x] 按功能模块拆分：Main 层 + BMP 层

**预估 Spec 数量**：2-3 个

**预估 Spec 列表**：

2. `story-erp-brand-purchase-so-split-bmp` - BMP 层循环创建 SO、错误处理
3. `story-erp-brand-purchase-so-split-ui`（可选）- 审批界面展示拆分预览

### 风险识别

**潜在风险**：

1. **数据不一致风险**：TTPOS 与 ERPNext 库存数据存在 15 分钟同步延迟
2. **并发竞争风险**：多个采购申请同时审批可能导致库存超卖
3. **回滚复杂性**：部分 SO 创建成功、部分失败时的回滚处理
4. **性能风险**：仓库数量多时，循环创建 SO 可能较慢

**缓解措施**：

1. 依赖 DN 创建时 ERPNext 校验库存，作为最终兜底
2. 审批前可选触发同步，或依赖定时同步（15分钟）
3. BMP 层实现统一的取消逻辑，失败时取消已创建的单据
4. 批量创建优化，或接受串行创建的延迟

## 📝 附录

### User Story（初稿）

**作为** 总部仓库管理员
**我想** 在品牌采购审批后，收到只包含本仓库负责商品的独立 SO
**以便于** 独立管理发货流程，提高作业效率和准确率

### AC 验收标准（初稿）

1. **WHEN** 总部审批品牌采购单 **THEN** 系统 **SHALL** 按仓库库存分组创建多个 SO
2. **WHEN** 某 Item 在所有仓库都无库存 **THEN** 系统 **SHALL** 拒绝整个采购申请并返回明确错误信息
3. **WHEN** 同一 Item 在多个仓库有库存 **THEN** 系统 **SHALL** 为每个有库存的仓库都创建包含该 Item 的 SO
4. **WHEN** PO 创建 **THEN** 系统 **SHALL** 不再强制要求指定 warehouse_erp_code

### 技术讨论记录

**数据源选择**：使用 TTPOS 数据库作为库存查询来源，而非 ERPNext Bin 表
- 优点：无额外 HTTP 调用，利用现有扣库存逻辑
- 风险：依赖 15 分钟定时同步机制

**库存校验策略**：查询库存用于分组，不用于数量校验
- 仅校验库存是否 > 0（用于分组）
- 数量校验依赖 DN 创建时 ERPNext 自动校验

**并发处理**：依赖 ERPNext 在 DN 创建时的库存校验
- SO/PO 创建不扣库存
- DN 创建时才真正扣减库存，此时 ERPNext 会校验
