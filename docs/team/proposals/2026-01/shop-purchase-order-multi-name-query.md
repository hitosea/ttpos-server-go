## 🎯 背景和动机

### 问题描述

当前 `buying.GetPurchaseOrderListReq` 接口的 `name` 字段只支持单个值查询，用户在商家管理端查询采购单时，如果需要筛选多个供应商或多个品类的采购单，必须进行多次查询操作，效率较低。

### 业务价值

- **匹配前端能力**：前端已支持多选筛选，后端需要配合支持 IN 查询
- **提升查询效率**：一次请求获取多个条件的结果，减少重复操作
- **支持批量业务场景**：满足批量对账、批量审核等需要同时查看多个条件采购单的场景

### 目标用户

- [x] 店长
- [x] 商户管理员
- [x] 运营人员

## 💡 解决方案概述

### 方案描述

在 `buildPurchaseOrderListFilters` 方法中，当请求参数 `name` 存在时，将原有的等值查询改为 IN 查询。支持前端传入多个 name 值（以逗号分隔），后端自动解析并生成 `{"name", "in", "value1,value2,value3"}` 格式的 filter 条件。

### 核心功能点

1. 修改 `buildPurchaseOrderListFilters` 方法，支持 name 字段 IN 查询
2. 当 name 包含逗号时，自动拆分为多个值进行 IN 匹配
3. 保持向后兼容，单个 name 值时行为不变

### 风险识别

**潜在风险**：
1. IN 查询值过多可能影响查询性能
2. 需确认前端传参格式与后端解析逻辑一致

**缓解措施**：
1. 限制 IN 查询的最大值数量（如不超过 50 个）
2. 与前端确认参数传递格式，保持一致

**作为** 店长/商户管理员/运营人员

2. **WHEN** 用户传入单个 name 参数（不含逗号） **THEN** 系统 **SHALL** 保持原有等值查询行为
