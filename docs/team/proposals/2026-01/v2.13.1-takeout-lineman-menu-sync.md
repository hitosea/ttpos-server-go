## 🎯 背景和动机

### 问题描述

TTPOS 需要与泰国外卖平台 Lineman 进行菜单数据同步，以便商家可以在 Lineman 平台上展示和销售商品。当前系统缺少对 Lineman Menu Sync V2 API 的支持。

**核心需求**：
- 商家在 TTPOS 中管理的菜单（分类、商品、规格、属性、价格等）需要实时同步到 Lineman 平台
- 支持菜单的完整结构同步，包括：商品分类、商品信息、规格组、加料组、属性组等
- 支持商品状态同步（可用、售罄、暂停销售等）
- 确保数据映射准确，符合 Lineman API V2 规范

### 业务价值

**商业价值**：
- **扩展销售渠道**：接入 Lineman 外卖平台，帮助商家覆盖泰国市场更多线上用户
- **提升运营效率**：菜单统一管理，自动同步，减少人工维护成本
- **保证数据一致性**：实时同步确保 TTPOS 和 Lineman 平台菜单信息一致，避免订单错误
- **增强竞争力**：支持主流外卖平台集成，提升 TTPOS 产品竞争力

**用户价值**：
- 商家只需在 TTPOS 中维护一份菜单，自动同步到外卖平台
- 减少因菜单不一致导致的客诉和退单
- 快速响应菜单变更（价格调整、商品上下架等）

### 目标用户

- [x] 商户管理员（维护菜单和同步配置）
- [ ] 收银员
- [ ] 厨房人员
- [ ] 顾客

## 💡 解决方案概述

### 方案描述

在 `ttpos-bmp/app/ttpos-takeout` 模块中实现 Lineman Menu Sync V2 API 的调用逻辑，负责将 TTPOS 的菜单数据转换并同步到 Lineman 平台。

**技术路径**：
1. 在 `ttpos-bmp/app/ttpos-takeout/internal/logic` 实现 MenuSyncV2 的业务逻辑
2. 实现 TTPOS 菜单结构到 Lineman API 格式的数据映射转换
3. 封装 RESTful API 调用（PUT `/v2/partners/{partnerId}/stores/{storeId}/menus`）
4. 处理认证（Bearer Token）、请求/响应、错误处理等
5. 支持增量同步和全量同步两种模式
6. 记录同步日志和状态

### 核心功能点

1. **数据映射与转换**
   - TTPOS 分类（categories）→ Lineman menuGroups
   - TTPOS 商品/套餐（goods/packages）→ Lineman menuItems
   - TTPOS 规格组/加料组/属性组 → Lineman properties/values
   - 支持多语言名称映射（中文 → 泰语 + 英语）
   - 价格单位转换（元 → 分）

2. **API 调用封装**
   - RESTful HTTP Client 封装
   - 认证管理（Access Token 获取与刷新）
   - 请求重试机制（网络故障、超时等）
   - 响应解析与错误码处理

3. **同步策略**
   - 全量同步：推送门店完整菜单结构
   - 增量同步：仅推送变更的分类/商品/属性
   - 状态同步：售罄、下架、价格调整等

4. **监控与日志**
   - 同步状态记录（成功/失败/部分成功）
   - 错误日志记录（便于问题排查）
   - 同步时间戳和请求 ID 追踪

4. **网络稳定性**：实现请求重试、超时控制、熔断机制；异步同步避免阻塞主流程
5. **多语言翻译**：建议商家在 TTPOS 中维护多语言菜单；可选集成自动翻译服务（如 Google Translate API）

## 📝 附录

### User Story（初稿）

**作为** 商户管理员  
**我想** 在 TTPOS 中一键同步菜单到 Lineman 平台  
**以便于** 快速上线外卖业务，无需在多个平台重复维护菜单

### AC 验收标准（初稿）

1. **GIVEN** 商家已在 Lineman 平台完成入驻并获取 Partner ID 和 Store ID  
   **WHEN** 在 TTPOS Shop 后台点击"同步菜单到 Lineman"按钮  
   **THEN** 系统应成功将当前门店的完整菜单数据推送到 Lineman，并显示同步状态

2. **GIVEN** 商家修改了某个商品的价格或规格  
   **WHEN** 触发增量同步  
   **THEN** 系统应仅同步变更的商品信息，而不是全量推送

3. **GIVEN** 商家将某个商品标记为"售罄"  
   **WHEN** 同步到 Lineman  
   **THEN** Lineman 平台该商品状态应显示为 SUSPENDED 或 SOLD_OUT_TODAY

4. **GIVEN** Lineman API 返回 400/404/500 错误  
   **WHEN** 同步失败  
   **THEN** 系统应记录详细错误日志，并在 Shop 后台显示失败原因

5. **GIVEN** 商品名称为中文  
   **WHEN** 同步到 Lineman  
   **THEN** 系统应提供泰语和英语的 nameTranslation 字段（可通过预设映射或自动翻译）

### 数据映射关系（关键字段）

| TTPOS 字段 | Lineman 字段 | 说明 |
| --- | --- | --- |
| `categories` | `menuGroups` | 菜单分类 |
| `categories[].id` | `menuGroups[].id` | 分类 ID（格式：`TTPOS-CAT-{id}`） |
| `categories[].name` | `menuGroups[].name.thai` | 分类名称（泰语） |
| `categories[].items` | `menuGroups[].menuItems` | 分类下的商品列表 |
| `items[].id` | `menuItems[].id` | 商品 ID（格式：`TTPOS-ITEM-{id}` 或 `TTPOS-PACKAGE-{id}`） |
| `items[].name` | `menuItems[].name.thai` | 商品名称（泰语） |
| `items[].price` | `menuItems[].price` | 商品价格（分为单位） |
| `items[].status` | `menuItems[].menuStatus` | 商品状态（`AVAILABLE` / `SUSPENDED` / `SOLD_OUT_TODAY`） |
| `items[].photos[0]` | `menuItems[].photoUrl` | 商品图片（取第一张） |
| `modifierGroups` | `properties` | 规格组/加料组/属性组 |
| `modifierGroups[].id` | `properties[].id` | 属性组 ID |
| `modifierGroups[].name` | `properties[].name.thai` | 属性组名称（泰语） |
| `modifierGroups[].selectionRangeMin` | `properties[].min` | 最小选择数 |
| `modifierGroups[].selectionRangeMax` | `properties[].max` | 最大选择数（>1 为复选，=1 为单选） |
| `modifiers` | `properties[].values` | 属性值列表 |
| `modifiers[].id` | `values[].id` | 属性值 ID |
| `modifiers[].name` | `values[].name.thai` | 属性值名称（泰语） |
| `modifiers[].price` | `values[].price` | 属性值价格（分为单位） |

- `useSellingTime`: 固定 `false`（TTPOS 全时段销售）

- `salesChannelsAvailability.pickup`: 固定 `true`
- `properties[].type`: 根据 `selectionRangeMax` 判断（`>1` 为 `2` 复选框，`=1` 为 `1` 单选）

## 🤝 需求评审

### 待确认问题

在进入技术设计前，需要确认以下问题：

1. **商家入驻流程**
   - 商家如何在 Lineman 平台完成入驻？
   - Partner ID 和 Store ID 如何获取并维护在 TTPOS 中？
   - 是否需要在 Shop 后台增加"Lineman 配置"页面？

2. **认证机制**
   - Access Token 如何获取？（OAuth 2.0 授权码模式 / Client Credentials 模式？）
   - Token 有效期多久？刷新策略？
   - 是否需要实现 Token 持久化（Redis / DB）？

3. **同步触发方式**
   - 手动触发：Shop 后台菜单管理页面添加"同步到 Lineman"按钮
   - 自动触发：商品变更后自动同步（需要事件监听机制）
   - 定时同步：每天固定时间全量同步（防止数据漂移）

4. **多语言处理**
   - 商家是否需要在 TTPOS 中维护泰语和英语菜单？
   - 如果商家只维护中文，是否需要自动翻译服务？
   - 翻译质量如何保证（人工审核 / 机器翻译后编辑）？

5. **错误处理**
   - 同步失败时是否需要告警通知（邮件 / 短信 / 系统通知）？
   - 是否需要同步历史记录查询功能？
   - 部分失败（某些商品同步成功，某些失败）如何处理？
