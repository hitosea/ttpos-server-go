## 🎯 背景和动机

### 问题描述

当前品牌采购限购功能存在以下问题：

1. **配置单一化**：现有限购功能只能配置全局限额，无法针对不同时间段（如一周中的某几天）、不同门店、不同物品进行精细化管理
2. **限制不灵活**：只支持按天或按月的简单周期限制，无法满足"仅周一、周三、周五限购"等业务场景
3. **管理效率低**：无法通过方案化管理多个限购规则，总部需要反复修改配置
4. **门店体验差**：门店在提交采购申请时，看不到清晰的限购规则和剩余额度提示，容易提交失败
5. **草稿单据问题**：创建的采购申请单保存为草稿后，跨天提交时无法识别限购方案变更，导致提交被拒绝

### 业务价值

- 提升总部采购管理精细化程度，优化库存管理
- 减少门店无效申请次数，提高采购申请通过率
- 引导门店合理规划采购，规范采购行为
- 降低总部审核工作量，提高运营效率
- 支持灵活的营销策略（如节假日限购调整）

### 目标用户

- [x] 总部采购管理员

- [x] 门店采购员
- [ ] 收银员

- [ ] 顾客

## 💡 解决方案概述

### 方案描述

在商家管理端的"参数设置"模块中新增"限购业务"入口，支持创建和管理多个限购方案，实现精细化的采购申请限额管理。每个限购方案可以独立配置周期（按星期）、物品限额、门店范围、每日申请次数等规则。

门店在提交品牌采购申请时，系统会自动根据限购方案过滤物品列表，并在输入数量时实时提示限额信息。如果草稿单据跨天提交，系统会重新校验限购方案，如果不符合则提示用户并阻止提交。

### 核心功能点

#### 总部视角：

1. **限购方案管理**
   - 支持创建多个限购方案，每个方案独立配置
   - 支持启用/禁用方案状态控制
   - 支持删除和编辑方案

2. **限购方案配置**
   - **方案名称**：必填，用于标识限购方案
   - **状态开关**：控制该限购方案是否生效
   - **周期设置**：支持按一周7天进行配置，可选择具体星期（周一到周日）
   - **物品配置**：可以选择具体物品，为每个物品配置限额（数量 + 单位）
   - **单位来源**：单位固定为该物品的销售单位；如果物品没有销售单位，则取物品的基准单位
   - **数量配置**：可为物品配置限额数量（默认为空，为空则不做限制）
   - **门店配置**：可以选择全部门店或指定门店
   - **每日申请次数**：限制门店每天可以申请的次数（不填入则不限制）

3. **物品限额配置**
   - 在物品选择页面，为每个选中的物品配置限额
   - 默认物品数量为空，为空则不做限制
   - 单位固定为该物品的销售单位（如果物品没有销售单位则取基准单位）
   - 支持删除限额项

4. **核心业务规则**
   - **限购方案优先级**：如果物品同时匹配多个限购方案，取**最小值**的限制
   - **草稿单据提交规则**：创建的采购申请单保存为草稿后，第二天提交时需要重新判断是否符合当天的限购方案
   - **物品列表过滤规则**：
     - 如果物品未配置在任何限购方案中 → 显示在列表中
     - 如果物品配置了限购方案但方案状态为关闭 → 显示在列表中
     - 如果物品配置了限购方案且方案状态为开启，且当前门店在方案的门店范围内，且当前日期对应的星期在周期配置中 → 显示在列表中
     - 如果物品配置了限购方案且方案状态为开启，且当前门店在方案的门店范围内，但当前日期对应的星期不在周期配置中 → **不显示**在列表中
   - **限额校验规则**：
     - 申请数量必须在限购方案配置的数量范围内（如果数量为空，则不限制数量）
     - 申请单位必须在限购方案配置的单位列表中（如果单位配置为空，则不限制单位）
     - 每日申请次数不能超过限购方案配置的次数（已驳回的单据不计入统计）
   - **数量限制规则**：默认物品数量为空，为空则不做限制；如果配置了数量，则限制申请数量不能超过配置的值
   - **审核修改规则**：单据提交后，审核人可以进行采购订单修改，修改的限制以**提交日期**的限购方案为准（而非当前日期的限购方案）

#### 门店视角：

1. **物品列表过滤**
   - 根据当前门店和当前日期的星期，自动过滤物品列表
   - 只显示允许申请的物品（符合限购方案的物品）

2. **限额信息展示**
   - 在采购申请页面，显示设置的限购数量
   - 显示剩余可申请次数（如"今日剩余申请次数：2 次"）

3. **数量输入校验**
   - 物品输入数量不可超过限购数量
   - 实时提示当前限额和剩余额度

4. **草稿单据跨天提交处理**
   - **场景1：采购订单没有被限购方案约束**
     - 点击【提交】按钮 → 提交成功
   - **场景2：采购订单跨天，被当天限购方案约束**
     - 点击【提交】按钮 → 提示："该采购申请单创建于{创建日期}，当前日期为{当前日期}，限购方案已变更，请检查物品和数量再进行提交。"
     - 问题物品出现红色感叹号标签（点击感叹号，展示当前物品问题）
     - 合计中展示问题项总数
   - **数量限制**：申请数量大于当天物品限制数量 → 提示："物品 {name} 的限额已变更为{数量}{单位}，请修改申请数量。"
   - **物品限制**：申请物品不在当天限购方案范围内 → 提示："物品 {name} 不在当天限购方案范围内，请删除该物品或联系管理员。"

5. **其他说明**
   - 单据审核时，驳回不计入次数统计，退回次数
   - 审核单据时进行修改，需使用提交日期的限购方案（修改的限购方案以提交日期为准）
   - 审核时修改物品数量，对物品数量减为0时，通过时提示"物品【name】的申请数量为0，提交后将移除该物品，是否继续提交？"

### 风险识别

**潜在风险**：
1. **性能风险**：物品列表过滤和限购校验涉及多表关联查询，可能影响性能
2. **数据一致性风险**：草稿单据跨天提交时，限购方案可能已变更，需要重新校验
3. **业务复杂度风险**：多个限购方案同时匹配时，需要取最小值，逻辑复杂
4. **用户体验风险**：门店在提交申请时，如果限购方案变更，可能导致提交失败，影响用户体验

**缓解措施**：
1. 使用数据库索引优化查询性能，必要时使用缓存
2. 在草稿单据提交时，增加限购方案变更检测逻辑，提示用户重新检查
3. 编写清晰的业务逻辑文档和测试用例，确保多方案匹配逻辑正确
4. 提供友好的错误提示和操作引导，降低用户操作成本

## 📄 模板使用说明

### 与现有限购功能的对比

| 维度        | 现有功能      | 新功能（限购方案）   |
| ----------- | ------------- | -------------------- |
| 配置方式    | 单个物品独立配置 | 方案化管理，支持多方案 |
| 周期设置    | 按天/按月     | 支持按星期配置（周一到周日） |
| 门店配置    | 全部门店或指定门店 | 全部门店或指定门店 |
| 单位限制    | 支持         | 支持（单位固定为销售单位或基准单位） |
| 数量限制    | 支持         | 支持（默认为空，为空则不限制） |
| 申请次数限制 | 支持         | 支持（每日申请次数，不填则不限制） |
| 物品列表过滤 | 不支持       | 支持（根据限购方案自动过滤） |
| 草稿单据处理 | 不支持       | 支持（跨天提交时重新校验） |
| 审核修改规则 | 不支持       | 支持（修改的限制以提交日期为准） |

### 数据库设计要点

现有表结构：
- `ttpos_purchase_quota_config`：限购配置表
- `ttpos_purchase_quota_config_shop`：限购门店配置表

新增表结构（待技术方案确认）：
- `ttpos_purchase_limit_scheme`：限购方案表
- `ttpos_purchase_limit_scheme_item`：限购方案物品配置表
- `ttpos_purchase_limit_scheme_shop`：限购方案门店配置表
- `ttpos_purchase_limit_scheme_weekday`：限购方案星期配置表

### 技术实现要点

1. **物品列表过滤逻辑**
   - 根据当前门店和当前日期的星期，查询匹配的限购方案
   - 如果物品配置了限购方案且方案状态为开启，且当前日期对应的星期不在周期配置中 → 不显示该物品

2. **限购校验逻辑**
   - 查询物品的所有匹配限购方案（按门店和星期过滤）
   - 如果物品同时匹配多个限购方案，取最小值的限制
   - 校验申请数量、单位、每日申请次数是否符合限购方案

3. **草稿单据跨天提交逻辑**
   - 对比草稿创建日期和当前日期
   - 如果跨天，重新查询当天的限购方案
   - 逐个检查草稿中的物品是否符合当天限购方案
   - 如果不符合，标记问题物品并阻止提交

4. **审核修改逻辑**
   - 读取单据的提交日期（`submitted_at` 或 `created_at`）
   - 查询提交日期当天的限购方案
   - 使用提交日期的限购方案进行修改校验
