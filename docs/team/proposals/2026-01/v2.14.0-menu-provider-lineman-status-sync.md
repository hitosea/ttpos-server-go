## 🎯 背景和动机

### 问题描述

当前 `UpdateMenuItemReq` 协议只支持 Grab 平台的菜单更新逻辑，所有字段都按照 Grab 的规范设计。随着业务拓展到 Lineman 平台，需要支持不同平台的差异化处理：

1. **平台识别缺失**：无法区分当前更新请求是针对哪个平台
2. **状态映射不一致**：Grab 和 Lineman 的状态枚举不同
   - Grab: `AVAILABLE`, `UNAVAILABLE`, `UNAVAILABLEHIDE`
   - Lineman: `AVAILABLE`, `SUSPENDED`, `SOLD_OUT_TODAY`
3. **字段限制不同**：Lineman 仅支持更新商品状态，不支持价格、库存等字段
4. **API 调用差异**：不同平台需要调用不同的第三方 API

**示例**：
> 当商户在 TTPOS 后台将某商品设置为"售罄"时，系统需要：
> - 对 Grab 平台：调用 Grab API，设置状态为 `UNAVAILABLE`
> - 对 Lineman 平台：调用 Lineman API，设置状态为 `SOLD_OUT_TODAY`

### 业务价值

- **平台扩展性**：为后续接入更多外卖平台（如 FoodPanda、ShopeeFood）奠定基础
- **状态一致性**：确保 TTPOS 与各平台的商品状态实时同步
- **用户体验**：商户在一个后台操作，自动同步到所有平台
- **降低错误率**：避免状态映射错误导致的商品上下架问题

## 💡 解决方案概述

### 方案描述

在 `UpdateMenuItemReq` 中增加 `provider_name` 字段用于标识平台，默认值为 `grab`（保持向后兼容）。当 `provider_name` 为 `lineman` 时，执行 Lineman 专用逻辑：

1. **字段限制**：仅支持更新 `available_status` 字段，忽略其他字段（price, max_stock 等）
2. **状态映射**：将 TTPOS 内部状态转换为 Lineman 状态
   - `AVAILABLE` → `AVAILABLE`
   - `UNAVAILABLE` → `SUSPENDED`
   - 新增支持 `SOLD_OUT_TODAY`（今日售罄，明天自动恢复）
3. **API 调用**：调用 Lineman 的菜单状态更新接口
   - `PUT /v1/partners/{partnerId}/stores/{storeId}/menu/items/status`

### 核心功能点

1. **增加 provider_name 字段**
   - 类型: `string`
   - 默认值: `grab`
   - 可选值: `grab`, `lineman`

2. **Lineman 状态映射**
   - TTPOS `AVAILABLE` → Lineman `AVAILABLE`
   - TTPOS `UNAVAILABLE` → Lineman `SUSPENDED`
   - 新增 TTPOS `SOLD_OUT_TODAY` → Lineman `SOLD_OUT_TODAY`（明天自动恢复）

3. **Lineman 专用处理逻辑**
   - 仅处理 `available_status` 字段
   - 校验：如果包含其他字段（price, max_stock），返回错误提示
   - 调用 Lineman API 进行状态更新

4. **向后兼容**
   - 未指定 `provider_name` 时，默认按 Grab 逻辑处理
   - 现有 Grab 调用方无需修改代码

## 📝 附录

### User Story（初稿）

**作为** 商户管理员  
**我想** 在 TTPOS 后台统一管理商品状态，自动同步到 Grab 和 Lineman 平台  
**以便于** 无需在多个平台分别操作，提高管理效率，减少状态不一致

### AC 验收标准（初稿）

1. **WHEN** 调用 `UpdateMenuItemReq` 且 `provider_name=lineman` **THEN** 系统 **SHALL** 调用 Lineman API 更新商品状态
2. **WHEN** 调用 `UpdateMenuItemReq` 且 `provider_name=lineman` 且包含 `price` 字段 **THEN** 系统 **SHALL** 返回错误提示"Lineman 仅支持更新 available_status"
3. **WHEN** `available_status=UNAVAILABLE` 且 `provider_name=lineman` **THEN** 系统 **SHALL** 映射为 Lineman 的 `SUSPENDED` 状态
4. **WHEN** `available_status=SOLD_OUT_TODAY` 且 `provider_name=lineman` **THEN** 系统 **SHALL** 映射为 Lineman 的 `SOLD_OUT_TODAY` 状态（明天自动恢复）
5. **IF** 未指定 `provider_name` **THEN** 系统 **SHALL** 默认使用 `grab` 处理逻辑

### 技术实现要点

#### 1. Protobuf 修改

```protobuf
// 更新菜单项请求
message UpdateMenuItemReq {
  string merchant_id = 1;                         // Grab MerchantID (必填)
  string item_id = 2;                             // 商品ID (partner item id, 必填)
  optional int64 price = 3;                       // 价格 (minor unit，单位：分)
  optional string available_status = 4;           // 可用状态: AVAILABLE, UNAVAILABLE, UNAVAILABLEHIDE, SOLD_OUT_TODAY
  optional int64 max_stock = 5;                   // 库存数量
  repeated AdvancedPricing advanced_pricings = 6; // 高级定价配置
  repeated Purchasability purchasabilities = 7;   // 购买能力配置
  string request_id = 8;                          // 请求 ID (可选，用于追踪)
  optional string provider_name = 9;              // 平台名称: grab (默认), lineman
}
```

#### 2. 状态映射表

| TTPOS 状态         | Grab 状态         | Lineman 状态    |
|--------------------|-------------------|-----------------|
| AVAILABLE          | AVAILABLE         | AVAILABLE       |
| UNAVAILABLE        | UNAVAILABLE       | SUSPENDED       |
| UNAVAILABLEHIDE    | UNAVAILABLEHIDE   | -（不支持）     |
| SOLD_OUT_TODAY     | -（不支持）       | SOLD_OUT_TODAY  |

#### 3. Lineman API 调用

**Endpoint**: `PUT /v1/partners/{partnerId}/stores/{storeId}/menu/items/status`

**Request Body**:
```json
{
  "menuItems": [
    {
      "id": "partner-item-id",
      "menuStatus": "SUSPENDED"  // or AVAILABLE, SOLD_OUT_TODAY
    }
  ]
}
```

**Response**:
```json
{
  "status": "ok",
  "code": "SUCCESS",
  "message": "Menu status updated"
}
```
