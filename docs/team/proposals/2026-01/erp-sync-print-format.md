## 🎯 背景和动机

### 问题描述

目前 ttpos-erp 模块需要从远程 ERP 系统获取打印格式配置时，运维人员必须手动登录 ERP 后台导出打印格式文档，然后手动保存到本地目录。这个过程繁琐且容易出错，尤其在多站点部署场景下效率极低。

### 业务价值

- 一键同步打印格式配置，减少手动操作时间
- 确保本地配置与 ERP 系统保持一致
- 降低人为操作失误风险
- 提升运维人员工作效率

## 💡 解决方案概述

### 方案描述

在 ttpos-erp 模块新增一个 CLI 指令 `sync-print-format`，类似现有的 `migrate` 指令。该指令通过 `--siteCode` 参数指定站点，自动从 site_code 配置中获取 ERP 地址，然后调用 ERP API 获取所有以 "Wallace" 开头的打印格式文档，并将文档内容保存为 `.json` 文件到 `manifest/printformat/html/` 目录下。

### 核心功能点

1. 通过 `--siteCode` 参数指定目标站点
2. 自动从 site 配置中获取 ERP 地址（参考 erp-migrate 实现）
3. 调用 ERP `/app/print-format` API 获取 "Wallace" 开头的文档列表
4. 将每个文档内容保存为独立的 `.json` 文件（文件名使用文档名称）

## 📝 附录

### User Story（初稿）

**作为** 运维人员
**我想** 通过 CLI 指令一键同步 ERP 打印格式配置
**以便于** 减少手动导出操作，提升工作效率

### AC 验收标准（初稿）

1. **WHEN** 执行 `sync-print-format --siteCode 1` **THEN** 系统 **SHALL** 从指定站点的 ERP 获取所有 "Wallace" 开头的打印格式文档
2. **WHEN** 获取文档成功 **THEN** 系统 **SHALL** 将每个文档保存为 `.json` 文件到 `manifest/printformat/html/` 目录
3. **WHEN** 同步完成 **THEN** 系统 **SHALL** 输出同步结果摘要（成功/失败数量）

### 参考实现

现有 `ErpMigrate` 指令（[cmd.go:47-72](ttpos-bmp/app/ttpos-erp/internal/cmd/cmd.go#L47-L72)）提供了类似的实现模式：
- 通过 `--siteCode` 参数获取站点配置
- 从 context 中传递 site_code
- 调用 service 层执行具体业务逻辑
