## 🎯 背景和动机

### 问题描述

LINE MAN 是泰国主流的外卖配送平台之一,需要通过 OAuth 2.0 Client Credentials 认证方式获取访问令牌,用于后续的 API 调用。目前 ttpos-takeout 模块已经实现了 Grab 平台的 OAuth 认证,但 LINE MAN 的 OAuth Token 接口尚未实现。

**当前状态**:
- LINE MAN OAuth Token 接口定义已存在 (`api/lineman/v1/oauth.go`)
- Controller 层代码已生成但未实现 (`internal/controller/lineman/lineman_v1_o_auth_token.go`)
- 缺少 Logic 层的 Token 生成和管理逻辑

### 业务价值

- 支持 LINE MAN 平台的接入,扩展外卖配送服务覆盖范围
- 为后续 LINE MAN 菜单同步、订单管理等功能提供认证基础
- 复用现有 OAuth 认证架构,降低开发和维护成本
- 提升系统对多平台外卖服务的支持能力

## 💡 解决方案概述

> ⚠️ **临时方案说明**  
> 本方案为临时实现方案,参考现有 Grab OAuth 认证架构快速实现 LINE MAN 平台接入。  
> 后续团队将建设统一的**权限中心单点登录系统**,届时会将所有第三方平台的认证逻辑迁移到统一的 SSO 服务中,实现集中化的认证管理和更好的安全控制。

### 方案描述

参考现有的 Grab OAuth Partner Token 实现方案,为 LINE MAN 实现类似的 OAuth 2.0 Client Credentials 认证流程:

1. **配置管理**: 在 `manifest/config/config.tpl.yaml` 中添加 LINE MAN 配置项,参考 Grab 架构区分 platform 和 partner 配置
2. **Logic 层实现**: 创建 `internal/logic/lineman_token/` 包,实现 Token 生成、验证和配置加载逻辑
3. **Partner 配置加载器**: 实现类似 Grab 的 Partner 配置加载器,支持多商户场景
4. **Service 注册**: 在 `internal/service/` 中注册 LinemanToken 服务接口
5. **Controller 实现**: 完成 `lineman_v1_o_auth_token.go` 的业务逻辑调用
6. **JWT Token 签发**: 使用 JWT 生成符合 LINE MAN 规范的访问令牌

### 核心功能点

1. **OAuth Token 生成**
   - 接收 `grant_type`, `client_id`, `client_secret` 参数
   - 验证客户端凭证的有效性
   - 生成 JWT 格式的 Access Token
   - 返回 `access_token`, `token_type`, `expires_in`

2. **配置管理**
   - 区分 Platform 和 Partner 两级配置架构
   - Platform: 平台级别配置,用于系统与 LINE MAN 平台的认证
   - Partner: 商户级别配置,支持多商户的 client_id/client_secret 管理
   - 配置懒加载和缓存机制,提升性能

3. **Token 验证**
   - 提供 Token 解析和验证方法
   - 用于后续 LINE MAN API 调用的中间件验证

4. **错误处理**
   - 参数验证失败返回标准错误响应
   - 凭证不匹配返回认证失败错误
   - 系统错误返回通用错误信息

### 风险识别

**潜在风险**:
1. LINE MAN OAuth 规范与 Grab 存在差异,可能需要调整 Token 结构
2. 配置管理方式可能需要适配多商户场景
3. Token 有效期和刷新机制需要明确
4. 临时方案可能造成技术债务,后续迁移到统一权限中心时需要额外的迁移成本

**缓解措施**:
1. 先调研 LINE MAN OAuth 官方文档,确认规范差异
2. 复用 Grab 的配置加载器模式,支持动态配置
3. 参考 Grab 的 Token 缓存和刷新机制
4. 在代码中清晰标注临时方案,并在设计文档中规划迁移路径

## 📝 附录

### User Story (初稿)

**作为** 系统管理员  
**我想** 配置 LINE MAN 的 OAuth 认证信息  
**以便于** 系统能够与 LINE MAN 平台进行安全的 API 通信

**作为** LINE MAN 平台  
**我想** 通过 OAuth 2.0 Client Credentials 方式获取访问令牌  
**以便于** 调用 TTPOS 系统提供的菜单和订单管理接口

### AC 验收标准 (初稿)

1. **WHEN** LINE MAN 平台发送 OAuth Token 请求 (包含正确的 client_id 和 client_secret) **THEN** 系统 **SHALL** 返回有效的 access_token 和过期时间
2. **IF** client_id 或 client_secret 不正确 **THEN** 系统 **SHALL** 返回认证失败错误 (HTTP 401)
3. **IF** grant_type 不是 "client_credentials" **THEN** 系统 **SHALL** 返回参数错误 (HTTP 400)
4. **WHEN** 生成的 Token 在有效期内 **THEN** 系统 **SHALL** 能够成功验证该 Token
5. **IF** Token 已过期 **THEN** 系统 **SHALL** 拒绝验证并返回过期错误

### 线框图/原型 (可选)

无需 UI 界面,纯后端 API 实现。
