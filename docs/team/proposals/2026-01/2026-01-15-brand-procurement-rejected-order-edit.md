## 🎯 背景和动机

### 问题描述

当前品牌采购流程中，当单据被驳回后，发起人无法直接基于被驳回的单据进行编辑和重新提交，导致以下问题：

1. **操作繁琐**：发起人需要重新创建新单据，无法复用原有单据信息
2. **信息丢失**：驳回原因和原始单据信息无法关联，发起人需要手动记录驳回原因
3. **无操作留痕**：无法追溯单据的驳回、编辑、重新提交的完整历史
4. **效率低下**：重复填写相同信息，增加操作成本

**示例场景**：
> 门店提交品牌采购申请后，总部审核发现某个商品数量填写错误，驳回单据。门店需要重新创建单据，手动复制商品信息，修改数量后再次提交。整个过程耗时且容易出错。

### 业务价值

解决这个问题能带来以下业务价值：

- ✅ **提升操作效率**：减少重复填写，预计节省 50% 的操作时间
- ✅ **降低错误率**：基于原单据编辑，减少信息遗漏和错误
- ✅ **改善用户体验**：驳回后可直接编辑，流程更顺畅
- ✅ **增强可追溯性**：完整记录驳回、编辑、重提的操作历史
- ✅ **提高审核通过率**：发起人能够根据驳回原因精准修改，减少二次驳回

## 💡 解决方案概述

### 方案描述

在品牌采购单据被驳回后，发起人可以在单据详情页看到"编辑并重新提交"功能。点击后，系统会：

1. **保留原单据信息**：自动加载被驳回单据的所有信息（商品列表、数量、备注等）
2. **显示驳回原因**：在编辑页面顶部显示驳回原因和驳回意见，方便发起人针对性修改
3. **支持编辑修改**：发起人可以修改任意字段（商品、数量、备注等）
4. **重新提交**：修改完成后，可以重新提交审核
5. **操作留痕**：完整记录驳回时间、驳回原因、重新提交时间等操作历史

**核心流程**：
```
单据被驳回 → 发起人查看驳回原因 → 点击"编辑并重新提交" → 
修改单据内容 → 重新提交 → 进入审核流程 → 记录操作历史
```

### 核心功能点

1. **驳回单据编辑入口**
   - 在被驳回的单据详情页显示"编辑并重新提交"按钮
   - 按钮仅在单据状态为"已驳回"时显示
   - 支持权限控制（仅发起人可操作）

2. **驳回信息展示**
   - 在编辑页面顶部显示驳回原因和驳回意见
   - 高亮显示驳回信息，确保发起人能够看到
   - 支持查看驳回历史（多次驳回的情况）

3. **单据编辑功能**
   - 保留原单据的所有信息（商品、数量、备注、仓库等）
   - 支持修改任意字段
   - 支持删除商品、添加商品、修改数量等操作
   - 表单验证规则与原单据创建保持一致

4. **重新提交流程**
   - 编辑完成后，点击"重新提交"按钮
   - 系统验证必填项和业务规则
   - 提交后单据状态变更为"待审核"
   - 通知审核人员有新单据需要审核

5. **操作留痕记录（批注内页）**
   - 在采购申请详情页中新增"批注"内页，用于展示所有操作留痕
   - **记录的操作类型**：
     - **门店通过**：记录通过时间、通过批注信息
     - **门店驳回**：记录驳回时间、驳回批注信息
     - **总部通过**：记录通过时间、通过批注信息
     - **总部驳回**：记录驳回时间、驳回批注信息
     - **重新提交**：记录重新提交时间
   - **展示格式**：按时间倒序排列，每条记录包含操作类型、操作时间、批注信息
   - **数据来源**：基于采购订单操作日志表（`ttpos_purchase_order_log`）的数据展示
   - **完整追溯**：在批注内页中展示完整的操作历史时间线，清晰展示每次操作的时间节点和批注信息

### 风险识别

**潜在风险**：
1. **数据一致性风险**：编辑过程中，原单据可能被其他操作影响（如系统自动处理）
   - **缓解措施**：编辑时锁定单据，或使用版本号机制
2. **操作历史数据量大**：如果记录字段级变更，可能产生大量历史数据
   - **缓解措施**：初期只记录关键操作，字段级变更作为可选功能
3. **权限控制复杂**：需要确保只有发起人可以编辑被驳回的单据
   - **缓解措施**：在 API 和前端都进行权限校验，确保安全性

## 📝 附录

### User Story（初稿）

**作为** 门店采购员  
**我想** 在被驳回的品牌采购单据上直接编辑并重新提交  
**以便于** 快速修正错误，避免重复填写，提高操作效率

**详细说明**：
- **前置条件**：品牌采购单据已被审核人员驳回
- **操作步骤**：
  1. 查看被驳回的单据详情
  2. 查看驳回原因和驳回意见
  3. 点击"编辑并重新提交"按钮
  4. 在编辑页面修改需要调整的内容（商品、数量、备注等）
  5. 点击"重新提交"按钮
  6. 单据重新进入审核流程
- **预期结果**：
  - 单据状态变更为"待审核"
  - 审核人员可以看到完整的操作历史（包括驳回和重新提交记录）
  - 发起人可以随时查看操作历史

### AC 验收标准（初稿）

1. **WHEN** 单据被驳回 **THEN** 发起人在单据详情页 **SHALL** 看到"编辑并重新提交"按钮
2. **IF** 发起人点击"编辑并重新提交" **THEN** 系统 **SHALL** 显示编辑表单，并自动填充原单据的所有信息
3. **IF** 编辑页面打开 **THEN** 系统 **SHALL** 在页面顶部显示驳回原因和驳回意见
4. **WHEN** 发起人修改单据内容并提交 **THEN** 系统 **SHALL** 验证必填项和业务规则
5. **IF** 验证通过 **THEN** 系统 **SHALL** 将单据状态变更为"待审核"，并记录操作历史
6. **WHEN** 用户在采购申请详情页查看单据 **THEN** 系统 **SHALL** 显示"批注"内页（Tab 标签页）
7. **WHEN** 门店审核通过采购申请 **THEN** 系统 **SHALL** 在批注内页中记录：操作类型为"门店通过"、操作时间、通过批注信息（**暂时不记录操作人**）
8. **WHEN** 门店驳回采购申请 **THEN** 系统 **SHALL** 在批注内页中记录：操作类型为"门店驳回"、操作时间、驳回原因、驳回批注信息（**暂时不记录操作人**）
9. **WHEN** 总部审核通过采购申请 **THEN** 系统 **SHALL** 在批注内页中记录：操作类型为"总部通过"、操作时间、通过批注信息（**暂时不记录操作人**）
10. **WHEN** 总部驳回采购申请 **THEN** 系统 **SHALL** 在批注内页中记录：操作类型为"总部驳回"、操作时间、驳回原因、驳回批注信息（**暂时不记录操作人**）
11. **WHEN** 用户重新提交被驳回的采购申请 **THEN** 系统 **SHALL** 在批注内页中记录：操作类型为"重新提交"、操作时间、重新提交批注信息（**暂时不记录操作人**）
12. **WHEN** 用户在批注内页查看操作记录 **THEN** 系统 **SHALL** 按时间倒序展示所有操作记录，每条记录包含操作类型、操作时间、批注信息（**暂时不包含操作人**）
13. **WHEN** 单据有多次驳回和重新提交操作 **THEN** 系统 **SHALL** 在批注内页中展示完整的操作时间线，清晰展示每次操作的时间节点和批注信息
14. **IF** 非发起人尝试编辑被驳回的单据 **THEN** 系统 **SHALL** 拒绝操作并提示权限不足
