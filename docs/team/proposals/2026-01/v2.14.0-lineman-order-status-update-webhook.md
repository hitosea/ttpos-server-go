## 🎯 背景和动机

### 问题描述

LINE MAN 外卖平台在订单配送完成或取消后，需要通过 Webhook 通知商户系统订单状态已变更：

- **订单完成**：骑手完成配送，订单状态变为 `FINISH`
- **订单取消**：顾客或平台取消订单，订单状态变为 `CANCELED`

当前系统已经实现了订单创建（PlaceOrder）和订单内容更新（OrderUpdate）接口，但 **缺少订单状态更新（OrderStatusUpdate）接口的完整实现**。

根据 [LINE MAN API 规范](https://docs.google.com/spreadsheets/d/1CKRl7tRLtp6dCAcXQqWhPvS_0M378-vdKpucR6ZtNbg/edit?gid=102046225#gid=102046225)，LINE MAN 会通过 `POST /v1/partners/{partnerId}/stores/{storeId}/order/status` Webhook 通知商户系统订单状态已变更，商户系统需要：

1. **接收状态通知**：接收 LINE MAN 发送的订单状态变更数据
2. **更新本地订单状态**：将状态同步到 TTPOS 数据库的 `takeout_order` 表
3. **触发业务流程**：通过消息队列（RocketMQ）发送 OrderEvent 通知下游系统（Main 模块）处理状态变更

**特殊处理**：
- LINE MAN 的 `FINISH` 状态需要转换为 TTPOS 内部的 `COMPLETED` 状态
- LINE MAN 的 `CANCELED` 状态保持不变

**示例场景**：
> 顾客在 LINE MAN 下单后，骑手完成配送。LINE MAN 通过 OrderStatusUpdate Webhook 通知 TTPOS 订单状态为 `FINISH`，TTPOS 将状态更新为 `COMPLETED` 并通知 POS 端关闭订单。

### 业务价值

- **订单状态准确性**：确保 TTPOS 系统中的订单状态与 LINE MAN 平台保持一致
- **业务流程完整性**：完善 LINE MAN 订单生命周期管理，支持订单完成和取消场景
- **用户体验提升**：商家能及时了解订单状态变化，减少手动查询和对账工作
- **运营效率提升**：自动化订单状态同步，减少人工干预和错误
- **消息可靠传递**：通过 RocketMQ 确保状态变更事件可靠传递到 Main 模块
- **数据统计准确**：完整的订单状态流转记录，支持订单报表和数据分析

### 目标用户

- [x] 商户管理员（通过后台查看订单状态）
- [x] 收银员（POS 端查看订单完成）
- [ ] 厨房人员
- [ ] 顾客（LINE MAN 用户）
- [x] 其他: **系统集成（BMP ↔️ Main）**

## 💡 解决方案概述

### 方案描述

实现 LINE MAN 订单状态更新 Webhook 接口，参考现有的 Grab 订单处理逻辑：

1. **接收 Webhook 请求**
   - 端点：`POST /v1/partners/{partnerId}/stores/{storeId}/order/status`
   - 验证请求签名（复用 Lineman 认证中间件）
   - 校验请求参数（使用 GoFrame 的验证器）

2. **状态映射转换**
   - LINE MAN `FINISH` → TTPOS `COMPLETED`
   - LINE MAN `CANCELED` → TTPOS `CANCELED`（保持不变）

3. **更新订单状态**
   - 查询现有订单（根据 `orderId` 查找）
   - 更新订单状态字段
   - 更新订单更新时间（`updated_at`）
   - 保存到 `takeout_order` 表

4. **发送 RocketMQ 事件**
   - 构造 `grab.OrderEvent` 消息（复用 Grab 的事件结构）
   - 设置 `action` 为 `"status_update"`
   - 设置 `providerName` 为 `"lineman"`
   - 设置 `status` 为转换后的 TTPOS 状态
   - 发送到 RocketMQ Topic（`takeout_grab_order` 或新建 Lineman Topic）
   - Main 模块监听 RocketMQ 并处理订单状态变更

5. **返回响应**
   - 成功返回 `200` 和 `{"status": "ok", "code": "SUCCESS"}`
   - 失败返回相应错误码（400/404/409/500）

参考代码路径：
- Grab 实现：`ttpos-bmp/app/ttpos-takeout/internal/logic/grab/grab_order.go`
- API 定义：`ttpos-bmp/app/ttpos-takeout/api/lineman/v1/order.go` （已定义 `OrderStatusUpdateReq`）
- Controller 骨架：`ttpos-bmp/app/ttpos-takeout/internal/controller/lineman/lineman_v1_order_status_update.go`

### 核心功能点

1. **分层架构设计**
   - **Controller 层**（`controller/lineman/lineman_v1_order_status_update.go`）
     - 接收请求，调用 Service 层
     - 参数验证（GoFrame 自动验证 `OrderStatusUpdateReq`）
     - 返回统一格式响应（`LinemanCommonResData`）
   
   - **Service 接口**（`service/lineman.go`）
     - 定义 `HandleOrderStatusUpdate` 接口方法
   
   - **Logic 层**（`logic/lineman/lineman_order.go`）
     - 实现 `HandleOrderStatusUpdate` 业务逻辑
     - 状态映射转换（`FINISH` → `COMPLETED`）
     - 查询、更新订单状态
     - 发送 MQ 事件

2. **状态映射逻辑**
   ```go
   // LINE MAN 状态 → TTPOS 状态
   const (
       LinemanStatusFinish   = "FINISH"
       LinemanStatusCanceled = "CANCELED"
   )
   
   func mapLinemanStatusToTTPOS(linemanStatus string) string {
       switch linemanStatus {
       case LinemanStatusFinish:
           return consts.OrderStatusCompleted // "COMPLETED"
       case LinemanStatusCanceled:
           return consts.OrderStatusCanceled  // "CANCELED"
       default:
           return linemanStatus
       }
   }
   ```

3. **订单状态更新逻辑**（Logic 层）
   - 查询现有订单（`dao.Order.Where("provider_order_id = ?").One()`）
   - 幂等性处理（检查当前状态，避免重复更新）
   - 更新订单状态（使用事务确保数据一致性）
     - 更新 `status` 字段为转换后的 TTPOS 状态
     - 更新 `updated_at` 字段为当前时间戳

4. **RocketMQ 事件发送**
   - 复用 `grab.OrderEvent` 结构体
   - Topic：`takeout_grab_order`（复用现有 Topic）
   - Action：`consts.OrderActionStatusUpdate` 或 `"status_update"`
   - Status：转换后的 TTPOS 状态（`COMPLETED` 或 `CANCELED`）
   - ProviderName：`consts.ProviderLineman`
   - 使用 `queue.PushWithContext()` 发送消息

5. **错误处理**
   - 订单不存在：Logic 层返回 error → Controller 返回 `fail` + `404`
   - 订单已完成/取消（幂等性）：Logic 层返回 nil（静默跳过）或返回 `409`
   - 数据库错误：Logic 层返回 error → Controller 返回 `fail` + `500`

### 风险识别

**潜在风险**：
1. **状态映射错误**：如果状态映射逻辑有误，可能导致订单状态不一致
2. **RocketMQ 消息丢失**：如果 RocketMQ 发送失败，Main 模块可能无法感知订单状态变更

   - 发送失败只记录日志，不影响主流程（订单状态已更新）
   - RocketMQ 自带重试机制，确保消息最终送达
3. **幂等性设计**：检查订单当前状态，如果已经是终态（`COMPLETED`/`CANCELED`），则跳过更新
4. **错误处理完善**：订单不存在返回 `404`，重复请求返回 `409` 或 `200`（幂等）

## 📝 附录

### User Story（初稿）

**作为** LINE MAN 外卖平台  
**我想** 通过 Webhook 通知 TTPOS 订单状态已变更（完成或取消）  
**以便于** TTPOS 系统能够同步最新的订单状态并更新商家端显示

**作为** 商家  
**我想** 在 POS/Shop 端自动看到订单完成或取消状态  
**以便于** 无需手动查询 LINE MAN 平台即可了解订单最终状态

### AC 验收标准（初稿）

1. **WHEN** LINE MAN 发送订单状态为 `FINISH` **THEN** TTPOS **SHALL** 将订单状态更新为 `COMPLETED` 并返回 200
2. **WHEN** LINE MAN 发送订单状态为 `CANCELED` **THEN** TTPOS **SHALL** 将订单状态更新为 `CANCELED` 并返回 200
3. **WHEN** 订单不存在 **THEN** TTPOS **SHALL** 返回 404 错误
4. **WHEN** 收到重复的状态通知（订单已是终态）**THEN** TTPOS **SHALL** 返回 409 或 200（幂等性）
5. **WHEN** 订单状态更新成功 **THEN** TTPOS **SHALL** 发送 MQ 事件到 Main 模块
6. **IF** MQ 发送失败 **THEN** TTPOS **SHALL** 记录错误日志但仍返回 200（订单状态已更新）

### 技术实现要点

#### 1. 状态映射（Logic 层）

```go
// LINE MAN 状态常量
const (
    LinemanStatusFinish   = "FINISH"
    LinemanStatusCanceled = "CANCELED"
)

// mapLinemanStatusToTTPOS 将 LINE MAN 状态映射为 TTPOS 内部状态
func mapLinemanStatusToTTPOS(linemanStatus string) string {
    switch linemanStatus {
    case LinemanStatusFinish:
        return consts.OrderStatusCompleted // "COMPLETED"
    case LinemanStatusCanceled:
        return consts.OrderStatusCanceled  // "CANCELED"
    default:
        return linemanStatus // 未知状态保持原样
    }
}

// controller/lineman/lineman_v1_order_status_update.go
func (c *ControllerV1) OrderStatusUpdate(ctx context.Context, req *v1.OrderStatusUpdateReq) (res *v1.OrderStatusUpdateRes, err error) {
    // 调用 Logic 层处理订单状态更新
    err = service.Lineman().HandleOrderStatusUpdate(ctx, req)
    if err != nil {
        // 返回失败响应
        return &v1.OrderStatusUpdateRes{
            LinemanCommonResData: v1.LinemanCommonResData{

                Code:    "500",
                Message: err.Error(),
            },
        }, nil // 返回 nil error，让 GoFrame 返回 HTTP 200

    // 返回成功响应
    return &v1.OrderStatusUpdateRes{
        LinemanCommonResData: v1.LinemanCommonResData{
            Status:  "ok",
            Code:    "200",
            Message: "Order status updated successfully",
        },
    }, nil
}
```

#### 4. Logic 层实现

```go
// logic/lineman/lineman_order.go

// HandleOrderStatusUpdate 处理 LINE MAN 订单状态更新 Webhook
func (s *sLinemanOrder) HandleOrderStatusUpdate(ctx context.Context, req *v1.OrderStatusUpdateReq) error {
    // 1. 状态映射
    ttposStatus := mapLinemanStatusToTTPOS(req.OrderStatus)
    
    // 2. 查询现有订单
    existingOrder, err := dao.Order.Ctx(ctx).
        Where(dao.Order.Columns().ProviderName, consts.ProviderLineman).
        Where(dao.Order.Columns().ProviderOrderId, req.OrderId).
        One()
    if err != nil || existingOrder.IsEmpty() {
        return gerror.New("订单不存在")
    }
    
    // 3. 幂等性检查
    currentStatus := existingOrder["status"].String()
    if currentStatus == ttposStatus {
        g.Log().Infof(ctx, "订单状态未变化，跳过: orderId=%s, status=%s", req.OrderId, ttposStatus)
        return nil
    }
    
    // 4. 更新订单状态
    orderUUID := existingOrder["uuid"].String()
    _, err = dao.Order.Ctx(ctx).Where("uuid", orderUUID).Update(&do.Order{
        Status:    ttposStatus,
        UpdatedAt: gtime.Now().Unix(),
    })
    if err != nil {
        return gerror.Wrap(err, "更新订单状态失败")
    }
    
    // 5. 发送 RocketMQ 事件
    event := &grab.OrderEvent{
        Action:       "status_update",
        ProviderName: consts.ProviderLineman,
        ShopUUID:     existingOrder["shop_uuid"].String(),
        OrderUUID:    orderUUID,
        OrderID:      req.OrderId,
        Status:       ttposStatus,
        Timestamp:    gtime.Now().Unix(),
    }
    if err := queue.PushWithContext(ctx, "takeout_grab_order", event); err != nil {
        // RocketMQ 发送失败只记录日志，不影响主流程（订单状态已更新）
        g.Log().Warningf(ctx, "发送订单状态更新 MQ 事件失败 %s: %v", orderUUID, err)
    }
    
    g.Log().Infof(ctx, "成功更新 LINE MAN 订单状态: %s (UUID: %s) -> %s", 
        req.OrderId, orderUUID, ttposStatus)
    return nil
}
```
