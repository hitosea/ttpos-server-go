## 🎯 背景和动机

### 问题描述

在当前的采购申请审核流程中，总店审核人员在审核采购申请时，如果发现申请单中存在错误（如物品选择错误、数量错误、遗漏物品等），只能选择驳回整个申请单，让申请人重新提交。这种方式导致：

1. **流程往返繁琐**：申请人需要重新编辑申请单，审核人员需要再次审核
2. **效率低下**：简单的错误修正需要经过完整的申请-审核循环
3. **时间成本高**：特别是紧急采购时，流程延迟会影响业务
4. **沟通成本高**：审核人员需要额外沟通说明问题，申请人需要理解并修改

### 业务价值

允许审核人员在审核时直接修改采购申请单，可以带来以下价值：

- **提高审核效率**：审核人员可以直接修正错误，无需驳回重审
- **缩短采购周期**：减少流程往返，加快采购审批速度
- **降低沟通成本**：直接修改替代反复沟通
- **提升用户体验**：审核人员和申请人都能更高效地完成工作
- **优化紧急场景**：紧急采购时可以快速处理

## 💡 解决方案概述

### 方案描述

在采购申请审核页面，为有审批权限的人员提供编辑功能，允许在审核过程中对申请单的物品明细进行修改（删除、搜索、添加）。修改后的申请单可以直接通过审核或驳回，修改内容会同步到子店。

**核心设计理念**：
- **权限控制**：仅对有审批权限的人员开放编辑功能
- **状态限制**：仅在待审核状态（店内审核、总部审核）下允许编辑
- **数据范围限制**：添加物品时，仅显示对应申请的供应商/库存下的物品
- **数据同步**：编辑后的单据内容需同步到子店

### 核心功能点

1. **物品明细删除**：审核人员可以删除申请单中不需要的物品
2. **物品搜索**：支持在供应商/库存物品列表中搜索需要添加的物品
3. **物品添加**：审核人员可以添加遗漏的物品，数据来源限定为对应申请的供应商/库存下的物品
4. **权限校验**：仅对有审批权限的人员显示编辑功能
5. **状态控制**：仅在待审核状态下允许编辑
6. **数据同步**：编辑并通过/驳回后，同步修改内容到子店

## 📊 初步评估

### 技术复杂度

- [ ] **低**：纯 UI 调整，无业务逻辑变更
- [x] **中**：需要前后端联调，基础业务逻辑
- [ ] **高**：涉及架构调整、第三方集成、复杂算法

**复杂度说明**：
- 需要前端实现编辑 UI（删除、搜索、添加）
- 需要后端实现权限校验、状态控制、数据范围限制
- 需要实现数据同步机制（总店→子店）
- 需要处理物品/单位不存在的异常场景

### 风险识别

**潜在风险**：
1. **数据同步一致性**：总店编辑后的内容可能包含子店不存在的物品/单位
2. **权限控制复杂**：需要精确控制不同角色的编辑权限
3. **状态流转逻辑**：编辑后的审核流程可能与原流程冲突
4. **历史记录追溯**：需要记录审核人员的修改操作

**缓解措施**：
1. **数据同步**：在子店收货时，对不存在的物品/单位给出明确提示（参考调拨单）
2. **权限校验**：后端严格校验审批权限，前端仅做 UI 隐藏
3. **状态控制**：仅在待审核状态允许编辑，已通过/已驳回不允许编辑
4. **操作日志**：记录审核人员的修改操作，便于追溯

## 📝 附录

### User Story（初稿）

**作为** 总店审核人员  
**我想** 在审核采购申请时能够修改申请单的物品明细（删除、搜索、添加）  
**以便于** 快速修正申请单中的错误，提高审核效率，减少流程往返

### AC 验收标准（初稿）

1. **WHEN** 有审批权限的人员进入待审核的采购申请单页面 **THEN** 系统 **SHALL** 显示编辑功能（删除、搜索、添加物品）
2. **WHEN** 审核人员点击删除物品 **THEN** 系统 **SHALL** 从申请单中移除该物品
3. **WHEN** 审核人员搜索物品 **THEN** 系统 **SHALL** 在对应申请的供应商/库存下的物品列表中搜索
4. **WHEN** 审核人员添加物品 **THEN** 系统 **SHALL** 仅显示对应申请的供应商/库存下的物品供选择
5. **WHEN** 无审批权限的人员进入审核页面 **THEN** 系统 **SHALL** 不显示编辑功能
6. **WHEN** 采购申请单已审核通过或已驳回 **THEN** 系统 **SHALL** 不允许编辑
7. **WHEN** 采购申请单编辑并通过/驳回后 **THEN** 系统 **SHALL** 将编辑后的单据内容同步到子店
8. **WHEN** 总店添加了一个物品，子店没有同步 **THEN** 子店收货时 **SHALL** 提示"物品（物品编码）未找到"
9. **WHEN** 总店添加了一个单位，子店没有同步 **THEN** 子店收货时 **SHALL** 提示"物品单位（单位名称）未找到"
