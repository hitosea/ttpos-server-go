## 🎯 背景和动机

### 问题描述

当前 `ItemInfo` 消息结构中只有 `stock_uom`（库存单位）和 `purchase_uom`（采购单位），缺少 `sales_uom`（销售单位）字段。这导致无法区分商品的库存单位与销售单位，而在实际业务中，商品的库存单位和销售单位可能不同（如：库存按"箱"计，销售按"瓶"计）。

### 业务价值

- **数据完整性**：保证商品单位信息完整，与 ERP 系统字段对齐
- **业务灵活性**：支持库存单位与销售单位不同的业务场景

### 目标用户

- [x] 系统集成（TTPOS 与 ERP 系统的自动数据同步）

---

## 💡 解决方案概述

### 方案描述

在 `item.proto` 的 `ItemInfo` 消息中新增 `optional string sales_uom` 字段，作为可选字段。修改查询和保存逻辑，使其支持该新字段的读取和写入。

### 核心功能点

1. 在 `ItemInfo` 消息中新增 `optional string sales_uom` 字段
2. `GetItemList` 和 `GetItem` 接口返回 `sales_uom` 字段
3. `SaveItem` 接口支持保存 `sales_uom` 字段

### 影响范围

**涉及终端**：
- [x] ERP 服务（ttpos-erp）

**涉及模块**：
- [x] API 接口（protobuf 定义）
- [x] 业务逻辑（查询和保存逻辑）

## 📝 附录

### User Story（初稿）

**作为** 系统集成服务
**我想** 在商品信息中包含销售单位（sales_uom）字段
**以便于** 支持库存单位与销售单位不同的业务场景，保持与 ERP 系统数据一致

### AC 验收标准（初稿）

1. **WHEN** 调用 `GetItemList` 或 `GetItem` 接口 **THEN** 系统 **SHALL** 返回 `sales_uom` 字段（如果有值）
2. **WHEN** 调用 `SaveItem` 接口并传入 `sales_uom` 字段 **THEN** 系统 **SHALL** 正确保存该字段值
3. **WHEN** 调用 `SaveItem` 接口未传入 `sales_uom` 字段 **THEN** 系统 **SHALL** 保持原有逻辑，不影响其他字段
