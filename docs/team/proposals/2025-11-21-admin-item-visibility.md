## 🎯 背景和动机

### 问题描述

有些库存在门店不能看到，需要设置可见性（如电子设备）。当前系统缺乏对物品可见性的控制机制，导致总部设置的某些物品（如电子设备等特殊库存）在门店端也能看到，这不符合业务需求。

**用户故事**：
> 作为 **总部管理员**，  
> 我想 **控制物品在子店的可见性**，  
> 以便于 **管理特殊库存（如电子设备），避免子店误操作或查看不应该看到的物品**。

### 业务价值

- 提升库存管理精细化程度
- 避免子店误操作特殊物品
- 满足多层级组织架构的权限控制需求
- 提高数据安全性和业务规范性

## 💡 解决方案概述

### 方案描述

在物品管理模块中增加"允许子店可见"设置开关，默认处于开启状态。总部管理员可以根据业务需要，控制物品是否在子店的相关业务模块中显示。当子店进行物品同步操作后，可见性设置才会生效。

### 核心功能点

1. **物品可见性设置**
   - 在物品管理中增加"允许子店可见"开关
   - 默认开启状态，未设置时所有子店可见
   - 仅总店有此设置权限

2. **同步机制**
   - 可见性设置通过物品同步操作生效
   - 开启/关闭仅对新数据生效（已有采购订单、调拨、盘点中的物品不受影响）

3. **业务模块控制**
   - 控制物品在以下模块的可见性：
     - 物品列表
     - 成本卡
     - 采购申请
     - 采购收货
     - 品牌采购
     - 品采收货
     - 盘点单
     - 调拨单
     - 库存查询
     - 出入库明细表

4. **批量操作**
   - 支持批量设置可见/不可见
   - 支持批量筛选可见/不可见物品
   - 逻辑与批量停用/开启保持一致

5. **操作提示**
   - 关闭时弹窗提示影响范围
   - 开启时弹窗提示影响范围
   - 明确告知同步前后状态差异

6. **业务逻辑保持**
   - 可见性控制不影响原有业务流程
   - 仅控制显示，不控制可用性

### 风险识别

**潜在风险**：
1. 同步机制可能影响现有业务流程
2. 已有数据（采购订单、调拨、盘点）的处理逻辑需要明确
3. 批量操作可能影响大量数据，需要性能优化

**缓解措施**：
1. 明确同步机制：仅对新数据生效，已有数据不受影响
2. 充分测试各种业务场景，确保不影响现有流程
3. 批量操作增加确认提示，并考虑分批处理

## 📝 附录

### User Story（初稿）

**作为** 总部管理员  
**我想** 控制物品在子店的可见性  
**以便于** 管理特殊库存（如电子设备），避免子店误操作或查看不应该看到的物品

### AC 验收标准（初稿）

1. **WHEN** 总部在物品管理中设置"允许子店可见"为开启 **THEN** 系统 **SHALL** 默认该状态为开启，所有子店可见该物品

2. **WHEN** 总部将物品设置为允许子店可见（开启） **THEN** 子店同步后 **SHALL** 在相关业务模块中正常显示该物品

3. **WHEN** 总部将物品设置为不允许子店可见（关闭） **THEN** 子店同步后 **SHALL** 在物品列表、成本卡、采购申请、采购收货、品牌采购、品采收货、盘点单、调拨单、库存查询、出入库明细表中均不可见该物品

4. **WHEN** 总部关闭"允许子店可见" **THEN** 系统 **SHALL** 弹窗提示：关闭后，门店在同步前仍可见该物品，但子店完成同步操作后，物品列表、成本卡、采购申请、采购收货、品牌采购、品采收货、盘点单、调拨单、库存查询、出入库明细表均不可见该物品。确定要关闭吗？

5. **WHEN** 总部开启"允许子店可见" **THEN** 系统 **SHALL** 弹窗提示：开启后，门店在同步前仍不可见该物品，但子店完成同步操作后，物品列表、成本卡、采购申请、采购收货、品牌采购、品采收货、盘点单、调拨单、库存查询、出入库明细表均可见该物品。确定要开启吗？

6. **WHEN** 总部进行批量设置 **THEN** 系统 **SHALL** 支持批量设置可见与不可见（同批量停用/开启逻辑一致）以及可批量筛选可见与不可见物品

7. **WHEN** 总部开启/关闭可见性 **THEN** 系统 **SHALL** 仅对新数据生效（采购订单、调拨、盘点已有物品则不进行隐藏）

8. **WHEN** 总部开启/关闭可见性 **THEN** 系统 **SHALL** 仅为可见/不可见（非不可用），保持原有的业务流程
