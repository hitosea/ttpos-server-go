## 🎯 背景和动机

### 问题描述

当前物品可见性控制粒度不够，只能在单个物品级别设置"允许子店可见"（`allowSubstoreVisible` 字段）。这种方式存在以下问题：

1. **管理成本高**：需要逐个物品设置可见性，物品数量多时操作繁琐
2. **无法按角色区分**：同一门店的不同角色无法看到不同的物品范围
3. **业务场景受限**：无法实现"建材只能由工程经理查看，设备只能区域经理查看"等精细化权限控制

### 业务价值

- 实现分类级别的权限管控，大幅降低配置成本
- 支持按门店角色精细化控制物品可见范围
- 提升物品管理的安全性和规范性
- 减少误操作风险（员工只能看到职责范围内的物品）

### 目标用户

- [x] 商户管理员（总店管理员配置可见性规则）
- [x] 店长（子店查看可见范围内的物品）
- [x] 服务员（子店各角色员工按配置查看物品）

## 💡 解决方案概述

### 方案描述

新增「可见性配置」功能，允许总店管理员按「物品类别 + 门店角色」组合配置可见性规则。配置保存后自动同步到所有子店生效。

核心逻辑：
- 用户所有角色都未被任何配置包含 → 可见全部物品类别（向后兼容）
- 用户有任意角色被配置包含 → 仅可见已配置角色的类别并集（白名单模式）

### 核心功能点

1. **可见性配置管理**：总店管理员在参数设置中新增/编辑/删除可见性配置
2. **物品类别选择**：支持多选物品类别，选中的类别对配置的角色可见
3. **门店角色选择**：支持"全部门店角色"或"部分门店角色"（跨库查询各子店实际角色）
4. **配置同步**：保存时立即推送到所有子店数据库
5. **可见性过滤**：在物品管理、成本卡、库存查询、调拨单、盘点单、采购申请、品牌采购等模块应用过滤逻辑

### 风险识别

**潜在风险**：
1. 跨库查询性能：获取所有子店角色可能涉及大量数据库连接
2. 同步一致性：总店保存时推送到多个子店，可能存在部分失败
3. 向后兼容：旧数据迁移和逻辑切换可能影响现有用户

**缓解措施**：
1. 角色数据缓存 + 分批查询
2. 异步同步 + 重试机制 + 同步状态监控
3. 默认"全部可见"保持向后兼容，渐进式切换

## 📝 附录

### User Story（初稿）

**作为** 总店管理员
**我想** 按物品类别和门店角色配置可见性规则
**以便于** 实现精细化的物品权限管控，让不同角色只能看到职责范围内的物品

### AC 验收标准（初稿）

#### 需求1：可见性配置管理入口

1. **WHEN** 总店管理员进入参数设置页面 **THEN** 系统 **SHALL** 显示"可见性配置"模块入口
2. **WHEN** 总店管理员点击"可见性配置" **THEN** 系统 **SHALL** 跳转到可见性配置列表页
3. **WHEN** 可见性配置列表页显示 **THEN** 系统 **SHALL** 展示所有已创建的配置，格式：`{配置名称} | {角色数量}角色 | {类别数量}类别可见`
4. **WHEN** 总店管理员点击"新增"按钮 **THEN** 系统 **SHALL** 跳转到新增可见性配置页面
5. **WHEN** 总店管理员点击某个配置项 **THEN** 系统 **SHALL** 跳转到编辑可见性配置页面
6. **WHEN** 总店管理员删除某个配置 **THEN** 系统 **SHALL** 提示确认，确认后删除配置并刷新列表

#### 需求2：新增/编辑可见性配置表单

**2.1 配置名称**
1. **WHEN** 总店管理员进入新增/编辑页面 **THEN** 系统 **SHALL** 显示"名称"输入框，标注为必填项
2. **WHEN** 名称为空或超过100字符 **THEN** 系统 **SHALL** 显示错误提示

**2.2 物品类别选择**
1. **WHEN** 总店管理员点击"物品类别"配置项 **THEN** 系统 **SHALL** 跳转到物品类别选择页面，支持搜索和多选
2. **WHEN** 选择完成后点击"保存" **THEN** 系统 **SHALL** 返回表单页面，回显"已选择 (X)"

**2.3 门店角色选择**
1. **WHEN** 总店管理员点击"门店角色"配置项 **THEN** 系统 **SHALL** 弹出选择菜单："全部门店角色"或"部分门店角色"
2. **WHEN** 选择"部分门店角色" **THEN** 系统 **SHALL** 跳转到门店角色选择页面（按门店分组展示各子店的实际角色）
3. **WHEN** 选择完成 **THEN** 系统 **SHALL** 回显"已选择 (全部)"或"已选择 (X)"

**2.4 保存配置**
1. **WHEN** 点击"保存"按钮 **THEN** 系统 **SHALL** 校验必填项并调用 API 保存
2. **WHEN** 保存成功 **THEN** 系统 **SHALL** 立即同步到所有子店数据库，显示成功提示并返回列表页

#### 需求3：可见性判断逻辑

1. **WHEN** 用户所有角色都未被任何可见性配置包含 **THEN** 系统 **SHALL** 显示全部物品类别（默认行为）
2. **WHEN** 用户有任意角色被可见性配置包含 **THEN** 系统 **SHALL** 仅显示已配置角色的可见类别并集
3. **WHEN** 某物品类别未出现在任何配置中，但用户角色被其他配置包含 **THEN** 系统 **SHALL** 不显示该类别（白名单模式）

#### 需求4：盘点场景特殊处理

1. **WHEN** 盘点类型为"全部物品盘点/日盘/周盘/月盘" **THEN** 系统 **SHALL** 显示所有物品类别，不受可见性配置限制
2. **WHEN** 盘点类型为"指定物品盘点" **THEN** 系统 **SHALL** 根据可见性配置过滤物品类别

#### 需求5：旧功能下线

1. **WHEN** 总店管理员编辑/添加物品 **THEN** 系统 **SHALL** 不再显示"允许子店可见"配置项
2. **WHEN** 系统判断物品可见性 **THEN** 系统 **SHALL** 仅根据新的可见性配置判断，不再使用 `allowSubstoreVisible` 字段
