## 🎯 背景和动机

### 问题描述

当前新管理端（Shop 端）首页只能查看当前登录门店的数据，多店管理员需要切换账号才能查看其他门店的经营数据，操作繁琐且效率低下。

### 业务价值

- **管理效率提升**：管理员可在同一界面快速切换查看多门店数据，无需反复登录切换账号
- **决策效率提升**：快速了解各门店经营情况，及时调整运营策略
- **操作体验改善**：减少繁琐的账号切换操作，提升用户满意度

### 目标用户

- [x] 多店管理员（区域经理/运营经理）
- [x] 商户老板
- [x] 运营人员

---

## 💡 解决方案概述

### 方案描述

在新管理端首页顶部增加门店选择下拉框（单选），门店列表沿用门店汇总统计的权限逻辑（用户没有权限查看的门店不显示）。在现有 3 个首页统计接口增加 `company_uuid` 参数，切换门店时保持当前时间范围不变，显示加载动画后重新加载数据。

### 核心功能点

1. **门店选择下拉框**：首页顶部显示门店选择器，沿用门店汇总统计的权限逻辑过滤可见门店
2. **接口扩展**：在现有 3 个首页统计接口增加 `company_uuid` 参数支持查询指定门店数据
3. **数据切换**：切换门店时保持时间范围，显示加载动画，完成后更新页面数据

### 影响范围

**涉及终端**：
- [x] Shop 商家管理端

**涉及模块**：
- [x] UI 组件（门店下拉选择器）
- [x] API 接口（增加 company_uuid 参数）
- [ ] 数据模型
- [x] 业务逻辑（门店权限过滤）

**涉及接口**（增加 `company_uuid` 参数）：
1. `/shop/statistics/business` - 统计营业数据，移动管理端首页-店内概况
2. `/shop/statistics/area` - 统计区域，移动管理端首页-区域数据
3. `/shop/statistics/product_rank` - 统计商品排行，移动管理端首页-销量、销售额排行

### 风险识别

**潜在风险**：
1. 接口增加 company_uuid 参数后需确保权限校验与门店列表一致
2. 数据量大时门店列表加载可能较慢

**缓解措施**：
1. 门店列表沿用门店汇总统计的权限逻辑，接口层校验传入的 company_uuid 是否在用户权限范围内
2. 门店列表通常数量有限，可考虑前端缓存

## 📝 附录

### User Story（初稿）

**作为** 多店管理员/商户老板
**我想** 在首页通过下拉框切换查看不同门店的数据
**以便于** 快速了解各门店经营情况，提升管理效率

### AC 验收标准（初稿）

1. **WHEN** 用户登录 Shop 端 **THEN** 首页顶部显示门店选择下拉框 **SHALL** 展示有权限的子店列表

2. **WHEN** 用户切换门店 **THEN** 时间范围选择保持不变 **SHALL** 使用当前时间范围重新加载数据

3. **WHEN** 用户切换门店 **THEN** 显示加载动画 **SHALL** 数据加载完成后更新页面
