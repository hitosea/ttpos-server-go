## 🎯 背景和动机

### 问题描述

当前外卖订单统计存在时间不精确的问题：
- 订单统计时间固定使用接单时间
- 但实际业务中，订单完成时间可能与接单时间相差较大
- 例如：订单在 1 点接单，2 点完成，当前统计会将订单归入 1-2 点时段，但实际应归入 2-3 点时段

这导致统计数据无法准确反映实际业务完成时段，影响运营决策准确性。

### 业务价值

- 提高统计准确性：最终统计数据精确反映实际完成时段
- 实时监控能力：订单接单时即可在统计中看到，便于实时监控
- 兼顾实时性和准确性：未完成订单按接单时间统计（实时），完成后调整到完成时间（准确）

## 💡 解决方案概述

### 方案描述

调整外卖订单统计的**查询逻辑**（不修改数据记录），实现「实时监控 + 最终准确」的双重目标：

- **查询时**根据订单状态判断使用哪个时间字段进行筛选：
  - 订单未完成：使用接单时间（`accepted_time`）
  - 订单已完成：使用完成时间（`completed_time`）

例如：查询 1-2 点的订单统计
- 订单 A：1:30 接单，未完成 → 命中（按 accepted_time 匹配）
- 订单 B：1:30 接单，2:15 完成 → 不命中（按 completed_time 匹配，属于 2-3 点）
- 订单 C：0:30 接单，1:15 完成 → 命中（按 completed_time 匹配）

### 核心功能点

1. 修改订单统计查询逻辑，根据订单状态动态选择时间字段
2. 未完成订单：WHERE accepted_time BETWEEN start AND end
3. 已完成订单：WHERE completed_time BETWEEN start AND end

## 📝 附录

### User Story（初稿）

**作为** 店长/运营人员
**我想** 外卖订单统计能够在未完成时实时显示，完成后按完成时间准确归类
**以便于** 既能实时监控订单处理情况，又能获得准确的时段统计数据

### AC 验收标准（初稿）

1. **WHEN** 查询某时段订单统计 **AND** 订单未完成 **THEN** 系统 **SHALL** 按接单时间匹配时段
2. **WHEN** 查询某时段订单统计 **AND** 订单已完成 **THEN** 系统 **SHALL** 按完成时间匹配时段
3. **IF** 订单 1:30 接单、2:15 完成 **THEN** 查询 1-2 点统计 **SHALL** 不包含该订单
4. **IF** 订单 1:30 接单、2:15 完成 **THEN** 查询 2-3 点统计 **SHALL** 包含该订单
