## 🎯 背景和动机

### 问题描述

当前多门店数据同步只能逐个门店手动执行，存在以下痛点：

1. **效率低下**：只能单个门店执行同步，需要多次重复操作
2. **缺少批量入口**：没有统一的批量同步命令或界面，运维人员需要逐一操作每个门店

### 业务价值

- **提升运维效率**：一次操作完成多门店同步，大幅减少手动操作时间
- **降低运维成本**：减少人工介入，降低人力成本
- **降低操作错误率**：避免逐个手动操作带来的遗漏和失误
- **改善数据一致性**：确保多门店数据同步状态一致

## 💡 解决方案概述

### 方案描述

开发一个 CLI 命令行工具，支持指定多个门店（company_uuid）进行批量数据同步。脚本将并行执行同步任务，同时控制并发数量避免系统过载。同步失败的门店会有明确的记录和反馈，便于后续重试处理。

同步逻辑本身已有现成方法，本方案主要是封装一个命令行入口，复用现有同步方法。

### 核心功能点

1. **CLI 命令行接口**：支持通过命令行参数指定门店列表
2. **并行同步执行**：多门店并发执行同步，提升效率
3. **并发控制**：控制最大并发数，避免系统资源过载
4. **失败记录与反馈**：同步失败的门店有明确记录，支持重试

## 📝 附录

### User Story（初稿）

**作为** 运维人员
**我想** 通过 CLI 命令一次性同步多个门店的数据
**以便于** 提升运维效率，降低操作成本和错误率

### AC 验收标准（初稿）

1. **WHEN** 运维人员执行批量同步命令并指定门店列表 **THEN** 系统 **SHALL** 并行执行各门店同步任务
2. **WHEN** 同步完成 **THEN** 系统 **SHALL** 显示每个门店的同步结果（成功/失败）
3. **WHEN** 某门店同步失败 **THEN** 系统 **SHALL** 记录失败门店并继续执行其他门店同步
