## 🎯 背景和动机

### 问题描述

当前收银端和点餐助手在结账时仅支持优惠券和积分抵扣，缺少满减营销活动的支持。商户需要更灵活的营销手段来吸引顾客消费，例如"消费满100减10元"、"每满200减30元"等阶梯满减活动。

**用户痛点**：
- 商户无法在收银端直接使用满减营销活动
- 需要手动计算满减金额，容易出错
- 无法实时查看活动状态和可用性
- 活动规则变更时无法及时感知

### 业务价值

- **提升营销灵活性**：支持满减、每满减等多种营销活动类型
- **提高收银效率**：自动计算满减金额，减少人工计算错误
- **增强用户体验**：实时显示活动状态，清晰展示活动规则
- **促进消费增长**：通过满减活动刺激顾客消费，提高客单价

## 💡 解决方案概述

### 方案描述

在收银端和点餐助手的结账页面增加【活动】选项，支持选择满减/每满减营销活动。系统自动计算活动抵扣金额，并在结账时进行验证和核销。活动信息会显示在结账单、预结账单和发票中。

**核心功能**：
1. 结账页面显示可用满减活动列表
2. 根据订单金额和活动规则自动计算抵扣金额
3. 活动状态实时校验（有效期、适用时段、满减条件）
4. 活动与优惠券、积分抵扣的互斥规则处理.活动满减与优惠券只能二选一
5. 活动信息记录到订单和打印单据中

### 核心功能点

1. **活动列表展示**
   - 显示有效日期内的满减活动
   - 根据适用时段和满减条件显示活动状态（可用/置灰）
   - 活动排序：可用时间范围内显示在前，不在可用时间范围内的活动在后

2. **活动选择与验证**
   - 单笔订单只能使用一个营销活动
   - 选择活动后，其他活动置灰不可选
   - 实时验证活动有效性（有效期、时段、满减条件）
   - 活动信息变更时提示重新确认
   - 结账完成时进行二次确认活动有效性和是否满足活动要求

3. **金额计算与互斥规则**
   - 自动计算活动抵扣金额（满减/每满减）
   - 活动抵扣金额不能超过订单金额（负数时显示为0）
   - 与会员折扣、积分抵扣的互斥处理,可以在会员折扣、积分抵扣后进行满减,但选择满减之后积分不再自动抵扣;更换会员后自动取消满减活动选择
   - 与抹零规则的兼容处理,可以在满减之后进行结账抹零

4. **活动核销与记录**
   - 结账时验证活动有效性
   - 记录活动抵扣金额到订单表
   - 活动抵扣金额不计入会员累计消费
   - 订单操作日志记录活动使用信息

**工作量分解**：

- 前端开发（UI组件、交互逻辑）：3-4 天
- 测试与联调：2-3 天

### 风险识别

**潜在风险**：
1. **活动规则复杂度**：阶梯满减、每满减等规则计算逻辑复杂，容易出错
2. **并发控制**：活动核销时的并发控制，防止重复使用
3. **数据一致性**：活动信息变更时，已选择活动的订单如何处理
4. **性能影响**：活动列表查询和验证可能影响结账页面加载速度

**缓解措施**：
1. **规则计算**：建立完善的测试用例，覆盖各种满减场景
2. **并发控制**：使用分布式锁和数据库事务保证数据一致性
3. **数据一致性**：在结账完成时重新验证活动有效性，变更则提示用户
4. **性能优化**：使用缓存优化活动列表查询，异步处理非关键验证

## 📝 附录

### User Story（初稿）

**作为** 收银员  
**我想** 在结账时选择满减营销活动  
**以便于** 自动计算活动抵扣金额，提高收银效率和准确性

**作为** 商户管理员  
**我想** 在收银端使用满减营销活动  
**以便于** 通过灵活的营销手段吸引顾客消费，提高客单价

### AC 验收标准（初稿）

基于任务详情中的需求，整理关键验收标准：

1. **WHEN** 进入结账页面 **THEN** 系统 **SHALL** 显示有效日期内的满减活动列表
2. **IF** 活动不在适用时段内 **THEN** 系统 **SHALL** 置灰显示，不可选择
3. **IF** 订单金额未达到满减条件 **THEN** 系统 **SHALL** 置灰显示，不可选择
4. **IF** 已选择一个活动 **THEN** 系统 **SHALL** 将其他活动置灰，不可同时选择多个
5. **IF** 活动信息发生变更 **THEN** 系统 **SHALL** 提示"活动信息已经变更，请重新确认"
6. **IF** 活动抵扣金额大于订单金额 **THEN** 系统 **SHALL** 最终应收金额为0，不显示负数
7. **IF** 选择活动后变更会员折扣/积分抵扣 **THEN** 系统 **SHALL** 提示活动规则已失效，取消活动选择
8. **IF** 积分抵扣后最终应收为0 **THEN** 系统 **SHALL** 不可选择满减活动
9. **IF** 订单已部分支付 **THEN** 系统 **SHALL** 所有活动不可点击（置灰）
10. **IF** 使用活动抵扣并结账完成 **THEN** 系统 **SHALL** 在结账单、预结账单、发票中显示活动抵扣金额
11. **IF** 使用活动抵扣并结账完成 **THEN** 系统 **SHALL** 活动抵扣金额不计入会员累计消费金额
12. **IF** 使用活动抵扣 **THEN** 系统 **SHALL** 在订单操作日志中记录活动名称和抵扣金额

### 技术实现要点（来自任务详情）

#### 数据库设计

1. **sale_order 表增加字段**：
   - `activity_amount`: 满减活动抵扣金额（结账完成后记录）
   - `full_reduction_activity_uuid`: 订单使用的满减活动UUID
   - `full_reduction_activity_message`: 满减规则信息（如"满200减20"）

2. **sale_bill 表增加字段**：
   - `activity_amount`: 满减活动抵扣金额（所有sale_order的满减扣减金额总和）

#### API 接口设计

1. **修改"获取结账页面信息"接口** (`GET /cashier/desk/order/payment/info`)
   - 增加"满减活动"列表
   - 每个活动item包含：活动多语言名称、满减类型、开始日期、结束日期等
   - 不显示已结束和已失效的活动
   - 不在适用时段内的活动显示但置灰
   - 未达到满减金额的活动置灰

2. **新增"选择或取消适用满减活动"接口** (`POST /cashier/desk/order/payment/activity`)
   - 选择活动
   - 取消活动
   - 替换活动

3. **修改"完成结账"接口** (`POST /cashier/desk/order/payment/finish`)
   - 检查所选活动是否有效
   - 如果无效则提示"活动信息已经变更，请重新确认"

4. **修改"反结账"接口**
   - 反结账时清空 `full_reduction_activity_uuid` 和 `full_reduction_activity_message` 字段

#### 业务逻辑要点

1. **活动抵扣金额计算**：
   - 如果扣减金额大于订单金额，则最终扣减金额为订单金额
   - 如果小于，则最终扣减金额为活动的扣减金额

2. **活动排序规则**：
   - 在可用时间范围内显示在前
   - 不在可用时间范围内的活动显示在后

3. **活动互斥规则**：
   - 与会员折扣、积分抵扣互斥
   - 选择活动后，变更会员折扣/积分抵扣会取消活动选择

4. **拆单场景**：
   - 拆单1使用满减活动，拆单2和3可再继续使用满减活动

5. **免单场景**：
   - 已选择活动但未结账，进行免单并结账操作，正常免单结账完成（此时订单未使用活动）
