## 🎯 背景和动机

### 问题描述

当前商家缺乏灵活的营销活动管理能力，无法通过满减优惠来吸引顾客消费，提升客单价和营业额。商家需要一个简单易用的满减营销功能，能够灵活设置不同档次的满减规则，并在管理端统一管理这些活动。

### 业务价值

- 提升商家营销能力，通过满减活动吸引顾客消费
- 提高客单价，通过阶梯满减引导顾客增加消费金额
- 增强顾客粘性，通过优惠活动提升顾客满意度
- 灵活的活动管理，支持多种满减规则和时段设置

## 💡 解决方案概述

### 方案描述

在新管理端（Shop）工作台增加【营销活动】入口，支持创建和管理满减营销活动。活动支持阶梯满减和循环满减两种模式，可设置活动日期、活动时间（全天或特定时段），并支持活动的编辑、失效和删除操作。

### 核心功能点

1. **营销活动入口**：工作台增加【营销活动】入口
2. **活动列表展示**：按添加顺序排序，显示活动名称、状态（进行中/未开始/已结束）、活动日期、活动时间
3. **添加促销活动**：
   - 活动名称（1-50字符）
   - 活动日期（开始日期和结束日期，不可选择以前的日期）
   - 活动时间（全天或特定时间段，24小时制）
   - 活动规则（阶梯满减/循环满减）
     - 阶梯满减：可设置多个满减档次（最多20项），按最高档次满减
     - 循环满减：设置满减基数和减价金额，每满足一个基数即减价
   - 满减金额范围：0.01-999999.99
4. **活动编辑**：
   - 未保存退出提示
   - 进行中活动编辑确认提示
   - 失效活动功能（手动设置为已结束状态）
5. **活动删除**：已结束/未开始的活动可删除，进行中的活动不可删除

### 风险识别

**潜在风险**：
1. 活动规则计算逻辑复杂，需要确保阶梯满减和循环满减的计算准确性
2. 活动状态判断需要考虑时区问题，确保在不同时区下状态判断正确
3. 进行中活动的编辑可能影响未结账订单，需要明确处理规则

**缓解措施**：
1. 详细设计活动规则计算逻辑，编写单元测试覆盖各种场景
2. 使用商户设置的时区进行时间判断，确保时间计算的准确性
3. 编辑进行中活动时明确提示影响范围，并记录操作日志

## 📝 附录

### User Story（初稿）

**作为** 商户管理员  
**我想** 创建和管理满减营销活动  
**以便于** 通过优惠活动吸引顾客消费，提升客单价和营业额

### AC 验收标准（初稿）

1. **WHEN** 商户管理员在工作台点击【营销活动】 **THEN** 系统 **SHALL** 显示活动列表页面
2. **IF** 商户管理员创建新活动 **THEN** 系统 **SHALL** 验证活动名称（1-50字符）、活动日期（不可选择以前的日期）、适用时间(如9:00-10:00)、活动规则（至少一个规则，满减金额范围0.01-999999.99）
3. **WHEN** 商户管理员保存阶梯满减活动 **THEN** 系统 **SHALL** 自动按金额从小到大排序规则
4. **IF** 商户管理员编辑进行中的活动 **THEN** 系统 **SHALL** 弹出确认提示，说明编辑后未结账订单将使用新规则
5. **WHEN** 商户管理员删除活动 **THEN** 系统 **SHALL** 仅允许删除未开始、已结束、已失效的活动

### 技术实现要点

#### 数据库设计

1. **活动实体表**
   - 活动名称（多语言，使用 `multi_language_name_uuid` 关联）
   - 活动日期开始时间（时间戳，精确到当天 00:00:00，使用商户时区）
   - 活动日期结束时间（时间戳，精确到当天 23:59:59，使用商户时区）
   - 适用时间开始时间（字符串，如 "09:00"）
   - 适用时间结束时间（字符串，如 "22:00"）
   - 满减方式（0=阶梯满减，1=循环满减）
   - 是否失效（1=失效，0=未失效，默认0）

2. **满减规则表**
   - 阈值（decimal 22,4，如满200减20中的200）
   - 扣减值（decimal 22,4，如满200减20中的20）
   - 活动uuid（关联活动实体）

#### 接口设计

1. **活动列表接口**
   - 过滤条件：status（全部/进行中/未开始/已结束）
   - 响应字段：活动多语言名称、满减方式、活动状态、活动日期、活动可用时段

2. **添加活动接口**
   - 参数：活动多语言名称、活动日期时间戳、适用时间字符串、满减方式、规则数组
   - 约束：活动名称1-50字符、活动日期不可选择以前日期、至少一个规则、满减金额范围验证

3. **活动详情接口**
   - 参数：活动uuid
   - 响应：完整的活动信息和规则列表

4. **活动编辑保存接口**
   - 参数：活动uuid + 活动信息
   - 约束：已结束和已失效的活动不可编辑

5. **删除活动接口**
   - 参数：活动uuid
   - 约束：只能删除未开始、已结束、已失效的活动

6. **失效活动接口**
   - 参数：活动uuid
   - 约束：只能失效进行中的活动

#### 开发步骤

1. 在 `shop_01.sql` 设计创建活动表、活动规则表
2. 创建数据库迁移文件
3. 实现 Go 业务逻辑
