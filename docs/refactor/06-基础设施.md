## 二、监控告警体系

### 2.1 技术选型：Prometheus + Grafana

**架构：**
```
Main Service
    ↓ /metrics
Prometheus (采集)
    ↓
Grafana (可视化)
    ↓
AlertManager (告警)
```

### 2.2 核心指标定义

**RED指标（请求维度）：**
```
1. Rate (QPS)
   ttpos_http_requests_total

2. Errors (错误率)
   ttpos_http_errors_total / ttpos_http_requests_total

3. Duration (延迟)
   ttpos_http_request_duration_seconds
```

**USE指标（资源维度）：**
```
1. Utilization (CPU/内存使用率)
2. Saturation (队列长度)
3. Errors (错误计数)
```

**业务指标：**
```
• ttpos_order_created_total      (订单创建总数)
• ttpos_order_amount_total       (订单金额总计)
• ttpos_desk_occupied            (桌台占用数)
• ttpos_inventory_low            (库存预警数)
```

### 2.3 告警规则

**关键告警：**
```yaml
groups:
  - name: ttpos_alerts
    rules:
      # 错误率告警
      - alert: HighErrorRate
        expr: rate(ttpos_http_errors_total[5m]) / rate(ttpos_http_requests_total[5m]) > 0.01
        for: 5m
        labels:
          severity: critical
        annotations:
          summary: "错误率超过1%"
      
      # 响应时间告警
      - alert: HighLatency
        expr: histogram_quantile(0.99, rate(ttpos_http_request_duration_seconds_bucket[5m])) > 0.5
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "P99延迟超过500ms"
      
      # 服务不可用告警
      - alert: ServiceDown
        expr: up{job="ttpos-main"} == 0
        for: 1m
        labels:
          severity: critical
        annotations:
          summary: "服务不可用"
```

## 三、API网关

### 3.1 技术选型：APISIX

**选型理由：**
```
✓ 高性能（基于Nginx + Lua）
✓ 动态配置（无需重启）
✓ 丰富插件（限流、熔断、认证）
✓ 国内社区活跃（Apache项目）
✓ 支持gRPC、HTTP/2
```

### 3.2 核心功能

**1. 统一鉴权**
```yaml
routes:
  - uri: /api/v1/cashier/*
    plugins:
      jwt-auth:
        key: "ttpos-jwt-key"
        algorithm: "HS256"
```

**2. 限流保护**
```yaml
plugins:
  limit-req:
    rate: 100          # 每秒100次
    burst: 200         # 突发200次
    key: "remote_addr" # 按IP限流
```

**3. 熔断降级**
```yaml
plugins:
  api-breaker:
    break_response_code: 503
    max_breaker_sec: 30
    unhealthy:
      http_statuses: [500, 503]
      failures: 3
    healthy:
      successes: 3
```

**4. 灰度发布**
```yaml
routes:
  - uri: /api/v1/order/*
    upstream:
      nodes:
        "main-v1:8080": 90  # 90%流量
        "main-v2:8080": 10  # 10%流量
      type: weighted
```

## 四、消息队列

### 4.1 技术选型：RabbitMQ

**选型理由：**
```
✓ 可靠性高（持久化、确认机制）
✓ 运维成熟（监控、管理界面）
✓ 支持多种模式（Direct、Topic、Fanout）
✓ 社区活跃
✓ 满足当前需求（QPS<10000）
```

**vs Kafka（为什么不选）：**
```
Kafka优势：
• 高吞吐（QPS>100000）
• 持久化存储

Kafka劣势：
• 运维复杂
• 资源消耗大
• 功能过剩（当前不需要）

结论：当前规模（QPS<10000），RabbitMQ足够
```

### 4.2 交换机设计

**Topic Exchange（推荐）：**
```
Exchange: ttpos.events
    ↓
Routing Key: order.created.v1
    ↓
Queue: message_service_queue
    ↓
Consumer: Message Service

Routing Key: order.created.v1
    ↓
Queue: analytics_service_queue
    ↓
Consumer: Analytics Service
```

**好处：**
- 一个事件可以被多个服务消费
- 支持通配符订阅（order.*）
- 解耦生产者和消费者

### 4.3 可靠性保证

**发布端：**
```go
// 1. 开启Confirm模式
channel.Confirm(false)

// 2. 发布消息
err := channel.PublishWithContext(ctx,
    "ttpos.events",      // Exchange
    "order.created.v1",  // Routing Key
    true,                // Mandatory
    false,               // Immediate
    amqp.Publishing{
        DeliveryMode: amqp.Persistent,  // 持久化
        ContentType:  "application/json",
        Body:         messageBody,
    },
)

// 3. 等待确认
if confirm := <-channel.NotifyPublish(); !confirm.Ack {
    log.Error("message not acked")
}
```

**消费端：**
```go
// 1. 手动ACK
channel.Qos(1, 0, false)  // prefetch=1

msgs, _ := channel.Consume(
    "message_service_queue",
    "",
    false,  // 手动ACK
    false,
    false,
    false,
    nil,
)

for msg := range msgs {
    // 2. 处理消息
    err := processMessage(msg)
    
    if err == nil {
        // 3. 成功：ACK
        msg.Ack(false)
    } else {
        // 4. 失败：Nack，重新入队
        msg.Nack(false, true)
    }
}
```

**死信队列：**
```go
// 主队列配置
args := amqp.Table{
    "x-dead-letter-exchange": "ttpos.dlx",
    "x-max-retries":          3,
}

// 消费失败3次后进入死信队列
// 人工处理或记录日志
```

## 六、日志系统

### 6.1 结构化日志

**日志格式：**
```json
{
  "timestamp": "2025-01-15T10:30:00Z",
  "level": "INFO",
  "service": "ttpos-main",
  "trace_id": "3c9f2e1a4b5d6e7f",
  "company_uuid": 123,
  "user_id": 456,
  "message": "order created",
  "order_id": 789,
  "amount": 100.50
}
```

**日志级别：**
```
DEBUG   详细调试信息
INFO    关键操作记录
WARN    警告信息（不影响业务）
ERROR   错误信息（影响业务）
FATAL   致命错误（服务不可用）
```

### 6.2 日志采集（可选）

**方案1：ELK Stack**
```
Main → Filebeat → Logstash → Elasticsearch → Kibana
```

**方案2：Loki（轻量级，推荐）**
```
Main → Promtail → Loki → Grafana
```

**优势：**
- 资源占用少
- 与Grafana集成
- 查询简单
- 适合中小规模
