# Desk 实体模型说明

## 基本信息

- **实体名称**: Desk
- **表名**: desk
- **所属模块**: model
- **描述**: 桌台实体，用于管理餐厅桌台信息和状态

### 被关联关系

## 数据流分析

### 数据来源
- 餐厅管理系统创建的桌台信息
- 桌台布局配置数据
- QR码生成系统

### 数据流向
1. **桌台创建流程**:
   - 餐厅管理员创建桌台
   - 设置桌台基本信息和容量
   - 配置桌台位置和尺寸
   - 生成桌台二维码
   - 设置桌台状态

2. **桌台状态管理流程**:
   - 客户就座时更新为occupied
   - 客户离座时更新为idle
   - 预定时更新为reserved
   - 清洁时更新为cleaning
   - 故障时更新为disabled

3. **桌台合并流程**:
   - 选择可合并的桌台
   - 设置合并组标识
   - 更新合并状态
   - 处理合并订单

4. **二维码管理流程**:
   - 生成桌台专用二维码
   - 二维码绑定桌台信息
   - 客户扫码识别桌台
   - 二维码过期和更新

### 业务场景
- 餐厅桌台管理
- 桌台状态实时监控
- 客户扫码点餐
- 桌台合并和拆分
- 桌台布局可视化

## 索引建议

- 主键索引: ID
- 唯一索引: Uuid
- 唯一索引: CompanyUuid + DeskNo（公司内编号唯一）
- 普通索引: CompanyUuid（公司查询）
- 普通索引: RegionUuid（区域查询）
- 普通索引: DeskType（桌台类型查询）
- 普通索引: Status（状态筛选）
- 普通索引: MergeGroup（合并组查询）
- 普通索引: SortOrder（排序查询）
- 普通索引: Capacity（容量查询）

## WebSocket推送

### AfterUpdate钩子
- **桌台状态推送**: 当桌台状态变更时，推送到相关终端
- **桌台信息推送**: 当桌台信息变更时，推送到前端

### 推送目标
- **收银端**: 桌台状态更新、订单分配
- **移动端**: 桌台可用性查询、扫码点餐
- **厨房端**: 新订单桌台通知
- **管理端**: 桌台使用率统计、状态监控

## 业务方法

### IsAvailable() bool
- **功能**: 判断桌台是否可用
- **返回**: 是否可用
- **用途**: 预订和就座验证

### CanSeat(customerCount int) bool
- **功能**: 判断是否可容纳指定人数
- **参数**: 客户数量
- **返回**: 是否可容纳
- **用途**: 客户就座验证

### GetOccupiedTime() int64
- **功能**: 获取占用时长
- **返回**: 占用时长（秒）
- **用途**: 使用率统计

### GetMergeableDesks() []Desk
- **功能**: 获取可合并的桌台
- **返回**: 可合并桌台列表
- **用途**: 桌台合并建议

### GetDistance(otherDesk *Desk) float64
- **功能**: 计算与另一桌台的距离
- **参数**: 另一桌台
- **返回**: 距离
- **用途**: 桌台布局优化

### UpdateStatus(status string) error
- **功能**: 更新桌台状态
- **参数**: 新状态
- **返回**: 错误信息
- **用途**: 状态管理

## 注意事项

1. **多租户支持**: 通过CompanyUuid实现数据隔离
2. **状态一致性**: 桌台状态需要与订单状态保持一致
3. **二维码安全**: 桌台二维码需要定期更新防止滥用
4. **位置精度**: 坐标和尺寸信息需要准确用于平面图
5. **合并逻辑**: 桌台合并需要考虑容量和位置因素
6. **实时同步**: 通过WebSocket确保桌台状态实时更新
7. **容量验证**: 客户数量需要在桌台容量范围内

## 业务规则

1. **编号唯一性**: 桌台编号在公司内必须唯一
2. **容量限制**: 客户数量不能超过最大容量
3. **状态流转**: 桌台状态需要按照业务规则流转
4. **合并限制**: 只有相邻或特定类型的桌台才能合并
5. **二维码绑定**: 每个桌台只能绑定一个有效二维码
6. **位置约束**: 桌台位置不能重叠
7. **预定管理**: 预定桌台需要设置预定时间
