# ERPNext 价格清单精度处理方案

> 解决 ERPNext 导入价格清单时，单价过小（如 0.00025）导致四舍五入变为 0.00 的问题

---

## 一、问题描述

在 ERPNext 中导入价格清单时，如果单价过小（例如 0.00025），导入后系统可能会因为精度限制而将其四舍五入为 0.00，导致价格数据丢失。

### 问题场景

- **单价示例**：0.00025 元/件
- **导入结果**：0.00 元/件
- **影响**：价格数据不准确，影响后续业务计算

---

## 二、解决方案

### 方案一：调整 ERPNext 货币精度设置（推荐）

这是最直接和根本的解决方案，通过调整 ERPNext 系统的货币精度设置来支持更小的单价。

#### 操作步骤

1. **登录 ERPNext 系统**
   - 进入 ERPNext 管理后台

2. **调整货币精度**
   - 导航路径：`设置` → `会计` → `货币`
   - 选择需要调整的货币（如 CNY、THB、USD 等）
   - 编辑货币设置，找到 `小数位数`（Decimal Places）字段
   - 将小数位数从默认的 2 位调整为 **6 位**或更高
   - 保存设置

3. **调整价格清单精度**
   - 导航路径：`设置` → `会计` → `价格清单`
   - 选择需要使用的价格清单
   - 检查价格清单的精度设置
   - 确保价格清单支持足够的小数位数

#### 注意事项

- ⚠️ **影响范围**：调整货币精度会影响所有使用该货币的文档和报表
- ⚠️ **数据一致性**：调整后需要重新导入之前因精度问题丢失的数据
- ✅ **推荐设置**：对于需要处理极小单价的情况，建议设置为 **6 位小数**

---

### 方案二：调整价格单位（业务层面）

如果无法调整系统精度设置，可以通过调整价格单位来避免精度问题。

#### 实现方式

将单价单位扩大，例如：

- **原单价**：0.00025 元/件
- **调整后**：0.025 元/100件 或 0.25 元/1000件

#### 操作步骤

1. **确定调整倍数**
   - 根据最小单价确定需要扩大的倍数
   - 例如：0.00025 → 0.025（扩大 100 倍）

2. **调整价格清单数据**
   - 在导入前，将所有单价乘以调整倍数
   - 同时调整对应的单位（如：件 → 100件）

3. **在业务逻辑中处理**
   - 在使用价格时，需要除以调整倍数还原实际单价
   - 确保所有相关计算都考虑单位换算

#### 优缺点

- ✅ **优点**：不需要修改系统设置，适用于所有 ERPNext 版本
- ❌ **缺点**：需要在业务逻辑中处理单位换算，增加复杂度

---

### 方案三：API 导入时确保精度（技术层面）

如果通过 API 导入价格清单，可以在代码层面确保精度。

#### 实现方式

在调用 ERPNext API 时，使用字符串格式传递价格，避免浮点数精度问题。

#### 代码示例

```go
// 示例：创建价格清单项
type PriceListItem struct {
    ItemCode string  `json:"item_code"`
    PriceListRate string `json:"price_list_rate"`  // 使用字符串格式
    // 或者
    PriceListRate float64 `json:"price_list_rate"` // 使用 float64，但确保精度
}

// 方法1：使用字符串格式（推荐）
func formatPrice(price float64) string {
    return fmt.Sprintf("%.6f", price)  // 保留6位小数
}

// 方法2：使用 decimal 库确保精度
import "github.com/shopspring/decimal"

func formatPriceDecimal(price float64) string {
    d := decimal.NewFromFloat(price)
    return d.StringFixed(6)  // 保留6位小数
}
```

#### 在项目中的应用

如果项目中有通过 API 创建价格清单项的逻辑，可以参考以下方式：

```go
// 在构建价格清单项数据时
priceListItem := map[string]interface{}{
    "item_code": itemCode,
    "price_list_rate": fmt.Sprintf("%.6f", price),  // 使用字符串格式，保留6位小数
    // 其他字段...
}
```

---

### 方案四：数据导入前预处理

在导入数据前，对价格数据进行预处理，确保精度。

#### 实现方式

1. **Excel 导入前处理**
   - 在 Excel 中，将价格列格式设置为"数值"，小数位数设置为 6 位或更高
   - 确保价格数据以文本格式存储，避免 Excel 自动四舍五入

2. **CSV 导入前处理**
   - 在 CSV 文件中，价格字段使用字符串格式
   - 确保小数点后保留足够的位数

3. **程序化导入前处理**
   - 在导入脚本中，对价格数据进行格式化
   - 使用高精度数值类型（如 `decimal.Decimal`）处理价格

## 三、推荐方案选择

根据实际情况选择最适合的方案：

| 方案 | 适用场景 | 优先级 |
|------|---------|--------|
| **方案一：调整货币精度** | 可以修改 ERPNext 系统设置 | ⭐⭐⭐⭐⭐ |
| **方案二：调整价格单位** | 无法修改系统设置，业务可接受单位换算 | ⭐⭐⭐ |
| **方案三：API 精度处理** | 通过 API 导入，可以修改代码 | ⭐⭐⭐⭐ |
| **方案四：数据预处理** | 批量导入，可以预处理数据 | ⭐⭐⭐ |

## 四、实施建议

### 1. 立即处理

- ✅ **优先尝试方案一**：调整 ERPNext 货币精度设置
- ✅ **如果方案一不可行**：考虑方案三（API 精度处理）或方案四（数据预处理）

### 2. 长期优化

- ✅ **统一精度标准**：在项目中统一价格精度处理方式
- ✅ **文档记录**：记录价格精度设置和单位换算规则
- ✅ **测试验证**：导入后验证价格数据是否正确

### 3. 预防措施

- ✅ **数据验证**：在导入前验证价格数据是否符合精度要求
- ✅ **错误提示**：如果价格过小，提示用户检查精度设置
- ✅ **日志记录**：记录价格导入过程，便于排查问题

## 六、常见问题

### Q1: 调整货币精度会影响现有数据吗？

**A**: 不会影响现有数据，但会影响显示格式。建议在调整前备份数据。

### Q2: 如果价格单位调整了，如何确保业务逻辑正确？

**A**: 需要在所有使用价格的地方添加单位换算逻辑，并编写测试用例验证。

### Q3: API 导入时使用字符串格式，ERPNext 会接受吗？

**A**: 是的，ERPNext API 接受字符串格式的数值字段，这样可以避免浮点数精度问题。

### Q4: 最小支持多少位小数？

**A**: ERPNext 默认支持 2 位小数，可以调整到 6 位或更高。建议根据实际业务需求设置。
