# ERPNext 公司权限配置指南

> 详细说明如何在 ERPNext 中配置用户只能看到他所在公司的文档（如报损单、销售订单等）

---

## 一、权限配置概述

### 1.1 权限隔离机制

ERPNext 通过 **User Permission（用户权限）** 机制实现公司级别的数据隔离：

- **用户权限**：控制用户可以访问哪些公司的数据
- **角色权限**：控制用户可以对文档执行哪些操作（读取、创建、编辑、删除等）
- **两者结合**：用户只能看到有权限的公司数据，且只能执行角色允许的操作

### 1.2 报损单说明

在 ERPNext 中，报损单通常对应以下文档类型：

- **Stock Entry（库存单据）**：类型为 `Material Issue`（物料发放）或 `Material Receipt`（物料接收）
- **Stock Reconciliation（库存盘点）**：用于库存调整和盘点

---

## 二、配置步骤

### 2.1 步骤 1：创建用户权限（User Permission）⭐ 关键步骤

这是最关键的配置，用于限制用户只能访问特定公司的数据。

#### 导航路径

```
主页 → 设置（Settings） → 用户和权限（Users and Permissions） → 用户权限（User Permissions）
```

或者直接访问：`/app/user-permission`

#### 配置步骤

1. **点击"新建"按钮**创建新的用户权限

2. **填写用户权限信息**：

```
用户权限配置：
├─ 用户（User）：选择需要限制权限的用户账号
├─ 允许（Allow）：选择"公司"（Company）
├─ 适用于（For Value）：选择该用户所属的公司名称
└─ 是否默认（Is Default）：✅ 是（如果该用户只属于一个公司）
```

**配置示例**：

| 字段 | 值 | 说明 |
|------|-----|------|
| **用户** | `user@example.com` | 需要限制权限的用户 |
| **允许** | `Company` | 固定选择"公司" |
| **适用于** | `Company A` | 用户所属的公司名称 |
| **是否默认** | ✅ 是 | 如果用户只属于一个公司，勾选此项 |

3. **保存并提交**用户权限

#### 重要说明

- ⚠️ **一个用户可以配置多个公司权限**：如果用户需要访问多个公司，需要为每个公司创建一条用户权限记录
- ⚠️ **"是否默认"字段**：如果用户只属于一个公司，建议勾选"是"；如果用户属于多个公司，只能有一个默认公司
- ⚠️ **公司名称必须准确**：确保"适用于"字段中的公司名称与 ERPNext 中实际的公司名称完全一致（区分大小写）

---

### 2.2 步骤 2：配置角色权限（Role Permissions）

配置用户角色对报损单的操作权限。

#### 导航路径

```
主页 → 设置（Settings） → 用户和权限（Users and Permissions） → 角色权限管理器（Role Permissions Manager）
```

或者直接访问：`/app/role-permissions-manager`

#### 配置报损单（Stock Entry）权限

**角色：Stock User（库存用户）**

```
角色名称：Stock User
文档类型：Stock Entry（库存单据）

权限配置：
✅ 读取（Read）：是
✅ 创建（Create）：是
✅ 写入（Write）：是（仅限 Draft 状态）
✅ 提交（Submit）：是
✅ 取消（Cancel）：是（仅限 Draft 状态）
✅ 删除（Delete）：是（仅限 Draft 状态）
```

**角色：Stock Manager（库存经理）**

```
角色名称：Stock Manager
文档类型：Stock Entry（库存单据）

权限配置：
✅ 读取（Read）：是
✅ 创建（Create）：是
✅ 写入（Write）：是（所有状态）
✅ 提交（Submit）：是
✅ 取消（Cancel）：是（所有状态）
✅ 删除（Delete）：是（仅限 Draft 状态）
✅ 修改已提交（Amend）：是（如果需要）
```

#### 配置库存盘点（Stock Reconciliation）权限

**角色：Stock User（库存用户）**

```
角色名称：Stock User
文档类型：Stock Reconciliation（库存盘点）

权限配置：
✅ 读取（Read）：是
✅ 创建（Create）：是
✅ 写入（Write）：是（仅限 Draft 状态）
✅ 提交（Submit）：是
✅ 取消（Cancel）：是（仅限 Draft 状态）
```

---

### 2.3 步骤 3：为用户分配角色

确保用户被分配了正确的角色。

#### 导航路径

```
主页 → 设置（Settings） → 用户和权限（Users and Permissions） → 用户（Users）
```

或者直接访问：`/app/user/{user_email}`

#### 配置步骤

1. **打开用户详情页面**
2. **在"角色"（Roles）部分**，添加相应的角色：
   - `Stock User`：普通库存用户
   - `Stock Manager`：库存经理（如果需要更多权限）
3. **保存**用户配置

---

### 2.4 步骤 4：验证权限配置

#### 验证步骤

1. **使用配置好的用户账号登录 ERPNext**

2. **访问报损单列表**：
   ```
   主页 → 库存（Stock） → 库存单据（Stock Entry）
   ```

3. **验证权限**：
   - ✅ 用户应该只能看到"公司"字段等于其权限中配置的公司的报损单
   - ✅ 用户应该无法看到其他公司的报损单
   - ✅ 用户创建新报损单时，"公司"字段应该默认显示为用户权限中的公司

4. **测试操作权限**：
   - ✅ 测试是否可以创建新的报损单
   - ✅ 测试是否可以编辑草稿状态的报损单
   - ✅ 测试是否可以提交报损单
   - ✅ 测试是否可以取消已提交的报损单（如果角色有权限）

## 三、权限配置原理

### 3.1 权限过滤机制

ERPNext 的权限过滤机制：

```
用户访问文档列表时：
1. ERPNext 首先检查用户的"用户权限"（User Permissions）
2. 获取用户有权限访问的公司列表
3. 在查询文档时，自动添加公司过滤条件：
   WHERE company IN (用户有权限的公司列表)
4. 用户只能看到这些公司的文档
```

### 3.2 权限继承

- **用户权限**：控制数据访问范围（哪些公司的数据）
- **角色权限**：控制操作权限（可以执行哪些操作）
- **两者结合**：用户只能对有权限的公司数据执行角色允许的操作

## 四、常见问题

### Q1: 用户配置了公司权限，但仍然可以看到其他公司的报损单？

**可能原因**：

1. **用户权限未提交**：用户权限创建后需要"提交"（Submit），否则不会生效
2. **公司名称不匹配**：检查"适用于"字段中的公司名称是否与 ERPNext 中实际的公司名称完全一致
3. **用户有多个公司权限**：如果用户配置了多个公司的权限，用户可以看到所有配置的公司数据
4. **用户是系统管理员**：系统管理员（System Manager）角色通常可以访问所有数据

**解决方案**：

1. 检查用户权限状态，确保已提交
2. 检查公司名称是否完全匹配（区分大小写）
3. 如果用户不应该访问其他公司，删除其他公司的用户权限
4. 检查用户角色，确保不是系统管理员

---

### Q2: 用户无法创建报损单？

**可能原因**：

1. **角色权限不足**：用户角色没有"创建"（Create）权限
2. **公司权限未配置**：用户没有配置公司权限，导致无法选择公司

**解决方案**：

1. 在"角色权限管理器"中，确保用户角色对 Stock Entry 有"创建"权限
2. 配置用户权限，确保用户至少有一个公司的权限

---

### Q3: 用户可以看到报损单，但无法编辑？

**可能原因**：

1. **文档状态限制**：报损单可能已经提交（Submitted），角色权限可能只允许编辑草稿（Draft）状态
2. **角色权限不足**：用户角色没有"写入"（Write）权限

**解决方案**：

1. 检查报损单状态，如果是已提交状态，需要先取消才能编辑
2. 在"角色权限管理器"中，检查用户角色是否有"写入"权限，以及是否限制了状态

---

### Q4: 如何让用户只能看到特定类型的报损单（如只看到 Material Issue）？

**解决方案**：

ERPNext 的用户权限机制是基于"公司"的，不能直接基于文档类型或子类型进行过滤。

如果需要限制用户只能看到特定类型的报损单，可以考虑：

1. **方案一**：使用自定义权限规则（Custom Permissions）
   - 需要开发自定义脚本，在查询时添加类型过滤条件

2. **方案二**：使用工作流（Workflow）
   - 通过工作流控制不同用户对不同类型报损单的操作权限

3. **方案三**：使用自定义视图（Custom Views）
   - 创建自定义列表视图，默认过滤特定类型的报损单

---

### Q5: 如何批量配置多个用户的公司权限？

**解决方案**：

1. **方案一**：使用 ERPNext 的导入功能
   - 导出用户权限模板
   - 批量填写用户和公司信息
   - 导入到 ERPNext

2. **方案二**：使用 ERPNext API
   - 通过 API 批量创建用户权限记录

3. **方案三**：使用脚本
   - 编写 Python 脚本，通过 ERPNext API 批量创建用户权限

## 五、配置示例

### 5.1 场景：单个用户，单个公司

**需求**：用户 `user@example.com` 只能看到公司 `Company A` 的报损单

**配置步骤**：

1. **创建用户权限**：
   ```
   用户：user@example.com
   允许：Company
   适用于：Company A
   是否默认：✅ 是
   ```

2. **分配角色**：
   ```
   用户：user@example.com
   角色：Stock User
   ```

3. **配置角色权限**：
   ```
   角色：Stock User
   文档类型：Stock Entry
   读取：✅ 是
   创建：✅ 是
   写入：✅ 是
   提交：✅ 是
   ```

---

### 5.2 场景：单个用户，多个公司

**需求**：用户 `manager@example.com` 可以看到公司 `Company A` 和 `Company B` 的报损单

**配置步骤**：

1. **创建用户权限（第一条）**：
   ```
   用户：manager@example.com
   允许：Company
   适用于：Company A
   是否默认：✅ 是（选择其中一个作为默认）
   ```

2. **创建用户权限（第二条）**：
   ```
   用户：manager@example.com
   允许：Company
   适用于：Company B
   是否默认：❌ 否
   ```

3. **分配角色**：
   ```
   用户：manager@example.com
   角色：Stock Manager
   ```

---

### 5.3 场景：批量配置多个用户

**需求**：为 10 个用户配置公司 `Company A` 的权限

**配置步骤**：

1. **准备 CSV 文件**（用户权限导入模板）：

```csv
user,allow,for_value,is_default
user1@example.com,Company,Company A,1
user2@example.com,Company,Company A,1
user3@example.com,Company,Company A,1
...
```

2. **导入到 ERPNext**：
   - 导航到：设置 → 数据导入 → 导入用户权限
   - 上传 CSV 文件
   - 执行导入

## 七、注意事项

### 7.1 权限配置顺序

建议按照以下顺序配置权限：

1. ✅ 先配置用户权限（User Permissions）- 确定用户可以访问哪些公司
2. ✅ 再配置角色权限（Role Permissions）- 确定用户可以执行哪些操作
3. ✅ 最后分配角色给用户（Assign Roles to User）

### 7.2 权限测试

配置完成后，务必：

1. ✅ 使用配置的用户账号登录测试
2. ✅ 验证只能看到有权限的公司数据
3. ✅ 验证可以执行角色允许的操作
4. ✅ 验证无法执行角色不允许的操作

### 7.3 权限维护

定期检查：

1. ✅ 用户权限是否正确（用户是否还在该公司）
2. ✅ 角色权限是否需要调整
3. ✅ 是否有用户需要新增或删除公司权限
