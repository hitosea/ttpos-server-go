# ERPNext 供应商高级设置指南

> 📖 **用途**: 详细说明如何在 ERPNext 中设置供应商的税务信息、引荐人、分类、认证人、信用限额等高级属性

---

## 一、概述

### 1.1 供应商高级设置包含的内容

在 ERPNext 中，供应商（Supplier）主数据除了基本信息（名称、地址、联系方式等）外，还包含以下高级设置：

| 设置项 | 字段名 | 用途 | 是否必填 |
|--------|--------|------|----------|
| **税务信息** | `tax_id`、`tax_category` | 供应商的税务登记号和税类 | 可选 |
| **引荐人** | `referrer` | 引荐该供应商的员工或联系人 | 可选 |
| **供应商分类** | `supplier_group` | 供应商分组，用于分类管理 | 必填 |
| **认证人/审批人** | `on_hold`、`hold_type` | 供应商是否被暂停及原因 | 可选 |
| **信用限额** | `credit_limit` | 供应商的信用额度限制 | 可选 |
| **付款条件** | `payment_terms` | 供应商的付款条件 | 可选 |
| **默认货币** | `default_currency` | 与供应商交易的默认货币 | 可选 |
| **默认价格表** | `default_price_list` | 供应商的默认价格表 | 可选 |

### 1.2 业务价值

- ✅ **税务合规**：正确设置税务信息，确保发票和税务报表准确
- ✅ **供应商管理**：通过分类和信用限额，有效管理供应商风险
- ✅ **审批控制**：通过认证人设置，控制供应商的使用权限
- ✅ **财务控制**：通过信用限额，防止超额度采购

## 二、税务信息设置（Tax）

### 2.1 税务登记号（Tax ID）

#### 通过 UI 设置

1. **打开供应商主数据**
   - 导航路径：`采购（Buying） → 供应商（Supplier） → 新建（New）`
   - 或编辑现有供应商：`采购 → 供应商 → 选择供应商`

2. **填写税务信息**
   - 在供应商表单中，找到"税务信息"（Tax Information）部分
   - **税务登记号**（Tax ID）：输入供应商的税务登记号，例如：`123456789012345`
   - **税类**（Tax Category）：选择供应商的税类（需要先在系统中创建税类）

3. **保存供应商**

#### 通过 API 设置

```python
# 创建供应商并设置税务信息
POST /api/resource/Supplier
{
    "supplier_name": "Supplier A - Company",
    "supplier_group": "本地供应商",
    "tax_id": "123456789012345",
    "tax_category": "标准税率"
}
```

### 2.2 税类（Tax Category）

税类需要在系统中预先创建，用于定义供应商的税率类型。

#### 创建税类

1. **导航路径**：
   ```
   会计（Accounting） → 税类（Tax Category） → 新建（New）
   ```

2. **填写税类信息**：
   - **税类名称**（Tax Category Name）：例如 `标准税率`、`免税`、`零税率`
   - **税率**（Tax Rate）：例如 `13%`、`0%`
   - **描述**（Description）：税类的说明

3. **保存税类**

#### 在供应商中使用税类

在创建或编辑供应商时，在"税务信息"部分选择已创建的税类。

**注意**：
- 税类主要用于采购发票的自动计算
- 如果供应商有多个税类，可以在采购发票中手动选择

## 三、引荐人设置（Referrer）

### 3.1 什么是引荐人

引荐人是指介绍或推荐该供应商的员工或联系人。设置引荐人有助于：
- 追踪供应商来源
- 评估引荐效果
- 管理供应商关系

### 3.2 通过 UI 设置引荐人

1. **打开供应商主数据**

2. **找到"其他信息"（Other Information）部分**

3. **填写引荐人信息**：
   - **引荐人**（Referrer）：选择员工或联系人
   - 如果系统中没有该员工，需要先创建员工或联系人

4. **保存供应商**

### 3.3 通过 API 设置引荐人

```python
# 设置供应商引荐人
PUT /api/resource/Supplier/Supplier-A-Company
{
    "referrer": "EMP-001"  # 员工编码或联系人名称
}
```

**注意**：
- 引荐人可以是员工（Employee）或联系人（Contact）
- 如果引荐人是员工，使用员工编码
- 如果引荐人是联系人，使用联系人名称

## 四、供应商分类设置（Supplier Group）

### 4.1 什么是供应商分类

供应商分类（Supplier Group）用于对供应商进行分组管理，例如：
- 按地区分类：本地供应商、外地供应商、海外供应商
- 按类型分类：原材料供应商、服务供应商、设备供应商
- 按规模分类：大型供应商、中型供应商、小型供应商

### 4.2 创建供应商分类

#### 通过 UI 创建

1. **导航路径**：
   ```
   采购（Buying） → 供应商分类（Supplier Group） → 新建（New）
   ```

2. **填写分类信息**：
   - **供应商分类名称**（Supplier Group Name）：例如 `本地供应商`
   - **父分类**（Parent Supplier Group）：可选，用于创建分类层级
   - **描述**（Description）：分类的说明

3. **保存分类**

#### 通过 API 创建

```python
# 创建供应商分类
POST /api/resource/Supplier Group
{
    "supplier_group_name": "本地供应商",
    "parent_supplier_group": "",  # 可选，父分类
    "description": "本地供应商分类"
}
```

### 4.3 在供应商中设置分类

#### 通过 UI 设置

1. **打开供应商主数据**

2. **在基本信息部分**：
   - **供应商分类**（Supplier Group）：**必填字段**，从下拉列表中选择分类

3. **保存供应商**

#### 通过 API 设置

```python
# 创建供应商并设置分类
POST /api/resource/Supplier
{
    "supplier_name": "Supplier A - Company",
    "supplier_group": "本地供应商"  # 必填
}
```

**注意**：
- 供应商分类是**必填字段**，创建供应商时必须选择
- 如果系统中没有合适的分类，需要先创建分类

## 五、认证人/审批人设置（Approver / On Hold）

### 5.1 什么是供应商认证

供应商认证用于控制供应商是否可以被使用。当供应商被"暂停"（On Hold）时：
- 无法创建新的采购订单
- 无法创建新的采购发票
- 需要审批人解除暂停后才能使用

### 5.2 通过 UI 设置供应商暂停

1. **打开供应商主数据**

2. **找到"其他信息"（Other Information）部分**

3. **设置暂停状态**：
   - **暂停**（On Hold）：勾选此选项，暂停供应商
   - **暂停类型**（Hold Type）：选择暂停原因，例如：
     - `质量问题`（Quality Issue）
     - `付款问题`（Payment Issue）
     - `合同到期`（Contract Expired）
     - `其他`（Other）
   - **暂停原因**（Hold Reason）：详细说明暂停原因

4. **保存供应商**

### 5.3 解除供应商暂停

1. **打开供应商主数据**

2. **取消勾选"暂停"（On Hold）选项**

3. **保存供应商**

### 5.4 通过 API 设置

```python
# 暂停供应商
PUT /api/resource/Supplier/Supplier-A-Company
{
    "on_hold": 1,  # 1=暂停，0=正常
    "hold_type": "质量问题",
    "hold_reason": "供应商提供的产品质量不符合要求"
}

# 解除暂停
PUT /api/resource/Supplier/Supplier-A-Company
{
    "on_hold": 0
}
```

### 5.5 审批人设置

在某些 ERPNext 配置中，可能需要设置供应商的审批人（Approver），用于审批与该供应商相关的采购订单。

**注意**：
- 审批人通常通过工作流（Workflow）配置，而不是直接在供应商中设置
- 如果需要在供应商级别设置审批人，可能需要自定义字段

## 六、信用限额设置（Credit Limit）

### 6.1 什么是信用限额

信用限额（Credit Limit）是指供应商允许的最大未付款金额。当供应商的未付款金额超过信用限额时：
- 系统会发出警告
- 可能需要审批才能继续采购

### 6.2 通过 UI 设置信用限额

1. **打开供应商主数据**

2. **找到"财务信息"（Financial Information）部分**

3. **填写信用限额**：
   - **信用限额**（Credit Limit）：输入金额，例如 `100000.00`
   - **货币**（Currency）：选择货币，例如 `CNY`（人民币）

4. **保存供应商**

### 6.3 通过 API 设置

```python
# 设置供应商信用限额
PUT /api/resource/Supplier/Supplier-A-Company
{
    "credit_limit": 100000.00,
    "default_currency": "CNY"
}
```

### 6.4 信用限额的使用

**系统自动检查**：
- 创建采购订单时，系统会检查供应商的未付款金额
- 如果超过信用限额，系统会发出警告
- 根据系统配置，可能需要审批才能继续

**查看供应商未付款金额**：
1. 打开供应商主数据
2. 在"财务信息"部分，可以看到：
   - **未付款金额**（Outstanding Amount）
   - **信用限额**（Credit Limit）
   - **可用信用额度**（Available Credit Limit）= 信用限额 - 未付款金额

## 七、付款条件设置（Payment Terms）

### 7.1 什么是付款条件

付款条件（Payment Terms）定义了与供应商的付款方式和期限，例如：
- `货到付款`（Cash on Delivery）
- `30天付款`（Net 30）
- `月结`（Monthly Payment）

### 7.2 创建付款条件

#### 通过 UI 创建

1. **导航路径**：
   ```
   会计（Accounting） → 付款条件（Payment Terms） → 新建（New）
   ```

2. **填写付款条件信息**：
   - **付款条件名称**（Payment Terms Name）：例如 `30天付款`
   - **描述**（Description）：付款条件的说明
   - **付款条件详情**（Payment Terms Details）：
     - **付款方式**（Mode of Payment）：例如 `银行转账`、`现金`
     - **付款期限**（Due Days）：例如 `30`（30天后付款）
     - **付款比例**（Invoice Portion）：例如 `100%`（全额付款）

3. **保存付款条件**

### 7.3 在供应商中设置付款条件

#### 通过 UI 设置

1. **打开供应商主数据**

2. **找到"财务信息"（Financial Information）部分**

3. **选择付款条件**：
   - **付款条件**（Payment Terms）：从下拉列表中选择

4. **保存供应商**

#### 通过 API 设置

```python
# 设置供应商付款条件
PUT /api/resource/Supplier/Supplier-A-Company
{
    "payment_terms": "30天付款"
}
```

**注意**：
- 付款条件会在采购发票中自动应用
- 可以在采购发票中手动修改付款条件

## 十、常见问题

### 10.1 为什么创建供应商时提示"供应商分类不能为空"？

**原因**：供应商分类是必填字段。

**解决方法**：
1. 如果系统中没有合适的分类，先创建供应商分类
2. 导航到：`采购 → 供应商分类 → 新建`
3. 创建分类后，再创建供应商

### 10.2 如何批量设置供应商的信用限额？

**方法 1：通过 Excel 导入**

1. 导出供应商数据
2. 在 Excel 中批量填写信用限额
3. 导入更新

**方法 2：通过 API 批量更新**

```python
# 批量更新多个供应商的信用限额
suppliers = ["Supplier A - Company", "Supplier B - Company"]
for supplier_name in suppliers:
    PUT /api/resource/Supplier/{supplier_name}
    {
        "credit_limit": 100000.00
    }
```

### 10.3 供应商被暂停后，如何解除暂停？

**通过 UI 解除**：
1. 打开供应商主数据
2. 取消勾选"暂停"（On Hold）选项
3. 保存供应商

**通过 API 解除**：
```python
PUT /api/resource/Supplier/Supplier-A-Company
{
    "on_hold": 0
}
```

### 10.4 如何查看供应商的未付款金额和可用信用额度？

**通过 UI 查看**：
1. 打开供应商主数据
2. 在"财务信息"部分，可以看到：
   - **未付款金额**（Outstanding Amount）
   - **信用限额**（Credit Limit）
   - **可用信用额度**（Available Credit Limit）

**通过 API 查询**：
```python
GET /api/resource/Supplier/Supplier-A-Company

# 响应中包含：
{
    "credit_limit": 100000.00,
    "outstanding_amount": 50000.00,
    "available_credit_limit": 50000.00  # 自动计算
}
```

### 10.5 供应商分类可以创建层级结构吗？

**可以**。ERPNext 支持供应商分类的层级结构。

**创建方法**：
1. 先创建父分类，例如：`供应商分类`
2. 创建子分类时，选择父分类：
   - 供应商分类名称：`本地供应商`
   - 父分类：`供应商分类`

**层级示例**：
```
供应商分类
├── 本地供应商
│   ├── 原材料供应商
│   └── 服务供应商
└── 外地供应商
    ├── 设备供应商
    └── 物流供应商
```

## 十二、TTPOS 系统集成

### 12.1 同步供应商高级设置

在 TTPOS 系统中，可以通过以下方式同步供应商的高级设置：

```go
// 代码位置：main/app/service/supplier.go
// 同步供应商信息（包含高级设置）
func (s *supplierSrv) SyncSupplierFromERPNext(ctx context.Context, erpCode string) error {
    // 从 ERPNext 获取供应商信息
    erpSupplier, err := erpSrv.GetSupplier(ctx, erpCode)
    if err != nil {
        return err
    }
    
    // 同步到 TTPOS 数据库
    supplier := &model.Supplier{
        ErpCode:           erpSupplier.Code,
        Name:              erpSupplier.Name,
        // 可以同步其他高级设置字段

    return s.supplierRepo.CreateOrUpdate(supplier)
}
```

## 十三、总结

供应商高级设置是 ERPNext 中重要的管理功能，通过正确设置：

1. ✅ **税务合规**：确保税务信息准确，符合法规要求
2. ✅ **风险控制**：通过信用限额和认证管理，控制供应商风险
3. ✅ **效率提升**：通过默认设置，提高采购流程效率
4. ✅ **管理优化**：通过分类和引荐人，优化供应商管理

**关键设置项**：
- ⭐ **供应商分类**：必填，用于分类管理
- ⭐ **信用限额**：可选，用于风险控制
- ⭐ **税务信息**：可选，用于税务合规
- ⭐ **付款条件**：可选，用于财务流程
- ⭐ **认证状态**：可选，用于权限控制
