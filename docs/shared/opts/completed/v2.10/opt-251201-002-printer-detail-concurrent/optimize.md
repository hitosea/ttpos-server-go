## 问题描述

### 当前问题

`/shop/printer/template/detail` 接口响应时间过长，用户反馈体验不佳。

**性能表现**：
- 单个模板：约 1 秒
- 3 个高级模板：约 3-4 秒
- 5 个高级模板：约 5-7 秒

**问题根源**：
```go
// printer.go Line 606-631
for _, customize := range customizes {
    if customize.IsAdv == 1 {
        // 串行调用 Parser，每次都要：
        // 1. 查询数据库（获取设置）
        // 2. 验证模板 JSON
        // 3. 生成图片（最耗时，约 800ms-1s）
        // 4. 写文件 → 读文件 → base64 编码
        printContent, err := s.Parser(ctx, customize.Data, testData)
    }
}
```

### 影响范围

**受影响终端**：
- **shop**: 店长配置打印模板时，每次打开详情都要等待数秒

**影响场景**：
1. 店长首次配置打印模板
2. 查看/编辑现有模板
3. 切换不同模板类型

**业务影响**：
- 用户体验差，加载时间过长
- 多个高级模板时更明显
- 影响店长配置效率

## 技术分析

### 性能瓶颈

**核心问题**：串行执行多个耗时的 `Parser` 调用

```
串行执行流程（5个高级模板）:
Parser(模板1) ─1s→ Parser(模板2) ─1s→ Parser(模板3) ─1s→ Parser(模板4) ─1s→ Parser(模板5) ─1s→ 返回
总耗时: 5秒
```

**Parser 方法耗时分析**（Line 375-424）：
1. 获取货币设置：50ms（数据库）
2. 创建解析器：10ms
3. 验证模板：50ms（JSON 解析）
4. 生成图片：**800ms-1s**（CPU 密集，图像渲染）
5. 保存文件：20ms（磁盘 I/O）
6. 读取文件：20ms（磁盘 I/O）
7. Base64 编码：30ms

**并发潜力**：
- 多个模板之间没有依赖关系
- 可以并行生成
- 多核 CPU 可充分利用

## 经验总结

**优化方法**: 使用 goroutine + channel + sync.WaitGroup 实现并发任务处理

**关键技术**: 
- 并发安全的 `ParserConcurrent` 方法（独立临时文件）
- 使用 `defer os.Remove()` 确保资源清理
- 通过 channel 收集并发结果
- 单个任务失败不影响其他任务（容错处理）

**核心代码**:
```go
// 并发生成所有模板预览图
var wg sync.WaitGroup
resultChan := make(chan templateResult, len(customizes)+1)

for _, customize := range customizes {
    wg.Add(1)
    go func(cust model.PrinterCustomize) {
        defer wg.Done()
        imgUrl, err := s.ParserConcurrent(ctx, cust.Data, testData, cust.Uuid)
        resultChan <- templateResult{...}
    }(customize)
}

// 等待所有任务完成
go func() {
    wg.Wait()
    close(resultChan)
}()
```

**注意事项**: 
- 每个并发任务必须使用唯一的临时文件名（UUID + 纳秒时间戳）
- 使用 `defer` 确保临时文件正确清理
- 正确传递 context 到 goroutine
- 错误日志记录便于排查问题

**适用场景**: 
- 多个独立任务可以并行处理的场景
- I/O 密集或 CPU 密集型任务的加速
- 需要充分利用多核 CPU 的性能优化
