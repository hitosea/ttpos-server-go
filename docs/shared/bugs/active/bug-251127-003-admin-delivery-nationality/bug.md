## 问题描述

### 问题概述

新管理端的外卖和国籍管理功能存在两个核心问题：
1. **列表排序问题**：新增配置项按创建时间正序显示，最新记录在底部不便查看
2. **删除限制问题**：已使用的配置项无法删除，影响数据维护

---

### 问题 1：列表排序不合理

**现象**：
- 在「业务设置 → 外卖/国籍管理」中新增配置项后
- 列表按创建时间**正序**排序
- 最新添加的记录显示在列表底部

**预期行为**：
- 新增配置项后，应按创建时间**倒序**显示
- 最新添加的记录应显示在列表顶部
- 方便用户快速查看和确认新增内容

**实际行为**：
- 新增记录显示在列表底部
- 用户需要滚动到底部才能看到新增内容
- 特别是数据量大时体验很差

**影响**：
- 用户体验不佳
- 增加操作步骤（需要滚动查找）
- 无法快速验证新增结果

---

### 问题 2：无法删除已使用的配置项

**现象**：
- 在「业务设置 → 外卖/国籍管理」中
- 尝试删除已被订单使用的外卖/国籍配置项
- 系统提示无法删除

**预期行为**：
- 应允许删除已使用的配置项
- 删除后，历史订单中的外卖/国籍记录仍然保留
- 新订单不再显示该配置项（软删除）

**实际行为**：
- 系统直接禁止删除已使用的配置项
- 无法进行数据维护和清理
- 过时或错误的配置项永久存在

**影响**：
- 配置项越来越多，无法清理
- 错误的配置项无法删除
- 影响用户选择体验（太多无效选项）
- 数据维护困难

## 复现步骤

### 问题 1 复现步骤

1. 登录新管理端
2. 进入「业务设置 → 外卖管理」或「国籍管理」
3. 点击「新增」按钮
4. 填写配置项名称（如"美团外卖"）
5. 点击保存
6. **观察列表顺序**：新增记录显示在底部

### 问题 2 复现步骤

1. 登录新管理端
2. 进入「业务设置 → 外卖管理」或「国籍管理」
3. 找到一个已被订单使用的配置项
4. 点击「删除」按钮
5. **观察结果**：系统提示无法删除或删除失败

## 初步分析

### 问题 1 分析：排序问题

**原因推测**：
- 前端列表组件默认使用数据库查询结果顺序
- 后端 API 未指定排序规则，或使用了 `ORDER BY created_at ASC`
- 缺少默认排序配置

**涉及代码**（推测）：
```
admin/views/shop/settings/delivery.vue  # 外卖管理页面
admin/views/shop/settings/nationality.vue  # 国籍管理页面
admin/app/shop/controller/Settings.php  # 后端控制器
```

**修复方向**：
1. 后端 API 添加 `ORDER BY created_at DESC` 排序
2. 前端列表组件添加默认排序逻辑

---

### 问题 2 分析：删除限制

**原因推测**：
- 后端删除逻辑使用了硬删除（DELETE）
- 有外键约束或业务逻辑校验，禁止删除已使用的配置项
- 缺少软删除机制

**涉及代码**（推测）：
```
admin/app/shop/controller/Settings.php  # 删除接口
admin/app/shop/model/Delivery.php  # 外卖配置模型
admin/app/shop/model/Nationality.php  # 国籍配置模型
订单相关表的外键关系
```

**修复方向**：
1. 将硬删除改为软删除（添加 `deleted_at` 字段）
2. 删除时只标记 `deleted_at`，不真正删除记录
3. 查询时过滤已删除的配置项（`WHERE deleted_at IS NULL`）
4. 历史订单展示时不过滤，保留完整信息

**数据库影响**：
- 需要添加 `deleted_at` 字段到外卖和国籍配置表
- 需要迁移脚本
