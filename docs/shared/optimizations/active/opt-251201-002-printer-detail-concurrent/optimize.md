## 问题描述

### 当前问题

`/shop/printer/template/detail` 接口响应时间过长，用户反馈体验不佳。

**性能表现**：
- 单个模板：约 1 秒
- 3 个高级模板：约 3-4 秒
- 5 个高级模板：约 5-7 秒

**问题根源**：
```go
// printer.go Line 606-631
for _, customize := range customizes {
    if customize.IsAdv == 1 {
        // 串行调用 Parser，每次都要：
        // 1. 查询数据库（获取设置）
        // 2. 验证模板 JSON
        // 3. 生成图片（最耗时，约 800ms-1s）
        // 4. 写文件 → 读文件 → base64 编码
        printContent, err := s.Parser(ctx, customize.Data, testData)
    }
}
```

### 影响范围

**受影响终端**：
- **shop**: 店长配置打印模板时，每次打开详情都要等待数秒

**影响场景**：
1. 店长首次配置打印模板
2. 查看/编辑现有模板
3. 切换不同模板类型

**业务影响**：
- 用户体验差，加载时间过长
- 多个高级模板时更明显
- 影响店长配置效率

## 技术分析

### 性能瓶颈

**核心问题**：串行执行多个耗时的 `Parser` 调用

```
串行执行流程（5个高级模板）:
Parser(模板1) ─1s→ Parser(模板2) ─1s→ Parser(模板3) ─1s→ Parser(模板4) ─1s→ Parser(模板5) ─1s→ 返回
总耗时: 5秒
```

**Parser 方法耗时分析**（Line 375-424）：
1. 获取货币设置：50ms（数据库）
2. 创建解析器：10ms
3. 验证模板：50ms（JSON 解析）
4. 生成图片：**800ms-1s**（CPU 密集，图像渲染）
5. 保存文件：20ms（磁盘 I/O）
6. 读取文件：20ms（磁盘 I/O）
7. Base64 编码：30ms

**并发潜力**：
- 多个模板之间没有依赖关系
- 可以并行生成
- 多核 CPU 可充分利用

## 预期收益

### 性能提升

| 场景           | 优化前 | 优化后 | 提升  |
| -------------- | ------ | ------ | ----- |
| 1个模板        | 1.0s   | 1.0s   | 0%    |
| 3个高级模板    | 3.5s   | 1.2s   | 66%   |
| 5个高级模板    | 6.0s   | 1.5s   | 75%   |
| 10个高级模板   | 11.0s  | 2.0s   | 82%   |

**理论分析**：
- 并发度：5（假设5个模板）
- 单个任务：1s
- 并行执行：1s + 线程切换开销（0.2-0.5s）

### 用户体验

- ✅ 多模板场景下响应时间大幅缩短
- ✅ 减少用户等待时间
- ✅ 提升配置操作流畅度

### 成本评估

- CPU 使用率短时提升（可控）
- 内存占用略增（goroutine 开销）
- 磁盘 I/O 并发（需处理文件冲突）
