## 📋 概述

商品销售统计功能旨在为新管理端（商家端）提供完善的商品销售数据筛选和导出能力。基于现有API实现，补充筛选条件并新增导出功能，满足商户精细化运营分析需求。

本功能主要涉及统计查询API参数扩展、筛选逻辑优化、以及Excel导出功能实现。

## 🎯 产品对齐

该功能支持公司2025年Q4的核心目标：
- **提升数据分析能力**: 支持多维度筛选，满足精细化运营需求
- **增强用户体验**: 与旧商家后台功能对齐，提供一致的使用体验
- **提升运营效率**: 支持数据导出，便于离线分析和报表制作

## 📝 用户故事

**作为** 商户管理员  
**我想** 在报表中心查看商品销售统计时，能够按订单类型、订单来源、商品分类等多维度筛选数据，并能够导出统计数据  
**以便于** 进行精细化运营分析和报表制作

## 功能需求

### Requirement 1: 完善时间类型筛选

**用户故事**: 作为商户管理员，我想通过时间类型快速筛选数据，以便于快速查看不同时间段的销售情况

#### 验收标准

1. **WHEN** 选择时间类型 **THEN** 系统 **SHALL** 自动计算对应的时间范围
2. **IF** 时间类型为1（今天） **THEN** 系统 **SHALL** 查询当天的数据
3. **IF** 时间类型为2（昨天） **THEN** 系统 **SHALL** 查询昨天的数据
4. **IF** 时间类型为3（本周） **THEN** 系统 **SHALL** 查询本周的数据
5. **IF** 时间类型为4（本月） **THEN** 系统 **SHALL** 查询本月的数据
6. **IF** 时间类型为5（近7天） **THEN** 系统 **SHALL** 查询近7天的数据
7. **IF** 时间类型为6（上月） **THEN** 系统 **SHALL** 查询上个月的数据
8. **IF** 时间类型为7（今年） **THEN** 系统 **SHALL** 查询今年的数据
9. **WHEN** 同时提供时间类型和自定义时间范围 **THEN** 系统 **SHALL** 优先使用自定义时间范围

#### 具体要求

- [ ] 1.1 在 `BusinessDataCountProductSalesReq` 中新增 `TimeType` 字段（int类型）
- [ ] 1.2 时间类型枚举值：1=今天, 2=昨天, 3=本周, 4=本月, 5=近7天, 6=上月, 7=今年
- [ ] 1.3 在 `buildCountOpts` 方法中处理时间类型，自动计算时间范围
- [ ] 1.4 时间计算需要考虑商户时区设置
- [ ] 1.5 默认时间类型为1（今天）

---

### Requirement 2: 订单类型筛选

**用户故事**: 作为商户管理员，我想按订单类型筛选商品销售数据，以便于分析不同订单类型的销售情况

#### 验收标准

1. **WHEN** 订单类型为空字符串 **THEN** 系统 **SHALL** 查询全部订单类型
2. **WHEN** 订单类型为"1" **THEN** 系统 **SHALL** 仅查询点餐订单
3. **WHEN** 订单类型为"2" **THEN** 系统 **SHALL** 仅查询桌台订单
4. **WHEN** 订单类型为"3" **THEN** 系统 **SHALL** 仅查询外送订单
5. **WHEN** 订单类型为"1,2,3" **THEN** 系统 **SHALL** 查询点餐、桌台、外送三种订单类型
6. **WHEN** 选择点餐订单时 **THEN** 系统 **SHALL** 显示订单来源筛选选项

#### 具体要求

- [ ] 2.1 在 `BusinessDataCountProductSalesReq` 中新增 `OrderType` 字段（string类型）
- [ ] 2.2 订单类型值：""=全部, "1"=点餐订单, "2"=桌台订单, "3"=外送订单
- [ ] 2.3 支持多选，格式为逗号分隔的字符串，如"1,2,3"
- [ ] 2.4 在统计查询中根据订单类型筛选数据（映射到 `SaleBillType`）
- [ ] 2.5 订单类型映射：1→SaleBillTypeInstant, 2→SaleBillTypeDesk, 3→SaleBillTypeTakeout

---

### Requirement 3: 订单来源筛选

**用户故事**: 作为商户管理员，我想按订单来源筛选点餐订单数据，以便于分析不同来源的销售情况

#### 验收标准

1. **WHEN** 订单来源为-1 **THEN** 系统 **SHALL** 查询全部订单来源
2. **WHEN** 订单来源为1 **THEN** 系统 **SHALL** 仅查询店内订单
3. **WHEN** 订单来源为2 **THEN** 系统 **SHALL** 仅查询外卖订单
4. **WHEN** 未选择点餐订单类型 **THEN** 系统 **SHALL** 不显示订单来源筛选
5. **WHEN** 选择点餐订单类型 **THEN** 系统 **SHALL** 默认订单来源为-1（全部）

#### 具体要求

- [ ] 3.1 在 `BusinessDataCountProductSalesReq` 中新增 `OrderSource` 字段（int类型）
- [ ] 3.2 订单来源值：-1=全部, 1=店内, 2=外卖
- [ ] 3.3 仅在订单类型包含点餐订单（"1"）时生效
- [ ] 3.4 在统计查询中根据订单来源筛选数据（需要关联订单表或销售账单表）
- [ ] 3.5 默认值为-1（全部）

---

### Requirement 4: 商品分类多选支持

**用户故事**: 作为商户管理员，我想选择多个商品分类进行筛选，以便于分析多个分类的销售情况

#### 验收标准

1. **WHEN** 商品分类UUID列表为空字符串 **THEN** 系统 **SHALL** 查询全部分类
2. **WHEN** 商品分类UUID列表为"uuid1,uuid2,uuid3" **THEN** 系统 **SHALL** 查询指定分类的商品
3. **WHEN** 商品分类UUID列表包含父分类 **THEN** 系统 **SHALL** 同时查询子分类
4. **WHEN** 商品分类UUID列表包含子分类 **THEN** 系统 **SHALL** 仅查询该子分类

#### 具体要求

- [ ] 4.1 将 `CategoryUuid` 字段改为 `CategoryUuids`（[]uint64类型），支持多选
- [ ] 4.2 支持空数组表示全部分类
- [ ] 4.3 在统计查询中使用 `IN` 查询支持多选
- [ ] 4.4 如果分类UUID包含父分类，需要同时查询子分类（递归查询）
- [ ] 4.5 保持向后兼容，如果传入单个UUID，自动转换为数组

---

### Requirement 5: 商品名称模糊查询

**用户故事**: 作为商户管理员，我想通过商品名称搜索商品，以便于快速定位特定商品的销售数据

#### 验收标准

1. **WHEN** 商品名称为空 **THEN** 系统 **SHALL** 不进行名称筛选
2. **WHEN** 输入商品名称关键词 **THEN** 系统 **SHALL** 使用模糊查询匹配商品名称
3. **WHEN** 查询结果 **THEN** 系统 **SHALL** 返回包含关键词的商品销售数据

#### 具体要求

- [ ] 5.1 保持现有 `ProductName` 字段的模糊查询功能
- [ ] 5.2 确保查询支持多语言商品名称

---

### Requirement 6: 导出功能

**用户故事**: 作为商户管理员，我想导出商品销售统计数据，以便于进行离线分析和报表制作

#### 验收标准

1. **WHEN** 调用导出API **THEN** 系统 **SHALL** 根据筛选条件导出数据
2. **WHEN** 导出数据为空 **THEN** 系统 **SHALL** 返回错误提示
3. **WHEN** 导出数据超过1000条 **THEN** 系统 **SHALL** 返回错误提示，要求缩小时间范围
4. **WHEN** 导出成功 **THEN** 系统 **SHALL** 返回Excel文件下载链接
5. **WHEN** 导出文件 **THEN** 系统 **SHALL** 包含完整的统计字段（商品名称、分类、销售数量、销售额等）

#### 具体要求

- [ ] 6.1 创建导出API：`/shop/statistics/product_sales/export`
- [ ] 6.2 导出参数与查询API参数一致
- [ ] 6.3 使用异步任务处理导出（参考 `ExportKitchenProductionDetail` 实现）
- [ ] 6.4 导出文件格式：Excel (.xlsx)
- [ ] 6.5 导出字段：序号、商品名称、商品分类、销售数量、原价销售额、赠菜、实际销售额、营业收入
- [ ] 6.6 导出文件支持多语言文件名
- [ ] 6.7 导出数据限制：最多1000条
- [ ] 6.8 导出任务状态记录到 `ttpos_export_record` 表

## 非功能需求

### 性能要求

- [ ] 查询响应时间 < 2秒（数据量 < 10000条）
- [ ] 导出任务创建时间 < 500ms
- [ ] 导出文件生成时间 < 30秒（数据量 < 1000条）

### 兼容性要求

- [ ] 保持现有API向后兼容
- [ ] 支持旧版本客户端调用（忽略新字段）

### 安全要求

- [ ] 导出功能需要权限验证
- [ ] 导出数据仅包含当前商户的数据

## 验收标准总结

### 列表筛选

- ✅ 时间筛选：默认当天，可修改，不限制可选时间（不能选择未来时间）
- ✅ 商品名称模糊查询
- ✅ 每次进入、筛选等刷新一次数据

### 筛选条件

- ✅ 日期：默认当天
- ✅ 订单类型：全部项与其他项互斥，选择点餐方式时，出现订单来源选择
- ✅ 订单来源：选择点餐订单时出现，默认全部，全部与其他项互斥
- ✅ 商品分类：可选择当前存在的分类，可多选

### 导出功能

- ✅ 根据筛选条件导出
- ✅ 表格取值采用旧商家后台-商品销售统计逻辑
