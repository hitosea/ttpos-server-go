## 📋 概述

Kiosk 自助点餐机商品浏览模块是用户点餐流程的核心环节，提供分类导航、商品列表、商品详情等功能。用户通过分类导航快速找到目标商品类别，浏览商品列表了解商品信息，查看商品详情选择商品规格、属性、加料等选项，最终完成商品选择并加入购物车。

该模块需要支持多语言展示，适配大屏触摸交互，提供清晰的商品展示和便捷的浏览体验，帮助用户快速找到目标商品并做出购买决策。

## 🎯 产品对齐

商品浏览模块是 Kiosk 自助点餐机终端功能的重要组成部分，支持产品愿景中的"提升服务效率"和"改善顾客体验"目标。通过清晰的商品展示和便捷的浏览体验，帮助用户快速找到目标商品，提升点餐效率，减少等待时间，提升顾客满意度。

## 功能需求

### Requirement 1: 商品分类列表

**用户故事**: 作为顾客，我想通过分类导航浏览商品分类，以便于快速找到目标商品类别

#### 验收标准

1. **WHEN** 用户进入商品浏览页面 **THEN** 系统 **SHALL** 显示商品分类列表
2. **WHEN** 用户点击商品分类 **THEN** 系统 **SHALL** 显示对应分类的商品列表
3. **WHEN** 用户切换语言 **THEN** 系统 **SHALL** 更新分类名称，显示对应语言的内容
4. **WHEN** 分类数据获取失败 **THEN** 系统 **SHALL** 显示友好提示，支持重试

#### 具体要求

- [ ] 1.1 实现 `GET /api/v1/kiosk/product/category/list` 接口，获取商品分类列表
- [ ] 1.2 分类列表按排序字段（sort）升序排列
- [ ] 1.3 只返回状态为启用（status=1）且未删除的分类
- [ ] 1.4 分类名称支持多语言显示，根据用户选择的语言返回对应语言的分类名称
- [ ] 1.5 分类列表响应包含分类 UUID、名称、排序等信息
- [ ] 1.6 参考实现：`/api/v1/tablet/product/category/list` 接口

---

### Requirement 2: 商品列表展示

**用户故事**: 作为顾客，我想查看商品列表，了解商品图片、名称、价格等信息，以便于做出购买决策

#### 验收标准

1. **WHEN** 用户浏览商品列表 **THEN** 系统 **SHALL** 以网格布局展示商品，包含图片、名称、价格、折扣等信息
2. **WHEN** 用户选择商品分类 **THEN** 系统 **SHALL** 显示对应分类的商品列表
3. **WHEN** 商品列表数据量大 **THEN** 系统 **SHALL** 支持分页加载，保证加载性能
4. **WHEN** 商品数据缺失（图片、描述等） **THEN** 系统 **SHALL** 显示默认占位图或降级方案，不影响用户浏览
5. **WHEN** 用户切换语言 **THEN** 系统 **SHALL** 更新商品名称、描述等，显示对应语言的内容

#### 具体要求

- [ ] 2.1 实现 `GET /api/v1/kiosk/product/list` 接口，获取商品列表
- [ ] 2.2 支持分页参数：`page_no`（页码）、`page_size`（每页条数）
- [ ] 2.3 支持按分类筛选：`category_uuid`（分类UUID，可选）
- [ ] 2.4 只返回在 Kiosk 终端显示的商品（`is_show_kiosk=1`）
- [ ] 2.5 只返回状态为启用（`status=1`）且未删除的商品
- [ ] 2.6 商品列表按排序字段（sort）升序、ID 降序排列
- [ ] 2.7 商品名称、描述支持多语言显示，根据用户选择的语言返回对应语言的内容
- [ ] 2.8 商品列表响应包含商品 UUID、名称、图片、价格、折扣、描述等信息
- [ ] 2.9 响应格式包含分页信息（total、page_no、page_size）
- [ ] 2.10 参考实现：`/api/v1/tablet/product/list` 接口

---

### Requirement 3: 商品详情查看

**用户故事**: 作为顾客，我想查看商品详情，了解商品规格、属性、加料等选项，以便于选择符合我需求的商品配置

#### 验收标准

1. **WHEN** 用户点击商品 **THEN** 系统 **SHALL** 显示商品详情，包含规格、属性、加料等选项
2. **WHEN** 用户查看商品详情 **THEN** 系统 **SHALL** 显示商品图片、名称、价格、折扣、描述等信息
3. **WHEN** 商品有多个规格 **THEN** 系统 **SHALL** 显示规格选择选项（中份/大份等）
4. **WHEN** 商品有属性选项 **THEN** 系统 **SHALL** 显示属性选择选项（熟度、加料等）
5. **WHEN** 商品是套餐 **THEN** 系统 **SHALL** 显示套餐配置选项
6. **WHEN** 用户切换语言 **THEN** 系统 **SHALL** 更新商品详情中的名称、描述、规格名称、属性名称等，显示对应语言的内容

#### 具体要求

- [ ] 3.1 实现 `GET /api/v1/kiosk/product/detail` 接口，获取商品详细信息
- [ ] 3.2 请求参数：`product_uuid`（商品UUID，必填）
- [ ] 3.3 返回商品基本信息：UUID、名称、图片、价格、折扣、描述等
- [ ] 3.4 返回商品规格列表：规格 UUID、名称、价格等
- [ ] 3.5 返回商品属性列表：属性组、属性项、价格等
- [ ] 3.6 返回商品加料列表：加料组、加料项、价格等
- [ ] 3.7 返回套餐配置信息（如果是套餐商品）
- [ ] 3.8 商品名称、描述、规格名称、属性名称等支持多语言显示
- [ ] 3.9 参考实现：`/api/v1/member/product/detail` 接口

## 非功能需求

### 代码架构和模块化

- **分层设计**: 严格遵循 Controller → Service → Repository 分层
- **单一职责原则**: 每个文件应有单一、明确的目的
- **模块化设计**: Service 和 Repository 应独立且可复用
- **依赖管理**: Service 只能依赖其他 Service 接口，不能直接依赖 Repository
- **遵循规范**:
  - `.cursor/rules/go-main.mdc` - Go Main 开发规范
  - `.cursor/rules/api.mdc` - API 设计规范
  - `.cursor/rules/structs.mdc` - 项目结构规范

### API 设计要求

- [x] URL 使用 snake_case 命名（如：`/api/v1/kiosk/product/category/list`）
- [x] data 字段必须是对象，不能是 null 或数组
- [x] 分页信息统一放在 meta 中
- [x] 响应格式：`{code, message, data{}}`
- [x] 参考: `.cursor/rules/api.mdc` - API 设计规范

### 数据库设计要求

- [x] 复用现有商品表（`ttpos_product`、`ttpos_product_category` 等）
- [x] 不需要新增表结构
- [x] 参考: `.cursor/rules/database.mdc` - 数据库开发规范

### 性能要求

- [ ] 本地响应时间 < 200ms
- [ ] 数据库查询优化（使用索引）
- [ ] 缓存策略（Redis，商品分类列表、商品列表缓存）
- [ ] 分页加载，避免一次性加载大量数据

### 测试要求

- [ ] Service 层测试覆盖率 ≥ 70%
- [ ] Repository 层测试覆盖率 ≥ 80%
- [ ] API 测试覆盖所有接口
- [ ] 集成测试覆盖核心流程
- [ ] 参考: `.cursor/rules/go-main.mdc` - 测试规范

### 国际化要求

- [ ] 支持多语言（中文、英文、日语、韩语等）
- [ ] 商品名称、描述、分类名称等多语言显示
- [ ] 根据用户选择的语言返回对应语言的内容
- [ ] 参考: `main/i18n/` - 国际化配置

### 安全要求

- [x] 所有 API 需要身份验证（JWT Token）
- [ ] SQL 注入防护（使用参数化查询）
- [ ] XSS 防护（前端输入校验）
- [ ] 参考: `.cursor/rules/security.mdc` - 安全开发规范

### 可靠性要求

- [ ] 网络异常时优雅降级
- [ ] 错误日志记录（使用 Logger）
- [ ] 数据缺失时显示默认占位图或降级方案
- [ ] 支持重试机制

## 约束条件

### 技术约束

#### Go Main 模块

- 必须使用 Gin 框架
- 接口以 `I` 开头，实现以 `Impl` 结尾
- Service 只能依赖其他 Service 接口
- Repository 只能持有 db 实例，不能持有 DBManager
- 不使用 panic，返回 error
- 复用现有的 `IProductSrv` 接口和实现

### 业务约束

- 商品分类和商品列表需要根据 Kiosk 终端的显示设置进行筛选
- 商品详情需要包含完整的规格、属性、加料等信息，支持商品配置
- 多语言数据需要完整，缺失时使用默认语言

### 资源约束

- 开发时间: 5-7 天
- Story Point: 8-13 (必须 ≤ 5，需要拆分)

## 风险和缓解

### 风险 1: 商品数据完整性风险

**影响**: 中  
**概率**: 中  
**缓解措施**:

- 建立商品数据管理流程，确保数据完整性
- 提供数据缺失时的降级方案（显示默认图片、占位符等）
- 在商品详情接口中处理数据缺失情况

### 风险 2: 多语言数据完整性风险

**影响**: 中  
**概率**: 中  
**缓解措施**:

- 建立多语言数据管理流程，确保数据完整性
- 提供多语言数据缺失时的降级方案（显示默认语言）
- 在接口中处理多语言数据缺失情况

### 风险 3: 性能风险

**影响**: 中  
**概率**: 低  
**缓解措施**:

- 实现分页加载，避免一次性加载大量数据
- 优化图片加载策略（懒加载、压缩等）
- 使用缓存机制（Redis），提升性能
- 优化数据库查询（使用索引）
