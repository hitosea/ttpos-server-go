## 📋 概述

在新管理端新增自助点餐机（Kiosk）客户端的配置和管理功能的后端 API 支持，包括：

1. **商品管理增强**：在商品新建/编辑接口中，增加"显示的客户端"参数，支持选择是否在自助点餐机显示，默认勾选
2. **菜品标签增强**：在标签新建/编辑接口中，增加"显示的客户端"参数，支持选择是否在自助点餐机显示，默认勾选
3. **各端设置新增**：新增自助点餐机客户端设置 API，包括高级密码、呼叫服务员、语言设置、轮播内容等配置

**实现范围**：仅实现后端 API 接口，参考现有类似功能的实现方式。

## 🎯 产品对齐

- 完善新管理端的功能覆盖，支持自助点餐机客户端的完整配置
- 提升商户使用体验，统一管理各端配置
- 为自助点餐机终端提供完整的后台管理支持
- 支持多语言、轮播内容等丰富的配置选项

## 功能需求

### Requirement 1: 商品管理 - 客户端显示配置

**用户故事**: 作为商户管理员，我想通过 API 接口在新建/编辑商品时配置是否在自助点餐机显示，以便于控制商品在自助点餐机的可见性

#### 验收标准

1. **WHEN** 调用商品新建接口并传递 `is_show_kiosk` 参数 **THEN** 系统 **SHALL** 接受参数并保存配置到数据库
2. **WHEN** 调用商品编辑接口并传递 `is_show_kiosk` 参数 **THEN** 系统 **SHALL** 更新配置到数据库
3. **WHEN** 调用商品查询接口 **THEN** 系统 **SHALL** 返回 `is_show_kiosk` 字段
4. **IF** 云平台已开启自助点餐机功能 **AND** 未传递 `is_show_kiosk` 参数 **THEN** 系统 **SHALL** 使用默认值（1-是）
5. **IF** 云平台未开启自助点餐机功能 **AND** 未传递 `is_show_kiosk` 参数 **THEN** 系统 **SHALL** 使用默认值（0-否）

#### 具体要求

- [x] 1.1 在商品数据模型中添加 `is_show_kiosk` 字段（uint类型，0-否，1-是）
- [x] 1.2 在商品新建接口 (`/shop/product/add` 或类似) 中添加 `is_show_kiosk` 参数（可选，int类型，默认值根据云平台自助点餐机开启状态：已开启则为1，未开启则为0）
- [x] 1.3 在商品编辑接口 (`/shop/product/edit` 或类似) 中添加 `is_show_kiosk` 参数（可选，int类型，默认值根据云平台自助点餐机开启状态：已开启则为1，未开启则为0）
- [x] 1.4 在商品列表查询接口中返回 `is_show_kiosk` 字段（int类型，0-否，1-是）
- [x] 1.5 在商品详情查询接口中返回 `is_show_kiosk` 字段（int类型，0-否，1-是）
- [x] 1.6 实现云平台自助点餐机开启状态检查逻辑（查询 `company_setting` 表的 `enable_kiosk` 字段）
- [x] 1.7 创建数据库迁移脚本，为 `ttpos_product_package` 表添加 `is_show_kiosk` 字段

### Requirement 3: 各端设置 - 自助点餐机配置

**用户故事**: 作为商户管理员，我想通过 API 接口配置自助点餐机的各项设置，以便于自定义自助点餐机的功能和展示

#### 验收标准

1. **WHEN** 调用自助点餐机设置查询接口 **THEN** 系统 **SHALL** 返回所有配置项（包括默认值）
2. **WHEN** 调用自助点餐机设置更新接口并传递高级密码参数 **THEN** 系统 **SHALL** 校验密码格式（4-8位整数），校验通过后保存配置，默认值为 666888
3. **IF** 高级密码参数不符合格式要求（非4-8位整数） **THEN** 系统 **SHALL** 返回参数错误
4. **WHEN** 调用自助点餐机设置更新接口并传递呼叫服务员开关参数 **THEN** 系统 **SHALL** 保存配置，默认开启
5. **WHEN** 调用自助点餐机设置更新接口并传递常用语言参数 **THEN** 系统 **SHALL** 保存配置，默认所有语言
6. **WHEN** 调用自助点餐机设置更新接口并传递默认语言参数 **THEN** 系统 **SHALL** 保存配置，默认语言1
7. **WHEN** 调用图片上传接口上传轮播图片 **THEN** 系统 **SHALL** 校验格式（JPG、JPEG、PNG、WEBP）、大小（<2MB）、尺寸（1160*1104px），最多10张
8. **WHEN** 调用视频上传接口上传轮播视频 **THEN** 系统 **SHALL** 校验格式（MP4）、大小（<10MB）、尺寸（1160*1104px），最多5个
9. **WHEN** 调用自助点餐机设置更新接口保存配置 **THEN** 系统 **SHALL** 成功保存所有配置到数据库

#### 具体要求

**高级密码设置**：
- [ ] 3.1 在数据模型中添加高级密码字段（默认值：666888，VARCHAR(8)）
- [ ] 3.2 在设置更新接口 (`/api/v1/kiosk_settings/update` 或类似) 中添加 `advanced_password` 参数（可选，默认 666888）
- [ ] 3.3 实现高级密码校验逻辑：必须为4-8位整数（使用正则表达式：`^[0-9]{4,8}$`）
- [ ] 3.4 在设置查询接口中返回 `advanced_password` 字段

**呼叫服务员开关**：
- [ ] 3.4 在数据模型中添加呼叫服务员开关字段（默认值：开启，1）
- [ ] 3.5 在设置更新接口中添加 `call_waiter_enabled` 参数（可选，默认 1）
- [ ] 3.6 在设置查询接口中返回 `call_waiter_enabled` 字段

**常用语言配置**：
- [ ] 3.7 在数据模型中添加常用语言字段（支持多选，JSON 数组，默认所有语言）
- [ ] 3.8 在设置更新接口中添加 `common_languages` 参数（可选，JSON 数组，默认所有语言）
- [ ] 3.9 在设置查询接口中返回 `common_languages` 字段

**默认语言设置**：
- [ ] 3.10 在数据模型中添加默认语言字段（默认值：旧后台对应的语言1）
- [ ] 3.11 在设置更新接口中添加 `default_language` 参数（可选，默认语言1）
- [ ] 3.12 在设置查询接口中返回 `default_language` 字段

**轮播内容管理**：
- [ ] 3.13 在数据模型中添加轮播内容字段（JSON 数组，支持图片和视频 URL，默认空数组，支持排序）
- [ ] 3.14 实现轮播内容上传接口 (`/shop/setting/kiosk/carousel/upload`)，支持图片（JPG、JPEG、PNG、WEBP）和视频（MP4）格式
- [ ] 3.15 实现图片校验逻辑：格式校验、大小校验（<2MB）、尺寸校验（1160*1104px）
- [ ] 3.16 实现视频校验逻辑：格式校验、大小校验（<10MB）、尺寸校验（1160*1104px）
- [ ] 3.17 实现轮播内容数量限制：最多10张图片 + 5个视频，总共最多15个（在更新接口中校验）
- [ ] 3.18 在设置更新接口中添加 `carousel` 参数（JSON 数组，包含图片和视频，支持排序）
- [ ] 3.19 在设置查询接口中返回 `carousel` 字段（JSON 数组，包含图片和视频，保持排序）
- [ ] 3.20 创建数据库迁移脚本，添加自助点餐机设置相关字段

## 约束条件

### 技术约束

#### Go Main 模块

- 必须使用 Gin 框架
- 接口以 `I` 开头，实现以 `Impl` 结尾
- Service 只能依赖其他 Service 接口
- Repository 只能持有 db 实例，不能持有 DBManager
- 不使用 panic，返回 error

### 业务约束

- 需要与旧后台的配置保持一致，确保数据兼容性
- 默认值必须与提案要求一致
- 商品和标签的 `is_show_kiosk` 默认值需根据云平台自助点餐机开启状态动态判断（查询 `company_setting.enable_kiosk` 字段）：已开启则为1，未开启则为0
- 高级密码必须为4-8位整数
- 文件上传需要支持现有的文件存储方案（如 CDN）

### 资源约束

- 开发时间: 3-5 天（仅后端 API）
- Story Point: 5-8 (必须 ≤ 5，可能需要拆分)

## 风险和缓解

### 风险 1: 文件上传功能需要处理图片和视频的格式、大小、尺寸校验

**影响**: 中  
**概率**: 中  
**缓解措施**:

- 后端进行文件格式、大小、尺寸的严格校验
- 复用现有的文件上传和存储方案
- 参考现有文件上传功能的实现

### 风险 2: 轮播内容管理涉及文件存储和 CDN 集成

**影响**: 中  
**概率**: 低  
**缓解措施**:

- 复用现有的文件上传和存储方案
- 确保与现有 CDN 集成兼容

### 风险 3: 需要与旧后台的配置保持一致，避免数据迁移问题

**影响**: 高  
**概率**: 中  
**缓解措施**:

- 在实现前先梳理旧后台的配置项和默认值，确保兼容性
- 进行数据迁移测试
- 提供数据迁移脚本（如需要）

### 风险 4: Story Point 超过 5，需要拆分

**影响**: 高  
**概率**: 高  
**缓解措施**:

- 将功能拆分为多个独立的 Story
- 优先实现核心功能，次要功能后续迭代
- 建议拆分方案（如需要）：
  - Story 1: 商品管理和标签管理的客户端显示配置 API（SP ≤ 5）
  - Story 2: 各端设置 - 自助点餐机基础配置 API（SP ≤ 5）
  - Story 3: 各端设置 - 轮播内容管理 API（SP ≤ 5）
