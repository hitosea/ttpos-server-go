## 📋 概述

为前端"总部-分店颗粒化同步"功能提供后端支持，实现分店可以选择性地同步总部的数据，而不是全量同步。

**核心功能**：
1. 将可同步数据分为三组：
   - **第一组：商品数据**：商品分类、单位、规格、属性、加料、商品、物品分类、成本卡、供应商、税类、仓库、仓库库存、商品库存、商品包图片
   - **第二组：活动数据**：优惠券、满额减、特价菜、菜品标签、邀请消费有礼（营销活动）
   - **第三组：其他数据**：支付方式

2. 提供2个新接口：
   - **获取总部可同步数据列表**：返回三组数据信息，每组包含总部数据列表 + 分店已同步uuid列表 + 是否勾选状态
   - **颗粒化同步数据**：接收勾选的uuid列表，先删除未勾选数据（支付方式除外），再同步勾选数据

**业务价值**：
- 支持分店按需同步总部数据，提升运营灵活性
- 降低数据管理复杂度，减少误操作
- 统一总部数据管理，分店选择性使用

## 数据分组定义

### 第一组：商品数据

包含以下数据类型：
- 商品分类（`product_category`）
- 单位（`product_unit`）
- 规格（`product_flavor`）
- 属性（`product_attribute`、`product_attribute_group`）
- 加料（`product_sauce`）
- 商品（`product_package`）
- 物品分类（`material_category`）
- 成本卡（`product_bom_card`）
- 供应商（`supplier`）
- 税类（`product_tax`）

### 第二组：活动数据

包含以下数据类型：
- 优惠券（`marketing_coupon`）
- 满额减（`full_reduction_activity`）- 有多语言
- 特价菜（`special_price_dish`）- 暂时没有这个数据表
- 菜品标签（`product_label`）
- 邀请消费有礼（`marketing_activity`）- 营销活动，有多语言

### 第三组：其他数据

包含以下数据类型：
- 支付方式（`payment_method`）- **复杂规则**

## 三组数据勾选逻辑

### 商品数据组勾选逻辑

**判断依据**：商品分类、单位、规格、属性、加料、商品、物品分类、成本卡、供应商、税类、仓库、仓库库存、商品库存、商品包图片中是否包含总部数据

**依赖关系**：不依赖活动数据和其他数据

**计算方式**：
- 如果以上任一数据类型中包含总部数据（`headquarter_uuid = 0` 且 `delete_time = 0`），则商品数据组标记为勾选
- 如果以上所有数据类型都不包含总部数据，则商品数据组标记为未勾选

**业务逻辑**：
- **勾选商品数据组**：表示要同步总部商品数据到分店
- **未勾选商品数据组**：表示隐藏子店中已同步的商品数据（通过设置 `delete_time` 标记删除，而不是物理删除）

### 活动数据组勾选逻辑

**判断依据**：优惠券、满额减、特价菜、菜品标签、邀请消费有礼（营销活动）中是否包含总部数据

**依赖关系**：依赖商品数据（如果有 `product_package` 使用了菜品标签）

**计算方式**：
- 如果以上任一数据类型中包含总部数据（`headquarter_uuid = 0` 且 `delete_time = 0`），则活动数据组标记为勾选
- 如果以上所有数据类型都不包含总部数据，则活动数据组标记为未勾选
- **特殊情况**：如果菜品标签关联了商品（通过 `product_package` 表），需要检查关联的商品是否已同步

**业务逻辑**：
- **勾选活动数据组但未勾选商品数据组**：如果活动数据依赖商品数据（例如：菜品标签关联了商品），系统需要返回错误提示："选择的数据正在使用商品数据，请一并勾选所需内容"
- **勾选活动数据组且已勾选商品数据组**：允许同步活动数据

### 支付数据组勾选逻辑

**判断依据**：支付方式是否包含总部数据

**依赖关系**：不依赖活动数据和商品数据

**计算方式**：
- 如果支付方式中包含总部数据（`headquarter_uuid = 0` 且 `delete_time = 0`，且 `code != 40` 和 `code != 10`），则支付数据组标记为勾选
- 如果支付方式中不包含总部数据，则支付数据组标记为未勾选

### Requirement 2: 获取总部可同步数据列表接口

**用户故事**: 作为分店管理员，我想查看总部有哪些可同步的数据，以便选择需要的数据同步到本店

#### 验收标准

1. **WHEN** 分店账号调用接口时 **THEN** 系统 **SHALL** 返回三组数据信息：
   - **商品数据组**：包含商品分类、单位、规格、属性、加料、商品、物品分类、成本卡、供应商、税类、仓库、仓库库存、商品库存、商品包图片
   - **活动数据组**：包含优惠券、满额减、特价菜、菜品标签、邀请消费有礼（营销活动）
   - **其他数据组**：包含支付方式

2. **WHEN** 非分店账号调用接口时 **THEN** 系统 **SHALL** 返回错误提示 "非分店账号无法查看总部数据"

3. **WHEN** 返回每组数据时 **THEN** 系统 **SHALL** 包含以下信息：
   - 组标识（group）：product_data（商品数据）、activity_data（活动数据）、other_data（其他数据）
   - 组名（group_name）：商品数据、活动数据、其他数据
   - 是否已同步（synced）：整个组是否已同步过（分店中是否存在该组的总部数据）
   - 依赖的分组（dependencies）：该组依赖的其他分组标识列表（如：如果product_package表中使用了product_label的值，则活动数据组依赖商品数据组，dependencies应包含"product_data"）

4. **WHEN** 计算是否已同步时 **THEN** 系统 **SHALL** 检查分店中是否存在该组的总部数据（`headquarter_uuid = 总部uuid` 且 `delete_time = 0`）

5. **WHEN** 判断活动数据组是否依赖商品数据组时 **THEN** 系统 **SHALL** 检查product_package表中是否存在使用了product_label的记录（`product_label_uuid > 0` 且 `headquarter_uuid = 0`），如果存在则活动数据组依赖商品数据组

### Requirement 3: 颗粒化同步数据接口

**用户故事**: 作为分店管理员，我想同步勾选的总部数据，以便快速配置营销活动和基础数据

#### 验收标准

1. **WHEN** 分店账号调用接口时 **THEN** 系统 **SHALL** 接收三组数据的勾选状态（只需要提交需要同步的分组，不需要提交具体的uuid列表）

2. **WHEN** 勾选了活动数据组但未勾选商品数据组时 **THEN** 系统 **SHALL** 检查活动数据是否依赖商品数据：
   - 如果活动数据依赖商品数据（例如：菜品标签关联了商品），**THEN** 系统 **SHALL** 返回错误提示："选择的数据正在使用商品数据，请一并勾选所需内容"
   - 如果活动数据不依赖商品数据，**THEN** 系统 **SHALL** 允许同步

3. **WHEN** 商品数据组勾选时 **THEN** 系统 **SHALL** 同步总部商品数据到分店

4. **WHEN** 商品数据组未勾选时 **THEN** 系统 **SHALL** 隐藏子店中已同步的商品数据（通过设置 `delete_time` 标记删除，而不是物理删除）

5. **WHEN** 执行同步时 **THEN** 系统 **SHALL** 先处理未勾选的数据：
   - **商品数据组未勾选**：依次将以下数据标记删除（设置 `delete_time`，不物理删除）：
     1. 商品分类
     2. 单位
     3. 规格
     4. 属性
     5. 加料
     6. 商品
     7. 物品分类
     8. 成本卡
     9. 供应商
     10. 税类
   - **活动数据组未勾选**：依次将以下数据标记删除（设置 `delete_time`，不物理删除）：
     1. 优惠券
     2. 满额减
     3. 特价菜
     4. 菜品标签
     5. 邀请消费有礼（营销活动）
   - **支付数据组未勾选**：不删除子店的支付数据

6. **WHEN** 执行同步时 **THEN** 系统 **SHALL** 再同步勾选的数据到分店，按照以下顺序执行（全量同步，不需要uuid列表）：
   - **商品数据组勾选**：按照以下顺序执行全量同步（使用SyncXxx方法，不需要uuid参数）：
     1. 商品分类（SyncProductShopCategory）
     2. 物品分类（SyncMaterialCategory）
     3. 税类（SyncProductTax）
     4. 单位（SyncUnit）
     5. 物品（SyncMaterial）
     6. 仓库（SyncWarehouse）
     7. 规格（SyncProductFlavor）
     8. 属性（SyncAttributeGroup）
     9. 加料（SyncSauce）
     10. 商品（SyncProduct）
     11. 成本卡（SyncProductBomCard）
     12. 供应商（SyncSupplier）
     13. 仓库库存（SyncWarehouseItemStock）
     14. 商品库存（SyncProductStockByBomCard）
     15. 商品包图片（SyncProductPackageImage）
   - **活动数据组勾选**：按照以下顺序执行全量同步（不需要根据uuid过滤）：
     1. 优惠券（SyncMarketingCoupon）：先硬删除子店中所有总部优惠券，再全量同步
     2. 满额减（SyncFullReduction）：先硬删除子店中所有总部满额减，再全量同步
     3. 特价菜（SyncSpecialPriceDish）：先硬删除子店中所有总部特价菜，再全量同步（暂时没有这个数据表）
     4. 菜品标签（SyncProductLabel）：先硬删除子店中所有总部菜品标签，再全量同步
     5. 邀请消费有礼（SyncMarketingActivity）：先硬删除子店中所有总部营销活动，再全量同步
   - **支付数据组勾选**：执行支付方式全量同步（SyncPaymentMethod，不需要根据uuid过滤，走原来的逻辑）
   - **最后**：执行多语言同步（SyncMultiLanguage）

7. **WHEN** 同步支付方式时 **THEN** 系统 **SHALL** 不删除分店中未勾选的总部数据（支付方式不删除）

8. **WHEN** 同步完成时 **THEN** 系统 **SHALL** 推送 WebSocket 通知

9. **WHEN** 已有同步任务在运行时 **THEN** 系统 **SHALL** 返回错误 "数据同步中，请稍后再试"

## 验收标准

### 功能验收

1. **扩展同步数据类型**: 支持同步三组数据（商品数据、活动数据、其他数据）
2. **获取总部数据列表**: 返回三组数据信息，每组包含总部数据列表 + 分店已同步uuid列表 + 是否勾选状态
3. **三组数据勾选逻辑**: 
   - 商品数据组：根据商品分类、单位、规格、属性、加料、商品、物品分类、成本卡、供应商、税类中是否包含总部数据判断
   - 活动数据组：根据优惠券、满额减、特价菜、菜品标签、邀请消费有礼中是否包含总部数据判断，依赖商品数据
   - 支付数据组：根据支付方式是否包含总部数据判断
4. **商品数据组业务逻辑**: 
   - 勾选：同步总部商品数据到分店
   - 未勾选：隐藏子店中已同步的商品数据（标记删除，不物理删除）
5. **活动数据依赖检查**: 如果勾选了活动数据但依赖商品数据却没勾选商品数据，返回错误提示："选择的数据正在使用商品数据，请一并勾选所需内容"
6. **颗粒化同步**: 根据勾选状态处理数据（商品数据组未勾选时标记删除，活动数据组未勾选时物理删除，支付方式不删除），同步勾选数据
7. **支付方式特殊规则**: 所有规则正确实现（详见测试用例）

### 测试验收

1. **单元测试**: Service 层核心方法测试通过

## 约束条件

- 必须遵循 Go Main 规范（`.cursor/rules/go-main.mdc`）
- Service 只依赖其他 Service 接口
- Repository 使用选项模式
- URL 使用 snake_case

### 业务约束

- 只有分店账号才能执行颗粒化同步
- **商品数据组未勾选时**：隐藏子店中已同步的商品数据（通过设置 `delete_time` 标记删除，而不是物理删除）
- **活动数据依赖检查**：如果勾选了活动数据但依赖商品数据却没勾选商品数据，需要返回错误提示："选择的数据正在使用商品数据，请一并勾选所需内容"
- 支付方式有复杂的同步规则:
  - 不同步 code=40 (现金) 和 code=10 (余额)
  - 特殊code (90111, 90222, 90333) 只更新 headquarter_uuid
  - 普通code同名跳过,不存在则创建
  - 支付方式不删除未勾选数据
- 多语言数据需要一并同步
- 同步任务不能并发执行
