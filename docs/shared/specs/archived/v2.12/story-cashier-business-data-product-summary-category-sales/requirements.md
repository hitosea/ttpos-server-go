## 📋 概述

调整收银机营业数据统计中，按商品统计的【合计】字段和按商品分类统计的【销售额】字段的计算逻辑。

**当前情况**：
- 按商品统计（`/cashier/statistics/product`）返回的 `Subtotal`（合计）字段取值对应为商家后台的原价销售额
- 按商品分类统计（`/cashier/statistics/product_category`）返回的 `Prices`（销售额）字段取值对应为商家后台的原价销售额

**调整目标**：
- 按商品统计的【合计】字段取值更改为对应商家后台的实际销售额（不包含退款金额）
- 按商品分类统计的【销售额】字段取值更改为对应商家后台的实际销售额（不包含退款金额）

**实现范围**：调整后端统计计算逻辑，确保退款金额正确扣减。

## 🎯 产品对齐

- 提升营业数据统计的准确性，确保数据与商家后台一致
- 确保按商品和按商品分类统计的数据一致性
- 提高商户对经营数据的信任度
- 支持更准确的经营分析和决策

## 📝 用户故事

**作为** 商户管理员  
**我想** 查看准确的按商品和按商品分类的营业数据统计（实际销售额，不包含退款）  
**以便于** 准确了解商品销售情况，做出正确的经营决策

## 功能需求

### Requirement 1: 调整按商品统计【合计】字段取值

**用户故事**: 作为商户管理员，我想查看按商品统计的实际销售额（不包含退款），以便于准确了解每个商品的真实销售情况

#### 验收标准

1. **WHEN** 查询按商品统计接口 (`/cashier/statistics/product`) **THEN** 系统 **SHALL** 返回 `Subtotal`（合计）字段为实际销售额（不包含退款金额）
2. **WHEN** 订单发生单品退款 **THEN** 系统 **SHALL** 在按商品统计的【合计】中扣减对应商品的退款金额
3. **WHEN** 订单发生整单退款 **THEN** 系统 **SHALL** 在按商品统计的【合计】中扣减对应商品的退款金额
4. **IF** 商品存在退款记录 **THEN** 系统 **SHALL** 在计算合计时排除退款金额
5. **IF** 商品无退款记录 **THEN** 系统 **SHALL** 返回原价销售额作为合计

#### 具体要求

- [ ] 1.1 调整 `CountProduct` 方法中 `Subtotal`（合计）字段的计算逻辑，从原价销售额改为实际销售额（不包含退款）
- [ ] 1.2 在统计计算中正确处理单品退款，扣减对应商品的退款金额
- [ ] 1.3 在统计计算中正确处理整单退款，扣减对应商品的退款金额
- [ ] 1.4 确保退款金额扣减逻辑与商家后台的实际销售额计算一致
- [ ] 1.5 验证调整后的合计金额与商家后台数据一致

**涉及文件**：
- `main/app/service/business.go` - `CountProduct` 方法
- `main/app/service/statistics.go` - `CountProduct` 方法
- `main/app/repository/statistics.go` - `CountProduct` 方法

### Requirement 3: 打印营业数据使用调整后的取值

**用户故事**: 作为收银员，我想打印准确的营业数据（实际销售额），以便于核对和记录真实的销售情况

#### 验收标准

4. **IF** 打印小票包含分类销售额 **THEN** 系统 **SHALL** 显示实际销售额（不包含退款）

## 验收标准

### 功能验收

1. **按商品统计合计调整**: 查询 `/cashier/statistics/product` 接口，返回的 `Subtotal`（合计）字段应为实际销售额（不包含退款），与商家后台数据一致
2. **按商品分类销售额调整**: 查询 `/cashier/statistics/product_category` 接口，返回的 `Prices`（销售额）字段应为实际销售额（不包含退款），与商家后台数据一致
3. **单品退款扣减**: 当订单发生单品退款时，对应商品的合计和对应分类的销售额应正确扣减退款金额
4. **整单退款扣减**: 当订单发生整单退款时，对应商品的合计和对应分类的销售额应正确扣减退款金额
5. **打印数据一致性**: 打印营业数据时，显示的合计和销售额应与调整后的接口数据一致

### 测试验收

1. **单元测试**: 统计计算逻辑测试覆盖率达标
2. **API 测试**: 所有统计接口测试通过
3. **集成测试**: 退款场景（单品退款、整单退款）测试通过
4. **手动测试**: 验证统计数据与商家后台数据一致性

## 风险和缓解

### 风险 1: 退款金额扣减逻辑不一致

**影响**: 高  
**概率**: 中  
**缓解措施**:

- 详细分析商家后台的实际销售额计算逻辑
- 与商家后台开发团队确认退款扣减规则
- 进行充分的数据对比测试

### 风险 2: 影响现有统计功能

**影响**: 中  
**概率**: 低  
**缓解措施**:

- 仅调整指定字段的计算逻辑，不影响其他统计字段
- 进行全面的回归测试
- 验证其他统计接口的数据准确性

### 风险 3: 打印数据不一致

**影响**: 中  
**概率**: 低  
**缓解措施**:

- 检查所有打印模板的数据来源
- 确保打印数据使用调整后的统计接口
- 进行打印功能测试
