## 📋 概述

实现全平台统一账号体系，通过手机号和邮箱作为唯一标识（两者都全平台唯一），支持员工跨门店复用账号。在云平台、新管理端、收银端、点餐助手、平板端、厨显端等所有终端实现统一的账号管理和门店切换功能。

**核心价值**：
- 提升用户体验：员工无需重复注册账号，一次注册全平台通用
- 简化账号管理：统一管理平台下所有用户，降低管理成本
- 支持多门店运营：员工可以轻松切换不同门店，支持连锁经营场景
- 提高数据一致性：统一账号体系，避免数据分散和重复

## 🎯 产品对齐

该功能支持 TTPOS 平台从 50 商户扩展到 500 商户的规模化目标，通过统一账号体系降低账号管理成本，提升用户体验，支持连锁经营场景。

## 功能需求

### Requirement 1: 云平台人员管理

**用户故事**: 作为云平台管理员，我想统一管理所有TTPOS用户，以便于简化账号管理

#### 验收标准

1. **WHEN** 添加商家时 **THEN** 用户管理中自动生成该商家手机+邮箱为唯一标识的账号
2. **WHEN** 商家为本门店添加员工时 **THEN** 用户管理中自动生成该员工手机+邮箱为唯一标识的账号
3. **WHEN** 云平台管理人员添加用户时 **THEN** 系统验证邮箱格式和唯一性（全平台），验证手机号唯一性（全平台）
4. **IF** 邮箱格式不正确 **THEN** 系统提示"请确认邮箱格式"
5. **IF** 邮箱或手机号在全平台已存在 **THEN** 系统提示"该邮箱/手机号已在平台注册，请使用其他邮箱/手机号"
6. **WHEN** 编辑用户时 **THEN** 不输入密码则为不修改密码
7. **WHEN** 账号关联多个门店时 **THEN** 账号在门店的角色在门店数据库中管理

#### 具体要求

- [ ] 1.1 云平台用户管理板块，增加"人员管理"板块，管理所有使用TTPOS侧的用户
- [ ] 1.2 添加用户功能：
  - 邮箱：最大64位，可输入英文、符号、数字，全平台唯一，需验证邮箱格式
  - 手机号：最长20位，不限制格式，全平台唯一
  - 门店角色：门店为单选，角色为多选（角色从所选门店的角色管理中获取）
- [ ] 1.3 编辑用户功能：可修改登录密码（不输入密码则为不修改）
- [ ] 1.4 已有用户：TTPOS侧的所有用户汇总到"人员管理"功能板块中
- [ ] 1.5 角色权限：在权限中，增加"人员管理"板块控制内容（添加、编辑、状态）

---

### Requirement 2: 新管理端门店和员工管理

**用户故事**: 作为总部管理员，我想管理所有门店和员工，以便于统一管理多门店运营

#### 验收标准

1. **WHEN** 总部登录新管理端 **THEN** 可查看商家所有的门店，并可修改分店内容
2. **WHEN** 上级门店查看员工列表 **THEN** 展示本店及下级门店所有的员工
3. **WHEN** 上级门店编辑员工 **THEN** 可为该员工配置本店及下级门店的角色（门店为单选，角色为多选）
4. **WHEN** 子店查看员工列表 **THEN** 只能查看本店的员工
5. **WHEN** 在门店添加员工时，该手机/邮箱已在其他门店有账号 **THEN** 提示"该账号（xxx@qq.com）已在其他门店注册！可直接导入关联当前门店，支持统一登录切换。"
6. **WHEN** 员工有多个门店权限时 **THEN** 登录时需进行门店选择
7. **IF** 员工只有单店权限 **THEN** 登录后直接进入，无需选择门店
8. **WHEN** 员工页面操作状态 **THEN** 可对员工启用/禁用操作，仅对当前门店有效

#### 具体要求

- [ ] 2.1 门店管理功能：
  - 总部：新增"门店管理"功能，可查看商家所有的门店
  - 可修改分店内容：商家名称、商家LOGO、地址、经纬度、公司名称、联系电话、税号、语言、时区
  - 分店：无此功能
- [ ] 2.2 员工账号管理：
  - 上级门店：展示本店及下级门店所有的员工，可对员工门店及门店角色进行增删查改操作
  - 可进入单个员工详情页，为该员工配置本店及下级门店的角色（门店为单选，角色为多选）
  - 子店：只能对本店的员工进行增删查改操作（现有功能不变）
- [ ] 2.3 账号导入：在门店添加员工时，若该手机/邮箱已在其他门店有账号，则提示导入关联
- [ ] 2.4 门店切换：通过总部员工账号，给员工赋予多个门店的权限，登录TTPOS后，可进行门店切换
- [ ] 2.5 员工状态：员工页面增加"状态"功能，可对员工启用/禁用操作，仅对当前门店有效

### Requirement 3: 各终端门店切换

**用户故事**: 作为员工，我想在多个门店间切换，以便于在不同门店工作

#### 验收标准

1. **WHEN** 员工有多个门店权限时 **THEN** 登录时需进行门店选择
2. **IF** 员工只有单店权限 **THEN** 登录后直接进入，无需选择门店
3. **WHEN** 员工登录后 **THEN** 可进行门店切换

#### 具体要求

- [ ] 3.1 收银端（POS）：支持门店切换功能，登录时门店选择
- [ ] 3.2 点餐助手（Assistant）：支持门店切换功能，登录时门店选择
- [ ] 3.3 平板端（Tablet）：支持门店切换功能，登录时门店选择
- [ ] 3.4 厨显端（KDS）：支持门店切换功能，登录时门店选择
- [ ] 3.5 新管理端：支持门店切换功能，登录时门店选择

## 非功能需求

### 代码架构和模块化

- **分层设计**: 严格遵循 Controller → Service → Repository 分层
- **单一职责原则**: 每个文件应有单一、明确的目的
- **模块化设计**: Service 和 Repository 应独立且可复用
- **依赖管理**: Service 只能依赖其他 Service 接口，不能直接依赖 Repository
- **遵循规范**:
  - `.cursor/rules/go-main.mdc` - Go Main 开发规范
  - `.cursor/rules/vue.mdc` - Vue 前端规范
  - `.cursor/rules/structs.mdc` - 项目结构规范

### API 设计要求

- [ ] URL 使用 snake_case 命名（如：`/api/v1/user_info`）
- [ ] data 字段必须是对象，不能是 null 或数组
- [ ] 分页信息统一放在 meta 中
- [ ] 响应格式：`{code, message, data{}}`
- [ ] 参考: `.cursor/rules/api.mdc` - API 设计规范

### 数据库设计要求

- [ ] 必须包含: `id`, `uuid`, `create_time`, `update_time`, `delete_time`
- [ ] 时间字段使用 int 类型，\_time 结尾，默认值 0
- [ ] 金额字段使用 decimal(20,8)
- [ ] UUID 字段使用 bigint unsigned
- [ ] 表名使用 ttpos\_ 前缀
- [ ] 字段名使用 snake_case

- [ ] **账号-门店关联表**：设计账号与门店的关联关系表

## 约束条件

### 技术约束

#### Go Main 模块

- 必须使用 Gin 框架
- 接口以 `I` 开头，实现以 `Impl` 结尾
- Service 只能依赖其他 Service 接口
- Repository 只能持有 db 实例，不能持有 DBManager
- 不使用 panic，返回 error

#### Vue 模块

- 必须使用 Vue 3 + TypeScript + Vite
- 使用 Element Plus 组件库
- 遵循 `.cursor/rules/vue.mdc`

### 业务约束

- **账号唯一性**: 邮箱和手机号都必须全平台唯一，不能重复
- **角色管理**: 账号在门店的角色在门店数据库中管理，不在云平台统一管理
- **数据迁移**: 需要将现有用户数据迁移到新账号体系，处理重复数据

### 资源约束

- 开发时间: 15-20 天

## 风险和缓解

### 风险 1: 数据迁移风险

**影响**: 高  
**概率**: 中  
**缓解措施**:

- 制定详细的数据迁移方案，处理重复数据（邮箱和手机号都必须全平台唯一）
- 在迁移前进行数据清洗，识别和处理重复账号
- 提供数据迁移回滚机制

### 风险 2: 账号唯一性验证

**影响**: 高  
**概率**: 中  
**缓解措施**:

- 在云平台、新管理端等所有创建/编辑账号的地方，增加邮箱和手机号的全平台唯一性验证
- 使用数据库唯一索引保证唯一性
- 使用分布式锁防止并发创建重复账号

### 风险 3: 角色管理架构

**影响**: 中  
**概率**: 低  
**缓解措施**:

- 设计清晰的账号-门店-角色关联关系，账号在门店的角色在门店数据库中管理
- 充分测试权限体系的兼容性，确保现有功能不受影响

### 风险 4: 多终端同步

**影响**: 中  
**概率**: 中  
**缓解措施**:

- 统一各终端的门店切换交互逻辑，保持一致性
- 提供清晰的用户引导和帮助文档
