## 📋 概述

当订单被标记为"已选"状态后，系统需要在所有相关的数据统计和展示场景中，自动排除这些已选订单的数据，确保各项业务数据的准确性和可靠性。

**核心价值**：
- ✅ **数据准确性**：确保交班、营业数据等关键统计的准确性，避免账务错误
- ✅ **财务管理**：准确的钱箱金额统计，保障资金安全
- ✅ **经营决策**：准确的营业数据支持，帮助商户做出正确的经营决策
- ✅ **操作规范**：清晰的订单状态管理，提升收银操作规范性

## 🎯 产品对齐

本功能支持收银系统的数据管理需求，确保已选订单（通常用于批量操作或数据导出）不会影响日常的财务统计和营业数据分析，提升数据管理的准确性和可靠性。

## 功能需求

### Requirement 1: 打印记录过滤

**用户故事**: 作为收银员，我想已选订单不在打印记录列表中显示，以便于准确管理打印记录

#### 验收标准

1. **WHEN** 查看打印记录列表 **THEN** 系统 **SHALL** 不显示已选订单的整条订单记录

#### 具体要求

- [ ] 1.1 打印记录查询接口需要排除已选订单
- [ ] 1.2 前端打印记录列表不显示已选订单
- [ ] 1.3 已选订单的打印记录不在任何打印相关的统计中显示

### Requirement 2: 交班弹窗数据过滤

**用户故事**: 作为收银员，我想交班时看到准确的统计数据（排除已选订单），以便于正确完成交班操作

#### 验收标准

1. **GIVEN** 备用金 500，现金收入 4500，中途取出 100，中途存入 50，本班已选订单现金收入 200  
   **WHEN** 打开交班弹窗  
   **THEN** 系统 **SHALL** 显示：
   - 当前钱箱现金总计 = 4950 - 200 = 4750
   - 现金收入 = 4500 - 200 = 4300
   - 余额收入 = 原余额收入 - 本班已选订单的余额收入
   - 微信收入 = 原微信收入 - 本班已选订单的微信收入（其他支付方式同理）
   - 退款金额 = 原退款金额 - 本班已选订单的退款金额
   - 本班取出现金 = 原取出现金 + 200
   - 本班遗留金额 = 0

#### 具体要求

- [ ] 2.1 交班统计接口需要排除本班已选订单的现金收入
- [ ] 2.2 交班统计接口需要排除本班已选订单的余额收入
- [ ] 2.3 交班统计接口需要排除本班已选订单的其他支付方式收入（微信、支付宝等）
- [ ] 2.4 交班统计接口需要排除本班已选订单的退款金额
- [ ] 2.5 本班取出现金需要加上本班已选订单的现金收入
- [ ] 2.6 本班遗留金额需要排除已选订单的影响，显示为 0
- [ ] 2.7 前端交班弹窗正确显示过滤后的统计数据

## 风险和缓解

### 风险 1: 数据一致性风险

**影响**: 高  
**概率**: 中  
**缓解措施**:

- 建立统一的订单状态过滤机制，确保所有查询场景一致
- 充分测试各种业务场景，包括边界情况
- 提供数据对比功能，便于验证统计准确性

### 风险 2: 历史数据影响

**影响**: 中  
**概率**: 低  
**缓解措施**:

- 明确已选订单的判断标准
- 考虑历史数据的迁移或处理方案
- 提供数据修复工具（如需要）

### 风险 3: 性能影响
