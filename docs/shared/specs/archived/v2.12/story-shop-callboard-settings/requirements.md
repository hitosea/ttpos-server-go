## 📋 概述

在新管理端（Shop 商家管理端）新增叫号系统配置管理功能，允许商户管理员设置叫号系统的名称、背景图片、超时限制、语音叫号开关、叫号内容和叫号次数等配置项。配置保存后，QDS 端（排号叫号端）将读取这些配置并应用到叫号展示中。

同时，扩展叫号设备管理功能，为每个叫号设备增加名称字段，支持商户自定义设备名称，便于识别和管理多个叫号设备。

该功能将显著提升商户对叫号系统的个性化配置能力，增强品牌展示效果，优化叫号流程，提升顾客体验。

## 🎯 产品对齐

该功能支持 TTPOS 产品的核心定位：**收银 + ERP + 会员 + 外卖**中的收银模块，通过完整的叫号系统配置管理，提升商户自主运营能力，增强品牌识别度，优化顾客排队等待体验。

## 📝 用户故事

**作为** 商户管理员  
**我想** 在新管理端设置叫号系统的名称、背景图片、超时限制、语音叫号开关、叫号内容和叫号次数，以及为每个叫号设备设置名称  
**以便于** 个性化展示品牌形象，优化叫号流程，提升顾客体验，便于管理多个叫号设备

## 功能需求

### Requirement 1: 叫号系统配置管理 API

**用户故事**: 作为商户管理员，我想通过 API 设置叫号系统的各项配置，以便于个性化展示品牌形象和优化叫号流程

#### 验收标准

1. **WHEN** 调用叫号系统配置保存 API **THEN** 系统 **SHALL** 保存配置到数据库
2. **WHEN** 调用叫号系统配置查询 API **THEN** 系统 **SHALL** 返回当前已保存的配置项
3. **IF** 必填字段未填写 **THEN** 系统 **SHALL** 返回错误信息（code != 0）
4. **WHEN** 配置保存成功 **THEN** 系统 **SHALL** 实时同步配置到 QDS 端（通过缓存或事件通知）

#### 具体要求

- [ ] 1.1 API 请求字段：叫号系统名称（版本 >= 2.11.0 时必填）、背景图片 URL（可选，可传空字符串）、超时限制（分钟，可选）、语音叫号开关（启用/关闭，可选）、叫号次数（版本 >= 2.11.0 时必填，最小1，最大3）
- [ ] 1.2 API 响应格式：`{code, message, data: {callboard_setting: {}}}`
- [ ] 1.3 配置存储：使用 `setting` 表，key 为 `callboard`，values 为 JSON 格式
- [ ] 1.4 配置查询接口：`GET /api/v1/shop/setting/callboard`
- [ ] 1.5 配置保存接口：`POST /api/v1/shop/setting/callboard`

---

### Requirement 2: 背景图片管理

**用户故事**: 作为商户管理员，我想上传并设置叫号系统的背景图片，以便于展示品牌形象

#### 验收标准

1. **WHEN** 商户管理员上传背景图片并保存 **THEN** 系统 **SHALL** 保存图片 UUID 并在 QDS 端显示新的背景
2. **IF** 背景图片 URL 为空字符串 **THEN** 系统 **SHALL** 允许保存空值（可选字段）
3. **IF** 客户端版本 >= 2.11.0 **THEN** 系统 **SHALL** 对 `name` 和 `call_count` 进行必填校验
4. **IF** 客户端版本 < 2.11.0 **THEN** 系统 **SHALL** 不进行参数校验，所有字段均为可选
5. **IF** 上传的图片格式不是 JPEG/PNG/WEBP **THEN** 系统 **SHALL** 返回错误提示
4. **IF** 上传的图片大小超过 20MB **THEN** 系统 **SHALL** 返回错误提示
5. **WHEN** 背景图片保存成功 **THEN** 系统 **SHALL** 实时同步至叫号系统（QDS 端）
6. **WHEN** QDS 端显示背景图片 **THEN** 系统 **SHALL** 对超出尺寸部分进行横/纵拉伸（参考收银机副屏实现）
7. **IF** QDS 端读取配置时背景图片 UUID 对应的图片不存在 **THEN** 系统 **SHALL** 使用默认图片（当前叫号系统背景图，逻辑与商品图片一致）

#### 具体要求

- [ ] 2.1 图片格式支持：JPEG、PNG、WEBP
- [ ] 2.2 图片大小限制：小于 20MB
- [ ] 2.3 图片上传：复用现有图片上传服务（`main/app/service/upload_file.go`）
- [ ] 2.4 默认图片处理：QDS 端读取配置时，如果图片 UUID 对应的图片不存在，使用默认图片（参考商品图片默认图片逻辑 `admin/views/shop/src/directive/index.js` - `v-img-url` 指令）
- [ ] 2.5 图片拉伸：参考收银机副屏背景图片拉伸实现（CSS `background-size: cover` 或类似方式）
- [ ] 2.6 实时同步：配置保存后通过缓存更新或事件通知机制同步到 QDS 端

---

### Requirement 3: 叫号设备名称管理

**用户故事**: 作为商户管理员，我想为每个叫号设备设置名称，以便于识别和管理多个叫号设备

#### 验收标准

1. **WHEN** 商户管理员绑定叫号设备时设置名称 **THEN** 系统 **SHALL** 保存设备名称
2. **WHEN** 商户管理员更新叫号设备信息时修改名称 **THEN** 系统 **SHALL** 更新设备名称
3. **IF** 客户端版本 >= 2.11.0 且设备名称为空 **THEN** 系统 **SHALL** 返回错误提示："请输入名称"
4. **IF** 客户端版本 >= 2.11.0 且设备名称超过 20 个字符 **THEN** 系统 **SHALL** 返回错误提示
5. **IF** 客户端版本 < 2.11.0 **THEN** 系统 **SHALL** 不进行参数校验，设备名称为可选
6. **IF** 查询已添加的设备且名称为空 **THEN** 系统 **SHALL** 返回默认名称："WALLACE"

#### 具体要求

- [ ] 3.1 扩展 `BindDeviceReq`：增加 `name` 字段（可选，版本 >= 2.11.0 时必填，最大长度 20 字符）
- [ ] 3.2 扩展 `UpdateBindInfoReq`：增加 `name` 字段（可选，版本 >= 2.11.0 时必填，最大长度 20 字符）
- [ ] 3.3 名称校验：版本 >= 2.11.0 时进行参数验证，空值返回错误提示："请输入名称"
- [ ] 3.4 名称长度限制：最大 20 字符，版本 >= 2.11.0 时进行校验
- [ ] 3.5 版本兼容：版本 < 2.11.0 时不进行参数校验，所有字段可选
- [ ] 3.6 默认名称：已添加设备名称为空时，返回默认名称 "WALLACE"（在响应中处理）
- [ ] 3.7 数据库存储：扩展设备表或缓存结构，存储设备名称
- [ ] 3.8 设备列表接口：`GET /api/v1/shop/callboard/device/list` 返回设备名称

---

### Requirement 4: 叫号系统配置项

**用户故事**: 作为商户管理员，我想设置叫号系统的各项配置参数，以便于优化叫号流程

#### 验收标准

1. **WHEN** 商户管理员设置叫号系统名称并保存 **THEN** 系统 **SHALL** 保存配置并在 QDS 端显示新的名称
2. **IF** 客户端版本 >= 2.11.0 且叫号系统名称为空 **THEN** 系统 **SHALL** 返回错误提示（必填字段校验）
3. **IF** 客户端版本 < 2.11.0 **THEN** 系统 **SHALL** 不进行参数校验，名称为可选
4. **WHEN** 商户管理员设置超时限制为 X 分钟并保存 **THEN** 系统 **SHALL** 保存配置并在叫号超时 X 分钟后自动处理
5. **WHEN** 商户管理员关闭语音叫号开关并保存 **THEN** 系统 **SHALL** 保存配置并在 QDS 端禁用语音叫号
6. **WHEN** 商户管理员设置叫号次数为 N 次并保存 **THEN** 系统 **SHALL** 保存配置并在达到 N 次后停止叫号
7. **IF** 客户端版本 >= 2.11.0 且叫号次数小于 1 或大于 3 **THEN** 系统 **SHALL** 返回错误提示
8. **IF** 客户端版本 < 2.11.0 **THEN** 系统 **SHALL** 不进行参数校验，叫号次数为可选，使用默认值 1
9. **IF** 商户管理员未设置可选配置项（超时限制、语音叫号开关） **THEN** 系统 **SHALL** 使用默认值

#### 具体要求

- [ ] 4.1 叫号系统名称：文本输入，版本 >= 2.11.0 时必填，最大长度限制待定
- [ ] 4.2 超时限制：数字输入框，单位分钟，设置范围限制（如 1-60 分钟），可选，默认值待定
- [ ] 4.3 语音叫号开关：布尔值，启用/关闭，可选，默认值待定
- [ ] 4.4 叫号次数：数字输入框，版本 >= 2.11.0 时必填，最小值 1，最大值 3
- [ ] 4.5 版本兼容：版本 < 2.11.0 时所有字段可选，不进行参数校验
- [ ] 4.6 默认值处理：可选配置项缺失时使用合理的默认值（call_count 默认为 1）

- **分层设计**: 严格遵循 Controller → Service → Repository 分层

## 验收标准

### 功能验收

1. **叫号系统配置保存**: 能够成功保存所有配置项（名称、背景图片、超时限制、语音叫号开关、叫号次数），必填字段校验通过
2. **叫号系统配置查询**: 能够查询并返回已保存的配置项
3. **背景图片上传**: 支持 JPEG/PNG/WEBP 格式，大小限制 20MB，未设置时使用默认图片
4. **背景图片实时同步**: 配置保存后 QDS 端能够实时获取新的背景图片
5. **背景图片拉伸**: QDS 端显示时超出尺寸部分能够正确拉伸
6. **设备名称设置**: 绑定和更新设备时能够设置名称（必填，最大 20 字符）
7. **设备名称校验**: 名称为空时返回错误提示："请输入名称"
8. **设备名称默认值**: 已添加设备名称为空时返回默认名称 "WALLACE"
9. **叫号次数校验**: 叫号次数必填，范围 1-3，超出范围返回错误提示

2. **API 测试**: 所有接口测试通过

4. **手动测试**: 浏览器兼容性测试通过

## 约束条件

### 技术约束

#### Go Main 模块

- 必须使用 Gin 框架
- 接口以 `I` 开头，实现以 `Impl` 结尾
- Service 只能依赖其他 Service 接口
- Repository 只能持有 db 实例，不能持有 DBManager
- 不使用 panic，返回 error

#### Go BMP 模块

- 不涉及

#### PHP 模块

- 不涉及

#### Vue 模块

- 不涉及（本次仅开发后端 API）

- 配置项均为可选，需要提供合理的默认值
- 设备名称必填，但已存在设备需要兼容处理（返回默认值）
- 背景图片需要实时同步到 QDS 端

### 资源约束

- 开发时间: 3-5 天
- Story Point: 5 SP (必须 ≤ 5)

## 风险和缓解

### 风险 1: 配置实时同步延迟

**影响**: 中  
**概率**: 中  
**缓解措施**:

- 使用 Redis 缓存存储配置，QDS 端通过轮询或 WebSocket 获取更新
- 配置保存后立即更新缓存，确保实时性
- 设置合理的缓存过期时间

### 风险 2: 已存在设备名称兼容性

**影响**: 低  
**概率**: 高  
**缓解措施**:

- 在响应中处理：查询设备时，如果名称为空，返回默认名称 "WALLACE"
- 不影响现有设备绑定逻辑，向后兼容

### 风险 3: 背景图片拉伸效果不一致

**影响**: 中  
**概率**: 中  
**缓解措施**:

- 参考收银机副屏的实现方式（CSS `background-size: cover`）
- 前端统一处理图片显示逻辑
- 提供图片尺寸建议（在文档中说明）
