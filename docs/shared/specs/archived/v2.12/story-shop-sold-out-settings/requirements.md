## 📋 概述

建立统一的沽清判断机制，支持灵活的库存管理策略。在收银机、点餐助手、平板、扫码点餐、会员端、自助点餐机、Grab外卖的下单、送厨、结账环节，统一根据沽清设置进行库存判断。支持通过可售量控制商品售卖，支持负库存场景，优化库存计算逻辑。

## 🎯 产品对齐

该功能支持以下业务目标：

- **提升库存管理灵活性**：支持通过可售量控制商品售卖，满足不同场景需求
- **支持负库存场景**：允许在特定条件下产生负库存，入库后自动弥补，提升售卖连续性
- **统一沽清判断逻辑**：所有终端统一使用沽清设置进行库存判断，保证数据一致性
- **优化库存计算**：明确进销存计算与可售量的关系，支持关闭进销存时的灵活售卖
- **提升用户体验**：减少因库存限制导致的订单失败，提升顾客满意度

## 📝 用户故事

**作为** 收银员  
**我想** 在收银端设置商品的沽清规则（售罄、可售量、进销存计算）  
**以便于** 灵活控制商品的售卖策略，满足不同业务场景需求

**作为** 收银员/顾客  
**我想** 在下单时系统自动根据沽清设置判断商品是否可售  
**以便于** 避免超卖，提升订单成功率

**作为** 商户管理员  
**我想** 在特定场景下允许负库存  
**以便于** 在关闭进销存计算时仍能正常售卖，后续通过入库弥补负库存

## 功能需求

### Requirement 1: 新增接口 - 获取商品沽清设置信息

**用户故事**: 作为前端开发者，我想通过接口获取每个规格的沽清设置信息，以便于在弹窗中展示和编辑

#### 验收标准

1. **WHEN** 前端调用商品沽清设置信息接口 **THEN** 系统 **SHALL** 返回每个规格的完整沽清设置信息
2. **WHEN** 商品配置了成本卡 **THEN** 系统 **SHALL** 返回根据成本卡计算的库存
3. **WHEN** 商品未配置成本卡 **THEN** 系统 **SHALL** 返回是否使用成本卡库存为 false
4. **WHEN** 商品设置了可售量 **THEN** 系统 **SHALL** 返回可售数量

#### 具体要求

- [ ] 1.1 创建新接口 `/cashier/sold_out/settings` (GET)
- [ ] 1.2 接口返回每个规格的沽清设置信息，包括：
  - 是否使用成本卡库存 (`use_bom_card_stock`)
  - 根据成本卡计算的库存 (`bom_card_stock_num`)
  - 是否标记售罄 (`is_sold_out`)
  - 是否设置可售量 (`has_sellable_quantity`)
  - 可售数量 (`sellable_quantity`)
- [ ] 1.3 实现成本卡库存计算逻辑（如商品配置了成本卡）
- [ ] 1.4 创建对应的 Request DTO (`GetSoldOutSettingsReq`)
- [ ] 1.5 创建对应的 Response DTO (`SoldOutSettingsResp`)

---

### Requirement 2: 修改接口 - 添加沽清商品（增加可售量参数）

**用户故事**: 作为收银员，我想在设置沽清时配置可售量和进销存计算选项，以便于灵活控制商品售卖

#### 验收标准

1. **WHEN** 调用 `/cashier/sold_out/add` 接口，传入可售量参数 **THEN** 系统 **SHALL** 保存可售量设置
2. **WHEN** 调用 `/cashier/sold_out/add` 接口，传入是否使用成本卡库存参数 **THEN** 系统 **SHALL** 保存该设置
3. **WHEN** 设置可售量后下单 **THEN** 系统 **SHALL** 扣减可售量
4. **WHEN** 设置可售量且配置成本卡后下单 **THEN** 系统 **SHALL** 同时扣减可售量和库存

#### 具体要求

- [ ] 2.1 修改 `SoldOutItem` DTO，增加字段：
  - `use_bom_card_stock` (bool, 可选) - 是否使用成本卡库存
  - `has_sellable_quantity` (bool, 可选) - 是否设置可售量
  - `sellable_quantity` (float64, 可选) - 可售数量
- [ ] 2.2 修改 `AddSoldOut` Service 方法，支持保存新字段
- [ ] 2.3 在 `ProductBom` 表中新增字段：
  - `use_bom_card_stock` (INT(1), default 1) - 是否使用成本卡库存，默认使用
  - `has_sellable_quantity` (INT(1), default 0) - 是否开启可售量，默认不开启
  - `sellable_quantity` (DECIMAL(22,4), default 0.0000) - 可售数量
- [ ] 2.4 创建数据库迁移文件（如需要）

### Requirement 3: 统一沽清判断逻辑 - 下单/送厨/结账

**用户故事**: 作为系统，我想在所有终端的下单、送厨、结账环节统一使用沽清设置进行库存判断，以便于保证数据一致性

#### 验收标准

1. **WHEN** 未配置成本卡且设置了可售量 **THEN** 系统 **SHALL** 通过可售量进行售卖，下单扣减可售量
2. **WHEN** 已配置成本卡且设置了可售量且库存不足且不允许负库存 **THEN** 系统 **SHALL** 不允许售卖（使用库存不足提示）
3. **WHEN** 已配置成本卡且设置了可售量且库存不足但允许负库存 **THEN** 系统 **SHALL** 允许售卖，下单扣减可售量和库存
4. **WHEN** 未设置售罄和可售量且允许负库存 **THEN** 系统 **SHALL** 在所有端展示可继续下单

#### 具体要求

- [ ] 3.1 修改订单创建逻辑，统一使用沽清设置判断
- [ ] 3.2 修改送厨逻辑，统一使用沽清设置判断
- [ ] 3.3 修改结账逻辑，统一使用沽清设置判断
- [ ] 3.4 实现可售量扣减逻辑
- [ ] 3.5 实现成本卡库存计算和扣减逻辑
- [ ] 3.6 实现负库存判断逻辑（允许负库存场景）
- [ ] 3.7 更新商品库存查询逻辑，支持可售量显示

## 详细验收标准 (from DooTask 37487)

### 下单、送厨、结账环节

**Given 不配置成本卡**  
1. 开启售罄，则不可再售卖（注意：下单减库存/结账减库存，是下单减库存的，先下单再售罄再结账，允许）  
2. 关闭售罄，则无限售卖  
3. 关闭售罄，设置可售量，则只允许售卖可售量数量（售卖需扣减可售，注意：下单减库存/结账减库存，是下单减库存的，先下单再售罄再结账，允许）  

**Given 配置成本卡**  
1. 开启进销存计算，则根据物品库存判断库存  
2. 关闭进销存计算，开启售罄，则不可再售卖  
3. 关闭进销存计算，关闭售罄，则无限售卖  
4. 关闭进销存计算，关闭售罄，设置可售量，则只允许售卖可售量数量（售卖需扣减可售）  

**Given 开启or关闭或进行售罄、可售**  
**Then** 需要重新计算库存  

**注：**  
1. 关闭进销存时，只是不采用进销存计算来计算库存可售，需根据设置的可售量进行售卖，此时可能会产生负库存  
2. 示例：十翅制作需要10个鸡翅，目前鸡翅库存10。收银机关闭十翅桶的通过进销存计算，并售卖了2份十翅桶，则10-10-10=-10库存，在出入库明细中照常出库20，在鸡翅的库存将显示-10  
3. 以往未配置成本卡的，默认不配置成本卡，关闭售罄，无限售卖  
4. 负库存由物品控制，如A商品需要a跟b物品，a物品无库存但允许负库存，b物品无库存不允许负库存，则A商品因b库存不足不可售卖
