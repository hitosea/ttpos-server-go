# story-shop-import-grab-products / 技术设计（待评审）

## 1. 背景与目标
- 基于 Proposal 与 Requirements：从 Grab 拉取商品，支持映射或自动创建店内商品，建立 Grab-店内关联，支持分类/规格/属性/单位的选择或自动创建，多语言转换与幂等。

## 2. 范围与模块
- 后端：Go Main（Shop 管理端）。
- 依赖：
  - Grab 数据获取：通过 bmp 的 takeout RPC（待提供接口：GetGrabMenu / GetGrabBindingStatus / GetGrabBindingLink 或专用商品拉取接口）。
  - 翻译服务：已有多语言翻译服务。
  - 商品/分类/规格/属性/单位的现有服务与仓储。

## 3. 业务与数据流程（概要）
1) 拉取 Grab 商品列表（含分类/规格/属性/单位等元数据）。
2) 前端展示映射表单：为每个 Grab 商品选择店内商品；未选择时自动创建店内商品（默认下架，Grab 端保持可用）。
3) 分类/规格/属性/单位：可选择已有；未选则自动创建，名称翻译为本地语言（翻译失败回退原文并标记）。
4) 保存映射关系，返回结果（成功/失败明细、自动创建对象列表）。

## 4. 接口设计（后端）
- `POST /shop/takeout/menu/import`（已落地）：接收导入请求，调用应用服务完成导入。
- 需要新增/对接：
  - Grab 商品拉取接口：由 bmp 暴露 RPC，返回分页商品列表及分类/规格/属性/单位。
  - 翻译接口：沿用现有翻译服务。

## 5. 领域与数据模型
- 复用现有模型：
  - 商品、分类、规格/变体、属性组/属性值、单位。
  - 外卖商品与店内商品的关联（Grab 侧唯一键 + companyUuid）。
- 新增/补充：
  - 映射表（若现有不足）：grab_product_id ↔ product_package_uuid，带 company_uuid、状态、更新时间。
  - 导入结果记录（可选）：操作人、时间、成功/失败数量、明细。

## 6. 关键规则与幂等
- 幂等键：Grab 商品唯一 ID + companyUuid。
- 已有关联则不重复创建；允许更新映射。
- 自动创建的对象（分类/规格/属性/单位/商品）需先查重：同名/同 uuid/同唯一键避免重复。
- 翻译失败回退原文，并在结果中标记。

## 7. 多语言与翻译
- 输入：Grab 返回的多语言名称；若缺失，使用主名称。
- 翻译链路：调用翻译服务 -> 失败则原文回退 -> 在结果中标记待人工确认。

## 8. 错误处理与结果
- 校验 Grab 数据结构与必填字段，异常中止本批次并返回错误。
- 返回导入结果：成功/失败列表、自动创建对象清单、失败原因。

## 9. 安全与权限
- 路由挂在 `/shop`，使用 shop Auth 中间件；仅有权限的店内管理员可调用。

## 10. 影响与风险
- 依赖 bmp RPC 提供稳定商品拉取接口。
- 翻译服务可用性与时延。
- 批量导入性能：单次至少 500 条；需分页拉取、分批写入，必要时使用事务+批量插入。

## 11. 开发计划（参考）
- 接口对接：确定 bmp RPC 协议、请求参数与响应结构。
- 应用服务：拉取→映射/创建→关联→结果。
- 仓储：增加映射查询/幂等校验；必要时新增关联表。
- 多语言：统一封装翻译调用，返回标记。
- 返回结构：成功/失败/自动创建对象列表。

## 12. 验收要点（与 AC 对齐）
- 拉取列表分页正常，含分类/规格/属性/单位。
- 未选择店内商品时自动创建，默认下架；已选则仅建关联。
- 未选的分类/规格/属性组/属性值/单位自动创建并翻译（失败回退原文标记）。
- 幂等：重复导入不重复创建。
- 结果返回包含成功/失败/自动创建明细。
