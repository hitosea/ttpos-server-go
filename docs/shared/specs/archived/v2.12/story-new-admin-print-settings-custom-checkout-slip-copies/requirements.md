## 📋 概述

当前收银结账单打印联数只能按照打印机硬件设置的联数进行打印，无法灵活配置。实际业务场景中：

- **第一份给客户**：作为消费凭证，客户需要保留
- **第二份商家留存**：作为内部记录，用于后续核对

但不同商户对打印联数的需求不同，有些商户只需要打印一份给客户，有些需要多份用于不同用途。本功能旨在在新管理端增加打印设置，允许商户管理员自定义收银结账单的打印联数（0-10份），配置后立即生效，满足不同业务场景的打印需求。

## 🎯 产品对齐

该功能支持公司提升商户满意度的核心目标：

- **提升灵活性**：满足不同商户的打印需求（客户凭证、商家留存等）
- **减少浪费**：当商户只需要1份时，避免不必要的纸张浪费
- **增强竞争力**：灵活的打印配置是商户选择的重要因素
- **支持管理**：多联打印可用于不同部门的管理需求

## 功能需求

### Requirement 1: 角色权限管理

**用户故事**: 作为系统管理员，我想在"餐厅设置"下增加"打印设置"权限，以便于控制商户管理员对打印设置的访问权限

#### 验收标准

1. **WHEN** 系统管理员查看角色权限配置 **THEN** 系统 **SHALL** 在"餐厅设置"下显示"打印设置"权限选项
2. **WHEN** 创建新角色 **THEN** 系统 **SHALL** 默认勾选"打印设置"权限
3. **WHEN** 商户管理员无"打印设置"权限 **THEN** 系统 **SHALL** 隐藏打印设置入口

#### 具体要求

- [ ] 1.1 在权限表中增加"打印设置"权限项
- [ ] 1.2 新角色创建时默认勾选该权限
- [ ] 1.3 前端路由和菜单根据权限控制显示

---

### Requirement 2: 打印设置配置页面

**用户故事**: 作为商户管理员，我想在"工作台-餐厅管理"中配置打印联数设置，以便于自定义结账单打印联数

#### 验收标准

1. **WHEN** 商户管理员在新管理端"打印设置"中关闭"打印联数设置" **THEN** 系统 **SHALL** 保存配置，结账单按照打印机打印联数打印
2. **WHEN** 商户管理员开启"打印联数设置"并设置联数为 N（0-10） **THEN** 系统 **SHALL** 保存配置并同步到 POS/Assistant 端
3. **WHEN** 商户管理员开启"打印联数设置"但未填写结账单打印联数 **THEN** 系统 **SHALL** 在输入框下方提示"请输入打印联数"
4. **WHEN** 商户管理员输入非 0-10 的整数 **THEN** 系统 **SHALL** 提示错误并阻止保存
5. **WHEN** 商户管理员设置联数为 0 **THEN** 系统 **SHALL** 保存配置，结账时不打印结账单（仅电子记录）

#### 具体要求

- [ ] 2.1 在"工作台-餐厅管理"中增加"打印设置"入口
- [ ] 2.2 创建打印设置配置页面（Vue组件）
- [ ] 2.3 支持"票据类型打印联数设置"开关（默认关闭）
- [ ] 2.4 开启后显示结账单打印联数输入框
- [ ] 2.5 输入框支持0-10的整数输入
- [ ] 2.6 输入验证：非整数或超出范围时提示错误
- [ ] 2.7 创建打印设置保存API接口
- [ ] 2.8 配置数据存储到数据库
- [ ] 2.9 配置变更后同步到POS/Assistant端（通过配置同步机制）

---

### Requirement 3: POS/Assistant 端打印逻辑

**用户故事**: 作为收银员，我想在结账时按照配置的联数打印结账单，以便于满足商户的打印需求

#### 验收标准

6. **WHEN** 收银员在 POS/Assistant 端完成结账 **THEN** 系统 **SHALL** 根据配置的联数打印对应数量的收银结账单
7. **WHEN** 配置的联数为 0 **THEN** 系统 **SHALL** 不打印结账单，仅保存电子记录
8. **WHEN** 收银员补打结账单（打印小票） **THEN** 系统 **SHALL** 按照收银打印设置中配置的联数打印
9. **WHEN** 多语言打印结账单 **THEN** 系统 **SHALL** 所有语言的结账单打印联数完全一致

#### 具体要求

- [ ] 3.1 修改结账打印逻辑，读取打印联数配置
- [ ] 3.2 根据配置的联数循环打印结账单
- [ ] 3.3 联数为0时跳过打印，仅保存电子记录
- [ ] 3.4 修改补打结账单逻辑，使用相同的打印联数配置
- [ ] 3.5 确保多语言打印时使用相同的联数配置
- [ ] 3.6 打印时记录打印联数到日志（用于问题排查）

---

### Requirement 4: 优先级规则

**用户故事**: 作为系统，我想按照优先级规则确定打印联数，以便于保证配置的优先级正确

#### 验收标准

10. **WHEN** 收银打印设置-结账单打印联数已配置 **THEN** 系统 **SHALL** 优先使用该配置，忽略打印设置-打印机打印联数
11. **WHEN** 收银打印设置-结账单打印联数未配置（关闭） **THEN** 系统 **SHALL** 使用打印设置-打印机打印联数

#### 具体要求

- [ ] 4.1 实现打印联数优先级判断逻辑
- [ ] 4.2 优先级：收银打印设置-结账单打印联数 > 打印设置-打印机打印联数
- [ ] 4.3 在打印服务中应用优先级规则

---

### Requirement 5: 配置生效机制

**用户故事**: 作为商户管理员，我想配置变更后立即生效，以便于快速应用新的打印设置

#### 验收标准

12. **WHEN** 配置变更后 **THEN** 系统 **SHALL** 立即生效，影响后续所有新打印的订单
13. **WHEN** 配置变更后 **THEN** 系统 **SHALL** 不影响已打印的订单

#### 具体要求

- [ ] 5.1 配置保存后立即更新缓存（Redis）
- [ ] 5.2 配置变更后通知POS/Assistant端刷新配置
- [ ] 5.3 确保配置读取时优先从缓存获取
- [ ] 5.4 配置变更不影响已打印的历史订单

## 非功能需求

### 代码架构和模块化

- **分层设计**: 严格遵循 Controller → Service → Repository 分层
- **单一职责原则**: PrintSettingService 专注打印设置逻辑，PrintService 专注打印执行逻辑
- **模块化设计**: 打印设置配置和打印执行逻辑分离，便于维护
- **依赖管理**: PrintService 依赖 IPrintSettingService 接口获取配置
- **遵循规范**:

## 风险和缓解

### 风险 1: 打印联数配置与打印机硬件联数不匹配

**影响**: 中  
**概率**: 中  
**缓解措施**:

- 在配置时进行合理性校验，提示用户打印机硬件联数
- 配置保存时记录警告日志
- 打印时如果配置联数超过硬件联数，使用硬件联数并记录日志

### 风险 2: 多语言打印时联数配置的一致性保证

**影响**: 中  
**概率**: 低  
**缓解措施**:

- 确保多语言打印使用相同的打印联数配置
- 在打印服务中统一读取配置，不区分语言
- 增加单元测试验证多语言打印联数一致性

### 风险 3: 配置同步延迟导致打印联数不一致

**影响**: 中  
**概率**: 低  
**缓解措施**:

- 配置变更后立即更新缓存
- 配置变更后通知POS/Assistant端刷新配置
- 打印时优先从缓存读取，缓存失败时降级到数据库

### 风险 4: 补打功能需要兼容新的打印联数规则

**影响**: 低  
**概率**: 低  
**缓解措施**:

- 补打功能复用相同的打印联数计算逻辑
- 增加补打功能的单元测试和集成测试
