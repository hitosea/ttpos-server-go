## 📋 概述

当前系统在总店删除已被子店同步并使用的资源（规格、属性组、属性、加料、单位、商品）时，存在以下问题：

1. **提示不准确**：子店正在使用资源时，删除仍提示"删除成功"
2. **信息不完整**：未明确列出哪些子店正在使用该资源
3. **业务规则不清晰**：未明确区分"正在使用"和"已取消使用"的情况

本需求旨在优化总店删除资源时的后端验证逻辑和 API 响应，确保：
- 子店正在使用时禁止删除，并返回使用的子店名称列表
- 子店已取消使用时允许删除
- API 返回清晰、准确的错误信息和数据

**⚠️ 架构关键**：本项目每个门店有独立数据库，需采用跨数据库并发查询方案。

**📦 范围说明**：
- ✅ **包含**：Go Main 后端实现（Repository、Service、API）
- ❌ **不包含**：Vue 前端实现（由前端开发者负责）
- ❌ **不包含**：ERP 同步实现（由 ERP 集成开发者负责）

## 🎯 产品对齐

本功能支持以下产品目标：

1. **数据一致性保障**：防止总店误删除子店正在使用的资源，避免子店业务异常
2. **用户体验优化**：提供清晰的错误提示，帮助用户了解删除失败的原因
3. **总分店协同**：确保总店和子店之间的数据关系清晰可控
4. **ERP 集成**：自动同步删除状态到 ERP 系统

## 功能需求

### Requirement 1: 总店删除资源时检查子店使用情况

**用户故事**: 作为总店管理员，我想在删除被子店使用的资源时得到明确的失败提示和完整的子店列表，以便于避免误删除导致子店业务异常

**前置条件**: **仅当总店删除资源时触发检查**，子店删除自己的资源无需检查。

#### 验收标准

1. **WHEN** 总店管理员尝试删除规格 **AND** 该规格被至少一个子店商品关联（无论售罄/下架状态） **THEN** 系统 **SHALL** 阻止删除并返回所有使用该规格的子店名称列表
2. **WHEN** 总店管理员尝试删除属性组 **AND** 该属性组被至少一个子店商品关联 **THEN** 系统 **SHALL** 阻止删除并提示：`删除失败，子店1、子店2、子店3正在使用该属性组`
3. **WHEN** 总店管理员尝试删除属性 **AND** 该属性被至少一个子店商品关联 **THEN** 系统 **SHALL** 阻止删除并提示：`删除失败，子店1、子店2、子店3正在使用该属性值`
4. **WHEN** 总店管理员尝试删除加料 **AND** 该加料被至少一个子店商品关联 **THEN** 系统 **SHALL** 阻止删除并提示：`删除失败，子店1、子店2、子店3正在使用该加料`
5. **WHEN** 总店管理员尝试删除单位 **AND** 该单位被至少一个子店商品关联 **THEN** 系统 **SHALL** 阻止删除并提示：`删除失败，子店1、子店2、子店3正在使用该单位`
6. **WHEN** 总店管理员尝试删除商品 **AND** 该商品被至少一个子店套餐使用 **THEN** 系统 **SHALL** 阻止删除并提示：`删除失败，子店1、子店2、子店3正在使用该商品`
7. **WHEN** 总店管理员编辑属性组并移除某个属性 **AND** 该属性被至少一个子店商品关联 **THEN** 系统 **SHALL** 阻止编辑并提示：`编辑失败，子店1、子店2、子店3正在使用属性值【属性名称】`

#### 具体要求

- [ ] 1.1 **检查总店身份**：只有总店删除时才执行子店使用情况检查
- [ ] 1.2 删除规格前检查所有子店的商品是否关联该规格
- [ ] 1.3 删除属性组前检查所有子店的商品是否关联该属性组
- [ ] 1.4 删除属性前检查所有子店的商品是否关联该属性
- [ ] 1.5 删除加料前检查所有子店的商品是否关联该加料
- [ ] 1.6 删除单位前检查所有子店的商品是否关联该单位
- [ ] 1.7 删除商品前检查所有子店的套餐是否使用该商品
- [ ] 1.8 检查逻辑应包含所有状态（售罄、下架、正常）的商品
- [ ] 1.9 API 响应中返回**所有**使用该资源的子店名称（不限制数量）
- [ ] 1.10 总店编辑属性组时，如果移除了某个属性，需要检查该属性是否被子店商品使用，如果被使用，则阻止编辑并提示
- [ ] 1.11 API 响应中返回使用该资源的子店总数

### Requirement 2: 子店已取消使用时允许删除

**用户故事**: 作为总店管理员，我想在子店取消使用资源后能够成功删除，以便于保持数据整洁

#### 验收标准

1. **WHEN** 总店管理员删除规格/属性组/属性/加料/单位 **AND** 所有子店均已取消使用 **THEN** 系统 **SHALL** 成功删除并返回：`{code: 1, message: "删除成功", data: {}}`
2. **WHEN** 删除商品 **AND** 所有子店套餐均未使用该商品 **THEN** 系统 **SHALL** 成功删除
3. **IF** 删除成功 **THEN** 系统 **SHALL** 执行软删除（设置 delete_time）

#### 具体要求

- [ ] 2.1 删除成功后返回标准成功响应
- [ ] 2.2 使用软删除机制（设置 delete_time = 当前时间）
- [ ] 2.3 删除失败时返回使用情况详细信息

---

### Requirement 3: 使用情况检查的精确性

**用户故事**: 作为系统，我需要精确检查子店对资源的使用情况，以便于提供准确的删除验证

#### 验收标准

1. **IF** 当前用户是总店 **THEN** 系统 **SHALL** 执行子店使用情况检查
2. **IF** 当前用户是子店 **THEN** 系统 **SHALL** 跳过子店使用情况检查，直接执行删除
3. **WHEN** 检查子店使用情况 **THEN** 系统 **SHALL** 检查所有子店（不仅是当前激活的子店）
4. **WHEN** 检查商品关联 **THEN** 系统 **SHALL** 包含所有状态的商品（正常、售罄、下架）
5. **WHEN** 检查属性组使用 **THEN** 系统 **SHALL** 通过 ProductPackageAttributeGroup 检查商品关联
6. **WHEN** 检查套餐使用 **THEN** 系统 **SHALL** 包含套餐中的所有商品引用
7. **IF** 商品已软删除 **THEN** 系统 **SHALL** 不将其视为"正在使用"
8. **WHEN** 返回使用的子店列表 **THEN** 系统 **SHALL** 返回所有子店名称（不限制数量）

#### 具体要求

- [ ] 3.1 判断当前公司是否为总店（headquarter_uuid = 0）
- [ ] 3.2 查询所有子店的商品关联关系（包含售罄、下架状态）
- [ ] 3.3 查询所有子店的套餐商品关联关系
- [ ] 3.4 查询所有子店的商品属性组关联关系（通过 ProductPackageAttributeGroup）
- [ ] 3.5 排除已软删除的商品（delete_time != 0）
- [ ] 3.6 返回所有使用该资源的子店名称（不限制数量）
- [ ] 3.7 准确统计使用该资源的子店总数

## 约束条件

### 技术约束

#### Go Main 模块

- 必须使用 Gin 框架
- 接口以 `I` 开头，实现以 `Impl` 结尾
- Service 只能依赖其他 Service 接口
- Repository 只能持有 db 实例，不能持有 DBManager
- 不使用 panic，返回 error

#### Vue 模块

- 必须使用 Vue 3 + TypeScript + Vite
- 使用 Element Plus 组件库
- 遵循 `.cursor/rules/vue.mdc`

### 业务约束

- **总店专属功能**: 只有总店可以删除同步的资源
- **子店只读**: 子店无法删除从总店同步的资源
- **套餐关联检查**: 必须检查子店套餐对商品的引用

- 开发时间: 2.5 天（仅后端）

## 风险和缓解

### 风险 1: 性能问题（子店数量过多时）

**影响**: 中  
**概率**: 中  
**缓解措施**:

- 使用数据库索引优化查询
- 使用 JOIN 减少查询次数
- 限制提示中显示的子店数量（最多 10 个）
- 考虑使用缓存（如果子店列表变化不频繁）

### 风险 2: 数据一致性问题

**影响**: 高  
**概率**: 低  
**缓解措施**:

- 使用事务确保数据一致性
- 删除前加锁防止并发修改
- 详细的错误日志记录
- 提供数据修复工具
