## 📋 概述

在报表页面新增"门店汇总统计"功能，支持用户灵活选择数据指标（营业数据汇总/支付方式汇总/退款金额汇总），然后多选门店和多选日期，查看对应指标的每天各店数据和汇总数据，以便于快速对比各门店在不同日期的经营表现，了解每日和整体经营状况，并导出报表进行进一步分析。

**重要约束**：已经被数据管理的订单，不参与此模块的计算（需要过滤）。

## 🎯 产品对齐

- ✅ **提升数据分析效率**：支持多指标、多门店、多日期灵活组合查询
- ✅ **快速对比分析**：同时查看各门店在不同日期的经营表现
- ✅ **数据导出能力**：支持导出报表进行进一步分析
- ✅ **权限精细化控制**：根据用户角色和权限范围展示对应门店数据

## 📝 用户故事

**作为** 商户管理员（总店/分店/子店）  
**我想** 在报表页面先选择要查看的数据指标（营业数据汇总/支付方式汇总/退款金额汇总），然后多选门店和多选日期，查看对应指标的每天各店数据和汇总数据  
**以便于** 快速对比各门店在不同日期的经营表现，了解每日和整体经营状况，并导出报表进行进一步分析

## 数据来源和汇总规则

### 数据来源

- **营业数据汇总表**：基于 `StatisticsSummaryItem`（对应 `RespBusinessComprehensiveOperationsItem`）
- **支付方式汇总表**：基于 `StatisticsPaymentMethodItem`（对应 `RespPaymentMethodStatisticsItem`）
- **退款金额汇总表**：需要新增退款统计 API

### 汇总规则

- **金额类字段**：求和
- **数量类字段**：求和
- **比率类字段**（人均、单均、占比、退款率）：重新计算，避免简单平均导致的偏差
  - 人均 = 汇总金额 / 汇总人数
  - 单均 = 汇总金额 / 汇总订单数
  - 占比 = 汇总支付金额 / 汇总总实付金额
  - 退款率 = (汇总退款订单数量 ÷ 汇总总订单数量) × 100%
- **最值类字段**（最大、最小）：取最值

## 功能需求

### Requirement 1: 门店列表选择

**用户故事**: 作为 商户管理员，我想 选择要查看的门店列表，以便于 查看对应门店的统计数据

#### 验收标准

1. **WHEN** 当前登录的是总店 **THEN** 系统 **SHALL** 显示本店及下级所有子店供选择
2. **WHEN** 当前登录的是子店 **THEN** 系统 **SHALL** 显示本店及已授权的其他门店供选择
3. **WHEN** 用户点击【全部门店】 **THEN** 系统 **SHALL** 全选所有可查看门店
4. **WHEN** 用户再次点击【全部门店】 **THEN** 系统 **SHALL** 取消全选
5. **WHEN** 用户在全选状态下取消单个门店 **THEN** 系统 **SHALL** 自动取消【全部门店】的勾选
6. **IF** 用户选择门店 **THEN** 系统 **SHALL** 仅显示用户有权限的门店（不可跨集团取值）

#### 具体要求

- [ ] 1.1 根据用户角色（总店/分店/子店）和权限范围列出可查看的门店
- [ ] 1.2 总店用户可查看本店及下级所有子店
- [ ] 1.3 子店用户可查看本店及已授权的其他门店
- [ ] 1.4 不可跨集团取值
- [ ] 1.5 支持【全部门店】全选/取消全选功能
- [ ] 1.6 全选状态下取消单个门店，自动取消【全部门店】勾选

**用户故事**: 作为 商户管理员，我想 查看营业数据汇总（订单金额、实付金额、订单数量、用餐人数等），以便于 了解各门店的经营状况

  - [ ] 汇总表最后一行显示汇总行
- [ ] 2.2 表头字段（共14个字段）：
  - [ ] 营业日（格式：YYYY-MM-DD）
  - [ ] 门店名称
  - [ ] 订单金额（含优惠前，保留2位小数）
  - [ ] 实付金额（保留2位小数）
  - [ ] 订单数量
  - [ ] 用餐人数
  - [ ] 消费桌数
  - [ ] 平均客单价（实付金额/用餐人数，保留2位小数）
  - [ ] 订单金额人均（订单金额/用餐人数，保留2位小数）
  - [ ] 订单金额单均（订单金额/订单数量，保留2位小数）
  - [ ] 实付金额单均（实付金额/订单数量，保留2位小数）
  - [ ] 点餐订单金额（保留2位小数）
  - [ ] 桌台订单金额（保留2位小数）
  - [ ] 外送订单金额（保留2位小数）
- [ ] 2.3 筛选条件：

- [ ] 2.4 汇总规则：

### 风险 2: 权限控制复杂

**影响**: 中  
**概率**: 中  
**缓解措施**:

- 梳理权限模型，明确各角色的门店查看范围
- 参考现有的权限控制逻辑
- 充分测试权限控制功能

### 风险 3: 多门店、多日期数据聚合性能问题

**影响**: 高  
**概率**: 中  
**缓解措施**:

- 优化查询SQL，考虑使用索引和缓存策略
- 对于大数据量场景，考虑分页或异步处理
- 进行性能测试和优化

### 风险 4: 比率类字段计算准确性

**影响**: 中  
**概率**: 低  
**缓解措施**:

- 明确汇总规则：比率类字段必须重新计算，不能简单平均
- 编写单元测试验证计算准确性
- 参考现有统计服务的计算逻辑
