## 📋 概述

基于 Proposal「新管理端-桌面端-桌台地图」，在新管理端（桌面端）中提供可配置的桌台地图画布，并与收银机/点餐助手桌台地图模式及云平台商家「桌台地图」「数据管理」开关联动，实现真实空间布局驱动的桌台管理体验。

## 🎯 产品对齐

- 支持中大型餐饮门店以空间布局为核心的桌台管理方式，降低桌台误操作。
- 提升前厅桌台查找、翻台效率，降低排队等待时间。
- 通过云平台开关能力，支持按商家/批次渐进式上线桌台地图及相关数据能力。

## 📝 用户故事

**作为** 商户管理员  
**我想** 在新管理端（桌面端）中为每个区域配置与真实门店一致的桌台地图布局  
**以便于** 前台在各终端可以按真实空间位置管理桌台、提高翻台效率并减少操作错误。

**作为** 收银员/点餐员  
**我想** 在收银机或点餐助手中以「地图模式」查看和操作桌台  
**以便于** 快速定位桌台、减少点错桌，并在高峰期更快完成点单和结账。

**作为** 平台运营/实施人员  
**我想** 在云平台为商家开启/关闭「桌台地图」「数据管理」能力  
**以便于** 按商家分批试点、控制功能范围，并为后续数据分析能力做准备。

## 功能需求

### Requirement 1: 新管理端-桌台地图配置画布（对应任务 36930）

**用户故事**: 作为 商户管理员/实施人员，我想在新管理端中可视化配置每个区域的桌台地图，以便门店前台在各终端能按真实布局使用桌台。

#### 验收标准

1. **WHEN** 商户登录新管理端并进入「餐厅管理-桌台地图」页面 **THEN** 系统展示区域列表，包含区域名称、桌数、状态（已设置/未设置）、编辑入口。
2. **IF** 某区域已至少在画布中配置 1 张桌台并保存 **THEN** 该区域状态显示为「已设置」，否则显示为「未设置」。
3. **WHEN** 管理员点击某区域的「编辑」 **THEN** 进入编辑页，左侧展示该区域所有桌台列表，右侧展示可缩放的画布。
4. **WHEN** 管理员在画布中拖拽桌台位置或切换桌台样式（圆桌/方桌）、调整尺寸并点击保存 **THEN** 桌台布局变更被持久化，下次打开时还原上次保存结果。
5. **WHEN** 新增桌台或调整桌台类型/人数配置 **THEN** 对应桌台在画布中的默认样式按类型最大就餐人数展示（如 1-2 人用 2 人，3-4 人用 4 人等）。

#### 具体要求

- [ ] 1.1 桌台地图菜单仅在商家开启「桌台地图」能力时显示（依赖 Requirement 3 的云平台开关配置）。
- [ ] 1.2 区域列表支持基础分页/滚动展示，并显示「区域名称/桌数/状态/操作」。
- [ ] 1.3 编辑页左侧桌台列表支持勾选控制是否出现在画布中，取消勾选后桌台从画布隐藏但不删除。
- [ ] 1.4 画布支持缩放（放大/缩小/复位），支持桌台拖拽移动和旋转（如有需要）。
- [ ] 1.5 桌台样式支持圆桌/方桌切换，默认尺寸按该桌台类型最大人数生成，管理员可通过右下角拉伸点调整大小。
- [ ] 1.6 保存操作需要校验至少有 1 张桌台在画布内，避免误保存空布局。

### Requirement 2: 收银机/点餐助手-桌台地图模式展示（对应任务 36909）

**用户故事**: 作为 收银员/点餐员，我想在收银机或点餐助手中切换到「桌台地图模式」查看桌台，以便更快找到目标桌台并进行操作。

#### 验收标准

1. **IF** 商家未开启或未设置桌台地图 **THEN** 收银机/点餐助手不展示地图模式切换按钮，保持现有列表模式。
2. **WHEN** 商家开启且在新管理端完成桌台地图配置 **THEN** 收银机/点餐助手在桌台列表页展示「地图模式」切换按钮，默认非地图模式。
3. **WHEN** 用户点击地图模式按钮切换为高亮状态 **THEN** 当前页面切换为桌台地图视图，按新管理端配置渲染桌台位置、样式和大小。
4. **WHEN** 在地图模式下进行筛选（如按区域、状态筛选） **THEN** 地图中仅保留满足条件的桌台位置，其余桌台隐藏但整体布局不坍塌。
5. **WHEN** 用户在地图模式选择某桌台进入点单/结账流程 **THEN** 与列表模式选择同一桌台的行为一致，不影响后续业务流程。

#### 具体要求

- [ ] 2.1 地图模式按钮的显隐受「桌台地图」开关与配置状态双重控制（依赖 Requirement 1 & 3）。
- [ ] 2.2 地图视图应与列表视图共享筛选/搜索条件，切换模式时保持筛选条件一致。
- [ ] 2.3 地图缩放需适配不同终端分辨率，保证高密度桌台场景可用。
- [ ] 2.4 桌台状态（空闲、占用、预订等）在地图上需有清晰的颜色或图标区分。
- [ ] 2.5 地图模式下的交互（点击桌台、长按、右键等）需与现有列表模式的核心操作保持一致或给出明确替代路径。

---

### Requirement 3: 云平台-商家管理-桌台地图与数据管理开关（对应任务 36936）

**用户故事**: 作为 平台运营/实施人员，我想在云平台为商家配置「桌台地图」「数据管理」能力开关，以便按商家策略控制是否启用相关功能。

#### 验收标准

1. **WHEN** 在云平台添加/编辑商家时 **THEN** 表单中新增「桌台地图」「数据管理」两个布尔开关字段，默认均为关闭状态。
2. **WHEN** 「桌台地图」开关开启并保存 **THEN** 对应商家在新管理端显示桌台地图菜单，在终端（收银机/点餐助手）允许展示地图模式按钮（前提是已完成配置）。
3. **IF** 「桌台地图」开关关闭 **THEN** 新管理端隐藏桌台地图菜单，终端隐藏地图模式按钮，不影响原有桌台列表功能。
4. **WHEN** 「数据管理」开关开启 **THEN** 后续与桌台相关的数据管理与分析能力可以在该商家下启用（本期可预留占位与字段存储）。

#### 具体要求

- [ ] 3.1 在商家数据模型中新增对应字段（如 `enable_table_map`、`enable_data_management`），默认值为 0/false。
- [ ] 3.2 新增字段需要在云平台商家列表和详情中可见/可筛选（视产品要求可只在详情显示）。
- [ ] 3.3 与新管理端、终端间需约定统一的能力标识读取方式，避免多处写死开关逻辑。
- [ ] 3.4 日志中需能追踪开关变更记录（变更人、时间、前后状态）。

### 代码架构和模块化

- **分层设计**: 严格遵循 Controller → Service → Repository 分层
- **单一职责原则**: 每个文件应有单一、明确的目的
- **模块化设计**: Service 和 Repository 应独立且可复用
- **依赖管理**: Service 只能依赖其他 Service 接口，不能直接依赖 Repository
- **遵循规范**:
  - `.cursor/rules/go-main.mdc` - Go Main 开发规范
  - `.cursor/rules/go-bmp.mdc` - Go BMP 微服务规范
  - `.cursor/rules/php.mdc` - PHP 开发规范
  - `.cursor/rules/vue.mdc` - Vue 前端规范
  - `.cursor/rules/structs.mdc` - 项目结构规范

### API 设计要求

- [ ] URL 使用 snake_case 命名（如：`/api/v1/order_info`）
- [ ] data 字段必须是对象，不能是 null 或数组
- [ ] 分页信息统一放在 meta 中
- [ ] 响应格式：`{code, message, data{}}`
- [ ] 参考: `.cursor/rules/api.mdc` - API 设计规范

### 数据库设计要求

- [ ] 必须包含: `id`, `uuid`, `create_time`, `update_time`, `delete_time`
- [ ] 时间字段使用 int 类型，\_time 结尾，默认值 0
- [ ] 金额字段使用 decimal(20,8)
- [ ] UUID 字段使用 bigint unsigned
- [ ] 表名使用 ttpos\_ 前缀
- [ ] 字段名使用 snake_case
- [ ] 参考: `.cursor/rules/database.mdc` - 数据库开发规范

### 性能要求

- [ ] 本地响应时间 < 200ms
- [ ] 数据库查询优化（使用索引）
- [ ] 缓存策略（Redis）

## 验收标准

### 功能验收

1. **新管理端桌台地图配置**：满足 Requirement 1 所列所有功能与验收条目，能稳定保存并复现桌台布局。

3. **云平台商家开关**：满足 Requirement 3 所列所有功能与验收条目，开关状态能正确控制下游功能显隐。

## 风险和缓解

### 风险 1: 桌台地图配置与现有桌台/订单/排队业务耦合

**影响**: 高  
**概率**: 中  
**缓解措施**:

- 在数据模型上将「桌台实体」与「空间布局」解耦，允许无损回退为列表模式。
- 对试点门店进行灰度发布，收集问题后再扩展。

### 风险 2: 大量桌台场景的性能与可用性

**影响**: 中  
**概率**: 中  
**缓解措施**:

- 通过画布虚拟化和分区域加载控制渲染复杂度。
- 提供缩放、缩略图、快速定位能力，降低大地图操作负担。
