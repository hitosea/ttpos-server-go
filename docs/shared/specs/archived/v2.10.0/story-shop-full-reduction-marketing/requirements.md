## 📋 概述

在新管理端（Shop）工作台增加【营销活动】入口，支持创建和管理满减营销活动。活动支持阶梯满减和循环满减两种模式，可设置活动日期、活动时间（全天或特定时段），并支持活动的编辑、失效和删除操作。该功能旨在提升商家营销能力，通过满减活动吸引顾客消费，提高客单价和营业额。

## 🎯 产品对齐

该功能支持产品愿景中的"提升商家营销能力"和"增加顾客消费意愿"目标，通过灵活的满减规则设置，帮助商家制定有效的营销策略，提升营业额。

## 📝 用户故事

**作为** 商户管理员  
**我想** 创建和管理满减营销活动  
**以便于** 通过优惠活动吸引顾客消费，提升客单价和营业额

## 功能需求

### Requirement 1: 营销活动入口和列表展示

**用户故事**: 作为商户管理员，我想在工作台看到营销活动入口并查看活动列表，以便于快速访问和管理营销活动

#### 验收标准

1. **WHEN** 商户管理员在工作台点击【营销活动】 **THEN** 系统 **SHALL** 显示活动列表页面
2. **WHEN** 系统显示活动列表 **THEN** 活动 **SHALL** 按照添加顺序排序，最新添加的排在前
3. **WHEN** 系统显示活动列表 **THEN** 每条活动 **SHALL** 显示活动名称、活动状态（进行中/未开始/已结束）、活动日期、活动时间
4. **IF** 商户管理员选择状态筛选（全部/进行中/未开始/已结束） **THEN** 系统 **SHALL** 根据当前时间过滤显示对应状态的活动

#### 具体要求

- [ ] 1.1 在工作台增加【营销活动】入口
- [ ] 1.2 活动列表按添加顺序排序（最新在前）
- [ ] 1.3 列表显示字段：活动名称、活动状态、活动日期、活动时间
- [ ] 1.4 支持状态筛选：全部、进行中、未开始、已结束
- [ ] 1.5 活动状态根据当前时间和商户时区自动判断

---

### Requirement 2: 添加促销活动

**用户故事**: 作为商户管理员，我想创建新的满减营销活动，以便于设置优惠规则吸引顾客消费

#### 验收标准

1. **IF** 商户管理员创建新活动 **THEN** 系统 **SHALL** 验证活动名称（1-50 字符）、活动日期（不可选择以前的日期）、适用时间(如 9:00-10:00)、活动规则（至少一个规则，满减金额范围 0.01-999999.99）
2. **WHEN** 商户管理员选择活动日期 **THEN** 系统 **SHALL** 禁止选择以前的日期
3. **WHEN** 商户管理员选择活动时间 **THEN** 系统 **SHALL** 支持全天或特定时间段（24 小时制，精确到时分）
4. **WHEN** 商户管理员选择阶梯满减 **THEN** 系统 **SHALL** 支持设置多个满减档次（最多 20 项），同一满减金额只能设置 1 条规则
5. **WHEN** 商户管理员选择循环满减 **THEN** 系统 **SHALL** 支持设置满减基数和减价金额
6. **WHEN** 商户管理员保存阶梯满减活动 **THEN** 系统 **SHALL** 自动按金额从小到大排序规则

#### 具体要求

- [ ] 2.1 活动名称：1-50 字符，必填
- [ ] 2.2 活动日期：开始日期和结束日期，不可选择以前的日期，必填
- [ ] 2.3 活动时间：支持全天或特定时间段（24 小时制，格式：HH:mm），默认选中全天
- [ ] 2.4 活动规则：阶梯满减（默认）或循环满减，必选
- [ ] 2.5 阶梯满减：可设置多个满减档次（最多 20 项），阈值和扣减值范围：0.01-999999.99
- [ ] 2.6 循环满减：设置满减基数和减价金额，范围：0.01-999999.99
- [ ] 2.7 保存时自动排序：阶梯满减规则按阈值从小到大排序
- [ ] 2.8 保存时校验：所有参数必填，至少一个规则，满减金额范围验证

---

### Requirement 3: 活动编辑

**用户故事**: 作为商户管理员，我想编辑已创建的活动，以便于调整活动规则和设置

#### 验收标准

1. **IF** 商户管理员未保存编辑内容退出编辑页面 **THEN** 系统 **SHALL** 弹窗提示"确认退出吗？编辑的内容将不会被保存"
2. **IF** 商户管理员编辑进行中的活动并点击保存 **THEN** 系统 **SHALL** 弹出确认弹窗，提示"进行中的活动规则编辑后，当前店内未结账的订单将以编辑后的规则为准，是否确认编辑活动？"
3. **IF** 商户管理员对已结束或已失效的活动进行编辑 **THEN** 系统 **SHALL** 禁止编辑
4. **WHEN** 商户管理员保存编辑后的阶梯满减活动 **THEN** 系统 **SHALL** 自动按金额从小到大排序规则

#### 具体要求

- [ ] 3.1 未保存退出提示：检测表单是否有修改，如有修改则提示
- [ ] 3.2 进行中活动编辑确认：检测活动状态，如为进行中则弹出确认提示
- [ ] 3.3 已结束/已失效活动不可编辑：保存时校验活动状态
- [ ] 3.4 编辑时保持所有创建时的验证规则

---

### Requirement 4: 活动失效和删除

**用户故事**: 作为商户管理员，我想失效或删除活动，以便于管理不再需要的营销活动

#### 验收标准

1. **WHEN** 商户管理员点击失效按钮 **THEN** 系统 **SHALL** 弹窗提示"失效后将不可恢复，活动变为已结束状态"
2. **IF** 商户管理员确认失效 **THEN** 系统 **SHALL** 仅允许失效进行中或未开始的活动
3. **WHEN** 商户管理员点击删除按钮 **THEN** 系统 **SHALL** 弹窗提示"确认删除该活动吗？删除后将无法恢复"
4. **IF** 商户管理员确认删除 **THEN** 系统 **SHALL** 仅允许删除未开始、已结束、已失效的活动，进行中的活动不可删除

#### 具体要求

- [ ] 4.1 失效功能：仅允许失效进行中或未开始的活动
- [ ] 4.2 失效提示：明确说明失效后不可恢复
- [ ] 4.3 删除功能：仅允许删除未开始、已结束、已失效的活动
- [ ] 4.4 删除提示：明确说明删除后无法恢复
- [ ] 4.5 进行中活动保护：进行中的活动不可删除

---

### Requirement 5: 活动详情查看

**用户故事**: 作为商户管理员，我想查看活动的详细信息，以便于了解活动的完整配置

#### 验收标准

1. **WHEN** 商户管理员点击活动列表中的活动 **THEN** 系统 **SHALL** 显示活动详情页面
2. **WHEN** 系统显示活动详情 **THEN** 系统 **SHALL** 显示活动名称、活动日期、活动时间、满减方式、规则列表等完整信息

#### 具体要求

- [ ] 5.1 活动详情页面显示所有活动信息
- [ ] 5.2 阶梯满减显示所有规则（已排序）
- [ ] 5.3 循环满减显示基数和减价金额

## 约束条件

### 技术约束

#### Go Main 模块

- 必须使用 Gin 框架
- 接口以 `I` 开头，实现以 `Impl` 结尾
- Service 只能依赖其他 Service 接口
- Repository 只能持有 db 实例，不能持有 DBManager
- 不使用 panic，返回 error

#### Flutter 模块（新管理端）

- 新管理端位于 `ttpos-flutter/apps/shop`
- 使用 Flutter + Dart 开发
- 遵循 Flutter 开发规范和项目结构
- 注意：旧管理后台和店铺后台使用 Vue3（位于 `admin/views/`），但新管理端使用 Flutter

### 业务约束

- 活动日期不可选择以前的日期
- 满减金额范围：0.01-999999.99
- 阶梯满减最多 20 项，同一满减金额只能设置 1 条规则
- 进行中的活动不可删除
- 已结束和已失效的活动不可编辑
- 活动状态判断需考虑商户时区

### 资源约束

- 开发时间: 5-7 天
- Story Point: 8-13 SP (必须 ≤ 5，需拆分)

## 风险和缓解

### 风险 1: 活动规则计算逻辑复杂

**影响**: 高  
**概率**: 中  
**缓解措施**:

- 详细设计活动规则计算逻辑
- 编写单元测试覆盖各种场景（覆盖率 100%）
- 阶梯满减和循环满减分别实现和测试

### 风险 2: 活动状态判断需要考虑时区问题

**影响**: 中  
**概率**: 中  
**缓解措施**:

- 使用商户设置的时区进行时间判断
- 确保时间计算的准确性
- 编写时区相关的测试用例

### 风险 3: 进行中活动的编辑可能影响未结账订单

**影响**: 高  
**概率**: 低  
**缓解措施**:

- 编辑进行中活动时明确提示影响范围
- 记录操作日志
- 在订单计算时使用活动的最新规则
