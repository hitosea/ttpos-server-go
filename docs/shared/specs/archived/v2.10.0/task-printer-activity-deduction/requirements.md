## 📋 概述

在打印模板中新增"活动抵扣"字段显示，使用现有的 `activity_amount` 字段获取数据，放置在"优惠券抵扣"下一行。此功能旨在提升打印单据的信息完整性，让顾客和商家清楚看到满减营销活动的优惠金额，便于财务对账。

## 🎯 产品对齐

该功能支持以下产品目标：

- **提升用户体验**: 让顾客在结账单上清楚看到满减活动优惠明细
- **财务透明度**: 便于商家准确追踪营销活动的实际抵扣情况
- **信息规范化**: 统一优惠信息展示规范，与优惠券抵扣保持一致的显示逻辑

## 📝 用户故事

**作为** 商家或顾客  
**我想** 在打印的结账单/预结账单/发票上看到"活动抵扣"金额  
**以便于** 清楚了解满减营销活动的优惠情况，便于对账和核实

## 功能需求

### Requirement 1: 自定义打印模板支持活动抵扣字段

**用户故事**: 作为商家，我想在自定义打印模板中配置"活动抵扣"字段，以便在打印时显示满减活动优惠金额。

#### 验收标准

1. **WHEN** 商家配置自定义打印模板 **THEN** 系统 **SHALL** 在"应付信息(Amount due information)"分组中提供"活动抵扣"字段选项
2. **IF** "活动抵扣"字段被启用 **AND** `activity_amount` > 0 **THEN** 打印时 **SHALL** 在"优惠券抵扣"字段下一行显示"活动抵扣: ￥ XX.XX"
3. **WHEN** `activity_amount` ≤ 0 **THEN** 系统 **SHALL** 不显示"活动抵扣"行

#### 具体要求

- [ ] 1.1 在 `main/app/printer/pkg/template/statement_order_config.json` 中的 `"block_id": "amount_due_information"` 区块添加"activity_deduction"配置
- [ ] 1.2 配置包含完整的 9 种语言翻译（中文简体、繁体、英语、泰语、土耳其语、日语、韩语、瑞典语、缅甸语）
- [ ] 1.3 字段类型为 `label_value`，block_value 使用占位符 `{{activity_amount}}`
- [ ] 1.4 在 `main/app/printer/template/statement_order_img_custom.go` 的 `GetPrintContent()` 方法中读取 `activity_amount` 字段
- [ ] 1.5 使用 `decimal` 类型处理金额，保留两位小数
- [ ] 1.6 **仅当 `activity_amount` > 0 时才显示该字段**（≤ 0 时不显示）
- [ ] 1.7 将 `{{activity_amount}}` 占位符替换为实际格式化后的金额值

---

### Requirement 2: 标准打印模板显示活动抵扣

**用户故事**: 作为商家或顾客，我想在标准打印模板（结账单、预结账单、发票）上看到"活动抵扣"字段，以便了解优惠明细。

#### 验收标准

1. **WHEN** 打印结账单 **AND** `activity_amount` > 0 **THEN** 系统 **SHALL** 在"优惠券抵扣"下一行显示"活动抵扣"及金额
2. **WHEN** 打印预结账单 **AND** `activity_amount` > 0 **THEN** 系统 **SHALL** 显示"活动抵扣"字段
3. **WHEN** 打印发票模版 2 **AND** `activity_amount` > 0 **THEN** 系统 **SHALL** 显示"活动抵扣"字段
4. **IF** 订单存在活动抵扣金额（> 0）**THEN** 系统 **SHALL** 显示实际抵扣金额（如: ￥ 50.00）
5. **IF** `activity_amount` ≤ 0 **THEN** 系统 **SHALL NOT** 显示"活动抵扣"行

#### 具体要求

- [ ] 2.1 修改 `main/app/printer/template/statement_order_img.go` 渲染逻辑
- [ ] 2.2 在结账单模板中添加"活动抵扣"行渲染
- [ ] 2.3 在预结账单所有模板中添加"活动抵扣"行渲染
- [ ] 2.4 在发票模版 2 中添加"活动抵扣"行渲染
- [ ] 2.5 确保显示位置在"优惠券抵扣"之后、"减免金额"之前
- [ ] 2.6 保持与其他优惠字段一致的格式: `标签: ￥金额`

---

### Requirement 3: 多语言支持

**用户故事**: 作为国际化商家，我想打印模板根据系统语言显示对应的"活动抵扣"翻译，以便不同语言环境的顾客理解。

#### 验收标准

1. **WHEN** 系统语言为中文简体 **THEN** 显示 **SHALL** "活动抵扣"
2. **WHEN** 系统语言为中文繁体 **THEN** 显示 **SHALL** "活動抵扣"
3. **WHEN** 系统语言为英语 **THEN** 显示 **SHALL** "Activity Deduction"
4. **WHEN** 系统语言为泰语 **THEN** 显示 **SHALL** "หักลดจากกิจกรรม"
5. **WHEN** 系统语言为其他支持语言 **THEN** 系统 **SHALL** 显示对应翻译

#### 具体要求

- [ ] 3.1 在 JSON 配置中添加完整的 `block_label` 多语言定义
- [ ] 3.2 支持的语言包括: zh(简体)、zhtw(繁体)、en(英语)、th(泰语)、tr(土耳其语)、ja(日语)、ko(韩语)、sv(瑞典语)、my(缅甸语)
- [ ] 3.3 确保渲染时根据商家语言设置选择正确的翻译

## 非功能需求

### 代码架构和模块化

- **分层设计**: 严格遵循打印模板的配置层（JSON）和渲染层（Go）分离
- **单一职责原则**: 配置文件只定义字段结构，渲染逻辑只负责数据处理和格式化
- **模块化设计**: 渲染方法应独立且可复用
- **遵循规范**:
  - `.cursor/rules/go-main.mdc` - Go Main 开发规范
  - `.cursor/rules/structs.mdc` - 项目结构规范

### 数据兼容性

- [ ] `activity_amount` 字段已存在于数据库，无需创建新字段
- [ ] 字段类型为 `decimal(10,2)`，默认值 0.00
- [ ] 兼容历史数据（`activity_amount` 为 null 时显示为 0.00）

### 性能要求

- [ ] 打印模板渲染时间不应明显增加（增量 < 5ms）
- [ ] JSON 配置解析性能无影响
- [ ] 不增加额外的数据库查询

### 测试要求

- [ ] 覆盖自定义模板和标准模板的渲染测试
- [ ] 覆盖多语言环境下的显示测试
- [ ] 覆盖 `activity_amount` 为 0 和非 0 的场景
- [ ] 回归测试：确保其他打印字段不受影响

### 国际化要求

- [ ] 支持 9 种语言（中文简体、繁体、英文、日语、韩语、泰语、土耳其语、瑞典语、缅甸语）
- [ ] 所有翻译由母语者审核确认

### 安全要求

- [ ] 金额显示格式化，防止注入风险
- [ ] 不涉及敏感数据访问，使用现有权限控制

### 可靠性要求

- [ ] 打印模板渲染失败时不影响订单流程
- [ ] 错误日志记录（使用 Logger）
- [ ] 故障时优雅降级（字段不显示或显示默认值）

## 验收标准

### 功能验收

1. **自定义模板配置**: 在 JSON 配置中可找到"activity_deduction"字段定义，包含完整的多语言翻译
2. **自定义模板渲染**: 打印自定义模板时，当 `activity_amount` > 0 时，"活动抵扣"字段在"优惠券抵扣"下一行正确显示，金额格式正确（保留两位小数）
3. **标准模板渲染**: 结账单、预结账单、发票模版 2 均在 `activity_amount` > 0 时显示"活动抵扣"字段
4. **金额显示**: 当 `activity_amount` 为 50.00 时，显示"活动抵扣: ￥ 50.00"
5. **零金额/负金额处理**: 当 `activity_amount` ≤ 0 时，不显示"活动抵扣"行
6. **位置正确**: "活动抵扣"字段位于"优惠券抵扣"之后、"减免金额"之前

### 多语言验证

1. **中文简体**: 显示"活动抵扣"
2. **中文繁体**: 显示"活動抵扣"
3. **英语**: 显示"Activity Deduction"
4. **泰语**: 显示"หักลดจากกิจกรรม"
5. **其他语言**: 土耳其语、日语、韩语、瑞典语、缅甸语显示正确

### 回归测试

1. **其他字段不受影响**: 商品总价、会员优惠、会员积分抵扣、优惠券抵扣、减免金额、应付金额等字段显示正常
2. **打印布局正常**: 无错位或重叠，排版整齐
3. **性能无明显下降**: 打印速度与之前相当

## 风险和缓解

### 风险 1: 多语言翻译错误

**影响**: 中  
**概率**: 中  
**缓解措施**:

- 提交前由母语者审核翻译准确性
- 参考现有打印模板中的类似翻译（如"优惠券抵扣"）
- 在测试环境验证各语言显示效果

### 风险 2: 打印布局错乱

**影响**: 中  
**概率**: 低  
**缓解措施**:

- 测试各类打印机和纸张尺寸（58mm、80mm）
- 参考现有字段的显示格式，保持一致性
- 在真实打印机上验证，而不仅仅是预览

### 风险 3: 历史数据兼容性

**影响**: 低  
**概率**: 低  
**缓解措施**:

- `activity_amount` 为 null 时显示为 ￥ 0.00
- 确保数据库字段有默认值 0.00
- 测试历史订单的打印效果

### 风险 4: 自定义模板配置冲突

**影响**: 低  
**概率**: 低  
**缓解措施**:

- 确保新字段以可选方式添加，不影响现有配置
- 使用唯一的 `block_id`: "activity_deduction"
- 测试从旧版本配置升级的兼容性
