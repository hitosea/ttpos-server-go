## 📋 概述

新管理端中，套餐分组排序功能保存后未生效，用户调整了套餐分组的排序顺序，但保存后排序没有按照预期更新。本需求旨在修复此问题，确保套餐分组排序在新管理端保存后能够持久化生效，并在各个端（新管理端、POS 端等）显示一致的排序顺序。

## 🎯 产品对齐

确保新管理端套餐分组管理功能的完整性和可靠性，提升商户管理体验，避免因功能异常导致的用户投诉。保证套餐分组排序设置能够在所有终端正确展示，提升用户体验的一致性。

## 📝 用户故事

**作为** 商户管理员  
**我想** 调整套餐分组的显示顺序并保存，使排序在所有终端生效  
**以便于** 按照我的业务需求展示套餐分组，提升管理效率和用户体验一致性

## 功能需求

### Requirement 1: 套餐分组排序保存功能修复

**用户故事**: 作为商户管理员，我想在新管理端调整套餐分组排序并保存，以便于排序设置能够持久化生效

#### 验收标准

1. **WHEN** 商户管理员在新管理端调整套餐分组排序并点击保存 **THEN** 系统 **SHALL** 保存排序设置并持久化到数据库
2. **IF** 商户管理员保存排序后刷新页面或重新进入 **THEN** 系统 **SHALL** 按照保存的排序顺序显示套餐分组
3. **WHEN** 排序保存成功 **THEN** 系统 **SHALL** 给出明确的成功提示
4. **WHEN** 排序保存失败 **THEN** 系统 **SHALL** 给出明确的错误提示

#### 具体要求

- [ ] 1.1 排查前端排序保存请求逻辑，确保排序数据正确发送
- [ ] 1.2 检查后端排序更新接口实现，确保排序数据正确处理
- [ ] 1.3 验证数据库排序字段更新，确保排序值正确保存
- [ ] 1.4 确保排序数据正确加载和展示，页面刷新后排序保持一致
- [ ] 1.5 修复排序保存未生效的问题（可能是前端请求参数格式、后端接口逻辑或数据库字段映射问题）

---

### Requirement 2: 套餐分组排序在各端一致性

**用户故事**: 作为商户管理员，我想确保套餐分组排序在所有终端显示一致，以便于用户体验的一致性

#### 验收标准

1. **WHEN** 商户管理员在新管理端保存套餐分组排序 **THEN** 系统 **SHALL** 在所有终端（新管理端、POS 端等）按照相同顺序显示套餐分组
2. **IF** 套餐分组排序已保存 **THEN** 系统 **SHALL** 在所有查询接口中按照排序字段正确排序
3. **WHEN** 套餐分组排序更新 **THEN** 系统 **SHALL** 立即在所有终端生效

#### 具体要求

- [ ] 2.1 检查新管理端套餐分组查询接口，确保按排序字段排序
- [ ] 2.2 检查 POS 端套餐分组查询接口，确保按排序字段排序
- [ ] 2.3 检查其他相关端点的套餐分组查询接口，确保排序一致性
- [ ] 2.4 验证排序字段在所有查询接口中正确使用

## 非功能需求

### 代码架构和模块化

- **分层设计**: 严格遵循 Controller → Service → Repository 分层
- **单一职责原则**: 每个文件应有单一、明确的目的
- **模块化设计**: Service 和 Repository 应独立且可复用
- **依赖管理**: Service 只能依赖其他 Service 接口，不能直接依赖 Repository
- **遵循规范**:
  - `.cursor/rules/go-main.mdc` - Go Main 开发规范
  - `.cursor/rules/vue.mdc` - Vue 前端规范
  - `.cursor/rules/structs.mdc` - 项目结构规范

### API 设计要求

- [x] URL 使用 snake_case 命名（如：`/api/v1/shop/product/edit`）
- [x] data 字段必须是对象，不能是 null 或数组
- [x] 分页信息统一放在 meta 中
- [x] 响应格式：`{code, message, data{}}`
- [x] 参考: `.cursor/rules/api.mdc` - API 设计规范

### 数据库设计要求

- [x] 必须包含: `id`, `uuid`, `create_time`, `update_time`, `delete_time`
- [x] 时间字段使用 int 类型，\_time 结尾，默认值 0
- [x] 金额字段使用 decimal(20,8)
- [x] UUID 字段使用 bigint unsigned
- [x] 表名使用 ttpos\_ 前缀
- [x] 字段名使用 snake_case
- [x] 参考: `.cursor/rules/database.mdc` - 数据库开发规范

### 性能要求

## 验收标准

### 功能验收

1. **排序保存功能**: 新管理端套餐分组排序保存后能够持久化生效
2. **排序加载功能**: 页面刷新或重新进入后，排序按照保存的顺序显示
3. **排序一致性**: 所有终端（新管理端、POS 端等）显示相同的排序顺序
4. **错误处理**: 排序保存失败时给出明确的错误提示

### 测试验收

1. **单元测试**: 覆盖率达标
2. **API 测试**: 所有接口测试通过
3. **集成测试**: 端到端流程测试通过
4. **手动测试**: 浏览器兼容性测试通过，各端排序一致性测试通过

### 文档验收

1. **技术文档**: design.md 完整且准确
2. **API 文档**: API 接口文档完整（如有）
3. **数据库文档**: 迁移脚本和表结构文档完整
4. **测试文档**: tasks.md 中的测试任务完成

## 约束条件

### 技术约束

#### Go Main 模块

- 必须使用 Gin 框架
- 接口以 `I` 开头，实现以 `Impl` 结尾
- Service 只能依赖其他 Service 接口
- Repository 只能持有 db 实例，不能持有 DBManager
- 不使用 panic，返回 error

#### Vue 模块

- 必须使用 Vue 3 + TypeScript + Vite
- 使用 Element Plus 组件库
- 遵循 `.cursor/rules/vue.mdc`

### 业务约束

- 套餐分组排序必须支持多语言
- 排序修改必须记录操作日志
- 排序修改必须进行权限验证

### 资源约束

- 开发时间: 1-2 天
- Story Point: 3-5 SP (必须 ≤ 5)

## 风险和缓解

### 风险 1: 前端请求参数格式问题

**影响**: 中  
**概率**: 中  
**缓解措施**:

- 先排查前端请求和响应日志
- 检查请求参数格式是否符合后端接口要求
- 进行完整的功能测试验证

### 风险 2: 后端接口逻辑遗漏

**影响**: 中  
**概率**: 中  
**缓解措施**:

- 检查后端接口实现和数据库更新逻辑
- 验证排序字段是否正确映射和更新
- 进行端到端测试验证

### 风险 3: 数据库字段映射问题

**影响**: 中  
**概率**: 低  
**缓解措施**:

- 检查数据库表结构和字段映射
- 验证排序字段是否正确保存和读取
- 进行数据库操作测试验证
