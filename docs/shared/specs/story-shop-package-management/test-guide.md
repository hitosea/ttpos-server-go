# 旧管理端-商品管理-套餐功能测试指南

> 本文档提供套餐功能增强的手动测试指南和测试用例。

## 📋 测试概述

本次测试主要验证套餐商品管理功能的增强，包括：
- 分组类型配置（固定/可选）
- 可选数量控制
- 必选/默认选项配置
- 价格加价模式
- 数量默认值
- 数据校验逻辑
- 商品详情回显

---

## 🧪 测试环境准备

### 前置条件

1. 数据库字段已添加（`group_type`, `optional_count`, `is_required`, `is_default`, `add_price`）
2. 后端代码已更新
3. 测试账号已准备
4. 测试商品已创建

### 测试工具

- Postman / Apifox（API 测试）

## 📝 测试用例

### TC1: 固定分组配置

**测试目的**：验证固定分组类型可以正常保存

**测试步骤**：
1. 调用商品编辑接口
2. 设置 `group_type = 0`（固定）
3. 添加商品到分组
4. 提交保存

**预期结果**：
- 保存成功
- 数据库中 `group_type` 字段为 0
- 商品详情接口返回 `group_type = 0`

**测试数据**：
```json
{
  "package_group": [
    {
      "group_name": "固定分组",
      "group_type": 0,
      "optional_count": 0,
      "product_list": [
        {
          "product_id": 123,
          "num": 1,
          "sort": 0
        }
      ]
    }
  ]
}
```

---

### TC2: 可选分组配置（正常）

**测试目的**：验证可选分组类型可以正常保存

**测试步骤**：
1. 调用商品编辑接口
2. 设置 `group_type = 1`（可选）
3. 设置 `optional_count = 2`
4. 添加商品，设置部分为必选
5. 提交保存

**预期结果**：
- 保存成功
- 数据库中 `group_type` 字段为 1
- 数据库中 `optional_count` 字段为 2
- 商品详情接口返回正确数据

**测试数据**：
```json
{
  "package_group": [
    {
      "group_name": "可选分组",
      "group_type": 1,
      "optional_count": 2,
      "product_list": [
        {
          "product_id": 123,
          "num": 1,
          "is_required": 1,
          "is_default": 0
        },
        {
          "product_id": 124,
          "num": 1,
          "is_required": 0,
          "is_default": 1
        }
      ]
    }
  ]
}
```

### TC3: 数据校验 - 必选数量大于可选数量

**测试目的**：验证数据校验逻辑

**测试步骤**：
1. 调用商品编辑接口
2. 设置 `group_type = 1`（可选）
3. 设置 `optional_count = 1`
4. 添加2个必选商品（`is_required = 1`）
5. 提交保存

**预期结果**：
- 保存失败
- 返回错误信息："必选不可大于可选数量"
- 数据库中数据未更新

**测试数据**：
```json
{
  "package_group": [
    {
      "group_name": "错误配置",
      "group_type": 1,
      "optional_count": 1,
      "product_list": [
        {
          "product_id": 123,
          "num": 1,
          "is_required": 1
        },
        {
          "product_id": 124,
          "num": 1,
          "is_required": 1
        }
      ]
    }
  ]
}
```

### TC6: 商品详情回显

**测试目的**：验证商品详情接口返回所有新字段

**测试步骤**：
1. 先保存一个包含所有新字段的套餐商品
2. 调用商品详情接口
3. 检查返回数据

**预期结果**：
- 返回数据包含 `group_type`
- 返回数据包含 `optional_count`
- 返回数据包含 `is_required`
- 返回数据包含 `is_default`
- 返回数据包含 `add_price`

**验证点**：
```json
{
  "package_group": [
    {
      "group_type": 1,
      "optional_count": 2,
      "product_list": [
        {
          "is_required": 1,
          "is_default": 0,
          "add_price": 5.00
        }
      ]
    }
  ]
}
```

---

### TC7: 编辑已有套餐

**测试目的**：验证可以编辑已有套餐的新字段

**测试步骤**：
1. 获取已有套餐商品详情
2. 修改 `group_type` 从 0 改为 1
3. 设置 `optional_count = 2`
4. 提交保存
5. 再次获取详情验证

**预期结果**：
- 保存成功
- 新字段值正确更新
- 详情接口返回更新后的值

---

### TC8: 边界值测试

**测试目的**：验证边界值处理

**测试场景**：

1. **optional_count = 0**（可选数量为0）
   - 预期：保存成功，但实际不可选

2. **optional_count = 很大值**（如 100）
   - 预期：保存成功

3. **add_price = 负数**
   - 预期：根据业务规则处理（可能需要前端校验）

4. **is_required 和 is_default 同时为 1**
   - 预期：保存成功（必选且默认）
