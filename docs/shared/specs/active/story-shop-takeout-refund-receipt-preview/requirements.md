## 📋 概述

在新管理端（桌面端）的餐厅设置-票据样式设置页面中，新增"外卖退单联"预览功能。商户管理员可以查看外卖订单退单时的打印样式（只读预览，不可编辑），商品名称使用店内商品名称，确保管理员了解退单联的打印效果。

**功能价值**：
- 提升管理透明度，让管理员清楚了解退单联的打印内容和格式
- 降低沟通成本，减少因退单联样式不明确导致的客服咨询
- 增强功能完整性，与现有外卖票据（商家联、顾客联）管理功能保持一致

## 🎯 产品对齐

该功能支持以下产品目标：
1. **完善票据管理体系**：补齐外卖退单联预览功能，形成完整的外卖票据管理闭环
2. **提升用户体验**：让商户管理员随时了解各类票据的打印效果，增强产品透明度
3. **标准化管理**：统一外卖票据预览体验，所有外卖票据（商家联、顾客联、退单联）均可预览

## 📝 用户故事

**作为** 商户管理员  
**我想** 在票据样式设置中查看外卖退单联的打印预览  
**以便于** 了解退单时打印的票据内容和格式，确保信息展示符合预期

## 功能需求

### Requirement 1: 外卖退单联预览入口

**用户故事**: 作为商户管理员，我想在票据样式设置页面看到外卖退单联的入口，以便于访问退单联预览功能

#### 验收标准

1. **WHEN** 商户管理员进入票据样式设置页面 **THEN** 系统 **SHALL** 显示"外卖退单联"预览入口
2. **WHEN** 预览入口展示时 **THEN** 系统 **SHALL** 与其他票据（外卖商家联、外卖顾客联）保持一致的UI风格
3. **IF** 系统数据库中存在外卖退单联模板（ID=14） **THEN** 系统 **SHALL** 正常显示预览入口

#### 具体要求

- [ ] 1.1 在票据样式设置页面添加"外卖退单联"选项卡或按钮
- [ ] 1.2 入口位置与"外卖商家联"、"外卖顾客联"并列展示
- [ ] 1.3 入口按钮/选项卡使用清晰的文字标识："外卖退单联"
- [ ] 1.4 入口状态默认为可点击状态

---

### Requirement 2: 外卖退单联预览展示

**用户故事**: 作为商户管理员，我想点击外卖退单联入口后看到完整的打印预览，以便于了解退单联的具体内容

#### 验收标准

1. **WHEN** 点击"外卖退单联"预览入口 **THEN** 系统 **SHALL** 显示外卖订单退单联的打印预览
2. **WHEN** 显示预览时 **THEN** 系统 **SHALL** 使用店内商品名称（非外卖平台名称）
3. **WHEN** 显示预览时 **THEN** 系统 **SHALL** 展示完整的票据内容（包括：店铺信息、订单信息、商品列表、金额信息、客户信息等）
4. **WHEN** 显示预览时 **THEN** 系统 **SHALL** 使用真实示例数据进行预览

#### 具体要求

- [ ] 2.1 预览界面展示完整的外卖退单联样式
- [ ] 2.2 预览内容包含以下模块：
  - 票据标题（"外卖退单联"或类似标识）
  - 店铺基本信息（店铺名称、地址、电话等）
  - 订单基本信息（订单号、下单时间、支付时间等）
  - 商品列表（商品名称、单价、数量、小计）
  - 金额汇总（商品金额、配送费、优惠金额、合计应收）
  - 客户信息（姓名、电话、收货地址）
  - 备注信息（如有）
  - 系统支持信息（底部品牌标识）
- [ ] 2.3 商品名称使用店内商品名称
- [ ] 2.4 预览数据参考 `takeout_merchant_receipt_data.json` 格式
- [ ] 2.5 预览界面支持滚动查看完整内容
- [ ] 2.6 预览加载时显示加载状态提示

---

### Requirement 3: 只读模式（不可编辑）

**用户故事**: 作为系统设计者，我要确保外卖退单联预览仅供查看，不可编辑，以便于保持票据样式的一致性

#### 验收标准

1. **WHEN** 预览外卖订单退单票据 **THEN** 系统 **SHALL** 仅提供预览功能，不提供编辑功能
2. **WHEN** 用户尝试编辑预览内容 **THEN** 系统 **SHALL** 不响应编辑操作
3. **IF** 用户需要修改票据样式 **THEN** 系统 **SHALL** 不提供此功能（产品策略决定）

#### 具体要求

- [ ] 3.1 预览界面不展示任何编辑按钮（如"编辑"、"保存"、"自定义"等）
- [ ] 3.2 预览内容不可通过拖拽、点击等方式修改
- [ ] 3.3 与外卖商家联、外卖顾客联的只读策略保持一致
- [ ] 3.4 预览界面提供"关闭"或"返回"按钮

## 非功能需求

- **分层设计**: 遵循 Controller → Service → Repository 分层（Go 后端）

- **模块化设计**: 票据预览组件独立，支持多种票据类型
- **遵循规范**:
  - `.cursor/rules/go-main.mdc` - Go Main 开发规范
  - `.cursor/rules/vue.mdc` - Vue 前端规范
  - `.cursor/rules/go-printer.mdc` - 打印模块开发规范
  - `.cursor/rules/structs.mdc` - 项目结构规范

- [ ] URL 使用 snake_case 命名（如：`/api/v1/printer/template/takeout_refund_receipt`）
- [ ] data 字段必须是对象，不能是 null 或数组
- [ ] 响应格式：`{code, message, data{}}`
- [ ] 参考: `.cursor/rules/api.mdc` - API 设计规范

### 数据库设计要求

#### Go Main 模块

- 必须使用 Gin 框架
- Service 层负责业务逻辑，Repository 层负责数据访问
- 不使用 panic，返回 error

- 必须使用 Vue 3 + TypeScript + Vite
- 使用 Element Plus 组件库

## 风险和缓解

### 风险 1: 模板数据不完整

**影响**: 中  
**概率**: 低  
**缓解措施**:

- 提前确认数据库中是否已存在外卖退单联模板记录（ID=14）
- 如模板数据缺失，协调后端团队补充
- 前端做好异常处理，模板缺失时显示友好提示

### 风险 2: 预览效果与实际打印不一致

**影响**: 中  
**概率**: 低  
**缓解措施**:

- 复用现有外卖票据预览组件，保持渲染逻辑一致
- 预览数据参考实际打印数据格式
- 联调测试时对比实际打印效果

### 风险 3: 不同分辨率下显示异常

**影响**: 低  
**概率**: 中  
**缓解措施**:

- 使用响应式设计，适配不同分辨率
- 多浏览器、多分辨率测试
- 提供滚动查看支持
