## 📋 概述

为前端"总部-分店颗粒化同步"功能提供后端支持，实现分店可以选择性地同步总部的数据，而不是全量同步。

**核心功能**：
1. 扩展现有同步任务，增加5种新数据类型的同步：
   - 优惠券（`marketing_coupon`）
   - 满额减（`full_reduction_activity`）- 有多语言
   - 菜品标签（`product_label`）
   - 营销活动（`marketing_activity`）- 有多语言
   - 支付方式（`payment_method`）- **复杂规则**

2. 提供2个新接口：
   - **获取总部可同步数据列表**：按种类分组，返回总部数据列表 + 分店已同步uuid列表
   - **颗粒化同步数据**：接收勾选的uuid列表，先删除未勾选数据（支付方式除外），再同步勾选数据

**业务价值**：
- 支持分店按需同步总部数据，提升运营灵活性
- 降低数据管理复杂度，减少误操作
- 统一总部数据管理，分店选择性使用

## 功能需求

### Requirement 1: 扩展同步数据类型

**用户故事**: 作为分店管理员，我想同步总部的优惠券、满额减等营销数据，以便快速配置营销活动

#### 验收标准

1. **WHEN** 分店执行同步任务时 **THEN** 系统 **SHALL** 支持同步以下5种新数据类型：
   - 优惠券（`marketing_coupon`）
   - 满额减（`full_reduction_activity`）
   - 菜品标签（`product_label`）
   - 营销活动（`marketing_activity`）
   - 支付方式（`payment_method`）

2. **WHEN** 同步满额减或营销活动时 **THEN** 系统 **SHALL** 一并同步多语言数据

3. **WHEN** 同步支付方式时 **THEN** 系统 **SHALL** 遵循特殊规则（详见 `PAYMENT_METHOD_SYNC_RULES.md`）

#### 具体要求

- [ ] 1.1 为5张表添加 `headquarter_uuid` 字段
- [ ] 1.2 实现按 uuid 列表同步各数据类型
- [ ] 1.3 同步满额减、营销活动时一并同步多语言数据
- [ ] 1.4 支付方式同步实现特殊规则（过滤code、同名判断、特殊code处理等）

---

### Requirement 2: 获取总部可同步数据列表接口

**用户故事**: 作为分店管理员，我想查看总部有哪些可同步的数据，以便选择需要的数据同步到本店

#### 验收标准

1. **WHEN** 分店账号调用接口时 **THEN** 系统 **SHALL** 返回总部各种类型的数据列表（按种类分组）

2. **WHEN** 非分店账号调用接口时 **THEN** 系统 **SHALL** 返回错误提示 "非分店账号无法查看总部数据"

3. **WHEN** 返回数据时 **THEN** 系统 **SHALL** 包含以下信息：
   - 数据类型（type）和类型名称（type_name）
   - 总部数据列表（items）
   - 分店已同步的uuid列表（synced_uuids）
   - 关联数据（related_data：明确类型和uuid列表）

4. **WHEN** 返回支付方式时 **THEN** 系统 **SHALL** 过滤 `code = 40` 和 `code = 10` 的支付方式

5. **WHEN** 返回菜品标签时 **THEN** 系统 **SHALL** 返回关联的商品uuid列表（type=product）

#### 具体要求

- [ ] 2.1 实现 `GetHeadquartersDataList` Service 方法
- [ ] 2.2 实现各数据类型的查询方法（getXxxGroup）
- [ ] 2.3 查询总部数据列表（headquarter_uuid = 0）
- [ ] 2.4 查询分店已同步uuid列表（headquarter_uuid = 总部uuid）
- [ ] 2.5 提取关联数据（明确类型）
- [ ] 2.6 创建 API 接口 `/api/v1/shop/sync/headquarters_data_list`

---

### Requirement 3: 颗粒化同步数据接口

**用户故事**: 作为分店管理员，我想同步勾选的总部数据，以便快速配置营销活动和基础数据

#### 验收标准

1. **WHEN** 分店账号调用接口时 **THEN** 系统 **SHALL** 接收每个种类勾选的uuid列表

2. **WHEN** 执行同步时 **THEN** 系统 **SHALL** 先删除分店中未勾选的总部数据（支付方式除外）

3. **WHEN** 执行同步时 **THEN** 系统 **SHALL** 再同步勾选的数据到分店

4. **WHEN** 同步支付方式时 **THEN** 系统 **SHALL** 不删除分店中未勾选的总部数据

5. **WHEN** 同步完成时 **THEN** 系统 **SHALL** 推送 WebSocket 通知

6. **WHEN** 已有同步任务在运行时 **THEN** 系统 **SHALL** 返回错误 "数据同步中，请稍后再试"

#### 具体要求

- [ ] 3.1 实现 `GranularSync` Service 方法
- [ ] 3.2 实现 `executeGranularSync` 异步执行方法
- [ ] 3.3 实现 `deleteUncheckedHeadquartersData` 删除方法（支付方式不删除）
- [ ] 3.4 实现各数据类型的按uuid同步方法（SyncXxxByUuids）
- [ ] 3.5 支付方式同步实现特殊规则
- [ ] 3.6 创建 API 接口 `/api/v1/shop/sync/granular_sync`
- [ ] 3.7 推送 WebSocket 通知

## 非功能需求

### 性能要求

- [ ] 获取总部数据列表接口响应时间 < 1s
- [ ] 颗粒化同步100条数据 < 30s
- [ ] 使用索引优化查询（`idx_headquarter_uuid`）
- [ ] 使用 `Pluck` 优化uuid列表查询

### 安全要求

- [ ] 只有分店账号才能查看和同步总部数据
- [ ] 使用 `headquarter_uuid` 隔离不同总部的数据
- [ ] 支付方式不删除，避免误删导致系统异常

### 可靠性要求

- [ ] 使用 `SyncTaskManager` 防止并发同步
- [ ] 异步执行同步任务，不阻塞接口响应
- [ ] panic 恢复处理，记录错误日志
- [ ] 事务保护，确保数据一致性

## 风险和缓解

### 风险 1: 支付方式规则复杂度高

**影响**: 高  
**概率**: 高  
**缓解措施**:

- 详细阅读 `PAYMENT_METHOD_SYNC_RULES.md`
- 充分测试所有边界情况（5个测试用例）
- 代码review确保规则实现正确

### 风险 2: 数据一致性风险

**影响**: 高  
**概率**: 中  
**缓解措施**:

- 使用事务保护删除和同步操作
- 详细的错误日志
- 同步失败时提供重试机制

### 风险 3: 性能问题

**影响**: 中  
**概率**: 低  
**缓解措施**:

- 添加索引（`idx_headquarter_uuid`）
- 使用 `Pluck` 优化查询
- 批量操作减少数据库访问
