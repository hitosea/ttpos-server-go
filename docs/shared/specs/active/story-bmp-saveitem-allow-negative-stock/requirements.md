## 📋 概述

在 ttpos-bmp 的 `SaveItem` 接口开放并持久化 `allow_negative_stock`，支持调用方按物料配置是否允许负库存；保持未传字段时行为不变；当物料已产生负库存时禁止关闭该开关并提示需先修正库存（库存校验可依赖 Stock Projected Qty）。

## 🎯 产品对齐

- 支撑门店/总部按经营策略控制负库存，避免无意放开或收紧库存校验。
- 降低库存阻塞或数据失真风险，为后续库存/调拨/生产策略留出扩展能力。

## 📝 用户故事

**作为** 总部物资/门店运营人员  
**我想** 在保存物料时可配置 `allow_negative_stock`  
**以便于** 按经营策略控制是否允许负库存开单或扣减，保持库存数据可信。

## 功能需求

### Requirement 1: 配置并返回 allow_negative_stock

**用户故事**: 作为物资管理者，我想在保存物料时设置 `allow_negative_stock`，以便业务侧决定是否允许负库存。

#### 验收标准

1. **WHEN** 通过 `SaveItem` 请求传入 `allow_negative_stock=true/false` **THEN** 系统保存该值并在物料详情及后续读取接口中返回对应布尔值。
2. **IF** 未传入 `allow_negative_stock` **THEN** 系统保持原值不变，沿用当前库存校验策略，不产生行为回归。

#### 具体要求

- [ ] 请求和响应模型新增 `allow_negative_stock` 字段（bool）。
- [ ] 持久化层写入/更新该字段；未传入时不覆盖存量值。
- [ ] 默认值策略与当前线上一致（避免回归），需在变更日志中说明。

---

### Requirement 2: 负库存下禁止关闭并提示

**用户故事**: 作为物资管理者，我想避免在物料已负库存时误关掉负库存开关。

#### 验收标准

1. **WHEN** 请求将 `allow_negative_stock` 从 true 改为 false **AND** 当前物料存在负库存（基于 Stock Projected Qty 等查询） **THEN** 系统拒绝关闭并提示：“物料已产生负库存，请修正库存后再进行操作。”
2. **WHEN** 关闭操作时未发现负库存 **THEN** 系统允许关闭并保存。

#### 具体要求

- [ ] 关闭前调用/复用库存查询（包含 Stock Projected Qty）判断是否存在负库存。
- [ ] 提示文案需与提案保持一致：“物料已产生负库存，请修正库存后再进行操作。”
- [ ] 校验逻辑可复用为公共服务，避免重复实现。

---

### Requirement 3: 下游库存校验与兼容性

**用户故事**: 作为系统维护者，我想让库存相关流程读取一致的负库存策略，避免行为不一致。

#### 验收标准

1. **WHEN** 负库存校验、扣减、调拨、生产等流程读取物料配置 **THEN** 能获取 `allow_negative_stock` 并按值决定是否放行负库存。
2. **IF** 旧调用方未传该字段 **THEN** 不改变其当前业务行为。

#### 具体要求

- [ ] 对库存相关服务的读取路径补充该字段（如已有模型，确保字段透传）。
- [ ] 保持向后兼容：未传字段不触发默认值变化。

## 非功能需求（聚焦相关项）

- **API 设计**: data 必须为对象，响应 `{code, message, data{}}`；URL snake_case；参考 `.cursor/rules/api.mdc`。
- **Go BMP 规范**: 遵循 `ttpos-bmp/.cursor/rules/go-rules.mdc`；禁止修改 dao/entity/do 生成目录；使用 GoFrame 2.x。
- **性能**: 本地响应 < 200ms，查询使用索引；校验调用的库存查询需可复用缓存或高效接口。
- **安全**: 需身份验证；参数校验防注入；错误日志记录。

## 验收标准

### 功能验收

1. **保存开关**: `allow_negative_stock` 传 true/false 时正确存取、回读。
2. **关闭校验**: 关闭时如存在负库存（Stock Projected Qty < 0），返回拒绝与提示文案。
3. **兼容性**: 未传字段时行为与现网一致，无额外库存放宽/收紧。

### 测试验收

1. **单元/Service 测试**: 覆盖新增字段保存、读取、关闭校验分支。
2. **API 测试**: 覆盖设置/关闭/未传字段场景。
3. **集成测试**: 关键库存流程读取该字段的端到端验证。

### 文档验收

1. design.md 完整描述接口/模型/校验改动。
2. 如有迁移或数据回填，提供脚本与说明。
3. tasks.md 列出测试与联调任务。

## 约束条件

- **技术**: GoFrame 2.x，遵循分层；不使用 panic，返回 error；库存查询需可复用。
- **业务**: 禁止在存在负库存时关闭该开关。
- **资源**: SP 预估 ≤ 5，具体由评审确认。

## 依赖关系

- 现有物料存取模型/存储结构。

## 风险和缓解

### 风险 1: 默认值处理不当导致回归
- **缓解**: 未传字段保持原值；增加回归用例。

### 风险 2: 下游未同步读取字段
- **缓解**: 梳理库存相关调用链，补充联调与监控。
