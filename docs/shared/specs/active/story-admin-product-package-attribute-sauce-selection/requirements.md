## 📋 概述

本需求旨在优化旧后台商品管理中的可选范围设置，将原有的"必选+最大可选"模式统一调整为"最小-最大可选范围"模式，涵盖成品的属性和加料，以及套餐的分组设置。此调整将提供更灵活的配置方式，改善用户体验，并保持与旧数据的兼容性。

**价值**：
- 提供更直观的可选范围配置方式
- 统一属性、加料、套餐分组的配置逻辑
- 兼容旧数据，平滑迁移
- 提升商家配置商品的效率

## 🎯 产品对齐

该功能支持产品愿景中"提升商家运营效率"的目标，通过优化配置界面和逻辑，减少商家在商品管理中的操作复杂度，降低配置错误率。

## 📝 用户故事

**作为** 商家管理员  
**我想** 通过统一的"最小-最大可选范围"方式配置商品属性、加料和套餐分组  
**以便于** 更灵活、更直观地设置商品可选项，减少配置错误

## 功能需求

### Requirement 1: 商品属性可选范围调整

**用户故事**: 作为商家管理员，我想为商品属性设置可选范围（最小-最大），以便于灵活控制客户可选择的属性数量

#### 验收标准

1. **WHEN** 旧数据迁移 **THEN** 系统 **SHALL** 按以下规则转换：
   - 不开启必选，不设置最大可选 → 可选范围：0 - 属性值数量
   - 开启必选 → 最小值：1
   - 开启最大可选 → 最大值：具体的值

2. **WHEN** 首次添加属性组 **THEN** 系统 **SHALL** 默认设置可选范围为：0 - 属性值数量

3. **WHEN** 用户输入最小值大于最大值 **THEN** 系统 **SHALL** 提示："最大可选不可小于最小可选"

4. **WHEN** 用户输入最大值 **THEN** 系统 **SHALL** 确保最大值 ≤ 属性值数量

5. **WHEN** 属性组数量超过100 **THEN** 系统 **SHALL** 提示："属性组数量不能超过100"

#### 具体要求

- [x] 1.1 数据库字段调整（已在任务 #37946 中完成）
- [x] 1.2 旧数据迁移脚本（已在任务 #37946 中完成）
- [ ] 1.3 添加商品时，默认可选范围为 0 - 属性值数量
- [ ] 1.4 编辑商品时，保持已有配置
- [ ] 1.5 前端验证：最大可选 ≥ 最小可选
- [ ] 1.6 后端验证：最大可选 ≥ 最小可选 && 最大可选 ≤ 属性值数量
- [ ] 1.7 属性组数量限制：≤ 100

### Requirement 3: 套餐分组可选范围调整

**用户故事**: 作为商家管理员，我想为套餐分组设置可选范围（最小-最大），以便于灵活控制客户可选择的商品数量

#### 验收标准

1. **WHEN** 设置可选分组类型 **THEN** 系统 **SHALL** 提供"本组可选数量"范围设置，默认：1 - 1

2. **WHEN** 用户输入最小值大于最大值 **THEN** 系统 **SHALL** 提示："分组N最大可选不可小于最小可选"（N为分组序号）

3. **WHEN** 用户输入可选范围 **THEN** 系统 **SHALL** 允许最小值和最大值为0

4. **WHEN** 分组数量超过100 **THEN** 系统 **SHALL** 提示："分组数量不能超过100"

#### 具体要求

- [x] 3.1 数据库字段调整（已在任务 #37946 中完成）
- [ ] 3.2 添加套餐时，默认可选范围为 1 - 1
- [ ] 3.3 编辑套餐时，保持已有配置
- [ ] 3.4 前端验证：最大可选 ≥ 最小可选，允许为0
- [ ] 3.5 后端验证：最大可选 ≥ 最小可选，允许为0
- [ ] 3.6 分组数量限制：≤ 100（现有限制为5，需调整）

## 风险和缓解

### 风险 1: 旧数据迁移失败

**影响**: 高  
**概率**: 中  
**缓解措施**:

- 编写可回滚的迁移脚本
- 在测试环境充分测试
- 提供数据备份方案

### 风险 2: 前端显示不兼容

**影响**: 中  
**概率**: 中  
**缓解措施**:

- 后端保持向后兼容
- 前端判断字段是否存在
- 提供降级方案

### 风险 3: 性能下降

**影响**: 低  
**概率**: 低  
**缓解措施**:

- 只调整字段，不改变查询逻辑
- 使用索引优化查询
