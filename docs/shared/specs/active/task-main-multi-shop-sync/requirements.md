## 📝 用户故事

**作为** 运维人员/开发人员
**我想** 通过 CLI 命令一次性同步多个门店的数据
**以便于** 提升运维效率，降低操作错误率，确保多门店数据一致性

---

## 功能需求

### Requirement 1: CLI 命令行接口

**用户故事**: 作为运维人员，我想通过命令行参数指定多个门店，以便于批量执行同步操作

#### 验收标准

1. **WHEN** 用户执行同步命令并通过参数指定门店列表（company_uuid）**THEN** 系统 **SHALL** 解析参数并获取待同步门店列表
2. **WHEN** 用户未指定门店参数 **THEN** 系统 **SHALL** 显示帮助信息或错误提示
3. **WHEN** 用户指定无效的 company_uuid **THEN** 系统 **SHALL** 终止执行，并反馈无效的 company_uuid

### Requirement 2: 并行同步执行

**用户故事**: 作为运维人员，我想多门店并行同步，以便于提升同步效率

#### 验收标准

1. **WHEN** 执行批量同步命令 **THEN** 系统 **SHALL** 并行执行各门店的同步任务
2. **WHEN** 用户指定并发数参数 **THEN** 系统 **SHALL** 按指定数量控制最大并发数
3. **WHEN** 用户未指定并发数参数 **THEN** 系统 **SHALL** 使用默认并发数（建议 5）

### Requirement 3: 进度显示与结果汇总

**用户故事**: 作为运维人员，我想看到同步进度和结果，以便于了解同步状态

#### 验收标准

1. **WHEN** 同步任务执行中 **THEN** 系统 **SHALL** 实时显示当前同步进度（已完成/总数）
2. **WHEN** 单个门店同步完成 **THEN** 系统 **SHALL** 显示该门店的同步结果（成功/失败）
3. **WHEN** 所有门店同步完成 **THEN** 系统 **SHALL** 汇总显示成功数量、失败数量和失败门店列表

### Requirement 4: 失败处理与容错

**用户故事**: 作为运维人员，我想单个门店失败不影响其他门店，以便于最大化同步成功率

#### 验收标准

1. **WHEN** 某门店同步失败 **THEN** 系统 **SHALL** 记录失败信息并继续执行其他门店同步
2. **WHEN** 同步完成且存在失败门店 **THEN** 系统 **SHALL** 输出失败门店列表（可用于重试）

### Requirement 5: 同步锁与幂等性保护

**用户故事**: 作为运维人员，我想系统自动跳过正在同步中的门店，以便于避免重复同步导致的数据冲突

#### 验收标准

1. **WHEN** 某门店已有同步任务正在执行 **THEN** 系统 **SHALL** 跳过该门店并标记为"跳过"状态
2. **WHEN** 同步完成且存在被跳过的门店 **THEN** 系统 **SHALL** 在汇总中单独显示跳过列表（区别于失败列表）
3. **WHEN** 某门店同步完成或失败 **THEN** 系统 **SHALL** 释放该门店的同步锁

## 风险和缓解

### 风险 1: 并发过高导致系统过载

**影响**: 中
**缓解措施**: 提供并发数配置参数，默认设置合理上限（建议 5），并在文档中说明生产环境推荐配置

### 风险 2: 部分门店同步失败

**影响**: 低
**缓解措施**: 实现失败隔离机制，记录失败门店列表便于重试
