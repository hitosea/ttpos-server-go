## 🎯 功能概述

在商家管理端的"参数设置"模块中新增"限购业务"功能，支持总部创建和管理多个限购方案，实现精细化的品牌采购申请限额管理。

### 核心价值

1. **精细化管理**：支持按时间段（星期）、门店、物品进行精细化限购控制
2. **方案化配置**：支持创建多个限购方案，每个方案独立配置
3. **智能校验**：自动过滤物品列表，实时校验限额，提供友好的错误提示
4. **跨天处理**：草稿单据跨天提交时重新校验限购方案，确保数据一致性

### 涉及终端

- [x] Shop 商家管理端（总部和门店）

### 涉及技术栈

- [x] Go (main/app/service/purchase_order/)
- [x] Vue 3 (admin/views/)
- [x] MySQL 8.0+ (新增 4 个表)
- [x] Redis 6.0+ (限购方案配置缓存)

## 📝 核心业务规则

### 限购方案匹配规则

1. **方案状态检查**：只匹配状态为"开启"的方案
2. **门店范围检查**：当前门店必须在方案的门店范围内
3. **星期检查**：当前日期对应的星期必须在方案的周期配置中
4. **物品检查**：物品必须在方案的物品配置中

### 限额校验规则

1. **单位校验**：如果方案配置了单位，申请单位必须匹配
2. **数量校验**：如果方案配置了数量，申请数量不能超过限额
3. **次数校验**：如果方案配置了每日申请次数，当天申请次数不能超限（已驳回的单据不计入）
4. **多方案匹配**：如果物品同时匹配多个方案，取最小值的限制

### 草稿单据跨天提交规则

1. **跨天检测**：对比草稿创建日期和当前日期
2. **重新校验**：如果跨天，重新查询当天的限购方案
3. **问题标记**：逐个检查草稿中的物品，标记不符合的问题物品
4. **阻止提交**：只有所有物品都符合当天限购方案才能提交

### 审核修改规则

1. **使用提交日期**：审核修改时使用单据提交日期的限购方案（而非当前日期）
2. **数量为0确认**：修改物品数量为0时，需要二次确认是否移除该物品
