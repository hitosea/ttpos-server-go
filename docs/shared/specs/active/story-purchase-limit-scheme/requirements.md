## 📋 概述

在商家管理端的"参数设置"模块中新增"限购业务"功能，支持总部创建和管理多个限购方案，实现精细化的品牌采购申请限额管理。每个限购方案可以独立配置周期（按星期）、物品限额（数量+单位）、门店范围、每日申请次数等规则。

门店在提交品牌采购申请时，系统会自动根据限购方案过滤物品列表，实时校验限额，并提供友好的错误提示。对于草稿单据跨天提交的场景，系统会重新校验限购方案变更，确保数据一致性。

## 🎯 产品对齐

本功能支持以下产品目标：

1. **提升采购管理精细化**：通过方案化管理，支持按时间段（星期）、门店、物品进行精细化限购控制
2. **优化库存管理**：引导门店合理规划采购，减少库存积压和浪费
3. **规范采购行为**：通过限额和次数控制，规范门店采购行为，降低总部审核工作量
4. **提高运营效率**：减少门店无效申请次数，提高采购申请通过率
5. **支持灵活的营销策略**：支持节假日限购调整等灵活的业务场景

**以便于** 引导门店合理规划采购，优化库存管理，规范采购行为

## 功能需求

### Requirement 1: 限购方案管理（总部视角）

**用户故事**: 作为总部采购管理员，我想在"参数设置"中管理多个限购方案，以便于灵活控制不同场景的采购限额

#### 验收标准

1. **WHEN** 用户进入商家管理端的"参数设置"页面 **THEN** 系统 **SHALL** 显示"限购业务"卡片入口
2. **WHEN** 用户查看"限购业务"卡片 **THEN** 系统 **SHALL** 显示描述文字："限制采购的数量、物品、门店等"
3. **WHEN** 用户点击"限购业务"卡片 **THEN** 系统 **SHALL** 跳转到限购方案列表页面
4. **WHEN** 用户进入限购方案列表页面 **THEN** 系统 **SHALL** 以卡片形式展示所有限购方案
5. **WHEN** 限购方案卡片展示 **THEN** 系统 **SHALL** 显示：方案名称、周期（如"周一、周三、周五"）、每日申请次数（如"5次"）、门店数量（如"10门店"或"全部门店"）、物品数量（如"45物品"）
6. **WHEN** 用户点击方案卡片 **THEN** 系统 **SHALL** 进入设置限购方案页面（编辑模式）
7. **WHEN** 用户点击页面底部的"新增"按钮 **THEN** 系统 **SHALL** 进入设置限购方案页面（新增模式）

#### 具体要求

- [x] 1.1 在"参数设置"页面新增"限购业务"卡片入口
- [x] 1.2 限购方案列表页面使用卡片布局，支持滚动查看
- [x] 1.3 每个方案卡片显示核心信息摘要（名称、周期、次数、门店、物品数量）
- [x] 1.4 支持点击卡片进入编辑页面
- [x] 1.5 底部固定"新增"按钮，随时可以创建新方案
- [x] 1.6 列表页面支持下拉刷新

### Requirement 2: 限购方案配置（总部视角）

**用户故事**: 作为总部采购管理员，我想配置限购方案的各项参数（名称、状态、周期、物品、门店、次数），以便于实现精细化的限购管理

8. **WHEN** 用户进入设置限购方案页面（新增模式） **THEN** 系统 **SHALL** 显示表单字段：名称（必填）、状态开关、周期、物品、门店、每日申请次数
9. **WHEN** 用户进入设置限购方案页面（编辑模式） **THEN** 系统 **SHALL** 显示表单字段和已保存的数据，底部显示"删除"和"保存"按钮
10. **WHEN** 用户未填写名称就点击保存 **THEN** 系统 **SHALL** 显示红色错误提示"名称不能为空"并阻止保存
11. **WHEN** 用户切换状态开关 **THEN** 系统 **SHALL** 更新方案状态（开启/关闭）
12. **WHEN** 用户点击周期字段 **THEN** 系统 **SHALL** 进入周期选择内页
13. **WHEN** 用户点击物品字段 **THEN** 系统 **SHALL** 跳转到物品选择页面
14. **WHEN** 用户点击门店字段 **THEN** 系统 **SHALL** 弹出门店选择器
15. **WHEN** 用户在每日申请次数输入框中输入数值 **THEN** 系统 **SHALL** 保存该方案的每日申请次数限制
16. **WHEN** 用户点击保存按钮 **THEN** 系统 **SHALL** 验证必填项（名称），验证通过后保存方案并返回列表页面
17. **WHEN** 用户在编辑模式点击删除按钮 **THEN** 系统 **SHALL** 弹出确认对话框，显示提示语"确定要删除限购方案"{方案名称}"吗？删除后无法恢复。"，确认后删除方案并返回列表页面

#### 具体要求

- [x] 2.1 方案名称为必填项，最多 50 个字符
- [x] 2.2 状态开关默认为"开启"
- [x] 2.3 周期配置默认为空，保存时至少选择一个星期
- [x] 2.4 物品配置默认为空，保存时至少选择一个物品
- [x] 2.5 门店配置默认为"全部门店"
- [x] 2.6 每日申请次数默认为空（不限制），如果输入则必须 > 0
- [x] 2.7 保存时校验必填项和数据有效性
- [x] 2.8 编辑模式显示"删除"按钮，新增模式不显示
- [x] 2.9 删除操作需要二次确认，防止误删

16. **WHEN** 用户在周期选择内页点击"取消"按钮 **THEN** 系统 **SHALL** 放弃修改，返回设置限购方案页面

#### 具体要求

- [x] 3.1 星期选择网格使用 7 个按钮，布局为 2 行（第一行 4 个，第二行 3 个）

- [x] 3.3 至少选择一个星期才能保存
- [x] 3.4 周期字段显示格式：逗号分隔（如"周一、周三、周五"）

**用户故事**: 作为总部采购管理员，我想选择物品并为每个物品配置限额（数量+单位），以便于精细化控制不同物品的采购量

19. **WHEN** 用户未选择任何物品就点击确定 **THEN** 系统 **SHALL** 在顶部显示红色提示"最少需选1个物品"并阻止确定
20. **WHEN** 用户在搜索框输入关键词 **THEN** 系统 **SHALL** 按"物品名称/内部编码/条形码"搜索并过滤物品列表
21. **WHEN** 物品按分类展示 **THEN** 系统 **SHALL** 显示分类名称和分类下的物品数量（红色徽章）
22. **WHEN** 用户查看物品列表 **THEN** 系统 **SHALL** 为每个物品显示：物品名称、内部编码、限额配置区域
23. **WHEN** 用户为物品配置限额项 **THEN** 系统 **SHALL** 显示数量输入框（带"+"和"-"按钮）、单位显示（固定显示该物品的销售单位，如果物品没有销售单位则显示基准单位，不可选择）、删除按钮（红色圆圈减号图标）
24. **WHEN** 用户点击物品限额配置区域的"+"按钮 **THEN** 系统 **SHALL** 添加新的限额项（数量+单位组合，单位固定为该物品的销售单位，如果物品没有销售单位则使用基准单位）
25. **WHEN** 用户点击限额项的删除按钮 **THEN** 系统 **SHALL** 从列表中移除该限额项
26. **WHEN** 用户配置物品的限额项数量 **THEN** 系统 **SHALL** 保存配置，数量可以为空（为空则不限制数量），如果输入数量则最小值为 0.001，单位固定为该物品的销售单位（如果物品没有销售单位则使用基准单位，不可选择）
27. **WHEN** 用户勾选底部"全选"复选框 **THEN** 系统 **SHALL** 选中所有物品
28. **WHEN** 用户选择物品后 **THEN** 系统 **SHALL** 在底部显示"已选X个"
29. **WHEN** 用户点击确定按钮 **THEN** 系统 **SHALL** 验证至少选择1个物品，验证通过后保存选择的物品和限额配置，返回设置限购方案页面并更新物品字段显示

- [x] 4.1 物品列表按分类分组展示，支持展开/收起
- [x] 4.2 搜索功能支持物品名称、内部编码、条形码模糊匹配
- [x] 4.3 限额配置的单位固定为物品的销售单位（如果没有销售单位则使用基准单位）
- [x] 4.4 数量配置默认为空（表示不限制数量）
- [x] 4.5 数量输入框支持小数，最小值 0.001，最大值 999999.999
- [x] 4.6 支持为同一物品配置多个限额项（后续可扩展多单位支持，当前版本每个物品只配置一个限额项）
- [x] 4.7 至少选择 1 个物品才能保存
- [x] 4.8 底部显示已选物品数量

34. **WHEN** 物品未配置在任何限购方案中 **THEN** 系统 **SHALL** 在列表中显示该物品（不受限额约束）

### Requirement 7: 限额校验（门店视角）

**用户故事**: 作为门店店长，我想在提交采购申请时系统自动校验限额，以便于避免提交超限的申请

#### 验收标准

39. **WHEN** 用户提交品牌采购申请 **THEN** 系统 **SHALL** 校验每个物品的限购方案配置（如果已配置）
40. **WHEN** 物品限额项的单位配置为空 **THEN** 系统 **SHALL** 不做单位限制，允许使用任何单位申请
41. **WHEN** 用户申请的单位不在限购方案配置的单位列表中（单位配置不为空时） **THEN** 系统 **SHALL** 拒绝提交并提示"物品 {name} 只能使用{单位列表}单位申请，请选择正确的单位"
42. **WHEN** 物品限额项的数量为空 **THEN** 系统 **SHALL** 不限制申请数量，仅校验单位
43. **WHEN** 用户申请的数量不满足限购方案配置的任一限额项（数量不为空时） **THEN** 系统 **SHALL** 拒绝提交并提示"物品 {name} 的申请限额为{数量}{单位}，当前申请数量{当前数量}{单位}超出限制"
44. **WHEN** 用户申请的门店不在限购方案的门店范围内 **THEN** 系统 **SHALL** 拒绝提交并提示"当前门店不在限购方案的门店范围内，无法申请该物品"
45. **WHEN** 统计申请次数时 **THEN** 系统 **SHALL** 只统计状态为"待审核"、"已审核"、"待总部审核"的申请，不统计状态为"已驳回"的申请
46. **WHEN** 申请次数超过限购方案配置的每日申请次数 **THEN** 系统 **SHALL** 拒绝提交并提示"物品 {name} 今日申请次数已达上限（{次数}次），剩余可申请次数：{剩余次数}次，请明天再试"
47. **WHEN** 限购方案和全局限额同时生效 **THEN** 系统 **SHALL** 取更严格的限制，优先应用限购方案
48. **WHEN** 物品同时匹配多个限购方案 **THEN** 系统 **SHALL** 取**最小值**的限制进行校验（例如：方案A限制5箱，方案B限制10箱，则实际限额为5箱；如果方案A数量为空，方案B限制10箱，则实际限额为10箱）
49. **WHEN** 物品在限购方案中单位配置为空 **THEN** 系统 **SHALL** 不做单位限制，在采购申请页面显示该物品的所有可用单位
50. **WHEN** 物品在限购方案中配置了单位 **THEN** 系统 **SHALL** 在采购申请页面只显示已配置的单位选项，未配置的单位不显示
51. **WHEN** 单据被驳回后 **THEN** 系统 **SHALL** 将该单据的申请次数从统计中移除，用户可以在当天继续提交申请（如果未达到上限）

#### 具体要求

- [x] 7.1 限额校验在提交采购申请时执行（后端实现）
- [x] 7.2 校验顺序：门店范围 → 星期匹配 → 单位匹配 → 数量限制 → 次数限制
- [x] 7.3 多方案匹配时取最小值逻辑：比较所有匹配方案的限额数量，取最小值
- [x] 7.4 申请次数统计使用当天（店铺时区）的时间范围
- [x] 7.5 驳回单据不计入次数统计
- [x] 7.6 错误提示清晰明确，包含具体的限额信息和剩余额度

### Requirement 8: 草稿单据跨天提交处理（门店视角）

**用户故事**: 作为门店店长，我想在草稿单据跨天提交时系统自动检测限购方案变更，以便于避免提交不符合当天限购规则的申请

#### 验收标准

52. **WHEN** 用户保存采购申请单为草稿，跨天提交时 **THEN** 系统 **SHALL** 显示跨天提交提示："该采购申请单创建于{创建日期}，当前日期为{当前日期}，限购方案已变更，请检查物品和数量再进行提交。"
53. **WHEN** 用户保存采购申请单为草稿，跨天提交时 **THEN** 系统 **SHALL** 重新判断草稿中的物品和单位是否符合当天的限购方案
54. **WHEN** 草稿中的物品数量不符合当天的限购方案 **THEN** 系统 **SHALL** 提示"物品 {name} 的限额已变更为{数量}{单位}，请修改申请数量后再提交"并阻止提交
55. **WHEN** 草稿中的物品单位不符合当天的限购方案 **THEN** 系统 **SHALL** 提示"物品 {name} 的单位限制已变更，当前使用的单位{当前单位}不在允许范围内，请修改后提交"并阻止提交
56. **WHEN** 草稿中的物品不在当天限购方案的门店范围内 **THEN** 系统 **SHALL** 提示"物品 {name} 已不在当前门店的限购方案范围内，请删除该物品或联系管理员"并阻止提交
57. **WHEN** 草稿单据跨天提交时检测到问题物品 **THEN** 系统 **SHALL** 在问题物品旁显示红色感叹号标签，点击感叹号展示具体问题描述
58. **WHEN** 草稿单据跨天提交时检测到问题物品 **THEN** 系统 **SHALL** 在合计区域展示问题项总数（如"2个物品存在问题"）

#### 具体要求

- [x] 8.1 草稿单据跨天提交校验在点击提交按钮时执行（后端实现）
- [x] 8.2 对比草稿创建日期和当前日期，判断是否跨天
- [x] 8.3 如果跨天，重新查询当天的限购方案并逐个检查草稿中的物品
- [x] 8.4 检查维度：物品是否在限购方案中 → 门店范围 → 星期匹配 → 单位匹配 → 数量限制
- [x] 8.5 如果检测到问题，标记问题物品并返回详细的问题描述
- [x] 8.6 前端展示：问题物品红色感叹号标签 + 点击展示问题详情 + 合计区域显示问题项总数
- [x] 8.7 只有所有物品都符合当天限购方案才能提交

- [x] 9.5 数量为0的物品需要二次确认，防止误操作
- [x] 9.6 移除物品后重新计算采购申请的总金额和总数量

## 验收标准

### 功能验收

1. **限购方案管理**: 总部可以创建、编辑、删除限购方案，方案列表正确显示所有方案信息
2. **限购方案配置**: 总部可以配置方案的名称、状态、周期、物品、门店、次数，所有配置项保存成功
3. **周期选择**: 总部可以选择方案的生效周期（星期几），至少选择一个星期才能保存
4. **物品选择和限额配置**: 总部可以选择物品并为每个物品配置限额（数量+单位），数量可以为空
5. **门店选择**: 总部可以选择方案适用的门店范围（全部或部分）
6. **物品列表过滤**: 门店在采购申请页面只能看到允许申请的物品（根据限购方案过滤）
7. **限额校验**: 门店提交采购申请时，系统自动校验限额（数量、单位、次数），超限时拒绝提交并提示
8. **多方案匹配**: 物品同时匹配多个限购方案时，取最小值的限制进行校验
9. **草稿单据跨天提交**: 草稿单据跨天提交时，系统重新校验限购方案，不符合时提示并阻止提交
10. **审核修改规则**: 审核人员修改采购申请时，使用提交日期的限购方案进行校验
11. **用户提示**: 门店在采购申请页面可以看到清晰的限购提示和剩余额度信息
12. **驳回单据处理**: 单据被驳回后，申请次数从统计中移除，用户可以继续提交申请

## 风险和缓解

### 风险 1: 性能风险 - 物品列表过滤查询可能影响性能

**影响**: 中  
**概率**: 中  
**缓解措施**:

- 使用数据库索引优化查询（`material_code` + `company_uuid`）
- 使用 Redis 缓存限购方案配置（TTL: 5分钟）
- 分页查询，避免一次性加载所有物品
- 压测验证性能，如果不达标则进一步优化（如使用 Elasticsearch）

### 风险 2: 数据一致性风险 - 草稿单据跨天提交时限购方案可能变更

**影响**: 高  
**概率**: 中  
**缓解措施**:

- 在提交时重新校验限购方案，确保数据一致性
- 提供清晰的错误提示和问题物品标记，引导用户修改
- 使用事务保证校验和提交的原子性
- 记录详细的错误日志，便于问题排查

### 风险 3: 业务复杂度风险 - 多方案匹配逻辑复杂，容易出错

**影响**: 高  
**概率**: 中  
**缓解措施**:

- 编写详细的业务逻辑文档和流程图
- 编写全面的单元测试和集成测试
- Code Review 重点关注多方案匹配逻辑
- 使用日志记录匹配过程，便于调试

### 风险 4: 用户体验风险 - 门店提交申请时限购方案变更，导致提交失败

**影响**: 中  
**概率**: 低  
**缓解措施**:

- 提供友好的错误提示和操作引导
- 在草稿单据跨天提交时提前提示用户检查
- 显示剩余可申请次数，避免用户盲目提交
- 记录用户反馈，持续优化提示文案
