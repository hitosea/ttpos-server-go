## 📋 概述

当订单在管理端被标记为"已选择"（数据管理订单）后，系统需要在所有相关的数据统计和展示场景中，自动排除这些已选择订单的数据，确保各项业务数据的准确性和可靠性。

**核心价值**：
- ✅ **数据准确性**：确保管理端首页和各类报表统计的数据真实反映实际营业情况
- ✅ **业务决策支持**：为商户提供准确的经营数据，支持正确的业务决策
- ✅ **数据管理能力**：增强商户对订单数据的控制能力，支持数据筛选和过滤
- ✅ **用户体验提升**：符合商户对"已选择订单"的预期行为（隐藏/排除）

**重要说明**：
- **导出接口同步过滤**：所有报表统计的导出接口（如 `/shop/statistics/business/time_period/export`、`/shop/statistics/channel_sales/export` 等）也需要排除已选择订单。导出接口内部调用统计接口时，必须传递相同的过滤参数，确保导出的 Excel 文件中的数据与页面展示的数据一致。
- **过滤逻辑统一**：所有统计接口和导出接口使用相同的过滤逻辑，通过 `ExcludeDataManage` 参数控制是否排除已选择订单。

## 🎯 产品对齐

本功能支持管理端的数据管理需求，确保已选择订单（通常用于批量操作或数据导出）不会影响首页和各类报表的统计数据，提升数据管理的准确性和可靠性，帮助商户做出正确的经营决策。

## 📝 用户故事

**以便于** 获得准确的营业数据，支持正确的业务决策

## 功能需求

### Requirement 1: 新管理端-首页数据过滤

**用户故事**: 作为商户管理员，我想已选择订单不在新管理端首页的统计数据中显示，以便于查看准确的营业数据

#### 验收标准

1. **WHEN** 查看新管理端首页 **THEN** 系统 **SHALL** 排除已选择订单，不显示以下统计数据：
   - 总销售额
   - 实收金额
   - 商品数量
   - 会员折扣
   - 营业收入
   - 服务费
   - 支付手续费
   - 税费
   - 退款金额
   - 优惠折扣
   - 优惠占比
   - 赠菜总额
   - 赠菜数量
   - 免单总额
   - 免单数量

2. **WHEN** 查看新管理端首页区域数据 **THEN** 系统 **SHALL** 排除已选择订单，不显示以下统计数据：
   - 总销售额
   - 营业收入
   - 商品数量

3. **WHEN** 查看新管理端首页渠道营业统计 **THEN** 系统 **SHALL** 排除已选择订单

4. **WHEN** 查看新管理端首页合计订单数、最小订单金额、最大订单金额、平均订单金额 **THEN** 系统 **SHALL** 排除已选择订单

5. **WHEN** 查看新管理端首页桌台方式统计（桌数、人数、最小/大订单金额、平均订单金额） **THEN** 系统 **SHALL** 排除已选择订单

6. **WHEN** 查看新管理端首页点餐方式-店内统计（订单数、最小/大订单金额、平均订单金额） **THEN** 系统 **SHALL** 排除已选择订单

7. **WHEN** 查看新管理端首页点餐方式-外卖统计（订单数、最小/大订单金额、平均订单金额） **THEN** 系统 **SHALL** 排除已选择订单

8. **WHEN** 查看新管理端首页支付数据（支付方式、订单数、金额） **THEN** 系统 **SHALL** 排除已选择订单

9. **WHEN** 查看新管理端首页销量及销售额 **THEN** 系统 **SHALL** 排除已选择订单

#### 具体要求

- [ ] 1.1 新管理端首页统计接口 `/shop/statistics/home` 需要排除已选择订单
- [ ] 1.2 新管理端首页营业数据统计接口 `/shop/statistics/business` 需要排除已选择订单
- [ ] 1.3 新管理端首页区域数据统计接口 `/shop/statistics/area` 需要排除已选择订单
- [ ] 1.4 新管理端首页渠道营业统计接口 `/shop/statistics/channel_sales` 需要排除已选择订单

## 约束条件

### 技术约束

#### Go Main 模块

- 必须使用 Gin 框架
- 接口以 `I` 开头，实现以 `Impl` 结尾
- Service 只能依赖其他 Service 接口
- Repository 只能持有 db 实例，不能持有 DBManager
- 不使用 panic，返回 error
- **复用现有过滤方法**: 使用 `CommonRepo.WhereNotInDataManageSubQuery` 方法

#### Go BMP 模块

- 不涉及

#### PHP 模块

- 不涉及（旧后台如使用相同接口，通过 Go Main 模块统一处理）

#### Vue 模块

- 不涉及（前端仅展示数据，过滤逻辑在后端）

### 业务约束

- 数据管理功能必须开启（公司开启数据管理 + 数据管理功能启用）
- 已选择订单的判断标准：`ttpos_data_manage` 表中 `type = 0` 且 `data_uuid = sale_bill_uuid`
- 过滤逻辑需要在 Handler 层判断数据管理功能是否开启，设置 `ExcludeDataManage` 参数
- **导出接口一致性要求**：所有导出接口导出的数据必须与对应统计接口页面展示的数据完全一致，都排除已选择订单
- **导出接口实现方式**：导出接口内部调用统计接口时，必须传递相同的 `ExcludeDataManage` 参数，确保过滤逻辑一致

### 资源约束

- 开发时间: 3-5 天
- Story Point: 5 SP (必须 ≤ 5)

### 实现细节说明

#### 导出接口实现要点

1. **导出接口调用统计接口**：
   - 所有导出接口（如 `ExportBusinessTimePeriod`、`ExportChannelSales` 等）内部都会调用对应的统计接口（如 `CountBusinessTimePeriod`、`CountChannelSales` 等）
   - 导出接口在调用统计接口时，必须传递 `ExcludeDataManage` 参数，确保过滤逻辑一致

2. **渠道营业统计特殊说明**：
   - `CountChannelSales` Service 方法调用 `CountChannelSale` Repository 方法时，需要传递过滤参数（`opts ...DBOption`）
   - Repository 方法 `CountChannelSale` 已支持 `opts` 参数，需要在 Service 层传递 `WhereNotInDataManageSubQuery` 过滤条件

3. **数据一致性保证**：
   - 导出接口必须使用与统计接口相同的过滤逻辑
   - 导出的 Excel 文件中的数据必须与页面展示的数据完全一致
   - 测试时需要验证：页面数据 = 导出数据（都排除已选择订单）

#### Handler 层实现要点

1. **数据管理功能判断**：
   - 在 Handler 层判断两个条件：
     - `CompanySetting.IsOpenDataManagement()` - 公司是否开启数据管理
     - `DataManageSetting.IsEnableDataManage` - 数据管理功能是否启用
   - 两个条件都满足时，设置 `ExcludeDataManage = true`

2. **参数传递**：
   - Handler 层设置 `ExcludeDataManage` 参数后，传递给 Service 层
   - Service 层根据参数决定是否添加过滤条件
   - Repository 层接收过滤选项（DBOption），执行数据库查询

## 风险和缓解

### 风险 1: 接口遗漏

**影响**: 中  
**概率**: 中  
**缓解措施**:

- 在开发前完整梳理所有涉及订单统计的接口，建立清单
- **特别注意导出接口**：确保所有导出接口（`/export` 结尾）都应用了过滤逻辑
- 参考收银机端的实现（`story-cashier-selected-order-data-exclusion`）
- 代码审查时重点检查接口覆盖，包括统计接口和导出接口

### 风险 2: 性能影响

**影响**: 中  
**概率**: 低  
**缓解措施**:

- 在数据库查询层面优化过滤逻辑，确保索引有效利用
- 复用现有的 `WhereNotInDataManageSubQuery` 方法（已优化）
- 进行性能测试，确保响应时间符合要求

### 风险 3: 旧后台兼容

**影响**: 低  
**概率**: 中  
**缓解措施**:

- 对比新旧管理端的接口调用，确保一致性
- 如果旧后台使用相同接口，统一在 Go Main 模块处理
- 验证旧后台和新管理端的数据一致性

### 风险 4: 导出数据与页面数据不一致

**影响**: 高  
**概率**: 中  
**缓解措施**:

- 导出接口必须调用相同的统计方法，并传递相同的过滤参数
- 在测试时，对比导出文件中的数据与页面展示的数据，确保完全一致
- 编写自动化测试，验证导出数据与统计接口返回数据的一致性
