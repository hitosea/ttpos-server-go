## 功能概述

### 二维限购控制架构

```
┌─────────────────────────────────────────────────────────────────┐
│                    门店提交品牌采购申请                          │
└────────────────────────┬────────────────────────────────────────┘
                         │
                         ▼
         ┌────────────────────────────────────────┐
         │  维度1：每日申请次数检查               │
         │  配置来源：ttpos_setting               │
         │  purchase_brand_daily_limit            │
         │  ⚙️  值=-1 表示不限制，直接通过        │
         └───────────┬────────────────────────────┘
                     │
         ┌───────────┴────────────┐
         │                        │
      超限 ▼                   通过 ▼
    ┌──────────┐      ┌────────────────────────────────────────┐
    │ ❌ 拒绝  │      │  维度2：物品限额检查                   │
    │   提交   │      │  配置来源：purchase_quota_config       │
    └──────────┘      │  按物品+单位精确控制                   │
                      │  ⚙️  无配置/禁用 表示不限制，直接通过  │
                      └───────────┬────────────────────────────┘
                                  │
                      ┌───────────┴────────────┐
                      │                        │
                   超限 ▼                   通过 ▼
                 ┌──────────┐          ┌──────────┐
                 │ ❌ 拒绝  │          │ ✅ 提交  │
                 │   提交   │          │   成功   │
                 └──────────┘          └──────────┘

💡 说明：
  • 维度1：配置值为 -1 时，表示不限制，校验直接通过
  • 维度2：如果物品没有限购配置，或配置状态为禁用(status=0)，则不限制
  • 物品限额支持按天或按月周期配置（period_type: 0=按天, 1=月度）
```

### 二维限购对比表

| 维度 | 说明 | 配置位置 | 校验时机 | 统计维度 | 限制值 | 周期支持 |
|------|------|----------|----------|----------|--------|----------|
| **每日申请次数** | 限制门店每天能提交的品牌采购申请次数 | `ttpos_setting` 表 | 提交订单时 | 门店级别 | -1=不限制 | - |
| **物品限额** | 限制特定物品在一定周期内的采购总量 | `purchase_quota_config` 表 | 提交订单时 | 物品+单位 | 具体数值 | 按天/月度 |

**字段说明：**

- 📦 **物品编码（material_code）**：来自 ERP 系统的物品编码，例如：`ITEM-20250108-001`
- 📏 **单位编码（unit_code / erpnext_uom）**：来自 ERP 系统的单位编码，例如：`kg`、`box`、`pcs`
- 🔗 **物品+单位组合**：限购配置精确到 `material_code` + `unit_code` 的组合，确保同一物品不同单位可以独立限购

### 关键特性

- ✅ **实时统计**：不维护额外状态，直接查询已提交订单统计
- ✅ **自动释放**：驳回的订单自动释放额度，无需手动干预
- ✅ **物品级精确控制**：通过 ERP 系统的 `material_code` + `unit_code` 精确限制
- ✅ **门店维度**：每个门店独立统计，互不影响
- ✅ **总部管控**：配置存储在总部数据库，统一管理

**术语说明：**

- **material_code**：物品编码，来自 ERP 系统（ERPNext），例如：`ITEM-20250108-001`
- **unit_code / erpnext_uom**：单位编码，来自 ERP 系统（ERPNext），例如：`kg`、`box`、`pcs`
- **company_uuid**：门店/公司唯一标识符（使用雪花算法生成）

## 涉及的数据库表

### 1. `ttpos_setting` - 全局配置表

存储每日申请次数限制和单次数量限制。

| 字段 | 类型 | 说明 |
|------|------|------|
| `key` | varchar(255) | 配置键名 |
| `values` | text | JSON 格式配置值 |
| `describe` | varchar(255) | 配置说明 |

**相关配置键：**

- `purchase_brand_daily_limit`：每日申请次数上限
  - 格式：`{"limit": -1}` 
  - `-1` 表示不限制

### 2. `purchase_quota_config` - 物品限购配置主表

存储物品级别的限购规则（按天或按月）。

| 字段 | 类型 | 说明 | 示例值 |
|------|------|------|--------|
| `uuid` | bigint(20) | 配置唯一ID | 雪花算法生成 |
| `material_code` | varchar(100) | 物品编码 | `ITEM001` |
| `unit_code` | varchar(50) | 限购单位编码 | `kg`, `box` |
| `quota_limit` | decimal(10,2) | 限购数量 | `100.00` |
| `apply_to_all_shops` | int(4) | 是否应用全部店铺 | `1`=是, `0`=否 |
| `period_type` | int(4) | 周期类型 | `0`=按天, `1`=月度 |
| `strict_mode` | int(4) | 超限策略 | `1`=严格拒绝 |
| `config_source` | int(4) | 配置来源 | `1`=门店, `2`=总部 |
| `status` | int(4) | 状态 | `1`=启用, `0`=禁用 |

### 3. `purchase_quota_config_shop` - 门店关联表

当 `apply_to_all_shops=0` 时，指定哪些门店受限。

| 字段 | 类型 | 说明 |
|------|------|------|
| `config_uuid` | bigint(20) | 关联配置UUID |
| `company_uuid` | bigint(20) | 门店UUID |

### 4. `ttpos_purchase_order` - 采购订单表

| 关键字段 | 类型 | 说明 | 用途 |
|----------|------|------|------|
| `purchase_type` | int(4) | 采购类型 | `2`=品牌采购 |
| `status` | int(4) | 订单状态 | `0`=草稿(不计入统计) |
| `order_time` | int(10) | 提交时间戳 | 用于统计日/月额度 |
| `company_uuid` | bigint(20) | 门店UUID | 按门店维度统计 |

**订单状态说明：**
- `0` - 草稿（不计入统计）
- `1` - 待审核（计入统计）
- `2` - 已审核（计入统计）
- `3` - 已驳回（不计入统计）
- `4` - 已完成（计入统计）
- `5` - 待总部审核（计入统计）

### 5. `ttpos_purchase_order_item` - 采购订单明细表

| 关键字段 | 类型 | 说明 |
|----------|------|------|
| `material_code` | varchar(100) | **物品编码（来自 ERP）** |
| `erpnext_uom` | varchar(50) | **单位编码（来自 ERP，uom = Unit of Measure）** |
| `num` | decimal(10,2) | 数量 |

**字段说明：**

- `material_code`：必须与 ERP 系统中的物品编码一致
- `erpnext_uom`：ERPNext 系统中的单位编码（Unit of Measure），如：`kg`、`box`、`pcs`
- 限购校验时使用 `material_code` + `erpnext_uom` 组合匹配配置

## 限购校验流程图

| 步骤 | 操作 | 判断条件 | 通过 → | 拒绝 → |
|------|------|----------|--------|--------|
| **1** | 类型检查 | 是否品牌采购？ | 步骤2 | ✅ 允许提交 |
| **2** | 总部检查 | 有总部配置？ | 步骤3 | ✅ 允许提交 |

### 🔹 维度1：每日申请次数校验

| 步骤 | 操作 | 判断条件 | 通过 → | 拒绝 → |
|------|------|----------|--------|--------|
| **3.1** | 读取配置 | 从 `ttpos_setting` 读取 `purchase_brand_daily_limit` | - | - |
| **3.2** | 检查限制 | 限制值 = -1？ | 步骤4 | 步骤3.3 |
| **3.3** | 统计今日 | 统计今日已提交次数 | - | - |
| **3.4** | 对比限制 | 已提交次数 >= 限制值？ | 步骤4 | ❌ 拒绝：今日次数已达上限 |

### 🔹 维度2：物品限额校验

| 步骤 | 操作 | 判断条件 | 通过 → | 拒绝 → |
|------|------|----------|--------|--------|
| **4.1** | 遍历明细 | 遍历订单明细（逐个物品） | - | - |
| **4.2** | 查配置 | 从 `purchase_quota_config` 查询限购配置 | - | - |
| **4.3** | 配置存在？ | 是否有限购配置？ | 步骤4.4 | 步骤4.9（下一物品） |
| **4.4** | 单位匹配 | 采购单位 = 配置单位？ | 步骤4.5 | ❌ 拒绝：单位不匹配 |
| **4.5** | 周期类型 | period_type = 0（按天）or 1（月度）？ | 步骤4.6 or 4.7 | - |
| **4.6** | 统计今日 | 统计今日已使用额度 | 步骤4.8 | - |
| **4.7** | 统计本月 | 统计本月已使用额度 | 步骤4.8 | - |
| **4.8** | 对比额度 | (已用额度 + 本次数量) > 限购额度？ | 步骤4.9 | ❌ 拒绝：额度超限 |
| **4.9** | 继续检查 | 还有更多物品？ | 步骤4.2 | ✅ 提交成功 |

**业务规则：**
- 门店每天最多提交 3 次品牌采购申请
- 第 4 次提交时应被拒绝

**数据库配置：**

```sql
-- 在总部数据库（headquarter_uuid）中配置
UPDATE ttpos_setting 
SET `values` = '{"limit": 3}' 
WHERE `key` = 'purchase_brand_daily_limit';
```

**测试步骤：**
1. 使用门店账号提交 3 次品牌采购申请（任意物品）
2. 第 4 次提交时，系统应提示：`今日申请次数已达上限（3次），请明天再试`

**验证 SQL：**

```sql
-- 查询今日已提交次数
SELECT COUNT(*) as today_count
FROM ttpos_purchase_order
WHERE company_uuid = {门店UUID}
  AND purchase_type = 2
  AND status != 0
  AND order_time > 0
  AND order_time >= UNIX_TIMESTAMP(CURDATE())
  AND order_time < UNIX_TIMESTAMP(CURDATE() + INTERVAL 1 DAY)
  AND delete_time = 0;
```

```
                 │
                 │ 配置生效

第1次申请: 60kg

  ├─ 查询已用: 0kg
  ├─ 计算: 0 + 60 = 60kg ≤ 100kg
  └─► ✅ 通过 (已用额度: 60kg)

  ├─ 查询已用: 60kg
```

**额度使用情况表：**

| 操作 | 本次申请 | 已用额度 | 计算公式 | 结果 | 剩余额度 |
|------|----------|----------|----------|------|----------|
| 初始状态 | - | 0kg | - | - | 100kg |
| 第1次申请 | 60kg | 0kg | 0 + 60 = 60 ≤ 100 | ✅ 通过 | 40kg |
| 第2次申请 | 50kg | 60kg | 60 + 50 = 110 > 100 | ❌ 拒绝 | 40kg |
| 第3次申请 | 40kg | 60kg | 60 + 40 = 100 ≤ 100 | ✅ 通过 | 0kg |

**业务规则：**
- 物品 `ITEM001`（单位：`kg`）每月限购 100kg
- 适用于所有门店
- ⚠️ **物品编码和单位编码必须从 ERP 系统获取**

**数据库配置：**

```sql
-- 在总部数据库中配置
INSERT INTO purchase_quota_config (
    uuid,
    material_code,
    unit_code,
    quota_limit,
    apply_to_all_shops,
    period_type,
    strict_mode,
    config_source,
    status,
    create_time,
    update_time
) VALUES (
    {雪花算法生成的UUID},
    'ITEM001',         -- ⚠️ 必须与 ERP 系统中的物品编码一致
    'kg',              -- ⚠️ 必须与 ERP 系统中的单位编码一致
    100.00,            -- 月度限额 100kg
    1,                 -- 应用到全部店铺
    1,                 -- 月度限购
    1,                 -- 严格拒绝
    2,                 -- 总部下发
    1,                 -- 启用
    UNIX_TIMESTAMP(),
    UNIX_TIMESTAMP()
);
```

**⚠️ 配置前准备：**

1. **从 ERP 系统查询物品信息**：
   ```sql
   -- 在 ERPNext 数据库中查询
   SELECT item_code, item_name, stock_uom 
   FROM `tabItem` 
   WHERE item_code = 'ITEM001';
   ```

2. **确认单位编码**：
   ```sql
   -- 查询物品支持的单位
   SELECT uom 
   FROM `tabUOM Conversion Detail` 
   WHERE parent = 'ITEM001';
   ```

**测试步骤：**
1. 门店 A 提交申请：`ITEM001` 60kg → 成功
2. 门店 A 再提交：`ITEM001` 50kg → 失败（60+50=110 > 100）
3. 门店 A 再提交：`ITEM001` 40kg → 成功（60+40=100）

**验证 SQL：**

```sql
-- 查询本月已使用额度
SELECT COALESCE(SUM(poi.num), 0) as used_qty
FROM ttpos_purchase_order po
JOIN ttpos_purchase_order_item poi ON po.uuid = poi.purchase_order_uuid
WHERE po.company_uuid = {门店UUID}
  AND po.purchase_type = 2
  AND poi.material_code = 'ITEM001'
  AND poi.erpnext_uom = 'kg'
  AND po.status != 0
  AND po.order_time > 0
  AND FROM_UNIXTIME(po.order_time, '%Y-%m') = DATE_FORMAT(NOW(), '%Y-%m')
  AND po.delete_time = 0;
```

### 场景 3：测试物品限额（按天，指定门店）

**业务规则：**
- 物品 `ITEM002`（单位：`box`）每天限购 50 box
- 仅适用于特定门店

### 场景 5：测试草稿订单不占用额度

**订单状态流转图：**

```
                     创建订单
```

**状态与统计关系表：**

| 状态值 | 状态名称 | 是否计入统计 | 是否占用额度 | 说明 |
|--------|----------|--------------|--------------|------|
| 0 | 草稿 | ❌ | ❌ | 未提交，可随意修改 |
| 1 | 待审核 | ✅ | ✅ | 已提交，等待审核 |
| 2 | 已审核 | ✅ | ✅ | 审核通过，采购中 |
| 3 | 已驳回 | ❌ | ❌ | 审核拒绝，自动释放 |

| 5 | 待总部审核 | ✅ | ✅ | 等待总部审核 |

**业务规则：**

- 驳回的订单（`status=3`）也不计入统计

3. 提交订单（`status=1`）
4. 查询已使用额度 → 应为 80
5. 订单被驳回（`status=3`）
6. 查询已使用额度 → 应为 0（驳回后自动释放）
