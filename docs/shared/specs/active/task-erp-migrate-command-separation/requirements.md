## 📋 概述

ERP 迁移命令分离优化旨在将 `ErpMigrate` 和 `ErpAllMigrate` 从 `Main` 的子命令改为独立的顶级命令，使得执行迁移命令时不需要启动 HTTP 服务器，提升执行效率并降低资源消耗。

本功能主要涉及命令行工具结构的调整和命令执行逻辑的优化。

## 🎯 产品对齐

该功能支持公司 2025 年 Q4 的核心目标：

- **提升开发效率**: 迁移命令执行更快，无需等待 HTTP 服务初始化
- **降低资源消耗**: 迁移工具独立运行，不启动不必要的服务
- **改善运维体验**: 命令行工具结构更清晰，便于维护和测试

## 📝 用户故事

**作为** 开发/运维人员  
**我想** 执行 ERP 迁移命令时不需要启动 HTTP 服务器  
**以便于** 提高执行效率，减少资源消耗，加快迁移速度

## 功能需求

### Requirement 1: 命令结构分离

**用户故事**: 作为开发人员，我想将迁移命令从 Main 的子命令改为独立命令，以便于迁移工具独立执行

#### 验收标准

1. **WHEN** 执行迁移命令 **THEN** 系统 **SHALL** 不启动 HTTP 服务器
2. **WHEN** 执行全量迁移命令 **THEN** 系统 **SHALL** 不启动 HTTP 服务器
3. **WHEN** 执行 Main 命令 **THEN** 系统 **SHALL** 正常启动 HTTP 服务器
4. **IF** 迁移命令执行成功 **THEN** 系统 **SHALL** 正常退出（`os.Exit(0)`）

#### 具体要求

- [ ] 1.1 修改 `main.go`，将迁移命令注册为独立命令
- [ ] 1.2 确保迁移命令执行时不触发 Main 命令的初始化逻辑
- [ ] 1.3 保持命令行参数格式不变（向后兼容）
- [ ] 1.4 确保命令执行逻辑正确

---

### Requirement 2: 命令执行优化

**用户故事**: 作为运维人员，我想迁移命令执行更快，以便于提高工作效率

#### 验收标准

1. **WHEN** 执行迁移命令 **THEN** 系统 **SHALL** 仅执行迁移逻辑，不进行 HTTP 服务初始化
2. **WHEN** 迁移命令执行完成 **THEN** 系统 **SHALL** 立即退出，不保持进程运行
3. **IF** 迁移命令执行失败 **THEN** 系统 **SHALL** 返回错误码并退出

#### 具体要求

- [ ] 2.1 优化命令执行流程，避免不必要的初始化
- [ ] 2.2 确保迁移命令执行完成后正确退出
- [ ] 2.3 错误处理和日志记录完善

---

### Requirement 3: 向后兼容性

**用户故事**: 作为运维人员，我想现有的 CI/CD 脚本和运维脚本继续正常工作，以便于不中断现有流程

#### 验收标准

1. **WHEN** 使用现有命令行参数格式执行迁移命令 **THEN** 系统 **SHALL** 正常工作
2. **WHEN** 使用现有命令行参数格式执行全量迁移命令 **THEN** 系统 **SHALL** 正常工作
3. **IF** 命令行参数格式变更 **THEN** 系统 **SHALL** 提供清晰的错误提示

#### 具体要求

- [ ] 3.1 保持命令行参数格式不变
- [ ] 3.2 保持命令功能不变
- [ ] 3.3 更新相关文档，说明新的命令执行方式

---

## 非功能需求

### NFR 1: 性能要求

- **迁移命令启动时间**: < 1 秒（不启动 HTTP 服务器）
- **命令执行响应**: 立即执行，无延迟

### NFR 2: 可维护性

- **代码结构清晰**: 命令分离，职责明确
- **易于测试**: 迁移命令可独立测试
- **文档完善**: 更新相关文档

### NFR 3: 兼容性

- **向后兼容**: 保持现有命令行参数格式
- **CI/CD 兼容**: 不影响现有自动化脚本
