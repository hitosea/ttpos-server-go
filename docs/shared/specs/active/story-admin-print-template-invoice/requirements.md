## 📋 概述

在现有的新管理端自定义打印模板功能基础上，增加发票模板类型。提供可视化编辑界面，支持发票专属字段（发票编号、统一信用代码、交易单号、店铺编号等）、拖拽排序、重复添加、分割线/空行插入等高级编辑能力，同时保留默认模板供商家快速使用。旧商家后台支持预览和使用自定义发票模板，但调整模板需前往桌面端操作。

## 🎯 产品对齐

- **统一票据管理**：将发票打印纳入统一的模板管理体系，简化商家操作流程
- **个性化配置**：支持发票的自定义配置，满足不同商家的个性化需求和合规要求
- **灵活可扩展**：通过可视化编辑器和高级功能，提升票据打印的灵活性和可扩展性
- **增强竞争力**：提供完善的发票打印功能，满足合规要求，增强产品竞争力

## 📝 用户故事

## 功能需求

### Requirement 1: 发票专属字段支持

**用户故事**: 作为 商户管理员，我想 在发票模板中配置发票专属字段，以便于 打印符合规范的发票信息

#### 验收标准

1. **WHEN** 用户点击左侧模板项 **THEN** 系统 **SHALL** 在编辑区显示对应配置项，并高亮选中项
2. **IF** 某字段内容为空（无数据时） **THEN** 系统 **SHALL** 不打印该项
3. **WHEN** 发票编号、统一信用代码、交易单号、店铺编号无内容时 **THEN** 系统 **SHALL** 不打印这些字段
4. **WHEN** 用户编辑票据名称 **THEN** 系统 **SHALL** 允许修改文字内容

#### 具体要求

- [ ] 1.1 支持以下发票专属字段：
  - 店铺编号
  - 发票编号
  - 统一信用代码
  - 交易单号
  - 价格说明
  - 发票信息
  - 注意事项
- [ ] 1.2 支持可编辑票据名称（支持多语言）
- [ ] 1.3 字段内容为空时不打印该项
- [ ] 1.4 左侧模板选择项点击后，编辑区显示对应配置并高亮
- [ ] 1.5 无法取消选中：左侧项仅可通过右侧编辑区删除
- [ ] 1.6 对比结账单模板，增加上述差异性字段

---

### Requirement 2: 可视化编辑器

**用户故事**: 作为 商户管理员，我想 通过可视化编辑器自定义发票布局，以便于 满足不同的打印需求

#### 验收标准

1. **WHEN** 用户点击"分割线"按钮 **THEN** 系统 **SHALL** 在选中项下方插入水平分割线
2. **WHEN** 用户点击"空行插入"按钮 **THEN** 系统 **SHALL** 在选中项上方或下方插入空行（字号正常大小）
3. **IF** 项目可删除 **THEN** 系统 **SHALL** 显示删除按钮
4. **WHEN** 用户输入自定义文字 **THEN** 系统 **SHALL** 限制最多500字符
5. **IF** 自定义文字对某语言未翻译 **THEN** 系统 **SHALL** 在该语言下不打印该文字
6. **IF** 自定义图片未上传 **THEN** 系统 **SHALL** 不打印该图片

#### 具体要求

- [ ] 2.1 左侧区（模板选择项）：
  - 显示可添加的字段列表
  - 点击后在编辑区显示配置项并高亮
- [ ] 2.2 右侧区（样式编辑）：
  - 分割线按钮：在选中项下方插入水平分割线
  - 空行插入按钮：在选中项上方或下方插入空行
  - 删除按钮：仅对可删除项显示
- [ ] 2.3 自定义文字：
  - 最多500字符
  - 支持多语言
  - 未翻译的语言不打印该文字
- [ ] 2.4 自定义图片：
  - 支持上传图片
  - 未上传时不打印
- [ ] 2.5 商品项默认开启，不可关闭

---

### Requirement 3: 高级编辑功能

**用户故事**: 作为 商户管理员，我想 使用拖拽排序和重复添加等高级功能，以便于 灵活调整发票布局

#### 验收标准

1. **WHEN** 用户选择某项 **THEN** 系统 **SHALL** 仅高亮该项，其他项取消高亮
2. **WHEN** 用户编辑高级票据模板名称 **THEN** 系统 **SHALL** 限制1-20字符
3. **IF** 用户未填写模板名称并尝试保存 **THEN** 系统 **SHALL** 显示 Toast 提示"请填写模板名称"
4. **WHEN** 用户拖动编辑区内的项/组 **THEN** 系统 **SHALL** 允许任意调整位置（默认模板不可拖动）
5. **WHEN** 单项被重复添加第三次时 **THEN** 系统 **SHALL** 弹窗提示"您已经多次添加【xxx】信息，仍然要继续添加吗？"
6. **IF** 单项已被添加5次 **THEN** 系统 **SHALL** 禁止再次添加该项

#### 具体要求

- [ ] 3.1 编辑区单次只有一项高亮
- [ ] 3.2 模板名称：
  - 高级票据模板可编辑/修改模板名称
  - 限制1-20字符
  - 未填写时保存提示"请填写模板名称"
- [ ] 3.3 拖拽排序：
  - 当前右侧编辑区所有项/组可拖动调整位置
  - 默认模板不可拖动调整位置
- [ ] 3.4 重复添加：
  - 单项最多可重复添加5次
  - 不同位置的相同组可独立操作
  - 重复添加第三次时弹窗提示确认
- [ ] 3.5 高级功能仅在高级票据模板中可用

---

### Requirement 4: 模板管理

**用户故事**: 作为 商户管理员，我想 管理多个发票模板，以便于 在不同场景下使用不同的模板

#### 验收标准

1. **WHEN** 用户点击"恢复默认"按钮 **THEN** 系统 **SHALL** 恢复模板到最初的默认样式
2. **WHEN** 用户鼠标移入未在使用的模板 **THEN** 系统 **SHALL** 显示"使用模板"按钮
3. **WHEN** 用户点击删除高级票据模板 **THEN** 系统 **SHALL** 弹窗提示"是否删除票据"（默认模板不可删除）
4. **IF** 模板正在使用中 **THEN** 系统 **SHALL** 禁止删除该模板
5. **IF** 云平台未开启高级票据模板 **THEN** 系统 **SHALL** 不显示高级票据自定义项（云平台默认关闭）

#### 具体要求

- [ ] 4.1 创建模板：
  - 支持创建自定义发票模板
  - 提供默认模板供快速使用
- [ ] 4.2 使用模板：
  - 鼠标移入未使用的模板显示"使用模板"按钮
  - 仅可选择一个模板使用
- [ ] 4.3 预览模板：
  - 支持预览模板效果
  - 显示实际打印样式
- [ ] 4.4 删除模板：
  - 支持删除高级票据模板
  - 删除时弹窗提示确认
  - 默认模板不可删除
  - 正在使用的模板不可删除
- [ ] 4.5 恢复默认：
  - 编辑票据模板后可通过"恢复默认"按钮恢复
  - 恢复到模板最初的默认样式
- [ ] 4.6 云平台开关：
  - 云平台未开启时不显示高级票据自定义项
  - 云平台默认关闭高级票据模板

### Requirement 5: 旧商家后台兼容

**用户故事**: 作为 使用旧商家后台的商户管理员，我想 预览和使用新的发票模板，以便于 保持功能一致性

#### 验收标准

1. **WHEN** 旧商家后台查看发票模板 **THEN** 系统 **SHALL** 仅允许预览和使用，调整需前往桌面端操作

#### 具体要求

- [ ] 5.1 旧商家后台发票新增自定义模板，可进行预览使用
- [ ] 5.2 旧商家后台仅可选择一个模版使用
- [ ] 5.3 如需调整自定义模板，需前往桌面端操作
- [ ] 5.4 确保旧商家后台能正确渲染新模板的所有字段

## 约束条件

### 技术约束

#### Go Main 模块

- 必须使用 Gin 框架
- 接口以 `I` 开头，实现以 `Impl` 结尾
- Service 只能依赖其他 Service 接口
- Repository 只能持有 db 实例，不能持有 DBManager
- 不使用 panic，返回 error
- 参考: `.cursor/rules/go-printer.mdc` - 打印模块开发规范

#### PHP 模块（旧商家后台）

- 必须使用 ThinkPHP 6.0
- 遵循 MVC 分层
- Controller 不写业务逻辑
- 使用验证器验证参数
- 使用软删除

#### Vue 模块

- 必须使用 Vue 3 + TypeScript + Vite
- 使用 Element Plus 组件库
- 使用成熟的拖拽库（如 Vuedraggable）
- 遵循 `.cursor/rules/vue.mdc`

### 业务约束

- 商品项默认开启，不可关闭
- 默认模板不可删除和拖动
- 正在使用的模板不可删除
- 单项最多重复添加5次
- 模板名称限制1-20字符
- 自定义文字限制500字符
- 仅可选择一个模板使用

### 资源约束

- 开发时间: 5-8 天
- Story Point: 5-8 SP (待技术评审确认)

## 风险和缓解

### 风险 1: 旧商家后台兼容性

**影响**: 高  
**概率**: 中  
**缓解措施**:

- 提前在旧商家后台进行预览测试，确保只读模式正常工作
- 在旧商家后台提供明确的引导，说明编辑需前往桌面端
- 确保新模板的所有字段都能在旧后台正确渲染

### 风险 2: 拖拽交互复杂度

**影响**: 中  
**概率**: 中  
**缓解措施**:

- 选用成熟的 Vue 拖拽库（如 Vuedraggable），降低开发风险
- 进行充分的交互测试，确保拖拽体验流畅
- 提供清晰的拖拽提示和引导

### 风险 3: 打印机兼容性

**影响**: 高  
**概率**: 中  
**缓解措施**:

- 在打印前做兼容性处理，提供降级方案
- 测试多种打印机型号，确保布局正确
- 提供打印预览功能，让商家提前确认效果

### 风险 4: 数据迁移

**影响**: 中  
**概率**: 低  
**缓解措施**:

- 设计数据库表结构时预留扩展字段，支持多种票据类型
- 确保现有的结账单模板和新的发票模板可以共存
- 提供数据迁移脚本和回滚方案
