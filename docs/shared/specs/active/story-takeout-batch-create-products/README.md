# Spec: 批量创建外卖商品

## 📋 概述

本 Spec 定义了"批量创建外卖商品"功能的完整需求、设计和任务分解。

## 🎯 目标

为商家端提供批量操作外卖商品的能力,包括:
- 批量创建商品到外卖平台(Grab、LINE MAN)
- 批量上架外卖平台商品
- 批量下架外卖平台商品
- 批量删除外卖平台商品

## 📋 核心功能点

### 1. 批量创建商品
- **接口**: POST `/shop/takeout/products/batch_create`
- **功能**: 批量将TTPOS商品推送到外卖平台
- **特性**: 并发处理、限流控制、失败重试

### 2. 批量上架商品
- **接口**: POST `/shop/takeout/products/batch_online`
- **功能**: 批量上架外卖平台商品
- **特性**: 状态检查、并发处理

### 3. 批量下架商品
- **接口**: POST `/shop/takeout/products/batch_offline`
- **功能**: 批量下架外卖平台商品
- **特性**: 状态检查、并发处理

### 4. 批量删除商品
- **接口**: POST `/shop/takeout/products/batch_delete`
- **功能**: 批量删除外卖平台商品
- **特性**: 状态检查、软删除

## 🎯 核心技术挑战

### 1. 并发处理
- **挑战**: 批量操作需要高效处理
- **方案**: 使用 Goroutine 并发处理,使用 sync.WaitGroup 等待完成

### 2. 限流控制
- **挑战**: 外卖平台API有限流限制
- **方案**: 使用 Ticker 控制请求频率,每秒不超过10个

### 3. 失败处理
- **挑战**: 部分商品可能推送失败
- **方案**: 失败自动重试3次,记录失败原因,直接返回失败列表

### 4. 数据一致性
- **挑战**: 确保TTPOS与外卖平台数据同步
- **方案**: 操作成功后同步更新数据库

### 5. 多平台适配
- **挑战**: Grab、LINE MAN等平台API规范不同
- **方案**: 为每个平台实现独立适配器,统一接口规范

## 📋 关键决策

### 决策 1: 并发 vs 串行

**决策**: 采用并发处理  
**理由**:
- 批量操作耗时长,并发处理提高效率
- 使用 sync.WaitGroup 等待所有任务完成
- 直接返回结果,用户体验更好

### 决策 2: 返回结果方式

**决策**: 直接返回结果  
**理由**:
- 不需要额外的任务表
- 实现简单,维护成本低
- 用户可以立即看到操作结果

### 决策 3: 限流策略

**决策**: 客户端限流(每秒10个请求)  
**理由**:
- 避免触发外卖平台API限流
- 实现简单,使用 Ticker 即可
- 可根据实际情况调整
