## 📋 概述

本功能旨在优化采购申请审核流程，允许审核人员在审核过程中直接编辑采购申请单的物品明细，而无需驳回申请单让申请人重新提交。这将显著提高审核效率、缩短采购周期、降低沟通成本，特别是在处理简单错误和紧急采购时。

**核心价值**：
- 提高审核效率 50%+（无需往返修改）
- 缩短采购周期（减少流程延迟）
- 降低沟通成本（直接修改替代反复沟通）
- 提升用户体验（审核人员和申请人都更高效）

## 🎯 产品对齐

**产品愿景**：打造高效、智能的餐饮管理系统，为商户提供一站式解决方案。

**业务目标对齐**：
- **效率提升**：优化审核流程，减少人工操作时间
- **用户体验**：简化操作流程，降低使用门槛
- **业务增长**：提高运营效率，支撑业务规模扩展

**目标用户**：
- 总店审核人员（品牌采购审核）
- 店内审核人员（采购申请审核）

## 📝 用户故事

**作为** 总店审核人员  
**我想** 在审核采购申请时能够修改申请单的物品明细（删除、搜索、添加）  
**以便于** 快速修正申请单中的错误，提高审核效率，减少流程往返

## 功能需求

### Requirement 1: 物品明细编辑功能

**用户故事**: 作为审核人员，我想在审核页面直接编辑物品明细，以便于快速修正错误

#### 验收标准

1. **WHEN** 有审批权限的人员进入待审核的采购申请单页面 **THEN** 系统 **SHALL** 显示编辑功能（删除、搜索、添加物品按钮）
2. **WHEN** 审核人员点击删除物品 **THEN** 系统 **SHALL** 从申请单中移除该物品，并更新总金额
3. **WHEN** 审核人员搜索物品 **THEN** 系统 **SHALL** 在对应申请的供应商/库存下的物品列表中搜索，并显示搜索结果
4. **WHEN** 审核人员添加物品 **THEN** 系统 **SHALL** 仅显示对应申请的供应商/库存下的物品供选择，并允许输入数量和价格
5. **WHEN** 编辑物品明细后 **THEN** 系统 **SHALL** 实时更新申请单总金额和物品数量

#### 具体要求

- [ ] 1.1 审核页面提供"编辑物品"按钮（仅对有审批权限的人员显示）
- [ ] 1.2 支持删除物品明细（点击删除按钮 → 确认提示 → 删除）
- [ ] 1.3 支持搜索物品（输入关键词 → 搜索供应商/库存下的物品 → 显示结果列表）
- [ ] 1.4 支持添加物品（选择物品 → 输入数量 → 输入价格 → 添加到明细）
- [ ] 1.5 实时更新申请单总金额和物品数量统计
- [ ] 1.6 编辑操作记录操作日志（谁在什么时间修改了什么内容）

---

### Requirement 2: 权限控制

**用户故事**: 作为系统管理员，我想严格控制编辑权限，以便于保证数据安全

#### 验收标准

1. **WHEN** 无审批权限的人员进入审核页面 **THEN** 系统 **SHALL** 不显示编辑功能按钮
2. **WHEN** 无审批权限的人员通过 API 直接调用编辑接口 **THEN** 系统 **SHALL** 返回 403 权限错误
3. **WHEN** 审批权限被撤销后 **THEN** 系统 **SHALL** 立即禁止该用户编辑采购申请单

#### 具体要求

- [ ] 2.1 前端根据用户权限隐藏/显示编辑功能按钮
- [ ] 2.2 后端 API 严格校验审批权限（不能仅依赖前端隐藏）
- [ ] 2.3 权限校验失败时返回明确的错误信息
- [ ] 2.4 权限变更时实时生效（无需重新登录）

---

### Requirement 3: 状态控制

**用户故事**: 作为系统管理员，我想严格控制可编辑的状态，以便于保证流程规范

#### 验收标准

1. **WHEN** 采购申请单处于待审核状态（店内审核/总部审核） **THEN** 系统 **SHALL** 允许编辑物品明细
2. **WHEN** 采购申请单已审核通过 **THEN** 系统 **SHALL** 不允许编辑，并提示"已通过的申请单不能修改"
3. **WHEN** 采购申请单已驳回 **THEN** 系统 **SHALL** 不允许编辑，并提示"已驳回的申请单不能修改"
4. **WHEN** 采购申请单已完成收货 **THEN** 系统 **SHALL** 不允许编辑，并提示"已收货的申请单不能修改"

#### 具体要求

- [ ] 3.1 仅在待审核状态（店内审核、总部审核）下显示编辑功能
- [ ] 3.2 已通过/已驳回/已收货的申请单不允许编辑
- [ ] 3.3 状态检查在前端和后端都要实现
- [ ] 3.4 状态不符时返回明确的错误提示

---

### Requirement 4: 数据范围限制

**用户故事**: 作为审核人员，我想只能添加供应商下的物品，以便于保证数据正确性

#### 验收标准

1. **WHEN** 审核人员搜索物品 **THEN** 系统 **SHALL** 仅返回对应申请的供应商/库存下的物品
2. **WHEN** 审核人员添加物品 **THEN** 系统 **SHALL** 仅允许添加对应申请的供应商/库存下的物品
3. **WHEN** 审核人员尝试添加其他供应商的物品 **THEN** 系统 **SHALL** 拒绝添加，并提示"该物品不属于当前供应商"

#### 具体要求

- [ ] 4.1 物品搜索接口根据供应商 ID 筛选物品
- [ ] 4.2 物品添加接口校验物品是否属于当前供应商
- [ ] 4.3 支持内部采购（库存物品）和外部采购（供应商物品）两种场景
- [ ] 4.4 数据范围校验在后端实现（不能仅依赖前端筛选）

---

### Requirement 5: 数据同步机制

**用户故事**: 作为子店管理员，我想及时看到审核后的申请单内容，以便于准备收货

#### 验收标准

1. **WHEN** 采购申请单编辑并通过审核后 **THEN** 系统 **SHALL** 将编辑后的单据内容同步到子店
2. **WHEN** 总店添加了一个物品，子店没有同步 **THEN** 子店收货时 **SHALL** 提示"物品（物品编码）未找到"
3. **WHEN** 总店添加了一个单位，子店没有同步 **THEN** 子店收货时 **SHALL** 提示"物品单位（单位名称）未找到"
4. **WHEN** 采购申请单编辑并驳回后 **THEN** 系统 **SHALL** 将编辑后的单据内容同步到子店（申请人可查看审核人的修改）

#### 具体要求

- [ ] 5.1 审核通过/驳回时，同步编辑后的申请单内容到子店
- [ ] 5.2 子店收货时，校验物品和单位是否存在
- [ ] 5.3 物品/单位不存在时，给出明确提示（参考调拨单）
- [ ] 5.4 数据同步失败时，记录错误日志并重试

---

### Requirement 6: 操作日志记录

**用户故事**: 作为系统管理员，我想记录所有编辑操作，以便于追溯和审计

#### 验收标准

1. **WHEN** 审核人员编辑物品明细 **THEN** 系统 **SHALL** 记录操作日志（谁、什么时间、修改了什么）
2. **WHEN** 查看采购申请单详情 **THEN** 系统 **SHALL** 显示操作日志列表
3. **WHEN** 审核人员添加物品 **THEN** 操作日志 **SHALL** 记录"添加物品：[物品名称]，数量：[数量]"
4. **WHEN** 审核人员删除物品 **THEN** 操作日志 **SHALL** 记录"删除物品：[物品名称]，数量：[数量]"
5. **WHEN** 审核人员修改物品数量 **THEN** 操作日志 **SHALL** 记录"修改物品：[物品名称]，数量从 [旧数量] 改为 [新数量]"

#### 具体要求

- [ ] 6.1 记录所有编辑操作（添加、删除、修改物品明细）
- [ ] 6.2 记录操作人、操作时间、操作内容、操作前后的数据对比
- [ ] 6.3 操作日志持久化存储（不能只存在内存中）
- [ ] 6.4 提供操作日志查询接口（按申请单 ID 查询）
- [ ] 6.5 操作日志展示在申请单详情页（时间倒序）

## 约束条件

### 技术约束

#### Go Main 模块

- 必须使用 Gin 框架
- 接口以 `I` 开头，实现以 `Impl` 结尾
- Service 只能依赖其他 Service 接口
- Repository 只能持有 db 实例，不能持有 DBManager
- 不使用 panic，返回 error

#### Vue 模块

- 必须使用 Vue 3 + TypeScript + Vite
- 使用 Element Plus 组件库
- 遵循 `.cursor/rules/vue.mdc`

### 业务约束

- 编辑功能仅在待审核状态下可用（店内审核、总部审核）

- 添加物品时，仅显示对应申请的供应商/库存下的物品
- 编辑后的内容需同步到子店

### 资源约束

- 开发时间: 3-5 天
- Story Point: 5-8 SP (必须 ≤ 5，可能需要拆分)

## 风险和缓解

### 风险 1: 数据同步一致性问题

**影响**: 高  
**概率**: 中  
**缓解措施**:

- 在子店收货时，对不存在的物品/单位给出明确提示（参考调拨单）
- 数据同步使用事务保证一致性
- 同步失败时记录日志并重试

### 风险 2: 并发编辑冲突

**影响**: 中  
**概率**: 低  
**缓解措施**:

- 使用 UUID 锁防止多人同时编辑同一申请单
- 前端提示"该申请单正在被其他人编辑"
- 使用乐观锁（版本号）检测冲突

### 风险 3: 权限控制漏洞

**影响**: 高  
**概率**: 低  
**缓解措施**:

- 后端严格校验审批权限（不能仅依赖前端隐藏）
- 权限变更时实时生效
- 定期进行安全审计

### 风险 4: 操作日志数据量大

**影响**: 中  
**概率**: 高  
**缓解措施**:

- 操作日志表设计合理索引
- 定期归档历史日志（超过 6 个月）
- 分页查询操作日志
