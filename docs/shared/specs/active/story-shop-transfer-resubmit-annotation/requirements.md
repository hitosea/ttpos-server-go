## 📝 用户故事

**作为** 店长/商户管理员、上级门店审核人、发货/收货门店
**我想** 在调拨单被驳回后能够修改并重新提交，同时在审核时能添加批注说明
**以便于** 减少重复录入工作，提高审批沟通效率

---

## 功能需求

### Requirement 1: 重新提交审核

**用户故事**: 作为单据发起人，我想在调拨单被驳回后能够修改并重新提交，以便于减少重复录入工作

#### 验收标准

1. **WHEN** 单据被驳回 **THEN** 发起人在调拨单据详情页 **SHALL** 看到"重新提交审核"按钮
2. **WHEN** 发起人点击"重新提交审核" **THEN** 系统 **SHALL** 自动加载被驳回单据的所有信息（商品列表、数量、备注等）
3. **WHEN** 发起人修改调拨单据内容并重新提交审核 **THEN** 系统 **SHALL** 验证必填项和业务规则
4. **WHEN** 验证通过 **THEN** 系统 **SHALL** 将单据状态变更为"待审核"，并记录操作历史
5. **WHEN** 用户重新提交被驳回的调拨申请 **THEN** 系统 **SHALL** 在批注内页中记录：操作类型为"重新提交"、操作时间（暂时不记录操作人）

---

### Requirement 2: 审核批注功能

**用户故事**: 作为审核人，我想在通过或驳回调拨单时添加批注说明，以便于发起人了解审核意见

#### 验收标准

**门店审核：**
1. **WHEN** 门店通过调拨申请 **THEN** 系统 **SHALL** 在批注内页中记录：操作类型为"门店通过"、操作时间、通过批注信息（暂时不记录操作人）
2. **WHEN** 门店驳回调拨申请 **THEN** 系统 **SHALL** 在批注内页中记录：操作类型为"门店驳回"、操作时间、驳回批注信息（暂时不记录操作人）

**上级门店审核：**
3. **WHEN** 上级门店审核通过调拨申请 **THEN** 系统 **SHALL** 在批注内页中记录：操作类型为"上级门店通过"、操作时间、通过批注信息（暂时不记录操作人）
4. **WHEN** 上级门店驳回调拨申请 **THEN** 系统 **SHALL** 在批注内页中记录：操作类型为"上级门店驳回"、操作时间、驳回批注信息（暂时不记录操作人）

**调入场景 - 发货门店审核：**
5. **WHEN** 发货门店通过调拨申请 **THEN** 系统 **SHALL** 在批注内页中记录：操作类型为"发货门店通过"、操作时间、通过批注信息（暂时不记录操作人）
6. **WHEN** 发货门店驳回调拨申请 **THEN** 系统 **SHALL** 在批注内页中记录：操作类型为"发货门店驳回"、操作时间、驳回批注信息（暂时不记录操作人）

**调出场景 - 收货门店审核：**
7. **WHEN** 收货门店通过调拨申请 **THEN** 系统 **SHALL** 在批注内页中记录：操作类型为"收货门店通过"、操作时间、通过批注信息（暂时不记录操作人）
8. **WHEN** 收货门店驳回调拨申请 **THEN** 系统 **SHALL** 在批注内页中记录：操作类型为"收货门店驳回"、操作时间、驳回批注信息（暂时不记录操作人）

---

### Requirement 3: 批注历史展示

**用户故事**: 作为单据发起人或审核人，我想查看完整的审核操作历史，以便于了解审批过程

#### 验收标准

1. **WHEN** 用户在批注内页查看操作记录 **THEN** 系统 **SHALL** 按时间倒序展示所有操作记录，每条记录包含操作类型、操作时间、批注信息（暂时不包含操作人）
2. **WHEN** 单据有多次驳回和重新提交操作 **THEN** 系统 **SHALL** 在批注内页中展示完整的操作时间线，清晰展示每次操作的时间节点和批注信息
3. **WHEN** 单据详情页顶部显示批注摘要 **THEN** 系统 **SHALL** 展示最新批注信息（最多展示8个字符），点击进入批注内页查看全部节点内容

## 风险和缓解

### 风险 1: 调拨单涉及多方审核节点

**影响**: 中
**缓解措施**: 复用通用审核批注记录表，通过操作类型字段区分不同审核节点

### 风险 2: 需要与盘点单、采购单保持一致的设计模式

**影响**: 低
**缓解措施**: 统一各单据类型的批注 API 和前端组件设计，确保用户体验一致
