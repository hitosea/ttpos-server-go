## 📝 用户故事

**作为** 总店管理员
**我想** 按物品类别和门店角色配置可见性规则，并自动同步到各子店
**以便于** 实现精细化的物品权限管控，让不同角色只能看到职责范围内的物品

---

## 功能需求

### Requirement 1: 可见性配置管理入口

**用户故事**: 作为总店管理员，我想在参数设置中管理可见性配置，以便于集中维护所有可见性规则

#### 验收标准

1. **WHEN** 总店管理员进入参数设置页面 **THEN** 系统 **SHALL** 显示"可见性配置"模块入口
2. **WHEN** 总店管理员点击"可见性配置" **THEN** 系统 **SHALL** 跳转到可见性配置列表页
3. **WHEN** 可见性配置列表页显示 **THEN** 系统 **SHALL** 展示所有已创建的配置，格式：`{配置名称} | {角色数量}角色 | {类别数量}类别可见`（若未选择物品类别，显示"0类别可见"）
4. **WHEN** 总店管理员点击"新增"按钮 **THEN** 系统 **SHALL** 跳转到新增可见性配置页面
5. **WHEN** 总店管理员点击某个配置项 **THEN** 系统 **SHALL** 跳转到编辑可见性配置页面
6. **WHEN** 总店管理员删除某个配置 **THEN** 系统 **SHALL** 提示确认，确认后删除配置、同步删除到子店并刷新列表

---

### Requirement 2: 新增/编辑可见性配置表单

**用户故事**: 作为总店管理员，我想配置名称、物品类别和门店角色，以便于定义完整的可见性规则

#### 2.1 配置名称

1. **WHEN** 总店管理员进入新增/编辑可见性配置页面 **THEN** 系统 **SHALL** 显示"名称"输入框，标注为必填项（带星号）
2. **WHEN** 总店管理员未填写名称 **THEN** 系统 **SHALL** 显示错误提示"名称不能为空"
3. **WHEN** 总店管理员填写的名称超过100字符 **THEN** 系统 **SHALL** 显示错误提示"名称不能超过100字符"
4. **WHEN** 总店管理员编辑现有配置 **THEN** 系统 **SHALL** 回显该配置的名称

#### 2.2 物品类别选择

1. **WHEN** 总店管理员点击"物品类别"配置项 **THEN** 系统 **SHALL** 跳转到物品类别选择页面
2. **WHEN** 物品类别选择页面显示 **THEN** 系统 **SHALL** 展示所有物品类别列表，支持搜索（按名称/编码）
3. **WHEN** 物品类别选择页面显示 **THEN** 系统 **SHALL** 每个类别项前显示复选框，支持多选
4. **WHEN** 总店管理员选择物品类别后点击"保存" **THEN** 系统 **SHALL** 返回表单页面，回显"已选择 (X)"（X为选中的类别数量），并显示提示"选中的物品类别则可见"
5. **WHEN** 总店管理员编辑现有配置 **THEN** 系统 **SHALL** 回显该配置已选择的物品类别
6. **WHEN** 总店管理员未选择任何物品类别 **THEN** 系统 **SHALL** 显示"已选择 (0)"

#### 2.3 门店角色选择

1. **WHEN** 总店管理员点击"门店角色"配置项 **THEN** 系统 **SHALL** 弹出选择菜单，显示两个选项：
   - "全部门店角色"：选择所有门店的所有角色
   - "部分门店角色"：进入门店角色选择页面
2. **WHEN** 总店管理员选择"全部门店角色" **THEN** 系统 **SHALL** 返回表单页面，回显"已选择 (全部)"
3. **WHEN** 总店管理员选择"部分门店角色" **THEN** 系统 **SHALL** 跳转到门店角色选择页面
4. **WHEN** 门店角色选择页面显示 **THEN** 系统 **SHALL** 按以下规则展示：
   - 跨库查询所有子店数据库中实际存在的角色
   - 显示所有子店"门店编号+门店名称"
   - 子店门店编码+门店名称下展现该门店的所有角色，每个角色前有复选框
   - 支持展开/折叠门店节点
   - 支持全选/取消全选
   - **总店角色不参与配置**
5. **WHEN** 总店管理员在门店角色选择页面选择角色后点击"确定" **THEN** 系统 **SHALL** 返回表单页面，回显"已选择 (X)"（X为选中的角色数量）
6. **WHEN** 总店管理员编辑现有配置 **THEN** 系统 **SHALL** 回显该配置已选择的门店角色（如果是全部，显示"已选择 (全部)"；如果是部分，显示"已选择 (X)"）
7. **WHEN** 总店管理员未选择任何门店角色 **THEN** 系统 **SHALL** 显示"已选择 (0)"，且保存时提示"至少选择一个门店角色"

#### 2.4 影响范围说明

1. **WHEN** 可见性配置表单显示 **THEN** 系统 **SHALL** 在"门店角色"配置项下方显示影响范围说明：
   - "影响范围: 物品管理、成本卡、库存查询、调拨单、盘点单、采购申请、品牌采购"
2. **WHEN** 影响范围说明显示 **THEN** 系统 **SHALL** 使用灰色文字，字体较小，作为提示信息

#### 2.5 保存配置

1. **WHEN** 总店管理员填写完配置信息后点击"保存"按钮 **THEN** 系统 **SHALL** 校验必填项（名称、门店角色）
2. **WHEN** 校验通过 **THEN** 系统 **SHALL** 调用 API 保存配置
3. **WHEN** 保存成功 **THEN** 系统 **SHALL** 立即同步配置到所有子店数据库
4. **WHEN** 同步完成 **THEN** 系统 **SHALL** 显示成功提示，并返回可见性配置列表页

### Requirement 3: 可见性判断逻辑

**用户故事**: 作为子店员工，我想只看到我有权限查看的物品类别，以便于专注于职责范围内的物品

#### 3.1 核心判断规则

1. **WHEN** 用户所有角色都未被任何可见性配置包含 **THEN** 系统 **SHALL** 返回全部物品类别（默认行为，向后兼容）
2. **WHEN** 用户有任意角色被可见性配置包含 **THEN** 系统 **SHALL** 仅返回已配置角色的可见类别并集（白名单模式）
3. **WHEN** 某物品类别未出现在任何配置中，但用户角色被其他配置包含 **THEN** 系统 **SHALL** 不显示该类别（严格白名单）

#### 3.2 多角色场景

1. **WHEN** 用户拥有角色A（可见分类1）和角色B（可见分类2） **THEN** 系统 **SHALL** 显示分类1和分类2（并集）
2. **WHEN** 用户拥有角色A（可见分类1）、角色B（可见分类2）和角色C（未配置） **THEN** 系统 **SHALL** 仅显示分类1和分类2（未配置角色不贡献"全部可见"）
3. **WHEN** 用户仅拥有角色C（未被任何配置包含） **THEN** 系统 **SHALL** 显示全部物品类别

#### 3.3 常规业务模块过滤

1. **WHEN** 子店员工在物品管理页面查看物品列表 **THEN** 系统 **SHALL** 根据可见性配置过滤物品类别
2. **WHEN** 子店员工在成本卡页面查看物品 **THEN** 系统 **SHALL** 根据可见性配置过滤物品类别
3. **WHEN** 子店员工在库存查询页面查询库存 **THEN** 系统 **SHALL** 根据可见性配置过滤物品类别
4. **WHEN** 子店员工在调拨单中选择物品 **THEN** 系统 **SHALL** 根据可见性配置过滤物品类别
5. **WHEN** 子店员工在采购申请中选择物品 **THEN** 系统 **SHALL** 根据可见性配置过滤物品类别
6. **WHEN** 子店员工在品牌采购中选择物品 **THEN** 系统 **SHALL** 根据可见性配置过滤物品类别

#### 3.4 盘点场景特殊处理

1. **WHEN** 子店员工创建盘点单，选择盘点类型为"全部物品盘点" **THEN** 系统 **SHALL** 显示所有物品类别，不受可见性配置限制
2. **WHEN** 子店员工创建盘点单，选择盘点类型为"日盘" **THEN** 系统 **SHALL** 显示所有物品类别，不受可见性配置限制
3. **WHEN** 子店员工创建盘点单，选择盘点类型为"周盘" **THEN** 系统 **SHALL** 显示所有物品类别，不受可见性配置限制
4. **WHEN** 子店员工创建盘点单，选择盘点类型为"月盘" **THEN** 系统 **SHALL** 显示所有物品类别，不受可见性配置限制
5. **WHEN** 子店员工创建盘点单，选择盘点类型为"指定物品盘点" **THEN** 系统 **SHALL** 根据可见性配置过滤物品类别

#### 3.5 特殊角色处理

1. **WHEN** 超级管理员查看物品列表 **THEN** 系统 **SHALL** 根据可见性配置过滤物品类别（超级管理员也受限制）
2. **WHEN** 总店员工查看物品列表 **THEN** 系统 **SHALL** 显示所有物品类别（总店角色不参与配置）

---

### Requirement 4: 配置同步机制

**用户故事**: 作为总店管理员，我想配置保存后立即生效到所有子店，以便于统一管理

#### 验收标准

1. **WHEN** 总店保存可见性配置 **THEN** 系统 **SHALL** 立即将配置推送到所有子店数据库
2. **WHEN** 总店删除可见性配置 **THEN** 系统 **SHALL** 立即将删除操作同步到所有子店数据库
3. **WHEN** 同步过程中部分子店失败 **THEN** 系统 **SHALL** 记录失败日志并支持重试机制
4. **WHEN** 子店查询可见性配置 **THEN** 系统 **SHALL** 从本地数据库读取（已同步的数据）

---

### Requirement 5: 旧功能下线

**用户故事**: 作为系统，我想废弃旧的物品级可见性控制，以便于统一使用新的分类级可见性配置

#### 验收标准

1. **WHEN** 总店管理员编辑/添加物品 **THEN** 系统 **SHALL** 不再显示"允许子店可见"配置项
2. **WHEN** 总店管理员查看物品列表 **THEN** 系统 **SHALL** 不再显示"允许子店可见"筛选条件
3. **WHEN** 总店管理员批量操作物品 **THEN** 系统 **SHALL** 不再提供"批量设置可见性"选项
4. **WHEN** 系统判断物品可见性 **THEN** 系统 **SHALL** 不再使用 `allowSubstoreVisible` 字段
5. **WHEN** 系统判断物品可见性 **THEN** 系统 **SHALL** 仅根据新的可见性配置进行判断

## 非功能需求

### 测试要求

- [ ] 单元测试覆盖率 ≥ 80%
- [ ] 可见性过滤方法测试覆盖所有场景（多角色、无配置、盘点特殊处理）
- [ ] 同步机制测试（成功、部分失败、重试）

### 性能要求

- [ ] 跨库查询子店角色响应时间 < 3s（支持分批查询）
- [ ] 可见性过滤方法执行时间 < 100ms
- [ ] 配置同步支持异步处理，不阻塞主流程

### 日志要求

- [ ] 所有日志必须包含 `company_uuid` 字段
- [ ] 同步失败时记录详细错误信息

## 风险和缓解

### 风险 1: 跨库查询性能

**影响**: 中
**描述**: 获取所有子店角色需要跨多个数据库查询
**缓解措施**: 角色数据缓存 + 分批查询 + 异步加载

### 风险 2: 同步一致性

**影响**: 中
**描述**: 总店保存时推送到多个子店，可能存在部分失败
**缓解措施**: 异步同步 + 重试机制 + 同步状态监控 + 失败日志

### 风险 3: 向后兼容

**影响**: 低
**描述**: 旧数据迁移和逻辑切换可能影响现有用户
**缓解措施**: 默认"全部可见"保持向后兼容，渐进式切换
