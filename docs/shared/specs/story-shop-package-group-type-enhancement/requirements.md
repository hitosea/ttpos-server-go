## 📋 概述

在套餐分组类型和加价功能的基础上，增加**必选**和**默认选中**两个属性，以提供更灵活的套餐配置能力。可选分组中的商品可以设置为"必选"（必须选择才能下单）或"默认选中"（用户选购时默认选中），从而引导顾客选择商家推荐的商品，提高客单价，改善用户体验。

## 🎯 产品对齐

该功能支持产品愿景中的"提升商家营销能力"和"增强用户体验"目标，通过必选和默认选中属性，帮助商家创建更符合顾客需求的套餐组合，引导顾客选择高价值商品，减少顾客选择时间。

## 📝 用户故事

**作为** 商户管理员  
**我想** 在可选分组中设置某些商品为必选或默认选中  
**以便于** 引导顾客选择商家推荐的商品，提高客单价，改善用户体验

**作为** 收银员/顾客  
**我想** 在选择套餐商品时，看到必选和默认选中商品的标识，并能够正确选择  
**以便于** 快速完成套餐选择，了解哪些商品是必选的

## 功能需求

### Requirement 1: 必选属性设置

**用户故事**: 作为商户管理员，我想在可选分组中设置某些商品为必选，以便于确保顾客必须选择某些商品才能下单

#### 验收标准

1. **WHEN** 配置可选分组商品 **THEN** 系统 **SHALL** 提供"必选"复选框
2. **IF** 设置商品为必选 **THEN** 系统 **SHALL** 验证必选数量不能大于可选数量
3. **IF** 必选数量大于可选数量 **THEN** 系统 **SHALL** 提示错误："必选不可大于可选数量"
4. **IF** 固定分组商品 **THEN** 系统 **SHALL** 不允许设置必选（固定分组的必选必须为0）

#### 具体要求

- [ ] 1.1 在可选分组商品配置中增加"必选"复选框
- [ ] 1.2 必选复选框仅在可选分组时显示
- [ ] 1.3 默认不设置必选（is_required = 0）
- [ ] 1.4 验证必选数量不能大于可选数量
- [ ] 1.5 数据库字段 `is_required`：TINYINT DEFAULT 0，0-不必选，1-必选
- [ ] 1.6 固定分组时，`is_required` 必须为0
- [ ] 1.7 必选商品在顾客选择时自动选中且不可取消
- [ ] 1.8 必选商品减最后一份时提示："必选商品不可删除"

---

### Requirement 2: 默认选中属性设置

**用户故事**: 作为商户管理员，我想在可选分组中设置某些商品为默认选中，以便于引导顾客优先选择常用商品

#### 验收标准

1. **WHEN** 配置可选分组商品 **THEN** 系统 **SHALL** 提供"默认选中"复选框
2. **IF** 设置商品为默认选中 **THEN** 系统 **SHALL** 验证默认数量不能大于可选数量
3. **IF** 默认数量大于可选数量 **THEN** 系统 **SHALL** 提示错误："默认不可大于可选数量"
4. **IF** 固定分组商品 **THEN** 系统 **SHALL** 不允许设置默认选中（固定分组的默认选中必须为0）

#### 具体要求

- [ ] 2.1 在可选分组商品配置中增加"默认选中"复选框
- [ ] 2.2 默认选中复选框仅在可选分组时显示
- [ ] 2.3 默认不设置默认选中（is_default = 0）
- [ ] 2.4 验证默认数量不能大于可选数量
- [ ] 2.5 数据库字段 `is_default`：TINYINT DEFAULT 0，0-默认不选中，1-默认选中
- [ ] 2.6 固定分组时，`is_default` 必须为0
- [ ] 2.7 默认选中商品在用户选购时默认选中，但可以取消
- [ ] 2.8 用户可以自由增加或减少默认选中商品的数量

### Requirement 3: 商家管理端 API 接口扩展

**用户故事**: 作为开发者，我想在API接口中支持必选和默认选中字段，以便于前后端数据交互

#### 验收标准

1. **WHEN** 调用创建套餐接口 `/shop/product/add [POST]` **THEN** 系统 **SHALL** 支持 `is_required`、`is_default` 字段
2. **WHEN** 调用编辑套餐接口 `/shop/product/edit [POST]` **THEN** 系统 **SHALL** 支持上述字段
3. **WHEN** 调用商品详情接口 `/shop/product/detail [GET]` **THEN** 系统 **SHALL** 返回上述字段

#### 具体要求

- [ ] 3.1 `ProductShopAddPackageGroupProductReq` 增加 `is_required`、`is_default` 字段
- [ ] 3.2 `ProductShopEditPackageGroupProductReq` 同步增加上述字段
- [ ] 3.3 商品详情响应中返回必选和默认选中字段
- [ ] 3.4 API 参数验证：`is_required` 为 0 或 1，`is_default` 为 0 或 1
- [ ] 3.5 固定分组时，验证 `is_required` 和 `is_default` 必须为0

---

### Requirement 4: 收银端商品列表接口扩展

**用户故事**: 作为开发者，我想在商品列表接口中返回必选和默认选中字段，以便于前端显示和交互

#### 验收标准

1. **WHEN** 调用商品列表接口 `/api/v1/{terminal}/product/list [GET]` **THEN** 系统 **SHALL** 返回 `is_required`、`is_default` 字段
2. **IF** 套餐分组商品 **THEN** 系统 **SHALL** 在 `PackageProductDetail` 中包含必选和默认选中信息

#### 具体要求

- [ ] 4.1 `PackageProductDetail` 结构体增加 `is_required`、`is_default` 字段
- [ ] 4.2 商品列表接口返回套餐分组商品的必选和默认选中信息
- [ ] 4.3 字段类型：`is_required` int，`is_default` int
- [ ] 4.4 字段说明：0-不必选/不默认选中，1-必选/默认选中

### Requirement 5: 数据库迁移

**用户故事**: 作为开发者，我想通过数据库迁移添加新字段，以便于平滑升级现有数据

#### 验收标准

1. **WHEN** 执行数据库迁移 **THEN** 系统 **SHALL** 为现有数据设置合理的默认值
2. **IF** 现有套餐分组商品 **THEN** 系统 **SHALL** 默认为不必选、不默认选中（`is_required=0`，`is_default=0`）

- [ ] 5.2 迁移时设置现有数据的默认值：`is_required=0`，`is_default=0`
- [ ] 5.3 迁移文件支持回滚
- [ ] 5.4 迁移前检查字段是否存在，避免重复添加

2. **IF** 保存套餐配置 **THEN** 系统 **SHALL** 验证默认数量不能大于可选数量
3. **IF** 固定分组 **THEN** 系统 **SHALL** 验证必选和默认选中必须为0

#### 具体要求

- [ ] 6.1 在套餐创建/编辑时验证必选数量 <= 可选数量
- [ ] 6.2 在套餐创建/编辑时验证默认数量 <= 可选数量
- [ ] 6.3 在套餐创建/编辑时验证固定分组的必选和默认选中必须为0
- [ ] 6.4 验证失败时返回明确的错误提示

## 🔒 数据验证规则

### 必选验证

- `is_required`：必须为 0（不必选）或 1（必选）
- 必选数量不能大于可选数量
- 固定分组时，`is_required` 必须为0

### 默认选中验证

- `is_default`：必须为 0（不默认选中）或 1（默认选中）
- 默认数量不能大于可选数量
- 固定分组时，`is_default` 必须为0
