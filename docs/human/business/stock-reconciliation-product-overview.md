# 盘点单功能产品概述

> 从产品经理视角梳理盘点单功能的实现情况

---

## 一、功能定位

### 1.1 业务价值
盘点单是库存管理的核心功能，用于：
- **库存准确性保障**：通过定期盘点，确保系统账面库存与实际库存一致
- **差异处理**：自动识别盘盈盘亏，生成出入库记录
- **期初建账**：支持期初库存盘点，用于新店开业或系统初始化

### 1.2 目标用户
- **店长/运营人员**：负责日常库存盘点工作
- **仓库管理员**：执行实际盘点操作
- **财务人员**：审核盘点结果，确保账实相符

---

## 二、核心业务流程

### 2.1 完整业务流程

```
创建盘点单 → 添加物品明细 → 保存草稿 → 提交审核 → 审核通过/驳回 → 更新库存
```

#### 阶段一：创建与编辑（已保存状态）
1. **创建盘点单**
   - 选择仓库（必须是 normal 类型且未禁用）
   - 选择盘点类型：指定物品盘点 / 全部物品盘点
   - 选择盘点目的：库存盘点 / 期初盘点
   - 系统自动生成单据编号（格式：ST + 年月日 + 4位序列号，如 ST202510160001）

2. **添加物品明细**
   - 选择仓库内的物品
   - 输入实盘数量（支持多单位输入）
   - 系统自动读取账面库存数量
   - 实时计算差异（实盘 - 账面）

3. **保存草稿**
   - 可多次保存，不改变状态
   - 每次保存都会重新读取账面库存（确保数据实时性）

#### 阶段二：提交审核（已提交状态）
1. **提交前校验**
   - 物品必须启用状态
   - 仓库必须启用状态
   - 至少有一个物品有实盘数量
   - 移除已禁用物品和待盘点物品（无实盘数量）

2. **提交到 ERP**
   - 如果公司开启了 ERP，会同步提交到 ERPNext 系统
   - 生成 ERP 盘点单号（格式：MAT-RECO-YYYY-XXXXX）
   - 记录提交时间

3. **状态流转**
   - 从"已保存" → "已提交"
   - 提交后不可修改，只能审核或驳回

#### 阶段三：审核处理（已审核/已驳回状态）
1. **审核通过**
   - 更新仓库物品库存为实盘数量
   - 生成盘盈盘亏出入库记录（仅记录有差异的物品）
   - 同步审核到 ERP（如果开启）
   - 异步计算关联成本卡的商品库存
   - 状态：已提交 → 已审核

2. **审核驳回**
   - 状态：已提交 → 已驳回
   - 驳回后可重新编辑（状态回退到已保存）

## 三、核心功能特性

### 3.1 盘点类型

| 类型 | 说明 | 使用场景 |
|------|------|----------|
| **指定物品盘点** | 手动选择需要盘点的物品 | 日常盘点、重点物品盘点 |
| **全部物品盘点** | 盘点仓库内所有物品 | 月末盘点、年度盘点 |

### 3.2 盘点目的

| 目的 | 说明 | 业务含义 |
|------|------|----------|
| **库存盘点** | 常规库存盘点 | 日常库存核对 |
| **期初盘点** | 期初库存建账 | 新店开业、系统初始化 |

### 3.3 多单位支持

- **支持多单位输入**：每个物品可以按不同单位输入实盘数量
- **自动换算**：系统自动将所有单位数量换算为基准单位
- **实盘数量计算**：实盘数量 = Σ(单位数量 × 换算率)

**示例**：
```
物品：大米
- 基准单位：公斤
- 其他单位：袋（1袋=10公斤）、箱（1箱=50公斤）

实盘输入：
- 袋：5袋
- 箱：2箱

实盘数量（基准单位）= 5×10 + 2×50 = 150公斤
```

### 3.4 盘盈盘亏识别

系统自动识别库存差异：

| 状态 | 判断条件 | 业务含义 |
|------|----------|----------|
| **盘盈** | 实盘数量 > 账面数量 | 实际库存多于账面，需要入库 |
| **盘亏** | 实盘数量 < 账面数量 | 实际库存少于账面，需要出库 |
| **正常** | 实盘数量 = 账面数量 | 无差异，不生成出入库记录 |

### 3.5 异常预警

**盘盈盘亏异常判断**：
- 如果账面数量为 0，实盘数量 > 0，判定为异常
- 如果账面数量 > 0，差异绝对值 > 账面数量的 20%，判定为异常

**异常提示**：前端会高亮显示异常物品，提醒用户复核

## 四、数据模型

### 4.1 盘点单主表（stock_reconciliation）

| 字段 | 类型 | 说明 |
|------|------|------|
| `order_no` | 字符串 | 单据编号（ST + 年月日 + 序列号） |
| `erp_code` | 字符串 | ERP 盘点单号（同步到 ERP 后生成） |
| `type` | 整数 | 盘点类型（1-指定物品，2-全部物品） |
| `warehouse_uuid` | 整数 | 仓库 UUID |
| `purpose` | 整数 | 盘点目的（1-库存盘点，2-期初盘点） |
| `status` | 整数 | 状态（0-已保存，1-已提交，2-已审核，3-已驳回） |
| `submit_time` | 整数 | 提交时间（时间戳） |

### 4.2 盘点单物品明细表（stock_reconciliation_item）

| 字段 | 类型 | 说明 |
|------|------|------|
| `stock_reconciliation_uuid` | 整数 | 盘点单 UUID |
| `material_uuid` | 整数 | 物品 UUID |
| `material_name` | 文本 | 物品名称（备份多语言） |
| `booked_quantity` | 小数 | 账面库存数量（基准单位） |
| `counted_quantity` | 小数 | 实盘库存数量（基准单位） |

### 4.3 盘点单物品单位明细表（stock_reconciliation_item_unit）

| 字段 | 类型 | 说明 |
|------|------|------|
| `stock_reconciliation_item_uuid` | 整数 | 物品明细 UUID |
| `material_unit_uuid` | 整数 | 物品单位 UUID |
| `material_unit_name` | 文本 | 单位名称（备份多语言） |
| `quantity` | 小数（可空） | 单位数量 |

## 五、状态流转图

```
┌─────────┐
│  已保存  │ ←─── 创建/编辑
└────┬────┘
     │ 提交
     ↓
┌─────────┐
│  已提交  │
└────┬────┘
     │
     ├─── 审核通过 ───→ ┌─────────┐
     │                 │  已审核  │
     │                 └─────────┘
     │
     └─── 驳回 ───────→ ┌─────────┐
                       │  已驳回  │ ──→ 可重新编辑（回退到已保存）
                       └─────────┘
```

### 5.1 状态说明

| 状态 | 状态值 | 可执行操作 | 限制条件 |
|------|--------|------------|----------|
| **已保存** | 0 | 编辑、删除、提交 | 无 |
| **已提交** | 1 | 审核、驳回 | 不可编辑、不可删除 |
| **已审核** | 2 | 查看 | 不可编辑、不可删除、不可驳回 |
| **已驳回** | 3 | 重新编辑（回退到已保存） | 无 |

## 六、业务规则

### 6.1 创建规则

1. **仓库限制**
   - 只能选择类型为 `normal` 的仓库
   - 仓库必须处于启用状态（未禁用）

2. **物品限制**
   - 只能选择仓库内已有的物品
   - 物品必须处于启用状态
   - 物品单位必须属于该物品的单位列表

3. **单据编号生成**
   - 格式：`ST + YYYYMMDD + 4位序列号`
   - 序列号每天重置，从 0001 开始递增
   - 使用商家时区计算日期
   - 使用分布式锁保证唯一性

### 6.2 保存规则

1. **账面库存实时读取**
   - 每次保存时，都会重新读取当前仓库物品的账面库存
   - 确保账面库存数据是最新的

2. **实盘数量计算**
   - 将所有单位数量换算为基准单位后求和
   - 保留 3 位小数精度

3. **数据校验**
   - 验证仓库和物品的有效性
   - 验证物品单位的有效性
   - 提交时，至少需要一个物品有实盘数量

### 6.3 提交规则

1. **提交前清理**
   - 自动移除已禁用的物品
   - 自动移除已删除的物品
   - 自动移除待盘点物品（无实盘数量）

2. **ERP 同步**
   - 如果公司开启了 ERP，会同步提交到 ERPNext
   - 生成 ERP 盘点单号
   - 如果 ERP 提交失败，会返回具体错误信息（如物品禁用、仓库禁用）

3. **状态保护**
   - 只有"已保存"状态的盘点单才能提交
   - 提交后状态变为"已提交"，不可修改

### 6.4 审核规则

1. **审核前校验**
   - 检查仓库是否被禁用
   - 检查物品是否被禁用（如果禁用，返回禁用物品列表）
   - 只有"已提交"状态的盘点单才能审核

2. **库存更新**
   - 如果仓库不存在该物品，创建仓库物品，库存为实盘数量
   - 如果仓库存在该物品，更新库存为实盘数量

3. **出入库记录**
   - 仅记录有差异的物品（盘盈或盘亏）
   - 盘盈：生成入库记录（场景：盘盈入库）
   - 盘亏：生成出库记录（场景：盘亏出库）
   - 记录包含：物品、数量、金额、单价、单据编号

4. **ERP 同步**
   - 如果开启了 ERP，同步审核到 ERPNext
   - 如果 ERP 审核失败，回滚事务

5. **后续处理**
   - 异步计算所有关联成本卡的商品库存
   - 确保商品库存与物品库存一致

### 6.5 驳回规则

1. **驳回条件**
   - 只有"已提交"状态的盘点单才能驳回
   - 驳回后状态变为"已驳回"

2. **驳回后处理**
   - 可以重新编辑（状态回退到"已保存"）
   - 可以重新提交

### 6.6 删除规则

1. **删除条件**
   - 只有"已保存"和"已驳回"状态的盘点单才能删除
   - 已提交和已审核的盘点单不可删除

2. **删除操作**
   - 软删除（设置 delete_time）
   - 同时删除关联的物品明细和单位明细

## 七、用户体验设计

### 7.1 列表页功能

- **筛选条件**
  - 多仓库筛选（支持选择多个仓库）
  - 关键字搜索（搜索单据编号和 ERP 盘点单号）
  - 创建时间范围筛选
  - 状态筛选（多选）

- **列表信息**
  - 单据编号
  - ERP 盘点单号
  - 仓库名称（多语言）
  - 盘点类型
  - 盘点目的
  - 状态
  - 创建时间
  - 物品数量（统计明细数量）

### 7.2 详情页功能

- **基本信息展示**
  - 单据编号、ERP 盘点单号
  - 仓库名称（多语言）
  - 盘点类型、盘点目的
  - 状态、创建时间、提交时间

- **物品明细展示**
  - 物品信息：编码、名称（多语言）、内部编码、条码
  - 账面数量：实时读取（已保存状态）或保存时的数量（其他状态）
  - 实盘数量：用户输入的数量（基准单位）
  - 差异数量：实盘 - 账面
  - 盘盈盘亏状态：盘盈/盘亏/正常
  - 异常标识：差异超过 20% 时高亮显示
  - 单位明细：显示各单位的实盘数量

### 7.3 操作流程

1. **创建盘点单**
   - 选择仓库 → 选择类型和目的 → 添加物品 → 输入实盘数量 → 保存

2. **提交盘点单**
   - 方式一：在详情页点击"保存并提交"
   - 方式二：在列表页直接点击"提交"（无需进入详情）

3. **审核盘点单**
   - 在列表页或详情页点击"审核"
   - 如果有物品被禁用，会提示禁用物品列表
   - 审核通过后，自动更新库存并生成出入库记录

4. **驳回盘点单**
   - 在列表页或详情页点击"驳回"
   - 驳回后可以重新编辑

## 八、技术实现要点

### 8.1 分布式锁

- **用途**：保证单据编号生成的唯一性
- **实现**：基于公司 UUID + 日期生成锁键
- **范围**：创建盘点单时加锁，生成编号后释放

### 8.2 事务处理

- **保存盘点单**：使用数据库事务，确保主表和明细表数据一致性
- **提交盘点单**：使用事务，确保 ERP 同步和状态更新的原子性
- **审核盘点单**：使用事务，确保库存更新、出入库记录创建、ERP 同步的原子性

### 8.3 ERP 集成

- **同步时机**：提交时同步创建，审核时同步审核
- **错误处理**：ERP 操作失败时，返回具体错误信息（物品禁用、仓库禁用等）
- **数据映射**：将内部数据转换为 ERP 格式（物品编码、数量、仓库等）

### 8.4 数据精度

- **数量精度**：使用 `decimal.Decimal` 类型，保留 4 位小数
- **计算精度**：实盘数量计算后截断到 3 位小数
- **差异计算**：差异数量保留 3 位小数

### 8.5 性能优化

- **批量查询**：物品详情、仓库物品等使用批量查询
- **异步处理**：审核通过后，异步计算商品库存
- **索引优化**：单据编号、仓库 UUID、状态等字段建立索引

## 九、边界情况处理

### 9.1 物品状态变更

- **提交时物品被禁用**：自动移除该物品明细
- **审核时物品被禁用**：返回错误，提示修改物品状态
- **审核时物品被删除**：自动移除该物品明细

### 9.2 仓库状态变更

- **提交时仓库被禁用**：返回错误，提示修改仓库状态
- **审核时仓库被禁用**：返回错误，提示修改仓库状态

### 9.3 数据一致性

- **账面库存实时性**：已保存状态实时读取，其他状态使用保存时的数据
- **单位换算**：使用物品的单位换算率，确保换算准确
- **库存更新**：审核时直接更新为实盘数量，不累加

### 9.4 空盘点单处理

- **无物品明细**：如果盘点单没有物品明细，返回默认盘点单号（MAT-RECO-0000-00000）
- **提交时无有效物品**：返回错误，提示添加物品后再操作

## 十一、总结

盘点单功能是一个完整的库存管理闭环，从创建到审核，每个环节都有严格的业务规则和校验机制。核心特点：

1. **数据准确性**：实时读取账面库存，确保数据准确
2. **流程规范性**：状态流转清晰，操作权限明确
3. **集成完整性**：与 ERP 系统深度集成，数据同步及时
4. **用户体验**：支持多单位输入，异常预警，操作便捷

该功能为餐饮企业的库存管理提供了可靠的工具，确保账实相符，为经营决策提供准确的数据支持。
