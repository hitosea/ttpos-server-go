# 04 - 数据库优化方案

> **目标**：解决多租户数据库连接数爆炸问题，支持500商户扩展
> 
> **核心方案**：从独立DB迁移到共享DB+TenantID模式

---

## 一、当前方案问题分析

### 1.1 当前架构

**一个商户一个数据库：**
```
ttpos (主库)
├── shop1 (商户1数据库)
├── shop2 (商户2数据库)
├── shop3 (商户3数据库)
└── ...
└── shop50 (商户50数据库)

DBManager管理：
• dbs[0] = ttpos主库
• dbs[1] = shop1
• dbs[2] = shop2
• ...
• dbs[50] = shop50
```

### 1.2 扩展到500商户的问题

**连接数爆炸：**
```
当前（50商户）：
• 主库连接池：50个连接
• 商户库连接池：50 * 10 = 500个连接
• 总计：550个连接

扩展（500商户）：
• 主库连接池：50个连接
• 商户库连接池：500 * 10 = 5000个连接
• 总计：5050个连接 👈 MySQL无法承受！

MySQL默认max_connections=151
调整到10000？→ 内存占用25GB+，性能急剧下降
```

**其他问题：**
```
1. 资源浪费
   - 小商户（10订单/天）占用10个连接
   - 大商户（1000订单/天）也只占用10个连接
   - 资源分配不合理

2. 运维成本高
   - 备份500个数据库
   - 监控500个数据库
   - 数据迁移逐个操作

3. 跨租户查询困难
   - 平台级统计需要遍历500个数据库
   - 全局商品搜索无法实现
   - JOIN查询不可能

4. 扩展性差
   - 新增商户需要创建新数据库
   - 数据库数量线性增长
   - 达到上限后无法扩展
```

## 二、优化方案：共享DB + TenantID

### 2.1 方案概述

**核心思想：**
```
所有商户共享一个数据库（或分库分表），
通过company_uuid（TenantID）区分租户数据，
在应用层强制数据隔离。
```

### 2.2 表结构设计

**改造示例：**
```sql
-- 改造前（独立数据库）
-- 数据库：shop1
CREATE TABLE ttpos_product (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    uuid BIGINT NOT NULL,
    name VARCHAR(255),
    price DECIMAL(20,8),
    status TINYINT,
    create_time INT,
    
    INDEX idx_uuid (uuid)
) ENGINE=InnoDB;

-- 改造后（共享数据库）
-- 数据库：ttpos_shared
CREATE TABLE ttpos_product (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    uuid BIGINT NOT NULL,
    company_uuid BIGINT NOT NULL,  -- 租户ID（关键！）
    name VARCHAR(255),
    price DECIMAL(20,8),
    status TINYINT,
    create_time INT,
    delete_time INT DEFAULT 0,
    
    -- 核心索引
    INDEX idx_company_uuid (company_uuid),
    INDEX idx_company_uuid_status (company_uuid, status),
    INDEX idx_company_uuid_delete (company_uuid, delete_time),
    
    -- 唯一约束（租户内唯一）
    UNIQUE KEY uk_company_uuid (company_uuid, uuid)
) ENGINE=InnoDB;
```

**关键点：**
```
1. 所有表都加上company_uuid字段
2. 所有查询都必须带上company_uuid
3. 索引必须包含company_uuid
4. 唯一约束需要加上company_uuid
```

### 2.3 Repository层改造

**改造前（问题）：**
```go
func (r *ProductRepo) FindByUuid(uuid uint64) (*Product, error) {
    var product Product
    err := r.db.Where("uuid = ?", uuid).First(&product).Error
    return &product, err
}
// 问题：没有带company_uuid，可能查到其他商户数据！
```

**改造后（正确）：**
```go
func (r *ProductRepo) FindByUuid(ctx context.Context, uuid uint64) (*Product, error) {
    // 从Context获取company_uuid
    companyUuid := ctx.GetCompanyUuid()
    if companyUuid == 0 {
        return nil, errors.New("company_uuid is required")
    }
    
    var product Product
    err := r.db.Where("company_uuid = ? AND uuid = ?", companyUuid, uuid).
        First(&product).Error
    
    return &product, err
}
```

### 2.4 中间件强制隔离

**Gin中间件：**
```go
func TenantIsolationMiddleware() gin.HandlerFunc {
    return func(c *gin.Context) {
        // 1. 从JWT Token中获取company_uuid
        companyUuid := c.GetUint64("company_uuid")
        if companyUuid == 0 {
            c.JSON(403, gin.H{"error": "company_uuid is required"})
            c.Abort()
            return
        }
        
        // 2. 注入到Context（Repository查询时自动带上）
        ctx := context.WithCompanyUuid(c.Request.Context(), companyUuid)
        c.Request = c.Request.WithContext(ctx)
        
        c.Next()
    }
}
```

**GORM插件（自动添加WHERE条件）：**
```go
// 自定义GORM插件，自动添加company_uuid过滤
func NewTenantPlugin() gorm.Plugin {
    return &tenantPlugin{}
}

type tenantPlugin struct{}

func (p *tenantPlugin) Name() string {
    return "tenantPlugin"
}

func (p *tenantPlugin) Initialize(db *gorm.DB) error {
    // 注册回调
    db.Callback().Query().Before("gorm:query").Register("tenant:query", tenantQuery)
    db.Callback().Create().Before("gorm:create").Register("tenant:create", tenantCreate)
    db.Callback().Update().Before("gorm:update").Register("tenant:update", tenantUpdate)
    return nil
}

func tenantQuery(db *gorm.DB) {
    if companyUuid := getCompanyUuidFromContext(db.Statement.Context); companyUuid > 0 {
        db.Where("company_uuid = ?", companyUuid)
    }
}

func tenantCreate(db *gorm.DB) {
    if companyUuid := getCompanyUuidFromContext(db.Statement.Context); companyUuid > 0 {
        db.Statement.SetColumn("company_uuid", companyUuid)
    }
}
```

## 三、数据迁移方案

### 3.1 迁移策略：双写+验证+切换

**阶段1：双写（2周）**
```
Main写入：
1. 写入旧DB（shop1, shop2, ...）
2. 同时写入新DB（ttpos_shared）
3. 对比数据一致性

目的：
• 新库积累数据
• 验证迁移正确性
• 不影响线上业务
```

**阶段2：数据对比验证（1周）**
```
定时任务：
1. 对比旧库和新库数据
2. 记录不一致的数据
3. 分析差异原因
4. 修复数据

验证指标：
• 数据一致性：>99.9%
• 数据完整性：100%
```

**阶段3：读切换灰度（2周）**
```
灰度步骤：
1. 10%商户读新库 → 监控1天
2. 50%商户读新库 → 监控3天
3. 100%商户读新库 → 监控7天

监控指标：
• 查询延迟
• 错误率
• 数据一致性
```

**阶段4：停止写旧库（1周）**
```
1. 关闭双写，只写新库
2. 旧库保留1个月（备份）
3. 验证业务正常

回滚方案：
• 保留旧库数据
• 可随时切回旧库
```

**阶段5：下线旧库（1个月后）**
```
1. 备份旧库数据
2. 删除旧库
3. 释放资源
```

### 3.2 迁移工具设计

**数据迁移脚本：**
```go
// 迁移工具
type DataMigrator struct {
    oldDBs map[uint64]*gorm.DB  // 旧库连接
    newDB  *gorm.DB              // 新库连接
}

func (m *DataMigrator) MigrateProducts() error {
    for companyUuid, oldDB := range m.oldDBs {
        var products []Product
        oldDB.Find(&products)
        
        for _, product := range products {
            product.CompanyUuid = companyUuid  // 添加租户ID
            m.newDB.Create(&product)           // 写入新库
        }
    }
    return nil
}

// 数据对比工具
func (m *DataMigrator) CompareData(companyUuid uint64) (*CompareResult, error) {
    oldDB := m.oldDBs[companyUuid]
    
    var oldProducts, newProducts []Product
    oldDB.Find(&oldProducts)
    m.newDB.Where("company_uuid = ?", companyUuid).Find(&newProducts)
    
    // 对比数量
    if len(oldProducts) != len(newProducts) {
        return &CompareResult{
            Match: false,
            Diff:  fmt.Sprintf("count mismatch: old=%d, new=%d", len(oldProducts), len(newProducts)),
        }, nil
    }

}
```

## 四、性能优化

### 4.1 索引优化

**原则：**
```
1. company_uuid必须是索引的第一个字段
2. 常用查询条件组合索引
3. 避免过多索引（影响写入性能）
```

**索引设计示例：**
```sql
-- 订单表索引
CREATE TABLE ttpos_sale_order (
    id BIGINT PRIMARY KEY,
    uuid BIGINT,
    company_uuid BIGINT,
    status TINYINT,
    create_time INT,
    -- ...
    
    -- 核心索引
    INDEX idx_company_uuid (company_uuid),
    
    -- 组合索引（按查询频率）
    INDEX idx_company_status_time (company_uuid, status, create_time),
    INDEX idx_company_member (company_uuid, member_uuid),
    INDEX idx_company_desk (company_uuid, desk_uuid),
    
    -- 唯一索引
    UNIQUE KEY uk_company_uuid (company_uuid, uuid)
);
```

### 4.2 分库分表（未来扩展）

**触发条件：**
```
单表数据量 > 5000万行
```

**分表策略：**
```sql
-- 按company_uuid哈希分表（16个表）
ttpos_order_0  (company_uuid % 16 == 0)
ttpos_order_1  (company_uuid % 16 == 1)
...
ttpos_order_15 (company_uuid % 16 == 15)

路由规则：
func getTableName(companyUuid uint64) string {
    tableIndex := companyUuid % 16
    return fmt.Sprintf("ttpos_order_%d", tableIndex)
}
```

**分库策略（更大规模）：**
```
单库数据量 > 5亿行，考虑分库

db_0 (company_uuid % 4 == 0)
├── ttpos_order_0
├── ttpos_order_1
├── ...
└── ttpos_order_15

db_1 (company_uuid % 4 == 1)
db_2 (company_uuid % 4 == 2)
db_3 (company_uuid % 4 == 3)
```

### 4.3 查询优化

**缓存策略：**
```go
// 热点数据多级缓存
func (r *ProductRepo) FindByUuid(ctx context.Context, uuid uint64) (*Product, error) {
    companyUuid := ctx.GetCompanyUuid()
    cacheKey := fmt.Sprintf("product:%d:%d", companyUuid, uuid)
    
    // L1: 本地缓存（5秒TTL）
    if product := localCache.Get(cacheKey); product != nil {
        return product.(*Product), nil
    }
    
    // L2: Redis缓存（5分钟TTL）
    if product := redis.Get(cacheKey); product != nil {
        localCache.Set(cacheKey, product, 5*time.Second)
        return product.(*Product), nil
    }
    
    // L3: 数据库
    var product Product
    err := r.db.Where("company_uuid = ? AND uuid = ?", companyUuid, uuid).
        First(&product).Error
    
    if err == nil {
        redis.Set(cacheKey, product, 5*time.Minute)
        localCache.Set(cacheKey, product, 5*time.Second)
    }
    
    return &product, err
}
```

**避免N+1查询：**
```go
// ❌ 错误：N+1查询
func (r *OrderRepo) GetOrdersWithProducts() ([]Order, error) {
    var orders []Order
    r.db.Where("company_uuid = ?", companyUuid).Find(&orders)
    
    for i := range orders {
        r.db.Where("order_uuid = ?", orders[i].Uuid).Find(&orders[i].Items)
    }
    return orders, nil
}

// ✅ 正确：Preload
func (r *OrderRepo) GetOrdersWithProducts() ([]Order, error) {
    var orders []Order
    err := r.db.Where("company_uuid = ?", companyUuid).
        Preload("Items").
        Preload("Items.Product").
        Find(&orders).Error
    return orders, err
}
```

## 五、数据隔离安全

### 5.1 安全措施

**1. 强制company_uuid验证：**
```go
// 所有Repository方法都需要Context
func (r *Repo) Create(ctx context.Context, data *Model) error {
    if ctx.GetCompanyUuid() == 0 {
        panic("company_uuid is required") // 强制要求
    }
    // ...
}
```

**2. 单元测试覆盖：**
```go
func TestDataIsolation(t *testing.T) {
    // 商户A的Context
    ctxA := context.WithCompanyUuid(context.Background(), 1)
    
    // 商户B的Context
    ctxB := context.WithCompanyUuid(context.Background(), 2)
    
    // 商户A创建商品
    productA, _ := repo.Create(ctxA, &Product{Name: "商户A的商品"})
    
    // 商户B尝试查询商户A的商品（应该失败）
    product, err := repo.FindByUuid(ctxB, productA.Uuid)
    assert.Error(t, err)  // 应该返回NotFound
    assert.Nil(t, product)
}
```

**3. 审计日志：**
```go
// 记录所有跨租户访问尝试
func (r *Repo) FindByUuid(ctx context.Context, uuid uint64) (*Product, error) {
    companyUuid := ctx.GetCompanyUuid()
    
    var product Product
    err := r.db.Where("company_uuid = ? AND uuid = ?", companyUuid, uuid).
        First(&product).Error
    
    if err == gorm.ErrRecordNotFound {
        // 记录审计日志
        auditLog.Warn("cross-tenant access attempt", 
            zap.Uint64("company_uuid", companyUuid),
            zap.Uint64("resource_uuid", uuid),
        )
    }
    
    return &product, err
}
```

## 六、数据库架构（优化后）

### 6.1 读写分离

```
┌────────────────────────────────────────────┐
│              MySQL主从集群                  │
│                                             │
│  ┌──────────┐         ┌──────────┐        │
│  │  Master  │────────▶│  Slave1  │        │
│  │  (写)    │   复制  │  (读)    │        │
│  └──────────┘         └──────────┘        │
│       │                     │              │
│       │                     │              │
│  ┌────▼─────┐         ┌────▼─────┐        │
│  │  Slave2  │         │  Slave3  │        │
│  │  (读)    │         │  (读)    │        │
│  └──────────┘         └──────────┘        │
└────────────────────────────────────────────┘
           ↑                     ↑
           │                     │
    ┌──────┴──────┐      ┌──────┴──────┐
    │  Write Pool │      │  Read Pool  │
    │  (Main)     │      │  (Main)     │
    └─────────────┘      └─────────────┘
```

**连接池配置（优化后）：**
```
Master（写库）：
  MaxOpenConns: 50
  MaxIdleConns: 10

Slave（读库，3个）：
  MaxOpenConns: 100（每个）
  MaxIdleConns: 20（每个）

总连接数：50 + 100*3 = 350个 👈 固定！
（与商户数量无关）
```

### 6.2 性能对比

| 指标 | 独立DB方案 | 共享DB方案 | 提升 |
|------|-----------|-----------|------|
| **连接数（50商户）** | 550 | 350 | 固定 |
| **连接数（500商户）** | 5050 | 350 | **93%↓** |
| **单商户查询延迟** | 20ms | 22ms | 持平 |
| **跨商户统计** | 不可能 | 50ms | **可实现** |
| **备份时间** | 50小时 | 1小时 | **98%↓** |
| **扩展性** | 线性增长 | 无限 | **质变** |

## 七、风险与应对

### 7.1 潜在风险

| 风险 | 概率 | 影响 | 应对措施 |
|------|------|------|---------|
| **数据泄露** | 低 | 高 | • 强制company_uuid验证<br>• 审计日志<br>• 单元测试覆盖 |
| **性能下降** | 中 | 中 | • 充分的索引优化<br>• 多级缓存<br>• 读写分离 |
| **迁移失败** | 低 | 高 | • 双写验证<br>• 灰度切换<br>• 快速回滚 |
| **数据不一致** | 中 | 中 | • 数据对比工具<br>• 定时校验<br>• 修复机制 |

### 7.2 回滚方案

```
任何阶段都可以回滚：

阶段1（双写期）：
• 停止写新库
• 继续使用旧库
• 无影响

阶段2-3（灰度期）：
• 切回旧库读取
• 数据已同步，无丢失
• 5分钟内完成

阶段4-5（新库期）：
• 旧库保留1个月
• 可恢复数据
• 但需要重新迁移
```
