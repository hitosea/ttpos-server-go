# 系统架构总览

> 👤 **受众**: 人类开发者  
> 📖 **用途**: TTPOS 系统的整体架构设计和核心理念

---

## 系统定位

TTPOS 是一个**餐饮行业收银系统**，采用**混合架构**设计：
- **Modular Monolith** (模块化单体) - main/admin 模块
- **Microservices** (微服务) - ttpos-bmp 模块群

## 核心模块

### 1. Go Main 模块 (`main/`)

**技术栈**: Go + Gin + GORM

**职责**:
- 核心业务 API
- 收银端 API
- 店铺端 API
- 微服务编排和调用

**特点**:
- 模块化单体架构
- 高性能、低延迟
- 事件驱动
- 多租户支持

**目录结构**:
```
main/
├── app/
│   ├── api/v1/         # API 控制器
│   ├── service/        # 业务逻辑层
│   ├── repository/     # 数据访问层
│   ├── model/          # 数据模型
│   └── dto/            # 数据传输对象
├── pkg/                # 基础设施
└── middleware/         # 中间件
```

---

### 2. PHP Admin 模块 (`admin/`)

**技术栈**: PHP + ThinkPHP 6.0 + Vue3

**职责**:
- 管理后台 API
- 店铺后台 API
- 旧系统维护

**特点**:
- 经典 MVC 架构
- 前后端分离
- 成熟稳定

**目录结构**:
```
admin/
├── app/
│   ├── admin/          # 管理后台
│   ├── shop/           # 店铺后台
│   └── common/         # 共享代码
├── views/              # Vue3 前端
└── database/           # 数据库迁移
```

---

### 3. Go BMP 模块 (`ttpos-bmp/`)

**技术栈**: Go + GoFrame + gRPC + Nacos

**职责**:
- ERP 服务（进销存）
- 消息服务（邮件、短信）
- 店铺服务
- 外卖服务
- WebSocket 服务

**特点**:
- 微服务架构
- gRPC 通信
- 服务注册发现
- 代码自动生成

**目录结构**:
```
ttpos-bmp/app/
├── ttpos-erp/          # ERP 服务
├── ttpos-manager/      # 管理服务
├── ttpos-message/      # 消息服务
├── ttpos-shop/         # 店铺服务
└── ttpos-takeout/      # 外卖服务
```

## 数据架构

### 多租户设计

**独立数据库模式**:
```
┌─────────────────────┐
│   saas (系统库)     │  # 商户信息、系统配置
└─────────────────────┘
           │
    ┌──────┴──────┐
    │             │
┌───▼───┐    ┌───▼───┐
│shop001│    │shop002│  # 每个商户独立数据库
└───────┘    └───────┘
```

**优点**:
- 数据完全隔离
- 便于备份和迁移
- 支持水平扩展
- 性能互不影响

## 服务通信

### 1. HTTP/REST API

**客户端 → main/admin**:
- 前端应用通过 HTTP REST API 调用后端
- 使用 JSON 格式
- JWT 认证

### 2. gRPC

**main → ttpos-bmp**:
- 内部服务间使用 gRPC 通信
- Protocol Buffers 序列化
- 高性能、类型安全

### 3. 事件总线

**模块内部**:
- 发布-订阅模式
- 异步解耦
- 内存队列

## 核心业务流程

### 订单创建流程

```
1. 收银端 → main API (创建订单)
2. main service:
   - 验证商品库存
   - 计算订单金额
   - 创建订单记录
   - 发布订单创建事件
3. Event Handler:
   - 更新库存
   - 发送通知
   - 记录日志
4. 返回订单信息
```

### 支付流程

```
1. 收银端 → main API (发起支付)
2. main service:
   - 调用支付网关（微信/支付宝）
   - 等待支付结果
3. 支付回调:
   - 验证签名
   - 更新订单状态
   - 发布支付成功事件
4. Event Handler:
   - 更新会员积分
   - 发送通知
   - 打印小票
```

## 性能指标

### 目标

- API 响应时间: <200ms (P99)
- 并发请求: >1000 QPS
- 数据库查询: <50ms
- 系统可用性: >99.9%

### 优化策略

1. **数据库层**:
   - 索引优化
   - 读写分离
   - 查询缓存
   - 连接池管理

2. **应用层**:
   - Redis 缓存
   - 异步处理
   - 批量操作
   - 代码优化

3. **架构层**:
   - 负载均衡
   - 服务拆分
   - CDN 加速
   - 限流熔断
