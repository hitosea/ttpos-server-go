# CustomerCall 实体模型说明

## 基本信息

- **实体名称**: CustomerCall
- **表名**: customer_call
- **所属模块**: model
- **描述**: 客户呼叫实体，用于记录客户的服务请求和呼叫信息

## 关联关系

### 关联实体

## 数据流分析

### 数据来源
- 客户通过桌台呼叫按钮发起
- 移动端客户发起服务请求
- 员工代客户记录服务请求
- 系统自动生成的服务提醒

### 数据流向
1. **呼叫发起流程**:
   - 客户按下桌台呼叫按钮或使用移动端
   - 系统创建CustomerCall记录
   - 呼叫状态为pending（待处理）
   - 推送呼叫信息到相关员工终端

2. **呼叫处理流程**:
   - 员工接收呼叫信息并响应
   - 更新呼叫状态为processing（处理中）
   - 记录处理人和处理时间
   - 推送状态更新到其他员工

3. **呼叫完成流程**:
   - 员工完成客户服务
   - 更新呼叫状态为completed（已完成）
   - 记录完成时间和响应内容
   - 推送完成状态到相关终端

4. **呼叫取消流程**:
   - 客户取消服务请求或员工判断无需处理
   - 更新呼叫状态为cancelled（已取消）
   - 记录取消原因和时间

## WebSocket推送

### AfterCreate钩子
- **新呼叫推送**: 推送到收银员、助手端、厨房端
- **推送内容**: 呼叫类型、桌台信息、呼叫时间、优先级

### 推送目标
- **收银员**: 结账呼叫、服务呼叫
- **助手端**: 所有类型的服务呼叫
- **厨房端**: 加菜呼叫、特殊要求
- **管理端**: 高优先级呼叫、超时未处理呼叫

## 业务方法

### GetResponseTime() int64
- **功能**: 计算响应时间（处理时间 - 呼叫时间）
- **返回**: 响应时间（秒）
- **用途**: 服务质量分析

### GetProcessTime() int64
- **功能**: 计算处理时长（完成时间 - 处理时间）
- **返回**: 处理时长（秒）
- **用途**: 效率分析

### GetTotalTime() int64
- **功能**: 计算总时长（完成时间 - 呼叫时间）
- **返回**: 总时长（秒）
- **用途**: 完整服务周期分析

### IsOverTime(limit int64) bool
- **功能**: 判断是否超时
- **参数**: limit 时间限制（秒）
- **返回**: 是否超时
- **用途**: 服务质量监控

### CanCancel() bool
- **功能**: 判断是否可以取消
- **返回**: 是否可取消
- **用途**: 取消权限验证

## 注意事项

1. **多租户支持**: 通过CompanyUuid实现数据隔离
2. **实时通知**: 通过WebSocket确保呼叫信息及时送达
3. **状态管理**: 严格的状态流转控制
4. **优先级处理**: 高优先级呼叫需要优先处理
5. **超时处理**: 长时间未处理的呼叫需要特殊提醒
6. **数据完整性**: 确保呼叫记录的完整性
7. **权限控制**: 不同员工可能只能处理特定类型的呼叫

## 业务规则

1. **呼叫类型限制**: 不同呼叫类型可能有不同的处理规则
2. **处理权限**: 只有特定角色的员工才能处理某些类型的呼叫
3. **响应时间要求**: 高优先级呼叫需要在规定时间内响应
4. **取消规则**: 已处理的呼叫不能取消
5. **重复呼叫**: 同一桌台在短时间内重复呼叫需要特殊处理
6. **呼叫转移**: 支持呼叫在不同员工间转移
7. **呼叫升级**: 超时未处理的呼叫可以升级给更高级别的员工

## 统计分析

### 服务质量指标
- **平均响应时间**: 从呼叫到处理的平均时间
- **平均处理时间**: 从处理到完成的平均时间
- **完成率**: 已完成呼叫占总呼叫的比例
- **超时率**: 超时未处理呼叫的比例

### 呼叫类型分析
- **呼叫类型分布**: 不同类型呼叫的数量统计
- **高峰时段分析**: 呼叫发生的时间分布
- **桌台呼叫频率**: 各桌台的呼叫频率统计

### 员工绩效分析
- **处理量**: 各员工处理的呼叫数量
- **响应效率**: 各员工的平均响应时间
- **客户满意度**: 基于完成率和处理时间的满意度评估
