# /optimize-spec - 创建优化方案

## 使用场景

在完成优化收益评估后，创建优化方案文档和任务分解清单。

> **前置条件**: 必须先使用 `/optimize-create` 创建优化需求，并完成收益评估。

## 使用方式

```bash
/optimize-spec @opt-251201-001
/optimize-spec order-query-performance
```

## 参数

- `opt_id_or_brief`: 必填，优化 ID（如 `opt-251201-001`）或优化简述（如 `order-query-performance`）
  - 支持 `@` 前缀
  - 支持部分匹配搜索

## 功能特点

- ✅ 创建 solution.md（优化方案）
- ✅ 创建 tasks.md（任务分解清单）
- ✅ 自动填充基本信息
- ✅ 从 optimize.md 提取需求内容
- ✅ 更新优化状态为「规划中」
- ✅ 提供任务模板
- ✅ 生成性能测试模板
- ✅ 生成经验总结模板

## 输出产物

```
docs/shared/opts/active/opt-{id}-{module}-{brief}/
├── optimize.md     # 优化需求（状态: 规划中）
├── solution.md     # 优化方案
└── tasks.md        # 任务分解清单
```

                                             ↑
                                         当前命令

## 执行流程

### Step 1: 查找优化

```yaml
IF 参数是完整优化 ID THEN
  查找: docs/shared/opts/active/opt-{id}-*/
ELSE IF 参数是简述 THEN
  搜索: docs/shared/opts/active/*/*-{brief}*/
  IF 找到多个 THEN
    显示列表让用户选择
  END IF
END IF

IF 未找到 THEN
  报错并退出
END IF
```

### Step 2: 验证 optimize.md 完整性

```yaml
检查 optimize.md 是否包含:
  - ✅ 优化需求
  - ✅ 触发原因
  - ✅ 影响面
  - ✅ 初步分析（建议填写）

IF 关键信息缺失 THEN
  警告用户
  询问是否继续
END IF
```

### Step 3: 创建 solution.md

```yaml
创建文件: solution.md
根据优化类型选择模板:
  - performance → 性能优化模板
  - ux → 体验优化模板
  - maintainability → 重构优化模板
  - scalability → 扩展性优化模板
填充内容:
  - 从 optimize.md 提取需求概述
  - 生成方案对比框架
  - 生成收益评估模板
```

### Step 4: 创建 tasks.md

```yaml
创建文件: tasks.md
根据优化类型生成任务:
  - performance → 性能测试 + 代码优化
  - ux → 原型设计 + 前端优化
  - maintainability → 重构 + 测试
  - scalability → 架构调整 + 压测
```

### Step 5: 更新 optimize.md 状态

```yaml
更新状态: 🟡 待评估 → 🟢 规划中
添加字段:
  - 优化方案: solution.md
  - 任务清单: tasks.md
```

### Step 6: 搜索相似优化

```yaml
搜索 Graphiti:
  - 查找相似优化的实施方案
  - 填充到 solution.md 参考链接
```

### Step 7: 记录活动日志

按 `activity_log.mdc` 规范记录：

```
| HH:mm | /optimize-spec | opt-{id}-{brief} | ✅ | 创建优化方案 |
```

## 智能功能

### 1. 自动生成任务

根据优化类型和影响范围，自动生成相关任务：

- **性能优化** → 基线测试 + 代码优化 + 性能测试
- **体验优化** → 原型设计 + 前端优化 + 用户测试
- **架构优化** → 方案设计 + 迁移任务 + 兼容性测试
- **安全优化** → 漏洞扫描 + 代码加固 + 安全测试

### 2. 参考相似优化

在 Graphiti 中搜索相似优化，提供方案参考。

### 3. 估算工作量

根据优化类型和影响范围，自动估算工作量：

- **critical** + 架构级 → 建议 1-2 周
- **high** + 模块级 → 建议 3-5 天
- **medium** + 单文件 → 建议 1-2 天
- **low** → 建议 0.5-1 天

### 4. 性能指标模板

根据优化类型自动生成合适的性能指标：

- **API 优化** → 响应时间、QPS、错误率
- **数据库优化** → 查询时间、慢查询数、连接数
- **前端优化** → 加载时间、首屏时间、白屏时间
- **资源优化** → CPU、内存、磁盘IO

## 状态流转

```yaml
/optimize-create 后:
  状态: 🟡 待评估

/optimize-spec 后:
  状态: 🟢 规划中

任务执行中:
  状态: 🟢 规划中 (保持不变)

所有任务完成:
  状态: 🔵 已完成 (手动更新)

/optimize-archive 后:
  移动到: completed/{version}/
```

## 错误处理

| 错误类型             | 处理方式                                     |
| -------------------- | -------------------------------------------- |
| 优化不存在           | 报错：优化不存在于 active/ 目录              |
| optimize.md 信息不全 | 警告：建议先完善 optimize.md                 |
| 找到多个匹配优化     | 显示列表，让用户选择                         |
| solution.md 已存在   | 询问是否覆盖                                 |
