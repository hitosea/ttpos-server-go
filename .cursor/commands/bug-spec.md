# /bug-spec - 创建 Bug 修复方案

## 使用场景

在完成 Bug 技术分析后，创建修复方案文档和任务分解清单。

> **前置条件**: 必须先使用 `/bug-create` 创建 Bug 报告，并完成技术分析。

## 使用方式

```bash
/bug-spec @bug-251127-001
/bug-spec order-payment-timeout
```

## 参数

- `bug_id_or_brief`: 必填，Bug ID（如 `bug-251127-001`）或 Bug 简述（如 `order-payment-timeout`）
  - 支持 `@` 前缀
  - 支持部分匹配搜索

## 功能特点

- ✅ 创建 solution.md（修复方案）
- ✅ 创建 tasks.md（任务分解清单）
- ✅ 自动填充基本信息
- ✅ 从 bug.md 提取技术分析内容
- ✅ 更新 Bug 状态为「规划中」
- ✅ 提供任务模板
- ✅ 生成经验总结模板

## 输出产物

```
docs/shared/bugs/active/bug-{id}-{module}-{brief}/
├── bug.md          # Bug 描述（状态: 规划中）
├── solution.md     # 修复方案
└── tasks.md        # 任务分解清单
```

## 工作流位置

```
发现 Bug → /bug-create → 技术分析 → /bug-spec → 实施修复 → /bug-archive
                                       ↑
                                   当前命令
```

## 执行流程

### Step 1: 查找 Bug

```yaml
IF 参数是完整 Bug ID THEN
  查找: docs/shared/bugs/active/bug-{id}-*/
ELSE IF 参数是简述 THEN
  搜索: docs/shared/bugs/active/*/*-{brief}*/
  IF 找到多个 THEN
    显示列表让用户选择
  END IF
END IF

IF 未找到 THEN
  报错并退出
END IF
```

### Step 2: 验证 bug.md 完整性

```yaml
检查 bug.md 是否包含:
  - ✅ 问题描述
  - ✅ 环境信息
  - ✅ 影响范围
  - ✅ 初步分析（建议填写）

IF 关键信息缺失 THEN
  警告用户
  询问是否继续
END IF
```

### Step 3: 创建 solution.md

```yaml
创建文件: solution.md
填充内容:
  - 从 bug.md 提取问题概述
  - 生成修复方案模板
  - 生成测试计划模板
  - 生成经验总结模板
```

### Step 4: 创建 tasks.md

```yaml
创建文件: tasks.md
生成任务清单:
  - 代码修复任务（根据影响范围）
  - 测试验证任务
  - 文档更新任务
  - 部署上线任务
```

### Step 5: 更新 bug.md 状态

```yaml
更新状态: 🔴 待分析 → 🟡 规划中
添加字段:
  - 修复方案: solution.md
  - 任务清单: tasks.md
```

### Step 6: 搜索相似问题

```yaml
搜索 Graphiti:
  - 查找相似问题的修复方案
  - 填充到 solution.md 参考链接
```

### Step 7: 记录活动日志

按 `activity_log.mdc` 规范记录：

```
| HH:mm | /bug-spec | bug-{id}-{brief} | ✅ | 创建修复方案 |
```

## 智能功能

### 1. 自动生成任务

根据 Bug 的影响范围，自动生成相关任务：

- 如果影响 Main 模块 → 生成 Go 代码修复任务
- 如果影响 Admin 模块 → 生成 PHP 代码修复任务
- 如果影响 BMP 模块 → 生成 gRPC 相关任务
- 如果影响前端 → 生成 Vue 组件修复任务

### 2. 参考相似问题

在 Graphiti 中搜索相似问题，提供修复方案参考。

### 3. 估算工作量

根据 Bug 严重程度和影响范围，自动估算修复工作量：

- **critical** + 多模块 → 建议 2-3 天
- **high** + 单模块 → 建议 1-2 天
- **medium** → 建议 0.5-1 天
- **low** → 建议 0.5 天内

## 状态流转

```yaml
/bug-create 后:
  状态: 🔴 待分析

/bug-spec 后:
  状态: 🟡 规划中

任务执行中:
  状态: 🟡 规划中 (保持不变)

所有任务完成:
  状态: 🟢 已修复 (手动更新)

/bug-archive 后:
  移动到: resolved/{version}/
```

## 错误处理

| 错误类型         | 处理方式                             |
| ---------------- | ------------------------------------ |
| Bug 不存在       | 报错：Bug 不存在于 active/ 目录      |
| bug.md 信息不全  | 警告：建议先完善 bug.md              |
| 找到多个匹配 Bug | 显示列表，让用户选择                 |
| solution.md 已存在 | 询问是否覆盖                       |

## 相关命令
