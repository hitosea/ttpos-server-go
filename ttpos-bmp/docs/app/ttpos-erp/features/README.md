## 服务架构

### 服务注册模式
所有服务都采用接口定义 + 实现注册的模式：
```go
// 定义接口
type IService interface {
    Method(ctx context.Context, req *Request) (*Response, error)
}

// 注册实现
service.RegisterService(serviceImpl)

// 获取服务实例
svc := service.Service()
```

### 上下文传递
所有服务方法都需要传入 `context.Context` 对象，用于：
- 请求链路追踪
- 超时控制
- 取消信号传递
- 元数据传递

## 数据流转

### 采购到库存流程
```
材料请求 → 采购订单 → 采购收货 → 库存入库
```

### 销售到出库流程
```
销售订单 → 送货单 → 库存出库
```

### 内部调拨流程
```
物料调拨 → 内部销售订单 → 内部采购订单 → 送货单 → 采购收货
```

### POS 销售流程
```
开帐 → POS 发票 → 支付 → 关帐
```

## 注意事项

1. **服务依赖**: 部分服务之间存在依赖关系，需要按顺序初始化
2. **事务处理**: 涉及多个服务的操作需要考虑事务一致性
3. **权限控制**: 所有操作都应该经过权限校验
4. **错误处理**: 统一的错误处理和日志记录
5. **性能优化**: 注意缓存使用和数据库查询优化
